1 · Three-state theming

BUILD.md §2.1, verbatim: “Three-state theming: bare :root = light; @media (prefers-color-scheme: dark) guarded with :root:not([data-theme="light"]); :root[data-theme="dark"] for the explicit toggle. Never define a color only inside a dark block.” That is the shape WO-029 ships, and WO-029's test collects every custom property named in any block and asserts each is present in :root. 

:root { /* light — every token, no exceptions */ }

@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) { /* dark overrides only */ }
}

:root[data-theme="dark"] { /* the explicit toggle — same overrides */ }

This sheet uses [data-pane] scopes instead, so both themes render at once whatever your OS is set to. The dark-only rule is still enforced structurally: the two blocks in this file's <style> declare an identical token list in an identical order, so an omission shows up as a diff.

Light is 0 1px 3px rgb(24 24 48/.045) — tuned for a light ground and invisible on #0e1116. §2.1 states no dark replacement and, unlike the -bg/-line case, no rule for deriving one. Bites every card in dark mode.

card

8.2  Dark --ring-accent

Light is 0 0 0 3px rgb(91 75 224/.18) — the light accent at 18%. The dark accent is #9bb4ff, a different hue. §2.1 states neither a dark value nor a derivation rule. Bites every focus ring and today’s ringed cell in the calendar grid.

A — ruled

0 0 0 3px rgb(155 180 255/.18)

today

The light construction applied to the dark accent — the mechanical answer, and the one closest to the 12%/28% precedent §2.1 already set.

B — not taken

0 0 0 3px rgb(155 180 255/.32)

today

Same geometry, raised alpha: a translucent light ring reads weaker on a dark ground than on a light one.

C — not taken

0 0 0 2px var(--bg), 0 0 0 4px rgb(155 180 255/.55)

today

Offset ring — highest contrast, best for keyboard focus, loudest for a calendar cell that is always on screen.
