16 · State coverage against rule 7.3

Rule 7.3: “Every data view specifies loading, empty, and error states.” Drawing the set is what makes the holes visible. Six of the fifteen are data views; this is what each of them actually carries.

Data viewLoadingEmptyError / degraded
Card— not registered— not registereddegraded — one written line
Alertn/athe empty state is an Alert; tone neutral or oktone warn or bad, message required
Stat— not registeredmeasured-zero prints 0 — a measurement, not an emptyunmeasured prints — plus the reason
Table— not registered, and “never a skeleton” rules out the usual answercaller-supplied written line— not registered
Progressdeterminate only — an indeterminate bar is refused by contractn/an/a
Stepsactive stage, every stage namedn/a— a stage that failed has no registered state

the finding No registered primitive carries a loading state. Steps is the only registered thing that shows work in progress at all, and it does it by naming stages, which is the right answer wherever the stages are known. Where they are not, the registry has nothing — and Progress refuses to be it, by its own rule. Two smaller holes sit beside it: Table has no error state, and Card has neither loading nor empty.

These are recorded, not filled. A state invented in a preview is a contract nobody agreed, which is the failure this gate exists to catch.

17 · Deliberately not drawn

Five things a work order consumes that no blueprint declares. None may be used until approved, so none is drawn as if it worked. This sheet neither settles nor styles them.

#WantedWhere it stands
1AiDotMatrix — three-state cell + row identity A boolean cell cannot hold three states and cannot say whose row it is. Fixed in its own work order; the surface sheet, not this one, draws it.
2Textarea (Markdown editor) The registered set has input and no multi-line control. The draft editor cannot be built from the registered fifteen.
3CodeBlock Verbatim, copyable, multi-line. Kbd is an inline key cap; the custom-CSS allowance lists five surfaces and a code block is not among them.
4Indeterminate “still running” affordance The waiting frame renders no elapsed, estimate, countdown, clock or percentage, so Progress cannot serve it — and an unlabelled spinner is forbidden. That frame has named stages, so Steps may be the answer; that is a decision to take, not an omission to paper over. §16’s finding is the same hole seen from the other side.
5TabBar (narrow-viewport nav) If it is a shell-local composition over registered Tabs with no custom CSS, no row is needed and the boundary should say so. If it needs custom CSS it is a sixth custom surface the design system does not admit. A boundary call, not a styling one.

Also not on this sheet, and not gaps: the four custom surfaces (Sidebar, AiDotMatrix, CalendarGrid, DayPanel) and the five closed chart forms. They are their own preview sheets and they depend on the spacing scale and heading scale the specimen sheet leaves open — which is why they come after a signature here, not before.

Sign-off

A signature on this sheet flips all fifteen primitive rows in design/components.md from proposed to approved and releases WO-031 and WO-032 to implementation. It flips no custom surface and no chart form — those are four and five more rows on their own sheets. It settles none of §16's or §17's open questions; those are named so a signature here cannot be read as answering them.

Changes iterate on this file, never on production code. There is no production code.
