One decision, in §2. REQ-071 criterion 13 forbids a domain change being shown as movement in any form and requires every chart or series spanning that date to be broken at it — naming a rival distance explicitly. GrowthLine carries a gapped state; RivalSparkline does not, and it is the one component that renders a rival distance. §2 draws the two side by side, which is how the missing state is best judged. Everything else on this sheet is a drawing of a registered contract.

In place of the chart, not inside it. No axes, no empty grid, no zero line — a chart frame with nothing in it reads as a measurement of nothing, and that is a different claim. The written line carries the first-due date, which is the only fact there is.

Two clauses of BUILD.md disagree and this sheet takes the stricter one. §2.4: “Every bar and point direct-labelled (name + value).” §4.5 module 2, of this same chart: “endpoint labelled.” Drawn here with every point labelled, per §2.4, because it is the general rule and the one components.md cites. It is legible at seven weekly points; at fifty-two it will not be, and that is a real question for whoever draws the Overview surface — not this sheet, and not a value to guess. Reported, not resolved.

2 · The break — RivalSparkline beside GrowthLine

REQ-071 criterion 13, verbatim on the shape: “every chart or series that spans that date is broken at it and states that the domain changed on that date, no number, distance or point measured for the previous domain is joined to one measured for the new, a direction, run of weeks or verdict is computed only over a span that does not contain that date and is not stated at all where every available span contains it.”

GrowthLine has gapped series. RivalSparkline has absolute and ratio and no break at all — and a rival distance is what criterion 13 names. Below: the state it has, and the state it is missing, drawn to the same rule.

2.1  What drawing them side by side settled

#FindingWhat it changes
a A sparkline is too small to carry its own written statement. §2.4 allows one axis and no legend; there is nowhere inside a 120×32 viewBox for “the domain changed on this date”. The break must therefore be drawn in the SVG and the statement rendered beside the row — the same shape GrowthLine’s gapped state already has (“that week’s own account beside it”) RivalSparkline’s gapped state needs a required account node, not just a break in the path. Proposed in §9
b The break silences the delta badge. §4.5 module 4 pairs each rival with a was 276× success badge; that is a direction over a span, and criterion 13 forbids one computed across the change date and forbids restating it over a shorter span The gapped state must not accept the was-badge, not merely omit it by convention. A prop that cannot be passed is the only version of this rule a test can hold — the same shape as the rival’s missing Tone
c The break mark reads at sparkline size — a dashed --ink-3 rule through the plot, in both themes. It is not a series colour and must not be: §2.4 admits exactly two, and a third stroke colour for a break would be a third series to a reader Nothing. The two-colour rule survives contact with the break, which was the risk worth checking
d Neither break is red, and neither carries a tone. A domain change is not a failure and not the customer’s problem — §2.5’s red is reserved, and the rival series has no Tone to pass in the first place Nothing. Recorded because a “something is wrong here” mark is exactly where a red would get added later

Outside this sheet, and reported once. Finding (b) reaches further than a chart. §4.5’s Overview head carries “▲ every week since you started” — a streak, and criterion 13 says a run of weeks spanning the change date “is not stated at all where every available span contains it”. That badge belongs to the Overview surface blueprint, not to any of the five charts, so this sheet does not draw it. It is named here so it is not lost: a chart that breaks correctly beside a head that still claims a streak is a worse defect than either alone.

8 · Loading, empty, error

Rule 7.3 requires all three of every data view, and all five of these are data views. previews/WO-033.html §7 proposes the general rule — a surface that is re-measuring keeps showing the last measurement and says which one it is showing, never a skeleton and never a spinner. That proposal covers loading here too and is not restated. What is specific to charts:

ChartEmptyError / degraded
GrowthLine registered no-measurement — one written line carrying the first-due date, in place of the chart. Drawn in §1 §4.1’s degraded rule: the section is absent with one written line, warn. Never a chart frame with nothing in it
PresenceBars A zero is a measurement, not an empty — §3. There is no empty state, and that is correct: if no rival was derived, the module does not render Same degraded rule
RivalSparkline No rival set is a state of the module, not the chart. REQ-071 c16 gives it its own written line Same degraded rule
AiDotMatrixChart A matrix over zero AI-answering questions is the denominator line’s to state — §6.2 requires the denominator anyway Same degraded rule
WeekStrip No empty state exists: seven days always render, and a day with nothing measured is a labelled mark — §6 Same degraded rule

No chart on this sheet has a loading state of its own, and none should: a chart is handed its series. What is loading is the module around it, which is the surface blueprint’s and is answered by previews/WO-033.html §7.1. Recorded so the absence is a decision and not an omission.
