# REQ-052 — A generated page answers the question before it names the product

> Superseded by REQ-050, which absorbed this requirement's acceptance criteria
> verbatim (2026-08-30; see `requirements/history/REQ-050-2026-08-30-requirement-cleanup.md`).
> Retired in place; cite REQ-050, not this file.

- Priority: Must

## User story
As a paying customer, I want every page to answer the search that brought the
reader there before it mentions my product, so that what I publish is useful on
arrival and is not a doorway built to funnel people elsewhere.

## Rationale
A page that leads with the brand instead of the answer is a doorway page — the
failure mode that gets a customer's whole site penalised rather than one page —
text a reader cannot see and text written at a machine rather than at the reader
are the other halves of the same abuse, so all three are gated before a draft can
reach the customer, and none of the three is ever turned on the customer's own
words. Source: `BUILD.md` §8 ("Not a
doorway: answers the target question before naming the product (checked: first
300 chars contain no brand mention)") and §14 (no prompt-shaped tricks, no hidden
instructions, in any generated page).

## Acceptance criteria
1. Given a draft is generated, when it is checked, then the customer's brand — the
   business name and the domain recorded for their site — is not named, in any
   letter case, within the first 300 characters of the page as a reader reads it:
   the words the published page shows, not the Markdown syntax that produces them.
2. Given a draft is generated, when it is checked, then the text ReachKit would
   hand to the destination — the draft's Markdown and any markup embedded in it —
   carries nothing a reader of the published page would not see: no embedded
   markup positioning text off-screen, sizing it to zero or colouring it to match
   its background, no comment, and no alternative text, caption or title text
   carrying anything but a description of what it labels. A hyperlink and the
   address it points at are not text this criterion restricts — REQ-050
   criterion 3 and REQ-051 criterion 1 both require a draft to carry links.
3. Given a draft is generated, when it is checked, then it carries no sentence
   addressed to a machine reader rather than a human one — no instruction,
   directive or assertion aimed at an assistant, a crawler or a ranking system
   about how to treat, cite, rank or recommend the page.
4. Given the customer edits a draft, when the edited text names their brand
   within its first 300 characters, then the edit is saved and neither held nor
   stopped for it: criteria 1 to 3 bind what ReachKit generates, not what the
   customer writes on their own site.
5. Given a draft that fails any of criteria 1 to 3, when the pipeline finishes,
   then the draft is not queued for review, no part of it is published or handed
   to a destination, and the item follows the hard-rule recovery path (REQ-053
   criterion 3).

## Non-goals
- How a destination's own theme renders the page it was handed (REQ-060) — this
  check binds the text ReachKit produces, not the site it lands on.
- Enforcing a house structure or word count on the page.
- Making a page more likely to be cited by structuring it well, which the product
  does deliberately — criterion 3 bars only text that speaks to the machine
  instead of the reader.
