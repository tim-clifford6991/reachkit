# REQ-046 — A draft is edited as Markdown with a live preview, and saves itself

- Priority: Must

## User story
As a paying customer, I want to change a draft's wording in Markdown and see the
rendered page as I type, so that I can fix a sentence in a minute without
learning an editor or losing my work.

## Rationale
Most reviews end in a small change rather than a veto, so the edit path must be
fast and lossless; it must never leave a stale check result attached to text the
customer has since altered and never throw away the customer's own words, while
the rule deciding when a page becomes publishable stays REQ-057's. Source:
`BUILD.md`
§4.6 (Markdown textarea with a live preview pane, autosaved, no rich-text editor;
an edited draft keeps its grounding highlight if the fact survives the edit and
drops the claim-check badge until the check re-runs on save).

## Acceptance criteria
1. Given a draft awaiting review, when the customer chooses to edit it, then they
   edit its Markdown and see the rendered result of their changes as they type.
2. Given an edit in progress, when the customer pauses or leaves the view, then
   the change is saved without an explicit save action and is present when they
   return; where two sessions edit the same draft, the most recently saved
   version is the draft.
3. Given a save does not land, when the customer is still in the view, then they
   are told the change is unsaved, and no text that failed to save is ever
   published.
4. Given an edited draft, when it is saved, then the grounding is still marked if
   the grounded fact survives the edit, and is no longer marked if the fact was
   removed.
5. Given an edited draft, when the edit is saved, then a claim check is run
   against the text as saved and its outcome is shown when it completes; until
   then no claim-check outcome is shown for that draft.
6. Given an edited draft, when its veto window expires, then it does not publish
   unless no edit is unsaved and a claim check has completed and passed against
   the text as it then stands — so text no check has run against never publishes;
   whether and when it publishes afterwards follows REQ-057 criterion 2's single
   rule for becoming publishable, and nothing here releases it earlier.
7. Given the check fails on an edited draft, whoever wrote the matching text,
   when the check completes, then a claim re-check stands outstanding on that
   draft until one passes against the text as it then stands, so the draft does
   not become publishable (REQ-057 criterion 2); it is never regenerated, and it
   is returned to the customer naming the entry it matched, with their own text
   intact, so no draft is ever held without the customer being told which entry
   held it.

## Non-goals
- A rich-text or WYSIWYG editor.
- Inserting images or media.
- Simultaneous editing by more than one person, comments, or suggestion mode.
- Merging two concurrent edits of the same draft.
- Version history browsing or diffing.
- Two-column versus tabbed layout — design system.
