# REQ-002 — A domain's owner can have the report about their domain removed, on written request to the address the report names

- Priority: Must

## User story
As the owner of a business somebody else scanned, I want the report about my
domain to name an address I can write to and to be gone within five working days
of my asking, so that a permanent public verdict about my business is never
something I have no way to stop.

## Rationale
A report is a public verdict about somebody else's website, published without
their asking, so whoever owns that domain must have a route to end it that they
can find on the page itself and that finishes inside a stated time — a promise
whose address is not on the page is a promise nobody can reach. In v1 that route
is one written request, judged by a person: nothing in the product removes a
report by itself, no report is taken down at ReachKit's own initiative, and the
line that replaces a removed report names the same address, so an owner who
changes their mind finds the way back where they will look for it. Whether report
pages are indexed at all is REQ-001 criterion 8's, and what any reader may correct
on a free report is REQ-094's. `BUILD.md` states no removal path anywhere; this
requirement, not the specification, is the authority for it. Placement: JN-006
steps 3 and 4. No implementation exists to touch: this repo carries no `src/`.

## Acceptance criteria
1. Given any report, when it renders, then it names in writing the address to
   which a request to remove the report about that domain is sent, readable by a
   visitor with no account, session, or payment.
2. Given a removal request for a domain received at the address criterion 1
   names, when it is granted, then within 5 working days of its receipt the
   report is no longer readable at its address.
3. Given a domain whose report has been removed, when its report address is
   opened, then it shows the removed report to nobody and starts no scan for
   anyone, on that visit or any later one, and in its place one written line says
   the report was removed at the domain owner's request and names the address
   criterion 1 names — until a request to that same address asks for that domain
   to be scannable again.
4. Given a domain whose owner has made no removal request, when its report
   address is opened, then no report is withheld this way: a report is taken down
   only by a removal request received at the address criterion 1 names, never at
   ReachKit's own initiative.

## Non-goals
- No self-service removal: no control in the product takes a report down, and a
  removal request is judged by a person.
- No proof that a requester controls the domain in v1 — no DNS TXT record, no
  confirmation link to a mailbox at the domain, no verified-owner session.
  Proving control as a mechanism is deferred to v1.1, and everything that would
  rest on it with it.
- No correcting of a report by the domain's proven owner, and no category a
  proven owner sets that binds later free scans: deferred to v1.1 with the proof
  that would authorise it. What any reader may correct on a free report is
  REQ-094's and is unaffected.
- No removal, hiding, or de-listing of a report at ReachKit's own initiative —
  stated as criterion 4, not left to this list.
- Whether report pages are indexed by search engines at all — REQ-001 criterion 8.
- No acknowledgement, status page, or progress tracking of a removal request
  while it is open: the promise is the outcome inside 5 working days, not a
  receipt.
