# REQ-012 — A return visit reads the stored report instead of re-running the scan

> Superseded by REQ-001, which absorbed this requirement's acceptance criteria
> verbatim as its criteria 12–18 (2026-08-30; see
> `requirements/history/REQ-001-2026-08-30-requirement-cleanup.md`). Retired in
> place; cite REQ-001, not this file.

- Priority: Must

## User story
As a founder who opens my report again a few days later, or after a scan of my
domain failed, I want to see the report I already have and decide myself when to
re-measure, so that the page is never re-running work I did not ask for.

## Rationale
A founder who opens their report again must see the report they already have,
dated, and decide for themselves when to re-measure: a page that silently
re-measures on every visit shows different numbers each time with no way to tell
what changed, and a failed domain that auto-retries on every reload turns one
bad fetch into a loop the visitor cannot stop. Source: `BUILD.md` §6.4 (the
7-day free re-scan window and the 24h failure cooldown) and §4.1 States
(cooldown).

## Acceptance criteria
1. Given a domain whose scan produced a stored report less than 7 days ago —
   whether it measured everything or only part of it (REQ-005) — when anyone
   opens its report address, then that stored report is shown with the date it
   was measured and no new measurement runs.
2. Given a stored report less than 7 days old that measured everything it set
   out to, when it is shown, then no re-scan control is offered.
3. Given a stored report that is incomplete — because part of it could not be
   measured (REQ-005), or because the scan stopped early at the 90-second
   ceiling (REQ-003 criterion 5, "when it reaches 90 seconds, then measuring
   stops") or the free path's spend ceiling (REQ-015 criterion 6, "reaches its
   spend ceiling while it is running") — when it is
   opened at any age, then one written line says it is incomplete and a re-scan
   control is offered, and the stored report stays readable until the visitor
   chooses to re-scan.
4. Given a stored report 7 days old or older, when it is opened, then a re-scan
   control is offered and the stored report stays readable until the visitor
   chooses to re-scan.
5. Given a domain whose scan failed without producing a report less than 24
   hours ago, when its report address is opened, then one written line says what
   happened and a manual retry control is offered, and no scan starts by itself.
6. Given a visitor who starts a re-scan, when it runs, then the stored report
   and its measurement date stay readable until a new report replaces them, and
   if the re-scan does not complete the previous report remains at that address.
7. Given a domain whose report was removed at its owner's request (REQ-002
   criterion 8, "shows the removed report to nobody and starts no scan"), when
   its report address is opened, then no stored report is shown, no re-scan or
   retry control is offered, and no scan starts — criteria 1 to 6 offer no route
   back to a removed report.

## Non-goals
- No scheduled or automatic re-measurement of a free report.
- No notification, email, or badge when a stored report becomes stale.
- No history of previous free reports for the same domain; one stored report per
  domain.
