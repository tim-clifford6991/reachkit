## Goal
Create the `drafts` core table with the columns that make an invented author unrepresentable and a grounded passage unrewritable, and the closed hard-rule vocabulary every rule module reports through.

## Steps
1. Write both test files first and run them: the schema test must fail on a missing table and the types test on a missing module.
2. Write the migration. The passage trigger compares `new.grounded_fact->>'passage'` with the old value and raises on a difference — the same shape as WO-181's acceptance trigger, and for the same reason: a statement the customer can still read against needs the copy to be unarguable.
3. Create `rules/types.ts` with BP-042's block verbatim, plus `SiteRuleInputs`.
4. The `information_schema` assertion is the test of record for c4's first half. It is a test about the schema, not about prose, because BP-042 decision 2 makes the absence of a field the enforcement ("adding an author field to `drafts` would silently re-open c4").
5. Run the tests. Then mutate: add an `author text` column in a scratch migration and confirm the schema test fails.

## Test plan
> Watch it fail first (constitution §8): every test below is written and
> run against the absent implementation before the implementation exists.

| Acceptance criterion (verbatim from REQ) | Test |
|---|---|
| **REQ-050 c1** Given a draft is generated, when it is queued for review, then it carries at least one statement of fact drawn from a page on the customer's own live site, stored with that page's URL, the date it was read and the passage it was drawn from copied word for word from the content fetched that day; the passage is kept unchanged from then on, so the statement can still be read against it after the customer's own page has moved on. | `schema.test.ts › an update to grounded_fact's passage raises` — the storage half; the rule that requires the fact is WO-192's |
| **REQ-050 c4** Given a draft is generated, when it is queued for review, then the only author it may attribute itself to is the customer — the business name or account-holder name recorded for their site — and it carries no other byline, no author biography and no persona; and every person it names or quotes other than the customer themselves is named in a public page the draft links. The customer's own attribution needs no such link. | `schema.test.ts › drafts holds no author, byline, bio, persona or contributor column` — the field-absence half; the quotation half is WO-193's |
| **REQ-050 c11** Given the site has no recorded business name or account-holder name to attribute to, when a page publishes, then it publishes with no author attribution rather than a generated one. | `schema.test.ts › attribution accepts null and the row inserts` — a site with nothing to attribute publishes with no attribution rather than a generated one |

**Discriminates (mutation check, constitution §8).**
- Adding any author-shaped column makes `schema.test.ts › drafts holds no author … column` fail; a prose-scanning test would not notice, which is why the assertion reads the catalogue.
- Dropping the passage trigger makes the c1 storage test fail — application-level guarding cannot make it pass, because the test issues the update directly.
- Making `attribution` `not null` makes the c11 test fail at insert.
