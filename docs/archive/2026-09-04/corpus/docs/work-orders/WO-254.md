# WO-254 — `StoredReport` and `readCurrentReport`

- Branch: wo/WO-254-stored-report
- Estimate: ≤1 day

## Goal
Declare the versioned report blob in the one place that writes it, ship the read
of the current report for a domain, and put the "one current report per domain"
promise in a partial unique index rather than in application logic.

## Provenance of this file plan
**This repository holds no `src/` and no `supabase/`.** All four paths are NEW.
`src/lib/scan/` is BP-012's row in `structure.md` ("The one scan pipeline — tier
is a parameter — plus free-path admission control, the time and spend ceilings,
degradation, and **the stored report blob**"), and BP-012's `code:` globs are
`src/lib/scan/**`, `supabase/migrations/*_scans*.sql` and `tests/scan/**`.
`report.ts` and `tests/scan/report/**` are claimed by no leaf: BP-023's `code:`
names four files and `tests/scan/free/**`, BP-036's is `src/lib/scan/deep/**`,
BP-050's is `src/lib/scan/weekly/**`.

**The migration's sub-token.** `<timestamp>_scans_current.sql` sits under
BP-012's own `scans` topic. `structure.md` rule 3a: "A sub-token is not a new
topic and needs no entry in the closed list." It is deliberately **not**
`scans_verdict`, which is BP-024's `code:` glob and WO-055's file.

**Reuse check (rule 7.2).** `capabilities.md`'s row "One current stored report
per domain · `src/lib/scan/` · BP-012 · `readCurrentReport()` · consumers
BP-001, BP-004" names this seam and **no work order authors it**: eleven work
orders name `readCurrentReport` (WO-015, WO-061, WO-110, WO-152, WO-156,
WO-184, WO-185, WO-186, WO-189, WO-191, WO-192) and every one of them is a
consumer; nine name `StoredReport` and copy BP-012's declaration into a
`## Interfaces` block without creating it. No file-plan row in the corpus names
`src/lib/scan/report.ts`. This work order creates the indexed capability.

**The columns.** BP-012's `## Data model delta` enumerates them: "`scans` — as
`BUILD.md` §10, plus `is_current` (partial unique index on `domain` where
`is_current`), `supersedes_scan_id`, `correction_state`, and `stopped_reason`".
No work order in the corpus writes them and two rest on their existing:
WO-055 and WO-056 both carry a `rests-on` row naming all four, and WO-056's
`## Out of scope` says "The `stopped_reason`, `is_current`, `supersedes_scan_id`
and `correction_state` columns — BP-012's, already declared there." This
migration is that file. (BP-002's data-model table assigns two of the four to a
different node; see the return.)

**Status.** Left `status: draft` — written and not self-certified in the same

## Interfaces

**Consumes:** `Measured<T>` (WO-052) and the nine section types named in the file
plan, each imported from its declaring node's file and restated nowhere here —
BP-012 decision 3: "every field is a type another node already declares, so a
section's shape changes in one place and this composition follows."

**Exposes** (verbatim from BP-012's `## Public interface`):
```ts
export type Tier = 'free' | 'deep' | 'weekly'

/** The versioned report blob `BUILD.md` §10 names ("report jsonb(versioned blob:
 *  measurements, questions, answers, market set)"), declared here because this
 *  node assembles it and is the only writer. Five blueprints named this type and
 *  none declared it; consumers were reading it through locally-invented reader
 *  interfaces, which is the second copy rule 2.4 exists to prevent.
 *
 *  Every section is a type its own node already owns. This node composes and
 *  stores; it defines none of the section shapes and re-derives no figure. A
 *  section that could not be measured is present with its `Measured` arms
 *  saying so — a section is never omitted, because an absent key and a
 *  `not_attempted` value read the same to a consumer and REQ-004 forbids that. */
export interface StoredReport {
  version: number                        // the blob is versioned; readers branch on nothing else
  scanId: string
  domain: CanonicalDomain                // ADR-020's one canonical key
  measuredAt: Date                       // one date; every figure under it is this scan's
  tier: Tier
  complete: boolean                      // false where `stopped_reason` is a ceiling or a failure
  stoppedReason: 'complete' | 'time_ceiling' | 'spend_ceiling' | 'failed'
  fromIncompleteRescan: boolean          // REQ-001 c14's re-scan control reads this
  verdict: Verdict                       // BP-024 — score, band, factors, missing, blockedReaders
  market: Measured<SuggestionRow[]>      // BP-025 — the measured market set
  questions: Measured<Question[]>        // BP-025 — the twelve, or as many as the market yielded
  answers: AiAnswersCard                 // BP-025 — REQ-006 c1's denominator lives in here
  serps: readonly Measured<SerpResult>[] // BP-026 — the bought top-tens, per target search
  rivals: Measured<RivalCandidate[]>     // BP-026
  rivalSizes: Measured<RivalSize[]>      // BP-052 — absent on the free path by REQ-096's non-goal
  onPage: OnPageFacts                    // BP-010
  robots: Measured<RobotsPolicy>         // BP-006's type, BP-010's measurement
  correctionState: CorrectionState       // BP-028's value domain, stored on the scan row too
}
export function readCurrentReport(domain: string): Promise<StoredReport | null>
```

> **The `market` / `Profile` disagreement, and what this file does about it.**
> Three blueprints describe the same section three ways (second `rests-on` row).
> This file ships **BP-012's** declaration verbatim, on BP-012 decision 3's own
> ownership ground, and therefore **the blob carries no `Profile`**. That is
> exactly the condition WO-183 wrote its stop condition against, and **that stop
> condition stands unchanged**: `rankOpen` reads the profile through
> `readCurrentReport` if the shipped `StoredReport` exposes one, and otherwise
> its implementer stops and logs `failed`, never calling `deriveProfile` (a
> vendor call on a read path) and never assembling a partial `Profile` (a
> fabricated drop set silently changes which searches score zero). Nothing in
> this work order relaxes it. The implementer of **this** file does not add a
> `profile` field to make WO-183 pass — widening `StoredReport` is BP-012's
> author's, and a field added here to unblock a consumer is the fourth
> description of one section.

## Steps
1. Write both test files first and run them; the schema suite must fail on a
   missing migration and the read suite on a missing module (constitution §8).
2. Write the migration. The partial unique index is the point: BP-012 decision 1
   — "a partial unique index, not application logic, enforces one current
   report" — so no trigger, no application-level lock and no `select … for
   update` appears anywhere in this work order.
3. Declare `Tier` and `StoredReport` in `report.ts`, importing all nine section
   types. Re-declare none of them, not even structurally.
4. Implement `readCurrentReport` as one indexed read. A domain with no current
   row returns `null`; there is no second query and no latest-scan fallback —
   BP-012 decision 1 rejected exactly that ("a 'latest scan wins' read-side
   query — rejected, a failed re-scan then becomes the report").
5. Implement the version guard: an unknown `version` throws naming the version
   and the scan id, rather than returning a value with fields missing. BP-012's
   own comment fixes the rule — "readers branch on nothing else".
6. Mutate to prove the suite discriminates: (a) drop the `where is_current`
   predicate from the index and confirm the two-current-rows case passes an
   insert it should reject; (b) make the version guard return `null` instead of
   throwing and confirm the guard row fails, since `null` is indistinguishable
   from "no report" at every call site.
