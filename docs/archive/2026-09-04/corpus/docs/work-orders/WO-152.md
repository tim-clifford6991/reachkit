# WO-152 — The release notice: one sentence projected from the current report, never a stored flag

- Branch: wo/WO-152-release-notice
- Estimate: ≤1 day

## Goal
Return the one written sentence that travels with the founder into the app —
what could not be measured, or that the measurement did not complete — derived
from the current report so it disappears the moment that stops being true.

## File plan
> Every path below is **NEW** (no `src/` on disk, checked 2026-08-31). Placement
> follows `structure.md` and BP-036's `code:` globs; provisional.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/scan/deep/notice.ts` | NEW | `releaseNotice()` — reads BP-012's `readCurrentReport()` and returns a copy key plus vars only while that report's status is `degraded` or `failed`; returns `null` otherwise. It stores nothing and reads no flag (BP-036 decision 3). The `unmeasured` parts of the report supply the vars. |
| `tests/scan/deep/notice.test.ts` | NEW | Key selection per report status, disappearance on a later good report, and the no-stored-flag property. |

## Interfaces
Consumes: `readCurrentReport()` (BP-012), `CopyKey` / `copy()` (BP-019),
`accountForWeek` is **not** consumed here — a later weekly pass moves BP-012's
current-report pointer and this function re-derives from it.

Exposes (verbatim from BP-036 `## Public interface`):
```ts
/** REQ-029 criteria 3, 5 and 6: the one written sentence that travels with the
 *  founder into the app, on every screen they arrive at, until it stops being
 *  true. Derived from the current report, never from a stored flag (decision 3).
 *  Returns null when there is nothing to say. */
export function releaseNotice(siteId: string):
  Promise<{ key: CopyKey; vars: Record<string, string> } | null>
```

## Steps
1. Write the failing tests first.
2. Implement `releaseNotice` as a read of the current report: `degraded` → the
   what-could-not-be-measured key with the unmeasured parts as vars; `failed` →
   the measurement-did-not-complete key; `done` → `null`.
3. Create the copy **keys** in BP-019's registry request (keys and their tests
   only — the strings are the owner's; never write a sentence here).
4. Assert the notice is a projection: move the current-report pointer to a
   `done` report and confirm the notice becomes `null` with no write anywhere.
5. Assert the notice invents nothing when the report found zero opportunities —
   the emptiness is stated through REQ-095's lines in BP-019, and this function
   produces no page, proposal, rival or number.
6. Mutation check: cache the notice in a module-level variable and confirm the
   disappearance test fails.
