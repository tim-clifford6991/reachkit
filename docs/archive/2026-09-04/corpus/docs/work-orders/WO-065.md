# WO-065 — `unblockLines` — the verbatim paste block, composed from the one pinned agent list

- Branch: wo/WO-065-unblock-lines
- Estimate: ≤1 day

## Goal
Compose the exact directives a founder pastes into their own robots file, one per
blocked reader, in list order, from the single pinned agent list and from no
other source — and assert them character for character.

## File plan

> Every path below is **NEW**. Verified 2026-08-31: this repo carries no `src/`.
> Placement per `structure.md`; `_problems/` is BP-027's private folder inside
> BP-001's `src/app/(public)/**`. Provisional against a repo with no code.

| File | New/Modify | Change |
|---|---|---|
| `src/app/(public)/scan/[domain]/_problems/unblock.ts` | NEW | `AiReaderAgent` and `unblockLines`. `AiReaderAgent` is derived as `(typeof AI_READER_AGENTS)[number]` — the type follows the pin, so a new member needs no edit here. `unblockLines` emits one directive per blocked member, in `AI_READER_AGENTS` order, with no per-report variation beyond which agents are blocked. No model call, no template read from data, no string assembled from a report field. |
| `tests/app/problems/unblock.test.ts` | NEW | The character-for-character fixture, the ordering and closure suites, and the no-model assertion named in the test plan. |

## Interfaces

Consumes: BP-005's `AI_READER_AGENTS`.

Exposes (verbatim from BP-027 `## Public interface`,
`src/app/(public)/scan/[domain]/_problems/unblock.ts`):

```ts
/** The lines a founder pastes, composed from BP-005's pinned agent list
 *  (ADR-022) and never from a model. Verbatim, in paste order, one directive
 *  per line — a wrong robots line is worse than none. */
export function unblockLines(blocked: readonly AiReaderAgent[]): readonly string[]
```

`AiReaderAgent` is not separately declared in any blueprint; it is derived here
from BP-005's pin as `(typeof AI_READER_AGENTS)[number]`, so the type and the
membership cannot drift apart. BP-005 owns the value; this file owns neither.

## Steps
1. Write the failing fixture suite first.
2. Derive `AiReaderAgent` from the pin.
3. Implement `unblockLines`: filter `AI_READER_AGENTS` to the members present in
   `blocked` — iterating the pin, not the argument, so the output order is always
   the pin's — and emit the robots directive pair for each, one directive per
   line. Emit nothing for an agent that is not blocked.
4. Return an empty array for an empty input. The caller (WO-064) never reaches
   this function on a `zero` or `unmeasured` count, but the function is total.
5. Add the fixture: the expected block for a given `blocked` set, asserted with a
   character-for-character equality against a checked-in fixture file rather than
   a per-line regex — BP-027's "asserted character-for-character in a fixture
   test".
6. Add the source assertion that no agent name is written anywhere in `src/`
   outside BP-005's `constants.ts`.

| Acceptance criterion (verbatim from REQ) | Test |

| REQ-009 c8 — "… and it follows that problem's own count and nothing else … of any two reports the one with the larger count for the same problem never carries the lower severity." | `unblock/lines · the set the lines are drawn from is the set the count is over` — asserts that `unblockLines` iterates `AI_READER_AGENTS` and that the returned line count equals the number of blocked members, so the paste block and WO-055's `blockedReaders` count can never disagree about the denominator (ADR-022 decision 5's property, asserted here on this side of it). |

| REQ-009 c5 — "… and neither lists or previews the pages themselves." | `unblock/lines · the block contains no page` — every returned line is asserted to be a robots directive over an agent token, and asserted to contain no URL path, no page title and no domain of the scanned site. |
