# WO-211 — The publishing ceilings — one a day, eight a week, Monday-start, in the customer's own zone

- Branch: wo/WO-211-publish-ceilings
- Estimate: ≤1 day

## Goal
Ship `ceilingRoom()`: the per-day and per-week publication counts, counted in the customer's own time zone on a Monday-start week, reading their limits from BP-005 so no setting can raise them.

## File plan

> This repository carries no `src/`, no `tests/`, no `supabase/` and no
> `package.json` (verified 2026-08-31). **Every path below is NEW** — none was
> verified to exist, because none can. Placement is anchored to
> `sdlc-factory/docs/registry/structure.md` and to this work order's blueprint
> `code:` globs, and is provisional against a repo with no code: if the
> implementer finds a file already present at one of these paths, they stop and
> log `failed` naming the drift rather than merging into it.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/publish/ceilings/index.ts` | NEW | `ceilingRoom(siteId, at)`. Two independent counts over `publications` by `(site_id, published_at)`, each resolved into `sites.timezone`: the calendar day containing `at`, and the Monday-start calendar week containing `at` (BP-045 decision 3). Limits come from BP-005's `RATE_LIMITS`; this module exports no function that returns a rate and reads no per-site column that could hold one. A refusal returns `{room:false, blockedBy, nextFreeAt}` — a hold, never a failure. |
| `tests/publish/ceilings/ceilings.test.ts` | NEW | Fixtures at a fixed zone with a fixed clock: the day boundary is the customer's midnight and not UTC's; the week boundary is Monday 00:00 local; a page published Sunday local counts in the week that Sunday ends, not the one it begins; the two ceilings hold independently (eight in a week with a free day still refuses a second on that day, and one a day with seven already published refuses the ninth in the week); no value written to any `sites` column changes either limit. |

## Interfaces

**Consumes**

- `db()` under RLS — BP-002.
- `RATE_LIMITS` — BP-005, `src/lib/config/constants.ts`, asserted in `tests/pins.test.ts`.
- `sites.timezone` — BP-002's declared addition on the `sites` topic.
- The `(site_id, published_at)` index — WO-208.

**Exposes** — copied exactly from BP-045's `## Public interface`:

```ts
// src/lib/publish/ceilings/index.ts
export function ceilingRoom(siteId: string, at: Date): Promise<
  { room: true } | { room: false; blockedBy: 'day' | 'week'; nextFreeAt: Date }
>
```

**Reuse check (rule 7.2).** BP-057 owns `nextPublishTimeAtOrAfter` (WO-219),
which resolves a *publish time* in the customer's zone. That is a different
question from a *calendar boundary* in the customer's zone, and BP-045 owns the
week key (decision 3). This work order therefore computes its own boundaries and
does not call BP-057 — but it must use the same zone library and the same
`sites.timezone` value, and a test asserts the two agree on a fixed date. If a
later reader finds two zone helpers, the one to delete is not this one: the
ceilings must not become answerable to a settings module (REQ-070 c3).

## Steps
1. Create `ceilings/index.ts` with `ceilingRoom` and no other export.
2. Resolve `at` into `sites.timezone`, derive the local calendar day and the Monday-start local calendar week, and count `publications` with a non-null `published_at` in each.
3. Read the two limits from BP-005's `RATE_LIMITS`. If the pin is absent when the implementer starts, they stop and log `failed — next: wait on BP-005's pins work order`.
4. Compute `nextFreeAt` as the start of the next local day or the next local Monday, whichever the refusal names.
5. Write the boundary fixtures and watch the Sunday case fail against a UTC-week implementation (constitution §8).
