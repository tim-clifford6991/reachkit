# WO-141 — The danger zone and the export handover — two actions, one ticket, nothing destroyed before the archive is taken

- Branch: wo/WO-141-danger-zone-handover
- Estimate: ≤1 day

## Goal
Declare the two irreversible actions, build and hand over the customer's archive
before either can run, and issue a ticket that refuses to be confirmed until the
whole archive has left this process.

## File plan
> **Every path below is NEW.** No `src/` exists. Anchored to
> `registry/structure.md` (`src/lib/account/**` is BP-017's) and BP-063's `code:`
> glob `src/lib/account/lifecycle/**`. Provisional against a repo with no code.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/account/lifecycle/danger-zone.ts` | NEW | Exports `DANGER_ZONE` and `DangerAction` with BP-063's declarations verbatim — **exactly two members**, each carrying a `sentenceKey` and `accountSurvives`. Naming only: the sentences are the owner's, in BP-019's registry. Frozen; a third member is a change to this constant and to REQ-079 c1. |
| `src/lib/account/lifecycle/handover.ts` | NEW | Exports `beginDangerAction` and `markExportTaken` with BP-063's signatures verbatim. `beginDangerAction` calls BP-062's `exportEverything(siteId)` and, on `ok: true`, writes a `danger_tickets` row (`expires_at = now() + DANGER_TICKET_TTL_MINUTES`) and returns the ticket alongside the archive stream and filename. On `ok: false` it returns `{ ok: false, reason, lineKey: 'danger.export_failed' }` and **issues no ticket** — there is no override, no "delete anyway" and no support path around it in this module. `markExportTaken(ticket)` stamps `taken_at`; it is called by BP-001's download route only after the last byte has been written to the response without error (decision 1). Nothing is unpublished or deleted by any function in this file. |
| `tests/account/lifecycle/danger-zone.test.ts` | NEW | `DANGER_ZONE` has exactly two members, in order, with the declared action names, sentence keys and `accountSurvives` values; the constant is frozen; a source-level assertion that this file contains no sentence — only keys. |
| `tests/account/lifecycle/handover.test.ts` | NEW | A successful begin returns a ticket and an archive and writes **no** other change (a whole-database write capture asserts nothing but the ticket row changed); a failed export returns `danger.export_failed`, issues no ticket, and leaves publishing on and the account intact — for **both** actions; `markExportTaken` stamps `taken_at` once and is idempotent; a ticket expires after the pinned TTL; **the discriminating case**: after a begin whose archive was never taken, nothing in the account has changed. |

## Interfaces
Exposes (verbatim from BP-063's `## Public interface`):
```ts
export const DANGER_ZONE: readonly [
  { action: 'unpublish_all';   sentenceKey: 'danger.unpublish_all';   accountSurvives: true },
  { action: 'delete_account';  sentenceKey: 'danger.delete_account';  accountSurvives: false },
]
export type DangerAction = typeof DANGER_ZONE[number]['action']

export function beginDangerAction(a: { siteId: string; action: DangerAction }): Promise<
  | { ok: true; ticket: string; archive: ReadableStream<Uint8Array>; filename: string }
  | { ok: false; reason: ExportFailure; lineKey: 'danger.export_failed' }   // c3: the action does not proceed
>

export function markExportTaken(ticket: string): Promise<void>
```
Consumes (verbatim from BP-062's `## Public interface`):
```ts
export function exportEverything(siteId: string): Promise<
  | { ok: true; archive: ReadableStream<Uint8Array>; filename: string; pages: number }
  | { ok: false; reason: ExportFailure; lineKey: 'export.failed' }
>
```
Consumes BP-005's `DANGER_TICKET_TTL_MINUTES: 30`.

## Out of scope
- Confirming or performing either action — WO-142 and WO-143.
- The danger-zone card, its two confirmations and the download route that calls
  `markExportTaken` — BP-001's surfaces.
- Every sentence behind `danger.unpublish_all`, `danger.delete_account` and
  `danger.export_failed` — BP-019's registry; the owner's words.
- Building the archive itself — WO-139.
- What the ticket can prove. BP-063 decision 1 states the limit plainly: "the
  strongest available claim is 'the whole archive left our process for this
  customer's session', not 'the customer holds the file'." No test in this work
  order may claim more.
