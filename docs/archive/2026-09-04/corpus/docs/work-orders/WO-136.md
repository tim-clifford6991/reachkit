# WO-136 — issueLink, redeemLink, currentSession and signOut — the token is the only key

- Branch: wo/WO-136-links-and-sessions
- Estimate: ≤1 day

## Goal
Issue a single-use hashed token, redeem it exactly once into a session, read that
session on every authenticated request, and end it on sign-out — applying no
eligibility policy of this module's own.

## File plan
> **Every path below is NEW.** No `src/` exists. Anchored to
> `registry/structure.md` (`src/lib/account/**` is BP-017's) and BP-061's `code:`
> glob `src/lib/account/session/**`. Provisional against a repo with no code.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/account/session/token.ts` | NEW | A 256-bit random token, its SHA-256 hash, and a constant-time comparison. No salt (BP-061 decision 3: "no salt needed for a high-entropy secret"). Exports no function that returns a stored plaintext, because none is stored. |
| `src/lib/account/session/links.ts` | NEW | Exports `LinkPurpose`, `issueLink` and `redeemLink` with BP-061's signatures verbatim. `issueLink` writes the hash, `purpose`, `sent_to` and `expires_at` (from `SIGNIN_LINK_TTL_H` or `EMAIL_CHANGE_TTL_H` per purpose, both BP-005 pins), marks any previous unspent token for that `(user_id, purpose)` spent, and hands the plaintext to `sendEmail` with kind `magic-link`. **It applies no eligibility policy** — BP-061 decision 1 — and a test asserts it reads no account state beyond the row it writes against. `redeemLink` marks spent and creates a session inside one transaction; `expired`, `spent` and `unknown` all return the same `lineKey: 'signin.link_dead'`. The `email_change` completion branch is added by WO-137; this work order lands the `sign_in` path and leaves `purpose: 'email_change'` redeeming into a session at the address on the link with no `users.email` write. |
| `src/lib/account/session/session.ts` | NEW | Exports `currentSession()` and `signOut()` with BP-061's signatures verbatim. `currentSession` is cookie-verified with at most one indexed read (p95 ≤ 5 ms). `signOut` ends **this session only** — other devices keep theirs; REQ-077 states no global sign-out and none is invented. Session creation stamps `users.first_signed_in_at` on the first successful redemption (the column WO-124 adds and WO-128's chase reads). |
| `tests/account/session/links.test.ts` | NEW | Issue writes a hash and never a plaintext; the plaintext appears only in the argument handed to `sendEmail`; a second issue for one `(user_id, purpose)` spends the first, so the newest link is the working one; redeem succeeds once and the second use is `spent`; expiry at the pinned TTL; **the three indistinguishable-answer cases** — expired, spent and never-existed return the same reason shape and the same line key; a source-level assertion that `links.ts` imports nothing from `src/lib/account/billing/**` or `src/lib/account/provisioning/**` (decision 1's one-way dependency). |
| `tests/account/session/session.test.ts` | NEW | A session is created on redemption and readable afterwards; `first_signed_in_at` is stamped once and not re-stamped on a later sign-in; sign-out ends this session and leaves a second device's session working; `currentSession` returns null with no cookie, with a tampered cookie and with a cookie for a session already ended. |
| `tests/account/session/redaction.test.ts` | NEW | No log call in `src/lib/account/session/**` receives a token plaintext, a cookie value or a link URL, in any environment (BP-061's NFR budget). |

## Interfaces
Exposes (verbatim from BP-061's `## Public interface`):
```ts
export type LinkPurpose = 'sign_in' | 'email_change'

export function issueLink(a: { userId: string; to: string; purpose: LinkPurpose }):
  Promise<{ issued: true; expiresAt: Date } | { issued: false; reason: 'vendor' }>

export function redeemLink(token: string): Promise<
  | { ok: true; purpose: LinkPurpose; userId: string; session: SessionCookie }
  | { ok: false; reason: 'expired' | 'spent' | 'unknown'; lineKey: 'signin.link_dead' }
>

export function currentSession(): Promise<{ userId: string; siteId: string } | null>

/** REQ-077 criterion 5. Ends this session only. */
export function signOut(): Promise<void>
```
Consumes (verbatim from BP-016's `## Public interface`):
```ts
export function sendEmail(m: {
  kind: MailKind; to: string; subject: CopyKey; blocks: MailBlock[]
  suppressible?: false
}): Promise<{ sent: true; id: string } | { sent: false; reason: 'suppressed' | 'vendor'; retryUntil?: Date }>
```
with `'magic-link': { occasionsFrom: 'REQ-024, REQ-077', stoppable: false }`.
Consumes BP-005's `EMAIL_CHANGE_TTL_H: 24` and `SIGNIN_LINK_TTL_H: 24`.

## Out of scope

  BP-019's.

## Rollback
Delete three source files and three test files. Rows already in `auth_links` stay;
the table is WO-135's. A rollback in a live environment leaves customers holding
links nothing can redeem — the product has no other credential, so pair it with a
maintenance window.
