# WO-163 — The Overview screen: the landing page, its head, its week strip, its alerts

- Branch: wo/WO-163-overview-page
- Estimate: ≤1 day
- Preview: sdlc-factory/docs/design/previews/WO-163.html
- Signed-off: <date>

## Goal
Compose Overview as the screen a signed-in customer lands on — head line, the
modules, the seven-day strip, the alerts and the one supply or stopped-work
statement.

## File plan
> Every path below is **NEW** (no `src/` on disk, checked 2026-08-31). Placement
> follows `structure.md` and BP-038's `code:` globs; provisional.

| File | New/Modify | Change |
|---|---|---|
| `src/app/(account)/app/overview/page.tsx` | NEW | Server component: one call to `readOverview`, then composes the head (the key `OVERVIEW_HEAD` selected for the measured direction, with the badge only on `rising`), the growth module, the three tiles, the rival module, the week strip, the alerts and the one supply/stopped statement. |
| `src/app/(account)/app/overview/WeekStrip.tsx` | NEW | Renders BP-018's `WeekStrip`: which days of this week are done, which is today and which are still to come, in `sites.time_zone`, with each week's `WeekAccount` attached. |
| `src/app/(account)/app/overview/AlertList.tsx` | NEW | Renders at most two alerts, each with one control, plus the overflow line. |
| `tests/app/overview/page.test.tsx` | NEW | Landing, head selection, composition, the alert cap rendered, the one-statement property. |
| `tests/app/overview/week-strip.test.tsx` | NEW | Done / today / to-come in the customer's zone. |

## Interfaces
Consumes (verbatim from BP-038 `## Public interface`):
```ts
export interface OverviewModel {
  head: { key: CopyKey; direction: HeadDirection }
  growth:
    | { kind: 'series'; points: readonly { weekStart: Date; value: Measured<number>; measuredAt: Date }[] }
    | { kind: 'none'; firstDueOn: Date }                 // criterion 3
  score: Module<number>
  aiAnswers: Module<number>
  pagesPublished: Module<number>
  rivals: RivalGapModule
  week: { days: readonly { date: Date; state: 'done' | 'today' | 'todo' }[]
          account: WeekAccount }                          // criterion 7, from BP-050
  supply?: { key: CopyKey; vars: Record<string, string> } // REQ-095 criteria 3, 5, 6 — one statement, never two
  alerts: readonly Alert[]                                // at most two (criterion 5)
  overflow?: { remaining: number; whereKey: CopyKey }
}
export function readOverview(siteId: string): Promise<OverviewModel>
```
and `WeekStrip` (BP-018), `copy()` (BP-019), the modules from WO-157, WO-159,
WO-160, WO-161 and the resolvers from WO-162.

Exposes: the `/app/overview` route. No new engine interface.

## Steps
1. **Precondition (rule 7.3):** signed preview. As of 2026-08-31
   `docs/design/tokens.md` is `Status: ready` and `components.md` registers 24
   components including `WeekStrip` — every row `proposed`, reaching `approved`
   only when a preview carrying it is signed off. `WeekStrip`'s registered
   contract already states this screen's week rule: "a day with nothing measured
   renders as a labelled empty mark, never a gap". This screen composes
   registered components and the tiles the other Overview WOs build; it
   registers none of its own — `components.md` §4 lists surface compositions
   (`MonthGrid`, `ScoreTile`, `GrowthModule` among them) and rules, verbatim:
   "They are not registry rows and must not become any."
2. Write the failing tests first.
3. Render the head from `OVERVIEW_HEAD[direction]`. `BUILD.md` §4.5's fixed
   *"The gap is closing."* and *"▲ every week since you started"* are **not
   built**: the badge renders only on `rising` and only over the weeks measured
   (BP-038 decision 4).
4. Compose one call to `readOverview` — no module fetches for itself; assert no
   measurement, vendor call or model call happens during render.
5. Render the week strip in `sites.time_zone`.
6. Assert the screen carries at most two alerts and exactly one supply or
   stopped-work statement.
7. Mutation check: render a fixed head sentence and confirm the falling-direction
   test fails.
