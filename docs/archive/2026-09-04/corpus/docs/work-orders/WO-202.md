## Goal
Implement the single rule that says what happens to a draft any generation hard rule stopped — pure, with no side effect and no knowledge of the state machine.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/lib/generate/claims/recovery.ts` | NEW | `Recovery` and `recoveryOutcome` verbatim from BP-043's public interface. Returns `regenerate_once` when a draft that has not entered review failed a hard rule and `automaticAttempts` is 0; `rest` in every other case — including every draft with `enteredReview: true`, whatever stopped it (ADR-070 point 4). It performs neither outcome: BP-042 regenerates, BP-015 transitions. No database access, no clock, no I/O. |

**Exposes** (verbatim from the blueprint):
```ts
/** The one recovery rule (REQ-053 c3), for every generation hard rule.
 *  Pure: takes what happened, returns what happens next. It performs neither. */
export type Recovery = 'regenerate_once' | 'rest'
export function recoveryOutcome(a: {
  failed: HardRule[]                 // non-empty
  automaticAttempts: number          // drafts.hard_rule_attempts, automatic only
  enteredReview: boolean             // ADR-070: post-review never regenerates
}): Recovery
```

## Steps
1. Write `recovery.test.ts` first and run it; it must fail on a missing module.
2. Implement `recovery.ts` as a total function over its three inputs — the full truth table is small enough to enumerate in the test, and enumerating it is what makes a later `switch` edit visible.
3. `enteredReview` is an input to a pure function precisely so the pre-review and post-review distinction survives every later edit to the pipeline (ADR-070 alternative 3: "a flag is what gets dropped in the refactor that follows").
4. `automaticAttempts` counts automatic attempts only. A customer-started regeneration resets the counter to 0 — that reset is BP-015's edge and this function simply reads the number it is given (ADR-070 point 2).
5. Do not add a cap, a schedule or a third outcome. ADR-070 alternative 2 rejects a job retrying `needs_attention` items with a small cap: it is not a smaller version of the promise, it is a different one.
6. Run the tests. Then mutate: return `regenerate_once` for a post-review draft and confirm the `enteredReview` case fails.

**Discriminates (mutation check, constitution §8).**
- Returning `regenerate_once` for a post-review draft passes every pre-review test and fails the `enteredReview` case — the mutation ADR-070 point 4 exists to stop, because in production it destroys customer edits with no undo and reports a successful regeneration.
- Counting customer-started attempts against the bound makes the reset case fail and would leave an item stuck in `needs_attention` with no way out (REQ-056 c3).
- Merging the pre-review and post-review paths behind a flag leaves the truth table incomplete; the test enumerates every combination, so a dropped arm cannot pass.
