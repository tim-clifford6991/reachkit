# WO-119 — recordCheckoutFacts — the billing country and VAT number a completed session collected

- Branch: wo/WO-119-record-checkout-facts
- Estimate: ≤1 day

## Goal
Read a completed Checkout Session and write the billing country and the VAT number
it collected onto the buyer's billing record, idempotently, before provisioning
runs — and write nothing else.

## File plan
> **Every path below is NEW.** No `src/` exists. Anchored to
> `registry/structure.md` and BP-030's `code:` glob
> `src/lib/account/checkout/**`. Provisional against a repo with no code.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/account/checkout/record.ts` | NEW | Exports `recordCheckoutFacts(sessionId)` with BP-030's signature verbatim. Reads the session from Stripe (expanding customer and customer details), then upserts onto `users` keyed on `checkout_session_id`: `stripe_customer_id`, `billing_country` (ISO-3166-1 alpha-2 exactly as Stripe reported it — never re-cased, never mapped), `vat_number` (verbatim as entered — never trimmed, uppercased, stripped of spaces, or validated), `checkout_session_id`. Returns the email, both recorded values, the customer id and the `CheckoutOrigin` reconstructed from session metadata. Idempotent: a second call for the same `sessionId` re-reads and returns the same values and performs no second write. Writes no column outside the four. |
| `src/lib/account/checkout/redaction.ts` | NEW | Exports `checkoutEvent(e: { sessionId: string; originKind: CheckoutOrigin['kind']; outcome: string })` — the one structured event this module emits. It has no parameter that can carry an address, a VAT number, a card field or a session URL, so BP-030's NFR ("The VAT number is logged nowhere") is a property of the type rather than a review comment. |
| `tests/account/checkout/record.test.ts` | NEW | The write, the idempotency, the verbatim guarantees (a lowercase country stays lowercase if Stripe reported it lowercase; a VAT number with internal spaces and mixed case round-trips byte-identical; an empty VAT field lands as `null`, not `''`), the null-country case, and a column-set assertion that only the four columns changed. |
| `tests/account/checkout/redaction.test.ts` | NEW | Asserts the emitted event object's keys, and that no log call in `src/lib/account/checkout/**` receives the session object, the VAT number or the email. |

## Interfaces
Consumes: `db()` · `dbAdmin()` (BP-002); `CheckoutOrigin` (WO-118).

Exposes (verbatim from BP-030's `## Public interface`):
```ts
/** Called by BP-032 when a session completes, before provisioning. Idempotent
 *  on `sessionId`: it writes the billing record and nothing else. */
export function recordCheckoutFacts(sessionId: string): Promise<{
  email: string
  billingCountry: string | null      // ISO-3166-1 alpha-2 as Stripe reported it
  vatNumber: string | null           // verbatim as entered; never normalised, never validated
  stripeCustomerId: string
  origin: CheckoutOrigin
}>
```

## Steps
1. Write `tests/account/checkout/record.test.ts` against a stubbed session and
   watch every case fail.
2. Implement `record.ts`, upserting on `checkout_session_id`.
3. Add the idempotency case (same session twice, one write).
4. Write `redaction.ts` and its test.
