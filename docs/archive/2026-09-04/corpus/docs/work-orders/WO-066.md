# WO-066 — The three problem cards and the three DIY method sections

- Branch: wo/WO-066-problem-cards
- Estimate: ≤1 day
- Preview: sdlc-factory/docs/design/previews/WO-066.html
- Signed-off: <date>

## Goal
Render exactly three problem cards — count, severity in words, who does the work,
and the paste block on the one arm that carries lines — and the three
instructional sections beneath them, on the same page, asking for nothing.

## File plan

> Every path below is **NEW**. Verified 2026-08-31: this repo carries no `src/`.
> Placement per `structure.md`; `_problems/` is BP-027's private folder inside
> BP-001's `src/app/(public)/**`. Provisional against a repo with no code.

| File | New/Modify | Change |
|---|---|---|
| `src/app/(public)/scan/[domain]/_problems/cards.tsx` | NEW | The three cards as one server component over WO-064's `cardsOf` result. Each renders the count through BP-019's `renderMeasured`, the severity word through `copy(SEVERITY[i])` where `i` is WO-064's handle index — `SEVERITY` is a `readonly [CopyKey, CopyKey, CopyKey]` **ascending in the count**, so it is indexed by ordinal and never keyed by the handle string — the `doer` key through `copy()`, and — on the `paste` arm only — the lines in a code block with a copy-to-clipboard control. The left border colour is the severity's `Tone`, and the word is always present beside it. No string literal a person reads appears in this file. |
| `src/app/(public)/scan/[domain]/_problems/method.tsx` | NEW | `MethodSections` — three `Collapse` sections, one per `ProblemName`, in the same order as the cards, rendered inside the same server component as the cards. Collapsed markup, not a lazy fetch. Every sentence is a `CopyKey`. |
| `tests/app/problems/cards.test.tsx` | NEW | The rendering suites named in the test plan. |
| `tests/app/problems/method.test.tsx` | NEW | The three-sections, no-payment and no-JavaScript suites. |

## Interfaces

Consumes: WO-064's `cardsOf`, `ProblemCard`, `ProblemName`, `Severity`, `Fix`;
WO-065's `unblockLines` output by way of the `paste` arm; BP-019's `copy()`,
`renderMeasured()`, `SEVERITY`; BP-018's registered components and `Tone`.

Exposes (verbatim from BP-027 `## Public interface`,
`src/app/(public)/scan/[domain]/_problems/method.tsx`):

```ts
/** REQ-009 criterion 6: three sections, one per problem, on the same page, no
 *  payment and no address asked for. The union is the same three, so a method
 *  section cannot go missing for a problem that has a card. */
export function MethodSections(p: { for: readonly [ProblemName, ProblemName, ProblemName] }): JSX.Element
```

`cards.tsx` exposes one server component over the three-tuple `cardsOf` returns;
its props are that tuple and nothing else, so the renderer cannot reach a report
field the model did not hand it.

## Steps
1. Produce the preview artifact at the path in the display bullets above and hold
   in draft until it is signed off (constitution rule 7.3). This WO does not
   proceed to implementation before that.
2. Write the failing rendering suites first.
3. Render each card as a total switch over `Fix`, so a new arm fails the build
   until it has a rendering.
4. Render count and severity through `renderMeasured` with the reason-specific
   `unmeasuredLine` key — REQ-004 criterion 6's key on `undeterminable`, criterion
   9's on `not_attempted`. Neither line is written here; both are keys.
5. Render the severity word from `SEVERITY[SEVERITY_INDEX[level]]` — BP-019
   declares `SEVERITY` as an **ordered triple**, `readonly [CopyKey, CopyKey,
   CopyKey]` ascending in the count, not a record keyed by `'low' | 'mid' |
   'high'`, so `SEVERITY[level]` does not type-check and the index map is
   WO-064's. Render the border tone beside the word; the word is never omitted
   when the tone is present.
6. Render the paste block only on the `paste` arm, with the copy-to-clipboard
   control as the only control on any fix.
7. Render `MethodSections` as three collapsed sections in the same server
   component, with no session read and no branch on payment or identity anywhere
   in either file.

## Test plan

> normalised to fit the table and no word is changed.

| Acceptance criterion (verbatim from REQ) | Test |
|---|---|
| REQ-009 c1 — "Given a completed report, when it renders, then it shows three problems — AI readers blocked, missing pages, unquotable pages — each with its own count and its severity, stated in words and never by colour alone; where a problem could not be measured, its count and its severity both read '—' (REQ-004). What those words may be is criterion 8's." | `problems/cards · three cards, each with a count and a severity in words` — the rendered output holds exactly three cards in order, each carrying a rendered count and a severity word resolved from `SEVERITY`. And `problems/cards · never by colour alone` — with all colour removed from the rendered tree, every severity is still readable as a word; a card that carries a tone and no word fails. And `problems/cards · an unmeasured problem dashes both` — for each `unmeasured` reason, count and severity both render as the dash `renderMeasured` produces, and the reason-specific line is present. |
| REQ-009 c2 — "Given AI readers are blocked on the customer's site, when that card renders, then the exact lines the founder must add are shown verbatim and copyable, labelled as a free fix the founder does themselves." | `problems/cards · the paste block is verbatim and copyable` — with a `paste` fix, the rendered code block's text equals the `lines` array joined by newlines, character for character, and a copy control is present and addresses that block. The "free fix the founder does themselves" label is asserted to be a `CopyKey` resolved through `copy()`, not a literal. |
| REQ-009 c3 — "Given a site with no access gate, when the blocked-readers card renders, then it shows a count of 0 and states that nothing is blocking AI readers, and no fix lines are offered — the card is never absent and never shows lines a founder should not paste." | `problems/cards · a zero count shows 0, a line, and no block` — with a `none_needed` fix the card renders the numeral 0, the nothing-is-blocking line by key, and no code block and no copy control anywhere in its subtree. The card is asserted present in every fixture, including the unmeasured ones. |
| REQ-009 c4 — "Given a site whose access rules the scan did not read — it tried and could not determine them, or it stopped early before attempting them — when the blocked-readers card renders, then it shows '—' in place of the count, states in writing which of those two happened in the words REQ-004 gives that case (criterion 6 for a read that could not be determined, criterion 9 for work the scan never got to), and offers no fix lines — it never shows 0, never states that nothing is blocking AI readers, and never tells the founder we could not read rules we never tried to read." | `problems/cards · the two unmeasured reasons render two different lines and no block` — `undeterminable` renders REQ-004 criterion 6's key, `not_attempted` renders criterion 9's, the two keys are asserted distinct, neither renders the numeral 0, neither renders the nothing-is-blocking key, and neither renders a code block. A mutation test swapping the two keys fails. |
| REQ-009 c5 — "Given the missing-pages and unquotable-pages problems, when they render, then each shows a count and names who does the work, and neither lists or previews the pages themselves." | `problems/cards · counts and a doer, never a page` — both cards render their count and their `doer` key; the rendered subtree of each is asserted to contain no anchor, no URL, no page title and no list of items. |
| REQ-009 c6 — "Given the report, when the visitor reads past the problem cards, then three instructional sections — one for each of the three problems — are readable on the same page, each stating the steps the founder performs themselves, with no payment and no email address asked for." | `problems/method · three sections, same page, nothing asked` — `MethodSections` renders exactly three sections in the same document as the cards, one per `ProblemName`; the rendered tree contains no form, no email input, no payment control and no sign-in link. And `problems/method · readable without JavaScript` — with scripting disabled the section bodies are present in the server-rendered markup, not fetched. |
| REQ-009 c7 — "Given any of the three fixes the report names, when the founder acts on it, then the report has only instructed them: ReachKit makes no change to their site, its files or its access rules, and offers no control that would. Every fix on the free report is one the founder performs themselves." | `problems/cards · the only control on a fix is copy` — the rendered tree's controls are enumerated and asserted to be exactly the copy-to-clipboard controls; no button, form or link in either file performs a write or an outbound request, asserted by source and by a runtime spy over the whole suite. |
| REQ-009 c8 — "Given the severity of any of the three problems, when it renders, then it is one of exactly three written levels drawn from one closed set — the same three words on every report the product renders, never wording chosen per report or per problem — and it follows that problem's own count and nothing else: a problem measured at 0 always carries the lowest of the three and states in writing that there is nothing to fix, and of any two reports the one with the larger count for the same problem never carries the lower severity." | `problems/cards · one closed set of three words, the same on every report` — across every fixture, the severity words rendered are drawn from `SEVERITY` and from nowhere else, are three distinct values, and are identical for the same level across different problems and different reports; a source assertion that neither file contains a severity string literal. And `problems/cards · the rendered words are the ruled words, in ascending order` — a `zero` count renders `Minor`, a count in the `mid` band renders `Worth fixing` and one in the `high` band renders `Critical`, asserted through the registry rather than as literals in this file; rendering `Critical` on a zero count is the mutation this test exists to fail, and it is only assertable now that the three words exist. |
