# WO-102 — The plain-text rendering of the same block list

- Branch: wo/WO-102-mail-blocks-text
- Estimate: ≤1 day
- Preview: sdlc-factory/docs/design/previews/WO-102.html
- Signed-off: (pending — design-guardian)

## Goal
Render the same `MailBlock[]` a second time as plain text, through the same
omission decision, so that no template can author a text body and none can omit
one.

## Provisional against an empty repo
**No `src/` exists.** The one file below is NEW. It sits inside BP-053's
`src/lib/mail/blocks/**` glob (ADR-040 point 3). It shares no file with WO-101 —
WO-101 creates `types.ts`, `omit.ts` and `html.ts`; this WO creates `text.ts` —
but it is sequenced after WO-101 because it imports both.

Reuse check (rule 7.2): no text renderer is indexed in
`registry/capabilities.md` and none exists on disk. BP-053 decision 3 rejects the
two alternatives explicitly ("an authored text body per template", "auto-stripping
tags from the HTML"), so there is nothing to extend and one thing to build.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/lib/mail/blocks/text.ts` | NEW | `renderBlocksText(blocks): { text: string; omitted: readonly number[] }`. One text form per arm: `heading` as its own line, `paragraph` as a wrapped paragraph, `stat` as `label: value` with the note on the following line, `list`/`verdicts` as one row per line under the label or the `emptyLine`, `action` as `label: href` with the URL written out (never a bare naked URL with no label), `notice` as its own line, `pageBody` as the label from `generatedLabel()` followed by the raw markdown. Omission is delegated to WO-101's `omittedIndexes()`; this file contains no second omission rule. |
| `tests/mail/blocks/text-parity.test.ts` | NEW | Both bodies carry the same block set. |
| `tests/mail/blocks/text-omission.test.ts` | NEW | The omission rule holds identically in text. |

## Interfaces
**Consumes** (from WO-101, this node's own): `MailBlock`, `omittedIndexes()`.
**Consumes** (verbatim from BP-053's boundary section): `renderMeasured()` and
`copy()` (BP-019), `generatedLabel()` (BP-020).

**Exposes**: `renderBlocksText(blocks: readonly MailBlock[]): { text: string; omitted: readonly number[] }`
— the twin of WO-101's `renderBlocksHtml`, chosen under rule 1.1 to give
BP-053 decision 3's "`composeMail` returns `{ html, text }` from the same blocks"
two symmetric halves. Reversal cost: none; the pair is internal to `blocks/`.

## Steps
1. Write both tests first and watch them fail.
2. `text.ts`: one function per arm, same arm order as `html.ts`, same call to
   `omittedIndexes()`.
3. Mutation check: change `text.ts` to compute its own omission set and confirm
   `text-omission.test.ts` still passes but `text-parity.test.ts` fails when the
   two decisions are made to disagree — the parity test is what discriminates.

## Test plan
| Acceptance criterion (verbatim from REQ) | Test |
|---|---|
| REQ-064 c5 — "Given any email the product sends, when it is delivered, then it carries a plain-text alternative." | `tests/mail/blocks/text-parity.test.ts` → `every block set renders a non-empty text body carrying the same blocks as the html body` — asserted over a fixture set covering all eight arms. **Covers the composition half.** The delivery half — that the vendor request carries both bodies — is WO-105's. |
| REQ-064 c1 — "Given a section of an email depends on a value that could not be measured, when the mail is composed, then that section is left out entirely and no zero, dash or placeholder appears in its place — except that where REQ-065 criterion 4 states the week was only partly measured, the mail names in one written line which of its sections could not be measured, rather than dropping them silently." | `tests/mail/blocks/text-omission.test.ts` → `an unmeasured block is absent from the text body and its index is in omitted` — the same main clause as WO-101, asserted on the second renderer, because a rule that holds in one body and not the other is the failure decision 3 exists to prevent. The clause after "except that" is WO-103's `tests/mail/shell/whole-mail-line.test.ts`, asserted there on both bodies. |

## Out of scope

- Any customer-visible string (REQ-093 c1). Line breaks and ordering are layout;
  the sentences are `CopyKey`s.
- HTML rendering (WO-101).
