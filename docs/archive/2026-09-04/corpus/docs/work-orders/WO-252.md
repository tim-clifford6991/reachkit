# WO-252 — The four measured quantities — `BUILD.md` §5's driver arithmetic as four pure functions

- Branch: wo/WO-252-drivers
- Estimate: ≤1 day

## Goal
Compute BP-010's four measured quantities — Foundations, Answerability,
SearchPresence and AIPresence — from counted facts and vendor rows, each as a
`Measured<number>`, with `BUILD.md` §5's formulas as the whole of the
arithmetic and no I/O of any kind.

## Provenance of this file plan
**This repository holds no `src/`.** Both paths are NEW. `src/lib/measure/` is
BP-010's row in `structure.md` and its `code:` globs are `src/lib/measure/**`
and `tests/measure/**`. `drivers.ts` is named by no leaf: BP-024's `code:`
enumerates five other files and `tests/measure/verdict/**`, so this file and
`tests/measure/domain/**` are the component's under `structure.md` rule 2.

**Reuse check (rule 7.2).** `capabilities.md`'s row "The three shown score
factors, the score and its band" is BP-024's `factorsOf` · `presenceOf` ·
`computeScore` · `bandOf`, shipped by WO-054 — those take `Drivers` and
`ScoreFactors` as *given* and are downstream of this file. There is no index row
and no work order for the four measured quantities themselves; BP-010's decision
3 states the separation ("keep four fields — they are what the parsers produce")
and WO-054's own `## Interfaces` consumes `Drivers` as "another node's file".
This work order produces what WO-054 consumes; it duplicates nothing.

**Status.** Left `status: draft` — written and not self-certified in the same
pass. A later audit sets the status against §3's gate list.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/lib/measure/drivers.ts` | **NEW** | The whole public interface below: `foundationsOf`, `answerabilityOf`, `searchPresenceOf`, `aiPresenceOf`. `BUILD.md` §5's formulas transcribed, and nothing else — no fetch, no vendor call, no clock read (`at` is a parameter), no persistence. Every function returns `Measured<number>` through WO-052's constructors and combinators; none returns a bare `number` and none has a branch that reaches a raw number out of an `unmeasured` arm. `foundationsOf` returns a **measured 0** — never `unmeasured` — for a document that was read and carries a generic `noindex` (BP-010 `## Error & edge behavior`; REQ-004 c7). `answerabilityOf` applies BP-005's floor, and applies it only to a `measured` or `zero` arm. `searchPresenceOf` and `aiPresenceOf` return `unmeasured` with the reason their input carried, folded by WO-052's `worseReason`, and never estimate from the part that was measured. The four numbers of §5's presence formulas (25, 0.55/0.45/4, 0.4/0.6) live here with `BUILD.md` §5 quoted in a comment beside each; the answerability floor does not (third and second `rests-on` rows). |
| `tests/measure/domain/drivers.test.ts` | **NEW** | A fixture suite per driver, as BP-010 decision 2 requires ("covered by a fixture suite per driver"), plus the boundary and mutation cases named in the test plan. |

**Exposes** — the four measured quantities. Their composed record type `Drivers`
is BP-010's and is declared in `src/lib/measure/index.ts` by WO-253, whose

```ts
/** `BUILD.md` §5: "Foundations = access gates + clarity signals, 0–100
 *  (generic noindex on the home document ⇒ 0, and score ⇒ 0)". A document we
 *  read that tells every reader not to index it is a **measured** 0, never an
 *  `unmeasured` — REQ-004 c7's case, and the reason both booleans exist on
 *  `OnPageFacts`. A document we could not read is `unmeasured`. */
export function foundationsOf(a: {
  onPage: OnPageFacts | null            // null = the home document could not be read
  robots: Measured<RobotsPolicy>
  at: Date
}): Measured<number>

/** §5: "Answerability = shape of the home + measured pages, 0–100, floored at 1
 *  · shape = (questionShaped + directAnswers + evidenceDensity) / 3", where
 *  `questionShaped` = question-shaped headings ÷ all headings × 100,
 *  `directAnswers` = direct-answer headings ÷ all headings × 100, and
 *  `evidenceDensity` is the saturating log curve over
 *  (numerals + dates + outboundCitations) per 1,000 visible characters.
 *  Empty denominators read 0, never null. */
export function answerabilityOf(a: {
  pages: readonly OnPageFacts[]         // empty = nothing was read
  at: Date
}): Measured<number>

/** §5: "SearchPresence = min(100, 25 × log10(ranked + 1)) ×
 *  (0.55 + 0.45 × min(1, top10share × 4))". Zero ranked rows is a legal result
 *  and a measured 0 (`BUILD.md` §6.3: "`ranked_keywords`@50 → the customer's own
 *  presence (0 rows is a legal result)"), not an `unmeasured`. */
export function searchPresenceOf(a: {
  ranked: Measured<readonly RankedRow[]>
  at: Date
}): Measured<number>

/** §5: "AIPresence = max(1, (0.4 × mentionRate + 0.6 × citationRate) × 100)".
 *  `BUILD.md` §6.3: "Brand mentions/citations = string match over references."
 *  The rates are over the SERPs whose AI-overview item was measured — never over
 *  the twelve asked for, because a SERP we could not read is not a SERP that
 *  named nobody. Every SERP `unmeasured` yields `unmeasured`, never 0. */
export function aiPresenceOf(a: {
  serps: readonly Measured<SerpResult>[]
  ownDomain: string
  at: Date
}): Measured<number>
```

## Steps
1. Read `src/lib/config/constants.ts` for the answerability floor. If the pin is
   absent, take the stop condition above.
2. Write `tests/measure/domain/drivers.test.ts` first and run it; every case must
   fail on a missing module (constitution §8, "Watch it fail first").
3. Implement `foundationsOf`. Order the branches so the read/not-read question is
   answered before the gate question: `onPage === null` is `unmeasured` with the
   reason the caller carried; `onPage.noindex && onPage.noindexAppliesToEveryReader`
   is `zero` with value 0; everything else is the access-gate and clarity-signal
   composition over `OnPageFacts` and `RobotsPolicy`.
4. Implement `answerabilityOf` over the three sub-measures, dividing by 3, then
   applying the pin's floor — and applying it only to a `measured` or `zero`
   arm, so an `unmeasured` answerability can never surface as 1.
5. Implement `searchPresenceOf` and `aiPresenceOf` with §5's formulas quoted
   beside each coefficient.
6. Route every arithmetic step through WO-052's `combine`, so no branch can
   reach a raw number from an `unmeasured` arm.
7. Mutate to prove the suite discriminates: (a) make the generic-noindex case
   return `unmeasured` instead of `zero` and confirm the REQ-004 c7 row fails;
   (b) apply the answerability floor to the `unmeasured` arm and confirm the
   floor row fails; (c) drop the `min(1, …)` from the top-10 share term and
   confirm the saturation row fails.
