## Goal
Implement the attributed-quotation and testimonial rules — the scanning half of no-invented-people, narrowed to what a pattern can decide, and the testimonial rule that fails an endorsement-shaped block whether or not it names a speaker.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/lib/generate/rules/people.ts` | NEW | `checkInventedPeople(a: { rendered: string; markdown: string; businessName: string | null }): RuleFailure | null` — a quoted remark (quotation marks or a blockquote) naming or attributing to anyone other than the customer requires a link in the same block; the customer's own attribution needs none. `checkUnsourcedTestimonial(a: { rendered: string; markdown: string }): RuleFailure | null` — a review-, endorsement- or reported-remark-shaped block with no link in the same block fails whether or not it names a speaker. Both deterministic; no entity recognition and no model call (BP-042 decision 2). |

## Steps
1. Write `people.test.ts` first and run it; it must fail on a missing module.
2. Implement both checks in one module: BP-042's edge behaviour states that the same check serves both rules, with the testimonial rule additionally failing an endorsement-shaped block with no link whether or not it names a speaker.
3. Do not add entity recognition or a model judge. BP-042 decision 2 records the residual — a persona named only in body prose, with no quotation and no attribution field, is not caught here — and states where it is caught instead. The residual is stated, not papered over.
4. Run the tests. Then mutate: exempt every blockquote and confirm the unlinked-attribution case fails.

## Test plan
> Watch it fail first (constitution §8): every test below is written and
> run against the absent implementation before the implementation exists.

| Acceptance criterion (verbatim from REQ) | Test |
|---|---|
| **REQ-050 c4** Given a draft is generated, when it is queued for review, then the only author it may attribute itself to is the customer — the business name or account-holder name recorded for their site — and it carries no other byline, no author biography and no persona; and every person it names or quotes other than the customer themselves is named in a public page the draft links. The customer's own attribution needs no such link. | `people.test.ts › a quotation attributed to a third party with no link fails` and `… the customer's own attribution needs no link` — the field-absence half is WO-191's |
| **REQ-050 c5** Given a draft is generated, when it is queued for review, then it carries no testimonial, review, endorsement or reported customer remark, whether or not it names a speaker, unless the draft links a public page carrying that same remark. | `people.test.ts › an endorsement-shaped block naming nobody and linking nothing fails` and `… the same block passes when it links a public page carrying the remark` |

**Discriminates (mutation check, constitution §8).**
- Exempting blockquotes, or scoping the link requirement to the whole document, makes the unlinked cases pass and both criteria's tests fail.
- Treating a speakerless testimonial as acceptable makes the c5 naming-nobody case fail — the criterion says "whether or not it names a speaker", and the test is the one that holds that clause.
- Comparing against a model-supplied author name instead of the site's recorded business name makes the customer's-own-attribution case fail, since no such name is in scope in this module.
