# WO-023 — DataForSEO transport, credentials and the never-list enforced by absence

- Branch: wo/WO-023-dataforseo-transport
- Estimate: ≤1 day

## Goal
Build the one typed boundary to DataForSEO — transport, credentials, error
mapping and the shape every endpoint function is written to — so that a call the
product may not make has no function to call.

**Risk: high — seams: money, and data leaving the system.** This file is the only place the DataForSEO credential is read and the only place an outbound call to a paid third party is made, and `00-project.md`'s cost envelope is enforced in exactly this kind of seam. Its central promise is negative — the never-list is enforced by a function's *absence*, so a call the product may not make has nothing to call — and a test that survives adding an endpoint function leaves that promise vacuous while every added call bills. Mutation-tested (doctrine 0.13.2, rule 2b).

## Provenance of this file plan
**This repository holds no `src/`.** Every path is NEW, anchored to
`structure.md`'s row for `src/lib/vendors/**` and BP-008's `code:` globs.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/lib/vendors/dataforseo/transport.ts` | NEW | The one request builder. Credentials from `env` (`DATAFORSEO_LOGIN`, `DATAFORSEO_PASSWORD`), never appearing in a log, a payload or an error message. Every call is fixed to `SERP_LOCATION` (Google US / en) and depth 10 — both read from `constants.ts`. `mode` is a required argument on every call it builds; there is no default. `PRICE_BOOK`/`SERP_LOCATION` (BP-005).
