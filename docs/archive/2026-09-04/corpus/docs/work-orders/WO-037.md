# WO-037 — Design-system enforcement — the no-emoji rule, the registry conformance test and the token/component audit

- Branch: wo/WO-037-design-enforcement
- Estimate: ≤1 day

## Goal
Make rule 7.3 mechanical: an unregistered component, an unnamed colour, a raw
numeral or an emoji anywhere in the product fails a check rather than a review.

## Provenance of this file plan
**This repository holds no `src/`.** The test paths are NEW under BP-018's
`code:` glob `tests/ui/**`. `eslint.config.mjs` exists only after WO-001 and is
also edited by WO-018 — this work order therefore names WO-018 in `depends-on`
purely to serialize that one shared file, not because it needs the egress guard.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `eslint.config.mjs` | MODIFY | Adds three project rules: (a) **no emoji** in any file under `src/` — BP-018: "No emoji anywhere; a lint rule enforces it"; (b) no literal colour (hex, `rgb(`, named colour) in any file under `src/app/`, `src/ui/components/` or `src/ui/charts/` — only `var(--token)` and daisyUI classes; (c) no import of a component under `src/ui/components/` by a deep path — every consumer imports from the barrel, so the registered set is the only reachable set. |
| `tests/ui/registry-conformance.test.ts` | NEW | Reads `sdlc-factory/docs/design/components.md` and asserts every export of BP-018's public interface has a row there, and that every row names an export that exists. This is the two-way check rule 7.3 needs; a row without code and code without a row both fail. |
| `tests/ui/numerals.test.tsx` | NEW | Renders each registered component and each chart with numeric fixtures and asserts every numeral, date, URL and query-like string is inside a `.num` element. |
| `tests/ui/tokens-audit.test.ts` | NEW | Asserts every token referenced anywhere under `src/` exists in `theme.css`'s `:root`, and that `theme.css` defines no token nothing references — the second half catches a token added and never wired. |
| `tests/ui/a11y.test.tsx` | NEW | Asserts, for every component and chart that carries state or a band, that the meaning is present as text and not only as colour. |

## Interfaces
Consumes: the full BP-018 public interface (WO-029 to WO-036) and
`sdlc-factory/docs/design/components.md`.
Exposes: no runtime interface — four checks and three lint rules.

## Steps
1. Add the three lint rules; run them against the shipped `src/ui/`.
2. Write `registry-conformance.test.ts`; run it and **record the failing list**
   (it will name all nineteen exports until the design-guardian registers them).
3. Write `numerals.test.tsx`, `tokens-audit.test.ts` and `a11y.test.tsx`.
4. For each, watch it fail first: insert an emoji, a hex literal, a bare numeral,
   an unknown token and a colour-only state, then remove each.

## Test plan
> **Criterion source: the blueprint and the constitution, not a requirement —
> and there is no requirement to draw on.** BP-018 has no requirement ancestor.

| Acceptance criterion (source quoted) | Test |
|---|---|
| BP-018 error behaviour: "No emoji anywhere; a lint rule enforces it." | Lint rule (a), exercised by a fixture in `tests/ui/a11y.test.tsx`; removing the rule lets the fixture pass, which is the mutation check. |
| Constitution rule 7.3: "UI uses named tokens and registered components only." | `tests/ui/registry-conformance.test.ts` and lint rules (b) and (c) together — an unregistered component is unreachable, and a literal colour is a lint error. |
| BP-018 decision 1: "a new component enters `sdlc-factory/docs/design/components.md` as `proposed` with its data contract and states before it can be exported." | `tests/ui/registry-conformance.test.ts` — the two-way check. Its current failure is the finding, not a defect in the test. |
| BP-018 error behaviour: "Every numeral, date, URL, search query and code-like string renders in JetBrains Mono with `tabular-nums`; a numeral in the UI font is a defect." | `tests/ui/numerals.test.tsx` across every registered component and chart. |
| BP-018 error behaviour: "a token missing from `:root` fails a test" | `tests/ui/tokens-audit.test.ts`, both directions. |
| BP-018 NFR budget: "Accessibility: colour is never the only carrier of meaning (bands and severities are words — REQ-004 criterion 4, REQ-009 criterion 1)" | `tests/ui/a11y.test.tsx` — for every stateful component, the state is asserted present as text. The two criteria named are discharged where the words render (BP-019, BP-024, BP-027); this checks the component cannot prevent it. |

## Out of scope
- Writing `design/tokens.md` or `design/components.md`. Both are the
  design-guardian's files; this work order only reads one of them.
- Any component or chart implementation — WO-029 to WO-036.
- Copy of any kind.

## Rollback
Revert the three lint rules and delete the four test files. The design system
still works and stops being enforceable, which is the state rule 7.3 exists to
prevent — treat a revert as a regression.
