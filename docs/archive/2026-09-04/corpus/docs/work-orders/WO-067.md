# WO-067 — Removal — the removed-address line, and the removal address named on every report

- Branch: wo/WO-067-removal
- Estimate: ≤1 day
- Preview: sdlc-factory/docs/design/previews/WO-067.html
- Signed-off: <date>

## Goal
Render the one written line a removed address serves, and the same removal
address on every report, from a single copy key — and make the absence of any
writer to `domain_blocks` a tested property of the product rather than a habit.

## File plan

> Every path below is **NEW**. Verified 2026-08-31: this repo carries no `src/`.
> Placement per `structure.md`; `_address/` is BP-022's private folder inside
> BP-001's `src/app/(public)/**`. Provisional against a repo with no code.

| File | New/Modify | Change |
|---|---|---|
| `src/app/(public)/scan/[domain]/_address/removal.tsx` | NEW | Two exports. `RemovedView` renders the `{ kind: 'removed' }` arm: one written line saying the report was removed at the domain owner's request, naming the removal address, served with HTTP 200 (the status is WO-069's to set; this file renders the body). `RemovalAddressLine` renders the same address for the foot of every report, so criterion 1 and criterion 3 name one address from one key. Both resolve `copy()` keys; neither composes an address from parts, and neither contains a string literal a person reads. |
| `tests/app/scan-address/removal.test.tsx` | NEW | The one-key, one-address, no-writer and no-control suites named in the test plan. |

## Interfaces

Consumes: WO-061's `AddressState` (`{ kind: 'removed' }` arm) and its `report`
arm; BP-019's `copy()` and `CopyKey`; BP-018's registered components.

Exposes:

```tsx
// src/app/(public)/scan/[domain]/_address/removal.tsx
export function RemovedView(): JSX.Element          // the { kind: 'removed' } arm's body
export function RemovalAddressLine(): JSX.Element   // REQ-002 c1, at the foot of every report
```

Both are BP-022's own composition of BP-018 primitives over BP-019 keys; BP-022's
`## Public interface` declares the state union, not the views, so these two
signatures are this WO's and are named here so WO-068 and WO-069 can consume
them without re-deriving anything.

Copy keys referenced (created in BP-019's registry by that node, **not here**):
one key for the removal address itself, one for the removed-report line, one for
the line that names the address on a live report. This WO references them; it
supplies no value for any of the three.

## Steps
1. Produce the preview artifact at the path in the display bullets above and hold
   in draft until it is signed off (rule 7.3).
2. Write the failing suites first.
3. Implement `RemovalAddressLine` over one address key and one framing key. The
   address is resolved by `copy()` and is never concatenated, templated from a
   domain, or read from `env`.
4. Implement `RemovedView` reusing `RemovalAddressLine`, so one key serves both
   surfaces and the address on the removal line and the address on a report can
   never differ.
5. Render no control on `RemovedView`: no re-scan, no retry, no landing field,
   no form.
6. Add the product-wide no-writer assertion: `domain_blocks` is written by no
   file under `src/`.

## Test plan

> Criteria are copied verbatim from `requirements/REQ-002.md` and
> `requirements/REQ-001.md`; line breaks are normalised to fit the table and no
> word is changed.

| Acceptance criterion (verbatim from REQ) | Test |
|---|---|
| REQ-002 c1 — "Given any report, when it renders, then it names in writing the address to which a request to remove the report about that domain is sent, readable by a visitor with no account, session, or payment." | `removal/address · every report names the address, from one key` — `RemovalAddressLine` renders on every `report` arm fixture; the rendered address is asserted equal to `copy()` of the single removal-address key, and a source assertion that key is referenced in exactly two places in `src/` — `RemovedView` and `RemovalAddressLine` — and that no other file in `src/` contains an address literal. And `removal/address · no session is read` — the component is asserted to read no cookie, no session and no header. **This test fails until the owner writes the address**: the key has no value in the corpus (this WO's first `rests-on` row), and that failure is the intended signal, not a defect in this WO. |
| REQ-002 c3 — "Given a domain whose report has been removed, when its report address is opened, then it shows the removed report to nobody and starts no scan for anyone, on that visit or any later one, and in its place one written line says the report was removed at the domain owner's request and names the address criterion 1 names — until a request to that same address asks for that domain to be scannable again." | `removal/view · one line, naming the same address, and nothing else` — `RemovedView` renders exactly one written line plus the address line; its subtree is asserted to contain no report content, no score, no band, no control and no form. And `removal/view · the address is the same address` — the address rendered by `RemovedView` is asserted identical to the one `RemovalAddressLine` renders on a live report, by both resolving the same key. |
| REQ-001 c18 — "Given a domain whose report was removed at its owner's request (REQ-002 criterion 3), when its report address is opened, then no stored report is shown, no re-scan or retry control is offered, and no scan starts — criteria 12 to 17 offer no route back to a removed report." | `removal/view · no control, no route back` — the rendered tree holds no button, link or form that starts a measurement; asserted by enumerating every interactive element in the subtree and finding none. The state-level half of this criterion is WO-061's. |
| REQ-002 c4 — "Given a domain whose owner has made no removal request, when its report address is opened, then no report is withheld this way: a report is taken down only by a removal request received at the address criterion 1 names, never at ReachKit's own initiative." | `removal/no-writer · nothing in the product writes domain_blocks` — a repository-wide source assertion that no file under `src/` contains an insert, update, upsert or delete against `domain_blocks`, and that no migration outside BP-002's `*_domainblocks*.sql` mentions the table. This is the structural discharge BP-022 names: the promise is kept by the absence of a writer, not by a permission check. |
| REQ-002 c2 — "Given a removal request for a domain received at the address criterion 1 names, when it is granted, then within 5 working days of its receipt the report is no longer readable at its address." | Not testable in code, and named here rather than left silent: the grant is a person's act (this WO's second `rests-on` row). What *is* tested is the effect — `removal/view · a domain_blocks row removes the report on the next read` — inserting a row by hand makes the address resolve `removed` on the very next request, with no cache to invalidate and no deploy. The five-working-day window is an operational promise recorded in ADR-002, not a code path. |

## Out of scope
- The removal address's **value** — the owner's, and outstanding. This WO
  creates the reference and the test and writes no string.
- The `domain_blocks` table and its migration — BP-002's.
- Deciding that a domain is removed — WO-057's admission step and WO-061's row 3.
- The HTTP status of the removed response — WO-069 serves it 200, not 404 or 410.
