# WO-130 — sites hosting columns and hostedServingState — the two ways serving ends, answered in one place

- Branch: wo/WO-130-hosted-serving-state
- Estimate: ≤1 day

## Goal
Add the hosted-retention clock and the two notice stamps under the
`sites_hosting` sub-token, and expose the single question the hosted edge asks
before serving a page.

## File plan
> **Every path below is NEW.** No `src/` and no `supabase/` exist. Anchored to
> `registry/structure.md` rule 3a and BP-060's `code:` globs. Provisional against
> a repo with no code.

| File | New/Modify | Change |
|---|---|---|
| `supabase/migrations/<ts>_sites_hosting_columns.sql` | NEW | `alter table sites add column hosted_serving_ends_at timestamptz null`, `hosting_end_notice_at timestamptz null`, `hosting_end_reminder_at timestamptz null`. An index on `hosted_serving_ends_at` for the due-work queries. No cascade (ADR-051 point 2). |
| `src/lib/account/billing/hosted-serving.ts` | NEW | Exports `hostedServingState(siteId)` with BP-060's signature verbatim. Computes from timestamps — never from a boolean a job flips: `serve: false, because: 'account_deleted'` while the owning user's `deleted_at` is non-null; `serve: false, because: 'retention_elapsed'` when `hosted_serving_ends_at <= now()`; `serve: true` otherwise. Server-only. Cacheable for 60 s. **Fails closed on deletion and open on retention** (BP-060's NFR budget): a lookup error while `deleted_at` is unknown returns `serve: false`. Reads through `dbAdmin()` because a tombstoned row is hidden from `db()` by BP-002's policy (ADR-051 point 3). |
| `tests/account/billing/hosted-serving.test.ts` | NEW | The three outcomes; the deletion case taking precedence over the retention case; the fail-closed case (a stubbed lookup error while the tombstone is unknown returns `serve: false`); the fail-open case (an error while retention alone is unknown returns `serve: true`); a fixed-clock boundary at exactly `hosted_serving_ends_at`. |

## Interfaces
Exposes (verbatim from BP-060's `## Public interface`):
```ts
export function hostedServingState(siteId: string): Promise<
  | { serve: true }
  | { serve: false; because: 'retention_elapsed' | 'account_deleted' }   // BP-004 answers 410
>
```
Consumes: `dbAdmin()` (BP-002).

## Steps
1. Write the migration.
2. Write `tests/account/billing/hosted-serving.test.ts` and watch it fail.
3. Implement `hosted-serving.ts` as a pure computation over three timestamps.
4. Add the two failure-direction cases — they are what BP-060's NFR budget fixes
   and what a later "simplification" would flatten.

migration. Dropping them while WO-134 is live would make hosted serving unbounded,
which breaks the promise REQ-076 c10 states rather than merely reverting it.
