# WO-159 — The rival gap module, rendered: names, sparklines, and a neutral series colour

- Branch: wo/WO-159-overview-rivals-render
- Estimate: ≤1 day
- Preview: sdlc-factory/docs/design/previews/WO-159.html
- Signed-off: <date>

## Goal
Render each confirmed competitor by name with its gap and how that gap has
moved, in both arms, with every value direct-labelled and rival series drawn in
the neutral rival colour.

## File plan
> Every path below is **NEW** (no `src/` on disk, checked 2026-08-31). Placement
> follows `structure.md` and BP-038's `code:` globs; provisional.

| File | New/Modify | Change |
|---|---|---|
| `src/app/(account)/app/overview/RivalModule.tsx` | NEW | Renders both arms of `RivalGapModule` through BP-018's `RivalSparkline`: the `absolute` arm shows the rivals' numbers alongside the customer's own as context values that render bare, the `ratio` arm shows the ratio with its previous value or the crossing measurement's counts. Every point is direct-labelled with name and value. |
| `tests/app/overview/rival-module.test.tsx` | NEW | Both arms rendered, the line key rendered, direct labelling, the series colour. |

## Interfaces
Consumes (verbatim from BP-038 `## Public interface`):
```ts
export type RivalGapModule =
  | { kind: 'absolute'                                   // criteria 9 and 10
      own: Measured<number>
      rivals: readonly { domain: string; ranked: Measured<number>; series: readonly Measured<number>[] }[]
      lineKey: CopyKey }                                 // NOT the gap-shrinking line
  | { kind: 'ratio'                                      // criterion 11
      rivals: readonly { domain: string; ratio: Measured<number>
                         previous: Measured<number> | { kind: 'first_ratio'; counts: { own: Measured<number>; rival: Measured<number> } }
                         series: readonly Measured<number>[] }[]
      lineKey: CopyKey }
```
and `RivalSparkline` (BP-018 — its props accept no `Tone` for a rival series),
`renderMeasured()` and `copy()` (BP-019).

Exposes: `RivalModule` inside the overview module; no new cross-node interface.

## Steps
1. **Precondition (rule 7.3):** signed preview. As of 2026-08-31
   `docs/design/tokens.md` is `Status: ready` and `components.md` registers 24
   components including `RivalSparkline` — every row `proposed`, reaching
   `approved` only when a preview carrying it is signed off. Its registered
   contract carries both arms this WO needs and the neutral-colour guarantee:
   "the props accept no `Tone` at all", so the rival-strength-is-never-red rule
   is unbreakable by a prop rather than checked in review.
2. Write the failing tests first.
3. Render each rival by name with its value and its series; the customer's own
   number and the rivals' absolute counts are `ContextValue`s and render bare
   (BP-038 decision 1 — criterion 4 does not bind them).
4. Draw rival series in `--chart-rival` neutral gray, never a status tone.
5. Direct-label every point with name and value; identity is never colour-alone.
6. Mutation check: pass a `Tone` to the rival series and confirm the type/test
   rejects it.
