# WO-271 — The three price pins — declared in constants.ts, asserted against REQ-022 in the pins test

- Branch: wo/WO-271-price-pins
- Estimate: ≤1 day

## Goal
Declare `PRICE_EUR_CENTS`, `PRICE_CURRENCY` and `PRICE_INTERVAL` once, in
`src/lib/config/constants.ts`, and assert each against its quoted source clause
in `tests/pins.test.ts`, so ADR-052 point 3's boot check and WO-117's
`PRICE_OBJECT_SPEC` have a pin to read instead of a number to mint.

## Provenance of this file plan
BP-005 decision 5 (accepted 2026-08-31) added the three price pins to BP-005's
`## Public interface` **after** WO-006's file-plan enumeration was cut; WO-006 was
built exactly to its plan and validated `pass` (TST-003), so the three are not
in the repository. WO-117 consumes them and declines to define them ("Defining
or editing `PRICE_EUR_CENTS`, `PRICE_CURRENCY`, `PRICE_INTERVAL` or `env` —
`src/lib/config/**` is BP-005's"); WO-007's plan names none of the three. No
not-started order carries them (grep over `work-orders/`, 2026-09-03). Every path
below exists once WO-006 and WO-007 merge; all three rows are MODIFY.

**Reuse check.** `registry/capabilities.md` row "Every pinned number and env
binding" names `src/lib/config/constants.ts` under BP-005 as the one home; this
order extends that home and creates no second one (rule 7.2).

**Type fan-out check.** Not applicable: the change adds three exports and no
required member to any existing exported type. The project's type-check command
is `npm run typecheck` (`tsc --noEmit`; `tsconfig.json` includes `tests/**`), and
it is the stop condition's first gate.

## Interfaces
Exposes (verbatim from BP-005 `## Public interface`):
```ts
export const PRICE_EUR_CENTS: 4900        // ADR-052 p1 · BP-030 · REQ-022 c1, c4
export const PRICE_CURRENCY: 'eur'        // ADR-052 p1 · BP-030 · REQ-022 c4
export const PRICE_INTERVAL: 'month'      // ADR-052 p1 · BP-030 · REQ-022 c1, c2
```
Consumes: nothing. BP-005: "Imported by every other module; imports nothing."
Consumers: WO-117's `PRICE_OBJECT_SPEC` (BP-030), and ADR-052 point 3's boot
check — both read these three and nothing else for the amount.

## Steps
1. Write the three `tests/pins.test.ts` blocks and the structural rows in
   `tests/config/constants.test.ts` first; run them and watch every one fail on
   the absence of the exports (the module has no `PRICE_EUR_CENTS`).
2. Append the price group to `constants.ts`, transcribed from BP-005 — the
   values are REQ-022's, not chosen (BP-005 decision 5: "every value is
   transcribed, none is chosen").
3. Run `npm run typecheck`, `npx vitest run tests/config/constants.test.ts
   tests/pins.test.ts`; confirm the eight WO-006 rows and every WO-007 block
   still pass over the enlarged module.
4. Mutation pass: perturb each pin in turn (`4901`, `'usd'`, `'year'`) and
   confirm exactly that pin's block fails and no other; restore.

  WO-006 was cut. Not declared here, deliberately: BP-005 says its "value is
  owner-owed, not derived" and "the pins test asserts it is present and
  non-empty; it cannot assert a value nobody has ruled" — so a declaration
  without the ruling is either a fabricated customer-visible string (rule 1.2)

  the stamp slice under BP-048/ADR-083 — the term written in the create call,
  `canStamp`, `stampApplied`, and this pin — which WO-237's fourth `rests-on`
  and WO-264 record as cut by no work order and held on the owner's ruling
  (BP-048 `## Open questions`). Cutting it here would split that slice
  horizontally (rule 2.6).
- The Price object, `PRICE_OBJECT_SPEC`, and the boot check — WO-117.
- `PRICE_COPY_KEYS` and every sentence about the price — WO-118 / BP-019.

  owner's alone" (BP-005 price comment).
