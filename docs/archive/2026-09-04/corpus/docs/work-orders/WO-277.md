# WO-277 — The verdict — the three-armed measurement, the partition, the score and its band, and the one Verdict the report is made of

- Branch: wo/WO-277-verdict
- Estimate: ≤1 day

## Goal
Ship the value the top of the report is made of, end to end: the three-armed `Measured<T>` no constructor can fabricate, the exhaustive classification of every scan outcome into one of its arms, `BUILD.md` §5's arithmetic over those arms, the four band handles, the limiting factor, and one `Verdict` the stored scalar cannot disagree with.

> **Read `decisions/ADR-021.md` before writing a line of this WO.** It is a
> landmine: raising the cap to finish the last call, and computing a partial
> score from the factors that were measured, both read as kindnesses and both
> break a promise a customer can be shown.

**Risk: high — seam: money.** ADR-021 has two halves and this order carries the second: a scan the spend cap clamped must yield *no* score rather than a partial one computed from the factors that were measured. The trigger is the cost cap (WO-276's clamp, WO-281's ceiling); the harm is a fabricated customer-visible number that reads exactly like a real one. That is silent, so this order's criteria are mutation-tested (doctrine 0.13.2, rule 2b).

### From WO-052

Consumes: nothing.

Exposes (verbatim from BP-024 `## Public interface`, `src/lib/measure/measured.ts`):

```ts
/** BP-010 declares this type; this node produces it and owns its combinators.
 *  Every stored and rendered number in the product is one of the three arms. */
export type Measured<T> =
  | { kind: 'measured';   value: T; at: Date }
  | { kind: 'zero';       value: T; at: Date }
  | { kind: 'unmeasured'; reason: UnmeasuredReason; at: Date }
export type UnmeasuredReason = 'undeterminable' | 'not_attempted'

/** The only constructors. There is no `Measured.of(number | null)`: a nullable
 *  number cannot say why, and the whole point of REQ-004 is that it must. */
export function measured<T>(value: T, at: Date): Measured<T>
export function measuredZero<T>(zero: T, at: Date): Measured<T>
export function unmeasured<T>(reason: UnmeasuredReason, at: Date): Measured<T>

/** Total combinators. Arithmetic never leaves the type, so no call site can
 *  reach a raw number by accident and no reason is lost on the way. */
export function mapMeasured<A, B>(m: Measured<A>, f: (a: A) => B): Measured<B>
export function combine<A extends readonly Measured<unknown>[], B>(
  parts: A, f: (values: Values<A>) => B
): Measured<B>          // unmeasured if any part is unmeasured — see `worseReason`
export function worseReason(a: UnmeasuredReason, b: UnmeasuredReason): UnmeasuredReason
```

`Values<A>` is the tuple of the `value` types of `A`'s arms; it is a local type
helper of this file and is not part of the exported surface BP-024 declares.

```ts
/** The three the score is composed of. **The report shows none of them**: since
 *  the owner's ruling of 2026-09-03 (`OWNER-QUESTIONS.md` item 4) the verdict is
 *  the score and its band word plus one written line naming the factor holding
 *  the score down — decision 6. `Presence` is the geometric mean of BP-010's
 *  `searchPresence` and `aiPresence`, floored at 1 (`BUILD.md` §5) — those two
 *  are sub-measures, not factors. */
export type ScoreFactorName = 'foundations' | 'answerability' | 'presence'
export type ScoreFactors = Readonly<Record<ScoreFactorName, Measured<number>>>

export function presenceOf(d: Pick<Drivers, 'searchPresence' | 'aiPresence'>): Measured<number>
export function factorsOf(d: Drivers): ScoreFactors
export function computeScore(f: ScoreFactors): Measured<{ score: number; band: BandHandle }>
export type BandHandle = 'invisible' | 'hard-to-find' | 'findable' | 'dominant'
export function bandOf(score: number): BandHandle   // thresholds are BP-005's SCORE_BAND_BOUNDS

/** Which factor holds the score down — the one thing about the composition the
 *  report says, and it says it in a written line BP-019 holds, never as a value.
 *  `at_ceiling` exists so that a domain with nothing holding it down renders no
 *  line rather than an arbitrary one; `score_unmeasured` is reachable exactly
 *  when `scoreAndBand` is `unmeasured`, which is a test, not a convention. */
export type LimitingFactor =
  | { kind: 'factor'; factor: ScoreFactorName }
  | { kind: 'none'; because: 'score_unmeasured' | 'at_ceiling' }
export function limitingFactorOf(f: ScoreFactors): LimitingFactor
```

The arithmetic, verbatim from `BUILD.md` §5: `Presence = max(1, √(SearchPresence
× AIPresence))`; `Score = round( ∛(Foundations × Answerability × Presence) )`;
`Bands: 0–24 Invisible · 25–49 Hard to find · 50–74 Findable · 75–100 Dominant`.

## Steps

**WO-052's steps** (renumbered; order within the block unchanged):

1. Write the failing suite first.
2. Declare the union and `UnmeasuredReason`.
3. Implement the three constructors. Export no `of`, no `fromNullable`, no
   `orElse`, and no default parameter that would let `at` be read from a clock.
4. Implement `mapMeasured` — it preserves the arm and the `at`, and never
   touches the `unmeasured` arm's reason.
5. Implement `combine`: if every part is `measured` or `zero`, apply `f` to the
   values and return `measured`; if any part is `unmeasured`, return
   `unmeasured` carrying the fold of every unmeasured part's reason under
   `worseReason`. It never calls `f` when any part is unmeasured.
6. Implement `worseReason` per BP-024 decision 3: `undeterminable` wins whenever
   either side is `undeterminable`.
7. Add the type-level negatives with `@ts-expect-error` so the build fails if
   the guard ever weakens.

**WO-053's steps** (renumbered; order within the block unchanged):

8. Write the failing suite first.
9. Declare `ScanInput`, `InputOutcome` and `SectionName`.
10. Implement `classify` as a total switch over `InputOutcome` per BP-024's
   classification table: `{read:true, empty:false}` → `measured(null, at)`;
   `{read:true, empty:true}` → `measuredZero(null, at)`; `{read:false,
   because:'undeterminable'}` → `unmeasured('undeterminable', at)`;
   `{read:false, because:'not_attempted'}` → `unmeasured('not_attempted', at)`.
   Reading is the whole of the line: no arm inspects the input name to decide.
11. Write `FEEDS` from BP-024's table, transitively closed: `home_document` →
   `['foundations','answerability']`; `pricing_document` → `['answerability']`;
   `access_rules` → `['foundations']`; `business_profile` → `['presence']`;
   `market_suggestions` → `['presence']`; `own_ranked_rows` → `['presence']`;

13. Add the exhaustiveness guards: a `never` check on both unions so a new member

**WO-054's steps** (renumbered; order within the block unchanged):

22. Write the failing suites first.
23. Implement `verdictOf`: factors from `factorsOf`, score from `computeScore`, `limiting` from `limitingFactorOf`. The factors are computed and stored under `scans.drivers`; they are not a field of `Verdict` (BP-024 decision 6).
