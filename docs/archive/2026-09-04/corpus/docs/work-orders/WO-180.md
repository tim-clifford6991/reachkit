# WO-180 — The Settings screen: fourteen settings, seven actions, and a danger zone that states its consequence

- Branch: wo/WO-180-settings-screen
- Estimate: ≤1 day
- Preview: sdlc-factory/docs/design/previews/WO-180.html
- Signed-off: <date>

## Goal
Render the Settings screen offering exactly the fourteen settings and the seven
actions and nothing else, reachable with setup unfinished, with each danger-zone
action stating its consequence before it runs.

## File plan
> Every path below is **NEW** (no `src/` on disk, checked 2026-08-31). Placement
> follows `structure.md` and BP-055's `code:` globs; provisional.

| File | New/Modify | Change |
|---|---|---|
| `src/app/(account)/app/settings/page.tsx` | NEW | Server component: reads `readSettings`, composes the panels in two columns, and posts every change to `POST /api/settings`. Renders no control whose key is outside `SETTABLE` and no action outside `ACTIONS`. |
| `src/app/(account)/app/settings/panels/MarketPanel.tsx` | NEW | Category, competitor set (≤ 5, with BP-011's suggestions) and domain, each stating that it takes effect at the next weekly re-measurement via `effectKey`. |
| `src/app/(account)/app/settings/panels/PublishingPanel.tsx` | NEW | Mode, veto window (whole days 0 to 7), publish time, time zone and whether pages publish at all, with the `outcomeKey` line for the selected pair; plus destinations with health and Reconnect. |
| `src/app/(account)/app/settings/panels/ContentPanel.tsx` | NEW | The voice description and the do-not-claim list — the customer's own content, never logged. |

## Interfaces
Consumes (verbatim from BP-055 `## Public interface`):
```ts
export const SETTABLE = [
  'category', 'competitors', 'domain',
  'mode', 'veto_hours', 'publish_time', 'time_zone', 'publishing_enabled',
  'destinations', 'voice_text', 'do_not_claim', 'notifications',
  'name', 'email',
] as const
export const ACTIONS = [
  'invoices', 'cancel', 'resume', 'sign_out', 'export', 'unpublish_all', 'delete_account',
] as const
export function readSettings(siteId: string): Promise<SettingsModel>
```
and `SETUP_INCOMPLETE_ALLOWLIST` (BP-033, WO-148), `copy()` (BP-019), the
registered component set (BP-018).

Exposes: the `/app/settings` route. No new engine interface.

## Steps
1. **Precondition (rule 7.3):** signed preview. As of 2026-08-31
   `sdlc-factory/docs/design/tokens.md` is `Status: ready` and `components.md`
   registers 24 components, every row `proposed` and reaching `approved` only
   when a preview carrying it is signed off. The panels are screen compositions
   over registered components: `components.md` §4 names "the settings panels"
   in that list and rules, verbatim, "They are not registry rows and must not
   become any." So every control here is `Input`, `Toggle`, `Btn`, `Badge`,
   `Card` or `Divider`, and this WO mints none.
2. Write the failing tests first (§8).
3. Render one control per `SETTABLE` key and one per `ACTIONS` entry; assert the
   rendered control set is exactly those two tuples and contains no engine
   control — no question count, locale, cadence, cap, row limit, freshness
   window, scoring weight or model choice, and no "advanced settings" section
   behind a flag.
4. Render the screen reachable with setup unfinished through the allow-list, and
   assert every one of the seven actions works there — cancellation running the
   identical BP-017 path a finished customer's does.
5. Render refusals (`unknown_key`, `invalid_value`, `not_owner`) as one written
   line from the registry; never an error payload.
6. State each danger-zone action's consequence before it runs.
7. Mutation check: add a control for a pinned constant and confirm the
   closed-offer test fails; hide it behind a flag and confirm the same test still
   fails — a hidden control is still offered.
