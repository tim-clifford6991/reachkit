# WO-020 — readRobots — robots.txt and its per-agent verdicts

- Branch: wo/WO-020-read-robots
- Estimate: ≤1 day

## Goal
Read a site's `robots.txt` once and answer, per named agent, whether it is
allowed — the input behind the blocked-readers count and the reason a fetch may
return `robots_disallowed`.

## Provenance of this file plan
**This repository holds no `src/`.** Both paths are NEW under BP-006's `code:`
glob `src/lib/egress/**`. It modifies no file WO-018 or WO-019 created.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/lib/egress/robots.ts` | NEW | `readRobots(origin)`. Fetches `/robots.txt` through `safeFetch`, parses group-by-group, and fills every field of WO-018's declared `RobotsPolicy`: `origin` and `readAt` from the fetch, `disallowsAll` from a `User-agent: *` group disallowing `/`, `disallowedAgents` keyed by the token **as written in the document, lowercased**, `sitemaps` in the order they appeared, and `absent`. `absent: true` on a 404 or equivalent — a read with nothing in it, REQ-004 criterion 7's zero — with `disallowsAll: false`, `disallowedAgents` all-false and `sitemaps: []`, never `{ ok: false }`. A document read successfully that gates nothing is `absent: false` with the same empty verdicts: read and empty, distinct from unread. `{ ok: false, reason }` is returned only when the document could not be read at all. Consults `AI_READER_AGENTS` for the tokens it must answer for; the membership list is BP-005's and is read, never restated. This file declares no type — `RobotsPolicy` is imported from `types.ts`. |
| `tests/egress/robots.test.ts` | NEW | The tests below. |

## Interfaces
Exposes (verbatim from BP-006 `## Public interface`):
```ts
export function readRobots(origin: string): Promise<RobotsPolicy | { ok: false; reason: string }>
```
Consumes: `safeFetch()` and the **declared** `RobotsPolicy` (WO-018,
`src/lib/egress/types.ts` — BP-006 declares the six fields as of 2026-08-31;
this WO neither re-declares nor widens them) and `AI_READER_AGENTS` (BP-005
`constants.ts`).

## Steps
1. Write the parser, group by group.
2. Write `readRobots` over `safeFetch` with `respectRobots: false` for this one
   fetch — the robots document itself is not gated by robots.
3. Populate `disallowedAgents` from the document's own tokens, lowercased, not
   from `AI_READER_AGENTS`: BP-006 fixes that the closed set "is applied by the
   caller, not here", so a site disallowing an agent nobody counts still appears
   in the map and a counted agent the document never names is absent from it.
4. Write the tests; watch the "a 404 is `absent: true`, not a failure" test fail
   first by returning `{ ok: false }` for 404.

## Out of scope
- Declaring `RobotsPolicy` — WO-018 ships the type; this WO produces values of it.
- Counting blocked readers and rendering the count — BP-024 and BP-027. This
  file answers per token and applies no closed set.
- The robots policy the product *serves* on a customer domain — BP-047.
- Sitemap reading: `BUILD.md` §17 and BP-006 exclude it.

## Rollback

which refuses nothing. That is the less safe direction, so revert WO-018 with it.
