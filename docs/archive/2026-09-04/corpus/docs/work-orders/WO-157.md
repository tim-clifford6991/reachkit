# WO-157 — The growth module: a break where a week was not measured, a line where none has run

- Branch: wo/WO-157-overview-growth
- Estimate: ≤1 day
- Preview: sdlc-factory/docs/design/previews/WO-157.html
- Signed-off: <date>

## Goal
Render searches-appeared-in over time with the current value labelled and dated,
a break rather than a segment across an unmeasured week, and — where nothing has
been measured — one line naming the date the first measurement is due.

## File plan
> Every path below is **NEW** (no `src/` on disk, checked 2026-08-31). Placement
> follows `structure.md` and BP-038's `code:` globs; provisional.

| File | New/Modify | Change |
|---|---|---|
| `src/app/(account)/app/overview/growth.ts` | NEW | Assembles the weekly series as `Measured<number>` per week with each point's own `measuredAt`, and the `{ kind: 'none'; firstDueOn }` arm from BP-050's `nextDueOn`. Attaches each week's `WeekAccount`. |
| `src/app/(account)/app/overview/GrowthModule.tsx` | NEW | Renders BP-018's `GrowthLine` with a **gapped** series, the current value labelled with its measurement date, each unmeasured week's account beside the break, and the no-measurement line in place of the chart. |
| `tests/app/overview/growth.test.ts` | NEW | Series assembly, the gap, the none arm. |
| `tests/app/overview/growth-render.test.tsx` | NEW | The rendered break, the dated current value, the replacement line. |

## Interfaces
Consumes (verbatim from BP-038 `## Public interface`):
```ts
  growth:
    | { kind: 'series'; points: readonly { weekStart: Date; value: Measured<number>; measuredAt: Date }[] }
    | { kind: 'none'; firstDueOn: Date }                 // criterion 3
```
and `renderMeasured()` (BP-019), `GrowthLine` (BP-018 — must accept a gapped
series; recorded as a dependency by BP-038 decision 3), `accountForWeek()` and
`nextDueOn()` (BP-050).

Exposes: `readGrowth()` and `GrowthModule` inside the overview module; no new
cross-node interface.

## Steps
1. **Precondition (rule 7.3):** signed preview. As of 2026-08-31
   `docs/design/tokens.md` is `Status: ready` and `components.md` registers 24
   components, every row `proposed` and reaching `approved` only when a preview
   carrying it is signed off. `GrowthLine` is among them and its registered
   contract already carries what this WO needs: weekly points each with **its
   own measurement date**, a gapped series that is "never carried forward, never
   interpolated", and a `no-measurement` state carrying the first-due date in
   place of the chart. Nothing further is owed by the registry; the preview is
   the gate.
2. Write the failing tests first.
3. Build the series with one `Measured<number>` per week and its own
   `measuredAt`; never carry a value forward and never interpolate (BP-038
   decision 3).
4. Render an `unmeasured` week as a break with that week's own account beside
   it; render a partially measured week's measured values with their date and
   state the rest as not measured.
5. Render every value through `renderMeasured` so an unmeasured input cannot
   appear as a zero and a measured zero cannot appear as a dash.
6. Where `kind: 'none'`, render one line carrying `firstDueOn` — the same date
   the shell states.
7. Mutation check: join the two points either side of a gap and confirm the
   break test fails.
