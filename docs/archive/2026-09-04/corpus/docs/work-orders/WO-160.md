# WO-160 — The score and AI-answers tiles: one headline each, its delta or its goal

- Branch: wo/WO-160-overview-tiles
- Estimate: ≤1 day
- Preview: sdlc-factory/docs/design/previews/WO-160.html
- Signed-off: <date>

## Goal
Render the score tile and the AI-answers tile, each leading with exactly one
headline number that carries its change since the previous measurement or its
goal, and never appears bare.

## File plan
> Every path below is **NEW** (no `src/` on disk, checked 2026-08-31). Placement
> follows `structure.md` and BP-038's `code:` globs; provisional.

| File | New/Modify | Change |
|---|---|---|
| `src/app/(account)/app/overview/ScoreTile.tsx` | NEW | Renders `Module<number>` for the score: the headline through `renderMeasured`, its delta where one exists, otherwise its goal (`score`, value from `GOAL_VALUES`) with the meaning key. |
| `src/app/(account)/app/overview/AiAnswersTile.tsx` | NEW | Same shape for AI answers, drawn with BP-018's `AiDotMatrixChart`; goal `ai_answers`, value from `GOAL_VALUES`. |
| `tests/app/overview/tiles.test.tsx` | NEW | One headline per tile, delta-or-goal, the never-bare property, the measured trichotomy. |

## Interfaces
Consumes (verbatim from BP-038 `## Public interface`):
```ts
export interface HeadlineNumber<T> {
  value: Measured<T>
  goal: GoalKey                      // every headline has one; a pin, not a setting
  delta?: Measured<T>                // change since the previous measurement, where one exists
}
export interface ContextValue<T> { value: Measured<T>; label: CopyKey }
export interface Module<T> { headline: HeadlineNumber<T>; context?: readonly ContextValue<unknown>[] }
export const GOALS: Readonly<Record<GoalKey, { value: number; meansKey: CopyKey }>>
```
and `renderMeasured()` / `copy()` (BP-019), `AiDotMatrixChart` (BP-018),
`GOAL_VALUES` (BP-005).

Exposes: `ScoreTile`, `AiAnswersTile` inside the overview module; no new
cross-node interface.

## Steps
1. **Precondition (rule 7.3):** signed preview. As of 2026-08-31
   `docs/design/tokens.md` is `Status: ready` and `components.md` registers 24
   components including `AiDotMatrixChart` — every row `proposed`, reaching
   `approved` only when a preview carrying it is signed off. The preview, not
   the registration, is the gate.
2. Write the failing tests first.
3. Render exactly one headline per tile; anything else the tile shows is a
   `ContextValue` and renders bare.
4. Render the delta where a previous measurement exists; otherwise render the
   goal with its meaning key. Never render the headline alone.
5. Render every value through `renderMeasured`, so an unmeasured input cannot
   appear as a zero and a measured zero cannot appear as a dash.
6. Mutation check: drop the goal fallback and confirm the no-previous-measurement
   test fails.

## Blocked — REQ-041 criterion 12

REQ-041 gained acceptance criterion 12 on 2026-09-03 and moved `approved → in-review`. The new criterion states:

> Given the AI-answers headline on Overview, when it renders, then it states, alongside its goal, in how many of a fixed trailing window of weeks the customer was named in at least one tracked question's AI answer, and **no other reading of AI-answer movement is shown anywhere on Overview: no change from the previous week's count, and no change reported for any single tracked question**.

This work order's goal specifies:

> Render the score tile and the AI-answers tile, each leading with exactly one headline number that carries its change since the previous measurement or its goal, and never appears bare.

The phrase "Same shape for AI answers" in the file plan (line 35) references the score tile's delta-or-goal pattern. This contradicts criterion 12, which forbids rendering "change from the previous week's count" on the AI-answers headline.

BP-038 decision 5 (added 2026-09-03) correctly addresses this conflict: `readOverview` never sets `aiAnswers.headline.delta` and instead attaches a `ContextValue<AiPresenceWindow>` (the windowed presence reading). This work order's specification has not been aligned with that decision.

**To clear the gate:** update WO-160's goal and file plan for `AiAnswersTile.tsx` to specify that it renders the goal (never a delta) with a `ContextValue<AiPresenceWindow>` as the windowed presence reading (the only place movement is shown on the card, at the aggregate, never per-question).
