## Goal
Decide whether a recorded test can be evaluated from what a week measured, turn a decided test into one of the three verdicts in the right order, and carry a decline rather than smoothing it.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/lib/opportunities/verdicts/evaluate.ts` | NEW | `evaluateAcceptance` verbatim from BP-051's public interface — pure, over the three `Acceptance` forms WO-181 recorded: `top20` decided from the week's measured position for that search, `named_on` from whether the week's answer for that question names the customer, `gate_cleared` from whether the barrier is cleared. Returns `{ decided: false, cause }` and never rewrites the recorded test to something it could decide. **It produces exactly two of `NotJudgeableCause`'s five members** — `search_untracked` (an absent key in `positions`) and `question_left_set` (an absent key in `namesCustomer`), absence being meaningful and never a zero. | `src/lib/opportunities/verdicts/verdict.ts` | NEW | `verdictFor(a: { decided: boolean; passes: boolean; publishedAt: Date; week: WeekStart }): Verdict` — the order is fixed: the test is evaluated **first**, and only a page that does not yet pass is aged into `too_early`. | `src/lib/opportunities/verdicts/movement.ts` | NEW | `movementFor(a: { previous: { week: WeekStart; value: Measured<number> } | null; current: Measured<number>; week: WeekStart }): Movement | null` — compares against the previous **recorded** measurement, sets `declined` from that comparison, carries `from` and `to` as raw `Measured<number>` values, and sets `spansWeeks` to the number of weeks the change covers where the previous recorded measurement is not the previous week's. |
| `tests/opportunities/verdicts/evaluate.test.ts` | NEW | One fixture per acceptance form, decided and undecided; a week that measured the search decides `top20` while a week that did not returns `search_untracked`; a question that left the tracked set returns `question_left_set`; the two causes are returned distinctly and neither is ever substituted for the other; a `gate_cleared` test whose barrier is absent from `gatesCleared` is undecided rather than failing. **Two negative cases, which are the ones that discriminate:** no input to this function produces `page_not_found` (an exhaustive sweep of the fixture space asserts the returned cause is always one of the two), and no input produces `unpublished` or `domain_changed` — a test that asserted only the positive cases would survive a helpfully-added branch that guessed at either. |

| `tests/opportunities/verdicts/movement.test.ts` | NEW | A worse measurement sets `declined` true and carries both raw values; nothing rounds a decline away and nothing substitutes the better earlier figure; a previous measurement two weeks back gives `spansWeeks: 2`; no previous measurement gives null. |

## Steps
1. Write the three test files first and run them; each must fail on a missing module.
2. Implement `evaluate.ts`. It reads the recorded `Acceptance` and never writes it — WO-181's trigger is the invariant, and this module holds no write path to `opportunities` at all (REQ-047 c8, REQ-063 c6).
3. Implement `verdict.ts` with the evaluation-then-age order. BP-051 decision 4: aging first would report a page that is demonstrably working as too early to judge, which is the opposite of the promise.
3a. Before writing a third `cause` branch in `evaluate.ts`, read ADR-085. This module has no publication row, no destination and no network: `page_not_found` is a fact only BP-049's one fetch at 24 hours ever learns, and a branch here that infers it from a missing measurement would put a live page into a state ADR-072 Decision 5 makes permanent. Two causes out, and the negative test above is what holds the line.
4. Implement `movement.ts`. `from` and `to` stay `Measured<number>`; nothing here rounds, averages or replaces a value.
5. Run the tests. Then mutate: age before evaluating and confirm the young-and-passing case fails; round the movement values to integers and confirm the decline case fails.

**Discriminates (mutation check, constitution §8).**
- Aging before evaluating makes the young-and-passing case read `too_early` — the test asserts `working`, and the mutation is the natural reading of "too early to judge".
- Collapsing `search_untracked` and `question_left_set` into one cause fails the distinctness case. The two are read from absences in two different maps and the customer is told which happened (c6's written line), so a single "not measured" cause would render one sentence for two facts.
- **Adding a branch that returns `page_not_found` from a missing measurement** — the plausible-looking completion of the union — fails the negative sweep, and nothing else. Its effect in production is a page retired from judgement forever (ADR-072 Decision 5) on the strength of a measurement gap this function cannot tell from a removed page. The negative case exists because a positive-only suite is green either way.
- Rounding or smoothing a decline makes the c3 test fail; a test that only checked `declined` would survive a substituted `from` value, which is why both raw values are asserted.
