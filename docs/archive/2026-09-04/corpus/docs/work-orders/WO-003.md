# WO-003 — Default-deny middleware and the one public allow-list

- Branch: wo/WO-003-middleware
- Estimate: ≤1 day

## Goal
Make authorisation default-deny at the edge of the web container, with one
declared allow-list of public paths, so a route added under `src/app/(account)/`
cannot become reachable by omission.

## Provenance of this file plan
**Re-checked against the tree on 2026-09-03**, after W1 closed and W2's WO-051,
WO-041, WO-056, WO-057, WO-058 and WO-062 merged. `src/` and `tests/` now exist;
`src/middleware.ts` still does not — no `middleware.ts` is anywhere on disk and
`grep -rn PUBLIC_PATHS src tests` returns nothing. Both paths below are still
NEW, anchored to BP-001's `code:` glob `src/middleware.ts`. The earlier
provenance line, "This repository holds no `src/`", was true when this order was
cut and is not true now; what follows replaces it.

What landed under this plan since it was written, and what each fact means here:

- **The three route groups are real** (WO-002). `src/app/(public)/layout.tsx`
  and `src/app/(account)/layout.tsx` are pass-throughs that each name this work
  order as the boundary — "The group's own existence, matched by WO-003's
  middleware, is the authorisation boundary; there is no check to write in this
  file" (`src/app/(public)/layout.tsx`). Neither layout is modified here.
- **`src/app/api/scan/route.ts` is on disk** (WO-062) — the first file BP-001's
  `src/app/api/**` glob has ever matched. `POST /api/scan` sits in BP-001
  `## Public interface` under "Routes (public)", so step 1's derivation now
  covers a route that exists rather than only ones that do not. WO-062's
  `rests-on` row 1 — "`src/middleware.ts` lists every path in this node on its
  public allow-list, so no session is read on this route" — is `open` solely
  because this file is absent; this work order's validator is the first stage
  that can observe it (§2.3b), and WO-062's `done` gate is held on it (§3.1).
- **No page or route file exists under `(public)` or `(account)` yet** — the
  landing surface is WO-070's `page.tsx`, still `approved`. So the deny branch
  ships against real groups but no live account route, and nothing already
  reachable is taken away.
- **Test placement needs no config change.** `tests/app/**` is collected by
  `vitest.config.ts`'s default `node` project and appears in none of its
  `exclude` lists (the excluded suites are `tests/ui/**`, three `tests/db/`
  files and `tests/scan/free/admission-claim.test.ts`). `tests/app/` holds
  seven suites today; this adds an eighth and touches no other file.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/middleware.ts` | NEW | One matcher over every request. Denies by default; permits only a path matching the exported `PUBLIC_PATHS` allow-list, `/api/jobs/*`, `/api/stripe/webhook`, and Next.js internals. `PUBLIC_PATHS` is derived from BP-001 `## Public interface` "Routes (public)" — which includes `POST /api/scan`, the one such route already on disk (`src/app/api/scan/route.ts`). A denied request is redirected to the sign-in address prompt and the response body states nothing about whether an account or a payment exists. Reads no database: the session presence check is a cookie/JWT check only. |
| `tests/app/middleware.test.ts` | NEW | The discriminating tests below. Collected by `vitest.config.ts`'s default `node` project as it stands; no config file is edited, and no route or layout file under `src/app/**` is added or modified by this order. |

## Interfaces
Exposes:
```ts
// src/middleware.ts
export const PUBLIC_PATHS: readonly string[]   // the one allow-list
export const config: { matcher: string[] }
export function middleware(req: NextRequest): NextResponse
```
Consumes: nothing outside Next.js. Session *identity* is BP-061's
(`currentSession()`); this middleware asserts only presence, so the account
container is not reachable before that node ships.

## Steps
1. Write `PUBLIC_PATHS` from BP-001's public route list, one entry per route.
2. Write the matcher and the deny branch.
3. Write the tests and watch the "new account route is denied by default"
   test fail before `src/middleware.ts` exists (constitution §8). Next.js
   middleware matches on the request path, not on a route file, so the
   by-omission case is a path under `(account)` that the allow-list does not
   name — no fixture route file is added under `src/app/(account)/`, which
   holds only WO-002's pass-through layout and must keep holding only that.
