# WO-108 — The kind-scoped unsubscribe token — one mail off, the other two untouched

- Branch: wo/WO-108-unsubscribe-token

- Estimate: ≤1 day

## Goal
Sign an unexpiring token over `(userId, kind)` that reads without writing and
switches off exactly the one mail it was signed for.

## Provisional against an empty repo
**No `src/` exists.** All files NEW, inside BP-059's
`src/lib/mail/notifications/**` glob. Shares no file with WO-107.

Reuse check (rule 7.2): `applyUnsubscribeToken()` is BP-059's in the capability
index and exists nowhere. BP-029's `optOutTokenFor()` / `applyOptOutToken()`
(WO-112) is a **different** token over a **different** subject and is not reused
here — ADR-042's table: `/unsubscribe/{token}` is signed on `(user, kind)`,
`/opt-out/{token}` is signed on the address. Two token formats, permanently. If a
shared HMAC helper is wanted later it is a signing utility in BP-005's config
module, never a shared token format.

## Read ADR-042 before touching this file
`applyUnsubscribeToken()` never writes `email_suppressions`. There is no code path
from this file to BP-029's store.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/lib/mail/notifications/unsubscribe.ts` | NEW | The three functions below. HMAC over `(userId, kind)` with the signing secret from BP-005's `env`; no expiry field is encoded at all, so none can be checked. `readUnsubscribeToken` is pure and performs no write — it is what BP-001's GET renders from. `applyUnsubscribeToken` calls `setNotifyPref(… on: false)` and is idempotent: a second use returns `{ switchedOff }` again. |
| `tests/mail/notifications/unsubscribe.test.ts` | NEW | REQ-075 c5, the read/write split, idempotency, and the no-expiry property. |

## Interfaces
**Exposes** (verbatim from BP-059 `## Public interface`):
```ts
// src/lib/mail/notifications/unsubscribe.ts
export function unsubscribeTokenFor(a: { userId: string; kind: NotifyKind }): string
export function readUnsubscribeToken(token: string):
  | { userId: string; kind: NotifyKind }
  | { error: 'invalid' }
export function applyUnsubscribeToken(token: string): Promise<
  | { switchedOff: NotifyKind }
  | { error: 'invalid' }>                 // idempotent: a second use succeeds
```
**Consumes**: `NotifyKind`, `setNotifyPref()` (WO-107); `env`'s unsubscribe
signing secret (BP-005, named in BP-059's diagram as "BP-005 · unsubscribe signing
secret").

## Steps
1. Write `unsubscribe.test.ts` first and watch it fail.
2. `unsubscribeTokenFor`, then `readUnsubscribeToken` (pure), then
   `applyUnsubscribeToken` (the only writer).
3. Assert by construction that this module imports nothing from
   `src/lib/mail/leads/` — the ADR-042 separation, checked as a dependency
   assertion rather than a review comment.
4. Mutation check: make `readUnsubscribeToken` write the preference and confirm
   the read-does-not-write test fails; add an expiry and confirm the
   year-old-token test fails.

## Out of scope

  This WO exposes a read that changes nothing precisely so BP-001's GET can render

  otherwise switch off mail nobody chose to stop").

- Any customer-visible string, including the confirmation page's (REQ-093 c1).
