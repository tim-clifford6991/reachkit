# WO-173 — The Markdown editor, its live preview, the unsaved indicator and the copy-out controls

- Branch: wo/WO-173-draft-editor
- Estimate: ≤1 day
- Preview: sdlc-factory/docs/design/previews/WO-173.html
- Signed-off: <date>

## Goal
Let the customer edit the draft's Markdown with a live preview as they type,
autosave on pause and on leaving, tell them plainly when a save has not landed,
and offer the Markdown and the HTML to copy.

## File plan
> Every path below is **NEW** (no `src/` on disk, checked 2026-08-31). Placement
> follows `structure.md` and BP-044's `code:` globs; provisional.

| File | New/Modify | Change |
|---|---|---|
| `src/app/(account)/app/draft/[draftId]/Editor.tsx` | NEW | Client component: a Markdown textarea (no rich-text, no WYSIWYG — REQ-045's non-goals), autosave debounced at `AUTOSAVE_DEBOUNCE_MS` with a flush on blur and on route change, a retry on the next tick after a failed save that keeps the buffer, and the unsaved indicator. |
| `src/app/(account)/app/draft/[draftId]/Preview.tsx` | NEW | The preview pane, re-rendered at most every `PREVIEW_DEBOUNCE_MS`, entirely client-side so "as they type" costs no round trip. |
| `src/app/(account)/app/draft/[draftId]/CopyOut.tsx` | NEW | The two copy controls, always shown, fetching `GET /api/drafts/{id}/export?as=md|html`. |
| `tests/app/draft/editor.test.tsx` | NEW | Typing and preview, the debounce and the flush, the unsaved indicator, the copy controls' presence for a draft and a published page. |

## Interfaces
Consumes (verbatim from BP-044 `## Public interface`):
```ts
/** PATCH /api/drafts/{id} — the autosave. Last write wins (criterion 6). */
export interface SaveBody { bodyMd: string }
export type SaveResult =
  | { ok: true; savedAt: Date; grounded: { present: boolean }; claim: { state: 'outstanding' } }
  | { ok: false; refused: 'not_editable' | 'too_large' | 'store_unavailable' }

export const AUTOSAVE_DEBOUNCE_MS: 1200
export const PREVIEW_DEBOUNCE_MS: 100
export const MAX_BODY_BYTES: 262144
```
and `copy()` (BP-019), the registered component set (BP-018), the export route
(WO-171).

Exposes: `Editor`, `Preview`, `CopyOut` inside the draft module; no new engine
interface.

## Steps
1. **Precondition (rule 7.3):** signed preview. As of 2026-08-31
   `sdlc-factory/docs/design/tokens.md` is `Status: ready` and `components.md`
   registers 24 components, every row `proposed` and reaching `approved` only
   when a preview carrying it is signed off. **One gap blocks this screen's
   preview:** the Markdown textarea in `Editor.tsx` has no registered
   component — `components.md` §4 row 2 records that `BUILD.md` §2.2's daisyUI
   set has `input` and no multi-line control, and that BP-018 declares none, so
   "the draft editor cannot be built from the registered set" and a BP-018 row
   is owed. (That row names WO-172 as the consumer; `Editor.tsx` is in **this**
   work order's file plan, not WO-172's.) Do not mint a control here — the
   preview resolves it. The two copy controls are `Btn`, which
   `components.md` §4 states explicitly: "It is `Btn`. No `CopyButton` is
   registered and none should be."
2. Write the failing tests first (§8).
3. Render the Markdown in a textarea and the rendered result in a preview pane
   updated at most every 100 ms, client-side only.
4. Autosave on a 1200 ms debounce plus a flush on blur and on route change — no
   explicit save action anywhere in the view.
5. On a refusal, show the unsaved line from the registry, keep the buffer and
   retry on the next tick. Never discard the customer's words and never redirect.
6. Show the copy-as-Markdown and copy-as-HTML controls always, for a draft and
   for a published page alike.
7. Mutation check: discard the buffer on a failed save and confirm the
   never-lose-words test fails; remove the blur flush and confirm the
   leaves-the-view test fails.
