# WO-128 — The 15-minute chase and the 24-hour backstop — no charge leaves a founder with nothing

- Branch: wo/WO-128-provisioning-due-work
- Estimate: ≤1 day

## Goal
Export the two due-work queries and the two actions behind REQ-024's backstops, so
that a founder who has paid is written to at 15 minutes and has an open account
at 24 hours, whatever the webhook did.

## File plan
> **Every path below is NEW.** No `src/` exists. Anchored to
> `registry/structure.md` and BP-032's `code:` glob
> `src/lib/account/provisioning/**`. Provisional against a repo with no code.
>
> **This work order writes no file under `src/jobs/**`.** BP-003 owns the
> `account/maintenance` tick that calls these four functions every 15 minutes
> (BP-003's `JobId` union names `BP-032.paymentsAwaitingSignIn -> chaseSignIn`
> and `BP-032.paymentsWithoutAccounts -> backstopProvision` explicitly). This
> node exports the rule; BP-003 owns the schedule (BP-032 decision 4).

| File | New/Modify | Change |
|---|---|---|
| `src/lib/account/provisioning/due-work.ts` | NEW | Exports `paymentsAwaitingSignIn(now)` — completed sessions charged at least 15 minutes ago whose account has `first_signed_in_at is null` and which have not already been chased — and `paymentsWithoutAccounts(now)` — completed Stripe sessions charged at least 24 hours ago with no matching `users.checkout_session_id`. Both take an explicit `now`, so the module is testable with a fixed clock and no scheduler. Both are indexed reads. |
| `src/lib/account/provisioning/chase.ts` | NEW | Exports `chaseSignIn(sessionId)`. Sends one `account` mail: it carries a working sign-in link where the account is open, and says the account is not open yet where it is not. It **never asks for payment again** — no checkout URL, no price key, no purchase call is reachable from this file. Stamped so a re-run of the tick does not re-send. |
| `src/lib/account/provisioning/backstop.ts` | NEW | Exports `backstopProvision(sessionId)`. Opens the account from the Stripe session alone by calling `provisionFromPayment`, and **never creates a charge and never calls `createCheckoutSession`** (BP-032). Emits an alert-level event: the backstop firing at all means the webhook path failed for a paying customer. |
| `tests/account/provisioning/due-work.test.ts` | NEW | Fixed-clock boundaries: at 14:59 not due, at 15:01 due; a founder who has signed in is never due; an already-chased session is not due twice; at 23:59 no backstop, at 24:01 backstop; a session with an account is never returned by `paymentsWithoutAccounts`. |
| `tests/account/provisioning/chase.test.ts` | NEW | Open account → the mail carries a working link; no account yet → the mail says so and carries none; **the discriminating case**: a source-level and behavioural assertion that no chase mail contains a checkout URL or price key, and that `chase.ts` imports nothing from `src/lib/account/checkout/**`. Running the tick twice sends one mail. |
| `tests/account/provisioning/backstop.test.ts` | NEW | A completed session with no account gets an account and a link within the run; **no second charge is created** (asserted against the Stripe stub's charge and session-creation calls); running twice provisions once; the alert event is emitted exactly once per firing. |

## Interfaces
Exposes (verbatim from BP-032's `## Public interface`):
```ts
export function paymentsAwaitingSignIn(now: Date): Promise<string[]>   // charged ≥15 min ago, nobody signed in
export function paymentsWithoutAccounts(now: Date): Promise<string[]>  // charged ≥24 h ago, no account opened
export function chaseSignIn(sessionId: string): Promise<void>          // the `account` mail, REQ-024 c5
export function backstopProvision(sessionId: string): Promise<void>    // REQ-024 c6; no second charge, ever
```
Consumes: `provisionFromPayment` (WO-126); `issueLink` (BP-061, WO-136);
`sendEmail` (BP-016) with `kind: 'account'`, whose register row reads
`'account': { occasionsFrom: 'REQ-024, REQ-074, REQ-076, REQ-077, REQ-079', stoppable: false }`.

## Steps
1. Write `tests/account/provisioning/due-work.test.ts` with a fixed clock and
   watch the boundaries fail.
2. Implement `due-work.ts` as two indexed queries.
3. Implement `chase.ts`, then its no-checkout assertions.
4. Implement `backstop.ts`, then its no-second-charge assertion.
