## Goal
Compose the three family derivations into `deriveOpportunities`, let the model label but never select, de-duplicate against the open set, persist, and return the three rejection counts.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/lib/opportunities/derive/typing.ts` | NEW | `refineType(c: CostContext, candidate: Candidate): Promise<Candidate>` — one `llm()` call at site `opportunity-typing`, tier `haiku`, whose parsed schema admits only a member of `OpportunityType` and a proposed slug/title. | `tests/opportunities/derive/typing.test.ts` | NEW | A stub `llm()` returning a type outside the enum, an `unmeasured` result, and a candidate with a different query: the first two leave the deterministic type in place, and no stub response can add a candidate, remove one, or change its evidence or acceptance. |

## Steps
1. Write both test files first and run them; both must fail on a missing module.
2. Implement `typing.ts`. The schema passed to `llm()` admits the closed enum and a string slug and nothing else, so a model response that names a ninth type does not parse and arrives as `unmeasured` (BP-009: "a response that does not parse against the schema is `unmeasured`").
3. Implement `persist.ts`, then `index.ts`. Every write goes through `db()`; nothing in this node uses `dbAdmin()`.
4. Order inside `deriveOpportunities`: derive (deterministic) → qualify and band (WO-182, already applied inside the family modules) → refine type → persist. Nothing after the derivation step may add a candidate.
5. Interface note: BP-013's component-level `deriveOpportunities` is declared with `ownRanked: number` returning `Opportunity[]`. BP-040 is the node cut from REQ-047 and its signature is the one implemented here, on the precedent BP-010 records for `computeScore` ("one symbol … cannot carry two signatures, and BP-024's is the one bound to the requirement"). Reported upward; no blueprint is edited by this WO.
6. Run the tests, then mutate: let `refineType` return a candidate it built itself and confirm `typing.test.ts › no stub response can add a candidate` fails.

## Test plan

| Acceptance criterion (verbatim from REQ) | Test |
|---|---|
| **REQ-047 c1** Given a completed scan, when opportunities are derived, then each is of exactly one kind from a fixed set of eight — four that propose writing a new page (answering a question rivals own, a search the customer is absent from, a comparison, a page format the customer lacks), three that propose improving a page the customer already has (expand it, make it answerable, refresh it), and one that asks the customer to remove an access barrier — and an opportunity of any other kind cannot be stored. | `typing.test.ts › a model type outside the enum leaves the deterministic type` and `derive.test.ts › every created row is one of the eight` |
| **REQ-047 c2** Given an opportunity, when it is stored, then it carries the measured evidence that produced it: for the four that propose writing a new page, the search, its volume, and the rival page or position that shows the gap; for the three that propose improving a page the customer already has, the search, its volume, the page of theirs it names, and the measurement on that page that shows the shortfall — its own position, its thinness, or its staleness — with no rival required; for the one that asks the customer to remove an access barrier, the barrier found and the page of theirs it was found on. Every one of those values is one the product measured and stored, never one it composed (REQ-093 criterion 4). | `derive.test.ts › the stored evidence equals the derived evidence, value and date` — nothing is recomputed on the way to the row |
| **REQ-047 c3** Given the available evidence has been exhausted, when upcoming days are filled, then no further opportunity is created and those days stay empty. | `derive.test.ts › a report yielding no qualifying candidate returns created: [] with counts and creates nothing` — the empty-day half is BP-001's calendar |

**Discriminates (mutation check, constitution §8).**
- Letting the `opportunity-typing` schema accept a free-form string makes `typing.test.ts`'s out-of-enum case store a ninth type — and WO-181's check constraint refuses the row, so the failure is visible in two places.
- Deleting the `ON CONFLICT` handling makes the re-run test throw instead of counting `duplicate_open`; deleting the partial unique index instead makes it create a second open row, which the same test catches.
- Making `deriveOpportunities` throw on an empty result makes the c3 test fail — empty is a success state (`BUILD.md` §2.5).
