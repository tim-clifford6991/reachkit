# WO-212 — The claim transaction — the switch read inside it, and the conflict clause that refuses only a delivered row

- Branch: wo/WO-212-publish-claim
- Estimate: ≤1 day

## Goal
Ship the one transaction that claims a publish attempt: lock the site row, re-read the switch, re-evaluate publishable and told, check the ceilings and the destination, then upsert the publication row and refuse only against a delivered one.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/publish/attempt/claim.ts` | NEW | The claim, in BP-045's stated order and no other: lock the `sites` row; re-read `publishing_enabled`; re-evaluate `becomesPublishable` and `toldCurrentPair`; `ceilingRoom`; the destination is live and `health = 'ok'`; then, quoted verbatim from BP-045 (the `…` is the blueprint's own elision of the column list, not an edge range): `insert into publications … on conflict (draft_id, destination_id) do update set attempt_no = publications.attempt_no + 1, claimed_at = now() where publications.delivery_state <> 'delivered' returning id`. No row returned means a delivered publication exists → return `alreadyPublished: true` and take no edge. Only then does the transaction set `state='publishing'` via WO-209's `transition()` and commit. **The adapter is never called inside this transaction.** The insert writes `made_live_by_us` **at its column default, `false`** (WO-208), and names it in no `set` list on either limb: at claim time no delivery has happened, so nothing is yet known about whether ReachKit made the page live, and `false` is the only honest value. See the note below the interface block. |
| `tests/publish/attempt/claim.test.ts` | NEW | The three discriminating tests ADR-080 decision 7 requires, plus the ordering assertions: a retry after a delivery whose outcome was never recorded creates no second publication and returns `alreadyPublished`; an attempt against an unpublished page creates no post; a disconnect-and-reconnect creates no second post. Plus: a switch recorded between the invocation start and the claim refuses with `heldBy:'switch_off'`; the transaction issues no outbound network call (egress seam stubbed to throw); a freshly claimed row has `made_live_by_us = false`; and **a re-claim of a row already carrying `made_live_by_us = true` leaves it `true`** — the conflict clause's `do update set` list is asserted, by re-reading the row, to contain neither `made_live_by_us` nor `live_url`. |

**Exposes** — copied exactly from BP-045's `## Public interface`:

```ts
// consumed by publish() in src/lib/publish/attempt/index.ts (WO-213).
// The result shapes are BP-045's publish() union, minus the delivery outcome:
//   | { ok: true; publicationId: string; alreadyPublished: boolean }
//   | { ok: false; reason: 'held'; heldBy: 'switch_off' | 'ceiling_day' | 'ceiling_week'
//                                        | 'destination_not_working' | 'not_publishable' | 'telling_owed' }
```

**The claim is not the writer of ADR-081's discriminator, and must not become
one.** `publications.made_live_by_us` is written from `DeliveryResult.madeLive`
when the outcome is recorded (BP-045's data-model delta; WO-213), which is after
this transaction has committed and the adapter has answered. Two edits here would
each look like tidying and each would break ADR-081:

- **Setting it in the insert from the destination's `kind`** — `'hosted' → true`.
  It is right today and it is the wrong fact: ADR-081 decision 2 states the
  discriminator is what *this call did to this page*, not a property of the
  destination, and a hosted delivery that failed did not make anything live.
- **Adding it to the `do update set` list** on the conflict limb. A re-claim
  after a recorded delivery is already refused by
  `where publications.delivery_state <> 'delivered'`, but a re-claim of a
  `failed` row would reset the column — and on the day a WordPress publication
  can be made live, that turns REQ-079 criterion 4's population into REQ-056
  criterion 16's silently, on a retry, with every test green.

`claim.ts` is internal to `attempt/`; BP-045's public surface is `publish()` and
`unpublish()` in `attempt/index.ts`. Splitting the claim into its own file is a
file-plan choice (rule 1.1) so the transaction can be tested without an adapter
and so the "the adapter is called after the commit" property is visible in the
module graph rather than only in a comment. Cost of reversing: merge two files.

## Steps
1. Read ADR-080 in full first. Every simplification of the conflict clause below is one this ADR forbids and none of them makes a happy-path test fail.
2. Implement the claim in exactly BP-045's order. Do not reorder the checks; the switch re-read must be inside the transaction, and it is what makes "instant" true.
3. Write the conflict clause verbatim, including `where publications.delivery_state <> 'delivered'`. `do nothing` refuses the legitimate retry; an unconditional `do update` allows the duplicate.
4. Map each refusal to its `heldBy` member. A ceiling refusal is a hold, not a failure; a destination that is not working is a hold at the claim and becomes `no_destination` only at the attempt (WO-213).
5. Assert the claim makes no network call by stubbing BP-006's egress seam to throw.
6. Write the three ADR-080 tests first and watch each fail with the guard removed — that is the mutation check §8 requires and the reason these three tests exist at all.

## Out of scope
- The adapter call, the outcome write and the retry — WO-213 and WO-214. Setting `made_live_by_us` to anything other than its default is WO-213's alone.
- Deleting a publication row for any reason whatsoever. ADR-080 decision 2 permits exactly one deletion path and it is BP-017's 30-day purge.
- The destination's health *check* — BP-058's (WO-226). This work order reads the recorded column.
