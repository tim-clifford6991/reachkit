# WO-177 — accountForWeek: the one account of a week that every surface reads

- Branch: wo/WO-177-weekly-account
- Estimate: ≤1 day

## Goal
Return the single total account of any week — complete, partial, not measured,
or not owed — so that the shell, Overview, the calendar and the weekly mail all
read one derivation instead of four.

## File plan
> Every path below is **NEW** (no `src/` on disk, checked 2026-08-31). Placement
> follows `structure.md` and BP-050's `code:` globs; provisional.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/scan/weekly/account.ts` | NEW | `WeekAccount` and `accountForWeek()` — total over the four cases, projected from the week's scan row or from the absence of one. One indexed row lookup; memoised per request by callers, never cached across requests. It renders nothing and holds no copy. |
| `tests/scan/weekly/account.test.ts` | NEW | The four variants, the ended-access silence, the stability of the not-measured line, the single-lookup budget. |

## Interfaces
Consumes: the `scans` row for `(site_id, week_start)` (BP-012's topic),
`nextDueOn()` (WO-174), `hasActiveAccess()` (BP-017).

Exposes (verbatim from BP-050 `## Public interface`):
```ts
/** REQ-065 criteria 2 to 5, as one total function. Every surface and every mail
 *  reads this; none derives a second account of the same week (rule 7.1). */
export type WeekAccount =
  | { kind: 'complete';     measuredAt: Date }
  | { kind: 'partial';      measuredAt: Date; unmeasured: readonly UnmeasuredPart[] }  // c4
  | { kind: 'not_measured'; nextDueOn: Date }                                          // c3
  | { kind: 'not_owed' }                                                               // c5
export function accountForWeek(a: { siteId: string; weekStart: string }): Promise<WeekAccount>
```

## Steps
1. Write the failing tests first (§8).
2. Implement the function as total over the four cases and make it the **only**
   producer: surfaces map its variants onto copy keys and never inspect scan
   status directly (BP-050 decision 3).
3. `not_measured` carries the day the next measurement is due; the line stands
   until a measurement for that week completes and is never replaced by an
   earlier week's figures.
4. `not_owed` is returned where access has ended: no week is stated as
   unmeasured and no next measurement is announced — but every measurement
   already taken stays readable with the date it was taken.
5. `partial` carries `measuredAt` and the unmeasured parts, and is never
   reported as `complete`.
6. Keep it to one indexed lookup: it is on the render path of every app screen.
7. Mutation check: return `complete` for a `degraded` row and confirm the
   partial test fails; return `not_measured` for an ended-access site and
   confirm the criterion 5 test fails.
