# WO-217 — The veto link — one hashed single-use token, one transition, no link at a zero window

- Branch: wo/WO-217-veto-link
- Estimate: ≤1 day

## Goal
Ship `issueVetoLink` and `redeemVeto`: a hashed, single-use, draft-bound token that expires at the veto deadline and performs exactly one transition, and no link at all where no interval exists.

## File plan

> This repository carries no `src/`, no `tests/`, no `supabase/` and no
> `package.json` (verified 2026-08-31). **Every path below is NEW** — none was
> verified to exist, because none can. Placement is anchored to
> `sdlc-factory/docs/registry/structure.md` and to this work order's blueprint
> `code:` globs, and is provisional against a repo with no code: if the
> implementer finds a file already present at one of these paths, they stop and
> log `failed` naming the drift rather than merging into it.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/publish/publishable/veto.ts` | NEW | `VetoLink`, `issueVetoLink`, `redeemVeto`. 32 bytes from a CSPRNG, stored as a SHA-256 hash in `drafts.veto_token_hash`, compared in constant time, single-use, expiring at `drafts.veto_deadline`. `expiresAt: null` and **no token issued** at a zero window (REQ-057 criterion 7: no interval exists in which one could be used). A redemption takes `in_review → skipped` through BP-045's `transition()` with `Actor{kind:'customer'}` and does nothing else. Refusals disclose nothing: `unknown` and `expired` do not name a draft; `not_in_review` is returned for a draft that already left review. |
| `tests/publish/publishable/veto.test.ts` | NEW | A valid token skips the draft exactly once and is refused on second use; an expired token is refused; an unknown token is refused without disclosing a draft id; a token for a draft that already published returns `not_in_review`; a zero window issues no token and returns `expiresAt: null`; no token, hashed or otherwise, appears in any log line. |

## Interfaces

**Consumes**

- `Actor` — WO-206.
- `transition()` — `src/lib/publish/machine/index.ts` (WO-209). The redemption performs exactly one transition and takes it through the machine, never by a direct write.
- `becomesPublishable` / the `GoverningPair` on `DraftView` — WO-215, to know whether the window is zero.
- `drafts.veto_deadline` — an existing `BUILD.md` §10 column; `drafts.veto_token_hash` and `drafts.veto_token_expires_at` are BP-014's migration (see `rests-on`).

**Exposes** — copied exactly from BP-046's `## Public interface`:

```ts
// src/lib/publish/publishable/veto.ts
export interface VetoLink { token: string; expiresAt: Date | null }   // null at a zero window: no link is issued
export function issueVetoLink(draftId: string): Promise<VetoLink>
export function redeemVeto(token: string): Promise<
  { ok: true; draftId: string } | { ok: false; reason: 'unknown' | 'expired' | 'not_in_review' }
>
```

A customer who clicks after the page published is shown the take-down action
instead (REQ-056 criterion 7), never a silent failure and never a second stop —
`not_in_review` is the value that surface reads. The route that receives the link
is BP-001's and is out of scope here.

## Steps
1. Create `publishable/veto.ts` with the block above verbatim.
2. Generate 32 bytes from a CSPRNG; store only the SHA-256 hash; compare in constant time.
3. Set expiry to `drafts.veto_deadline`. At a zero window issue nothing and return `{token: '', expiresAt: null}` — assert in test that no row is written in that case.
4. Mark the token used atomically in the same statement that reads it, so a double click cannot skip twice or skip a re-generated draft.
5. Take `in_review → skipped` through `transition()` with a customer actor. Take no other action.
6. Assert no log line contains a token or its hash. Write that test first and watch it fail against a debug log (constitution §8).
