# WO-117 — The Stripe Price object: a checked-in spec, a boot assertion, and a create-or-verify entry point

- Branch: wo/WO-117-price-object-spec
- Estimate: ≤1 day

## Goal
Give the Stripe Price behind `STRIPE_PRICE_ID` a home in this repository — a
checked-in specification, a boot check that refuses to start against a price that
differs from it, and one entry point that creates or verifies it — because the
Price object itself lives outside every `code:` glob in this corpus.

## File plan
> **Every path below is NEW.** No `src/` exists in this repository. Placement is
> anchored to `registry/structure.md` (`src/lib/account/**` is BP-017's) and to
> BP-030's `code:` glob `src/lib/account/checkout/**`. Provisional against a repo
> with no code.
>
> **Why these files exist at all.** ADR-052 states it plainly: "The Price object
> itself lives in Stripe, outside every `code:` glob in this corpus, which means
> no blueprint's file is where somebody would find this." This work order is the
> answer to that: the spec is checked in, the assertion runs at boot, and the CLI
> is the only sanctioned way the object is created. A new top-level `scripts/`
> directory would need an ADR (`structure.md` rule 7), so the entry point lives
> inside BP-030's own module.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/account/checkout/price-object.ts` | NEW | Exports `PRICE_OBJECT_SPEC` — a frozen literal `{ currency: PRICE_CURRENCY, unit_amount: PRICE_EUR_CENTS, recurring: { interval: PRICE_INTERVAL }, tax_behavior: 'inclusive' }` built from BP-005's pins, with `tax_behavior` the one literal this repository states about the price object. Exports `assertLivePriceMatchesSpec(): Promise<void>`, which reads the Price behind `env.STRIPE_PRICE_ID` and throws a named error naming the differing field when `unit_amount`, `currency`, `recurring.interval` or `tax_behavior` differ (ADR-052 point 3). |
| `src/lib/account/checkout/boot.ts` | NEW | Exports `assertCheckoutBootInvariants(): Promise<void>` — calls `assertLivePriceMatchesSpec()` and rethrows. This is the module's boot hook; wiring it into the application's startup path is BP-001's (see Out of scope). |
| `src/lib/account/checkout/bin/ensure-price.ts` | NEW | A server-only entry point with two modes: `--verify` (calls `assertLivePriceMatchesSpec` and exits non-zero on a difference) and `--create` (creates a Price from `PRICE_OBJECT_SPEC` against the product id in `env`, prints the new price id, and writes nothing to the database). `--create` refuses if `STRIPE_PRICE_ID` is already set to a price that verifies — creating a second price is how a subscription base gets split. |
| `tests/account/checkout/price-object.test.ts` | NEW | Asserts `PRICE_OBJECT_SPEC.tax_behavior === 'inclusive'` and that the other three fields equal BP-005's pins; asserts `assertLivePriceMatchesSpec` throws for each of the four fields differing, as four separate cases, with `tax_behavior: 'exclusive'` its own case (mutation discipline: deleting the `tax_behavior` comparison must fail exactly that case and no other). |

## Interfaces
Consumes: BP-005's pins, verbatim from ADR-052 point 1 — "`PRICE_EUR_CENTS = 4900`,
`PRICE_CURRENCY = 'eur'`, `PRICE_INTERVAL = 'month'` are pins in
`src/lib/config/constants.ts` (BP-005), asserted in `tests/pins.test.ts`" — and
`export const env: Readonly<Env>` (BP-005).

Exposes: `PRICE_OBJECT_SPEC`, `assertLivePriceMatchesSpec()`,
`assertCheckoutBootInvariants()`. None of these appears in BP-030's
`## Public interface`; they are module-internal to `src/lib/account/checkout/**`
and named here so WO-118 imports rather than re-derives them.

## Steps
1. Write `price-object.ts` with the spec built from the pins.
2. Write the four failing assertion cases in the test and watch them fail.
3. Implement `assertLivePriceMatchesSpec` against a stubbed Stripe price read.
4. Write `boot.ts` and `bin/ensure-price.ts`.
5. Run `--verify` against the configured environment.

## Out of scope
- Defining or editing `PRICE_EUR_CENTS`, `PRICE_CURRENCY`, `PRICE_INTERVAL` or
  `env` — `src/lib/config/**` is BP-005's.
- Calling `assertCheckoutBootInvariants()` from the application's startup —
  `src/app/**` is BP-001's.
- Enabling `automatic_tax` anywhere. ADR-052 point 6: enabling tax is a later,
  deliberate change and is the owner's, not this work order's.
- Any wiring of the CLI into a package manifest script.
- Every sentence about the price. This work order creates no customer-visible
  string; `PRICE_COPY_KEYS` is named in WO-118 and its content is the owner's.

## Rollback
Delete the three source files and the test. Nothing is written to the database or
to Stripe by `--verify`. A Price created by `--create` is not deleted by a
rollback — a Stripe Price cannot be un-created, only deactivated, and ADR-052's
consequence stands: "an exclusive price must be replaced and every existing
subscription moved to the new one".
