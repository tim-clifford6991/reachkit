# WO-079 — buildPresenceCard — one denominator, the absent-from list, and a card type with nowhere to put a rival's size

- Branch: wo/WO-079-presence-card
- Estimate: ≤1 day

## Goal
Implement `src/lib/market/rivals/presence.ts` so the Google-presence card is a share of the
searches actually measured, still means something when the customer's own number is zero,
and carries no field a size, a forecast or a severity could travel in.

## Context an implementer needs
No source code exists on disk; both paths below are NEW. **The honesty bound of this card is
held by the absence of a place to put a violation, not by a review** (BP-026 decision 1):
`PresenceCard` has no field for a rival's ranked count, size, band, revenue, traffic value,
funding, headcount or projected return, and no field a severity or warning level could be
written into. BUILD §6.4's never-pull list forbids the measurement that would make such a
claim true — per-rival `ranked_keywords` on the free path — and this module buys nothing at all.

## File plan

## Interfaces
**Consumes**: `Measured<T>` (BP-010), `SerpResult` (BP-008), `SelectedSearch` (WO-074),
`RivalCandidate` (WO-078), `registrableDomain` / `isPlatformDomain` / `isOwnDomain` (WO-077).

Note the deliberate asymmetry in BP-026's interface: `deriveRivals` takes `serps:
SerpResult[]` (the measured ones, already unwrapped by the caller) while
`buildPresenceCard` takes `serps: Measured<SerpResult>[]` — the card needs to know which
searches were *not* measured, because that is what its denominator excludes.

**Exposes** — copied exactly from BP-026's `## Public interface`:

```ts
// src/lib/market/rivals/presence.ts — REQ-008's card
export interface PresenceCard {
  measuredSearches: number                                   // the one denominator
  /** No `totalMonthlyVolume`. The market-total `{N}/mo` footnote was removed by
   *  the owner on 2026-09-03 (`OWNER-QUESTIONS.md` item 6), both halves —
   *  decision 4. The card's whole promise is the denominator, the customer's
   *  occupancy and the rivals' against it. */
  you: { domain: string; top10Count: number }
  rivals: readonly { domain: string; top10Count: number }[]  // ≤ 5, score order
  absentFrom: readonly {
    keyword: string; volume: number; topHolder: string | null
  }[]                                                        // ≤ 5, biggest volume first
  framing: 'shown' | 'suppressed_no_rivals'
}
export function buildPresenceCard(a: {
  serps: Measured<SerpResult>[]; selected: SelectedSearch[]
  ownDomain: string; rivals: RivalCandidate[]
}): PresenceCard
```

## Steps
1. `measuredSearches` = the count of `serps` whose `Measured` arm is not `unmeasured`. Every
   other figure on the card is computed over exactly that subset — one denominator, used once.
2. `you.top10Count` = measured SERPs in whose top ten `isOwnDomain(host, ownDomain)`. This is
   the customer's presence, and it appears on the card exactly **once**: add no second,
   differently measured figure.
3. `rivals` = one `{ domain, top10Count }` per supplied `RivalCandidate`, in the order given
   (already score order from WO-078), each count computed over the measured SERPs.
4. `absentFrom` = measured searches in whose top ten the customer does not appear, biggest
   `volume` first, capped at 5. `topHolder` is the registrable domain at position 1, or
   `null` where that position is a platform domain. An unmeasured SERP is neither an absence
   nor a presence and never appears here. `selected[i].volume` is read in this module only
   to order this list and to label each search listed on it (criterion 4); it is never summed
   (BP-026 decision 4).
5. `framing` = `'suppressed_no_rivals'` when `rivals.length === 0`, else `'shown'`. No
   sentence is written in this module (BP-026 decision 2).
6. Emit the observability field BP-026 names: the framing state.
7. Write the tests; watch each fail first.

Determinism: `card/byte-identical-on-every-run` — the same inputs 100 times, and with
shuffled `serps`, produce an identical card.

Discrimination: restoring a market-total volume field to the card, summing `selected[i].volume`
into any field it does have, letting `absentFrom` include an unmeasured search, or adding a
`rankedCount` field to a rival entry, must each fail a named test above.

  strings, owned by BP-019's copy registry and rendered by the report surface (BP-022).
  This module emits `framing` and nothing else (BP-026 decision 2).
- Criterion 1's colour/label rendering rule — BP-018's.
- Rival derivation — WO-078. Domain normalisation — WO-077.
- Any rival size or band — BP-052 (WO-086, WO-087, WO-088), unreachable from here.
- `report.market.totalVolume` on the stored blob — BP-025's, and deliberately kept (BP-026
  decision 4's consequences: "what is removed is the card, not the measurement's record").
  The figure still travels in the blob; it simply no longer reaches this card. Delete nothing
  upstream of `presence.ts` to satisfy the absence tests above.
