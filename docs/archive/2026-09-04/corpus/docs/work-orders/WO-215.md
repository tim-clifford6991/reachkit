# WO-215 — becomesPublishable() — REQ-057 criterion 2's four conjuncts, in exactly one place

- Branch: wo/WO-215-becomes-publishable
- Estimate: ≤1 day

## Goal
Ship `becomesPublishable()` as a pure function of `DraftView` — the only expression of REQ-057 criterion 2 in the codebase — with the `unsaved_edit` arm kept and pinned as unreachable-by-construction.

> verified to exist, because none can. Placement is anchored to
> `sdlc-factory/docs/registry/structure.md` and to this work order's blueprint
> `code:` globs, and is provisional against a repo with no code: if the

| File | New/Modify | Change |
|---|---|---|
| `src/lib/publish/publishable/predicate.ts` | NEW | The `NotPublishable` union and `becomesPublishable`. The rule, and nothing else: `(window expired under autopilot ∨ explicitly approved) ∧ ¬unsavedEdit ∧ ¬claimRecheckOutstanding`. Pure: no clock read of its own, no database read, no settings read. `at` is the first publish time at or after it became publishable, obtained from BP-057's `nextPublishTimeAtOrAfter` over the `GoverningPair` carried on the `DraftView` — never a second clock. |
| `tests/publish/publishable/predicate.test.ts` | NEW | Every boundary of the window; copilot expiry returns `unapproved` and never `publishable`; autopilot at a zero window is publishable at the moment the draft enters review; each of the four conjuncts is falsified alone and returns its own reason. **One test pins the `unsaved_edit` arm as unreachable-by-construction** — see the test-plan note. |

## Interfaces

**Consumes**

- `DraftView`, `State` — `src/lib/publish/types.ts` (WO-206).
- `nextPublishTimeAtOrAfter(instant, s)` — BP-057, `src/lib/publish/settings/clock.ts` (WO-219). Reused, not re-implemented (rule 7.2): "when does the next page go out" has one home.
- `claimRecheckOutstanding` on `DraftView` — REQ-053 criterion 5's state, supplied by BP-014. **This predicate is its one call site** (settled in consolidation).

**Exposes** — copied exactly from BP-046's `## Public interface`:

```ts
// src/lib/publish/publishable/predicate.ts
// Signature as BP-015 declares it. The four reasons are closed and are exactly
// REQ-057 criterion 2's conjuncts; a fifth would be a change to that criterion.
export type NotPublishable = 'window' | 'unapproved' | 'unsaved_edit' | 'claim_recheck'

export function becomesPublishable(d: DraftView):
  | { publishable: true; at: Date }          // `at` = the first publish time at or after it became publishable
  | { publishable: false; because: NotPublishable }
```

**The `unsaved_edit` arm is kept deliberately.** It is one of REQ-057 criterion
2's four conjuncts, written verbatim into this function, and no current caller
can reach it: the draft view is loaded after the editor has saved. Removing it
because "nothing reaches it" is exactly the cleanup ADR-080's neighbours exist to
prevent — the arm is a guard, not a behaviour, and its absence would make the
predicate silently weaker the first time an unsaved-edit path appears. This work
order ships a test that pins it rather than a comment that asks for it.

**`toldCurrentPair` is a second predicate, not a fifth reason.** BP-046 decision
1: REQ-057 criterion 8's "no page publishes at all without their having been
told" is a precondition none of the four arms expresses, so it is its own
predicate with its own guard (WO-216). Do not add a `'not_told'` member here.

## Steps
1. Create `publishable/predicate.ts` with the block above verbatim.
2. Write the rule as one expression of the four conjuncts, in criterion 2's own order, with the criterion quoted above it (rule 5.3).
3. Under `mode: 'copilot'` make the first disjunct unconditionally false, so an expired window returns `{publishable:false, because:'unapproved'}`.
4. At a zero window under autopilot the window is expired at the moment the draft enters review, so the page is publishable at once and `at` is the next publish time.
5. Keep the `unsaved_edit` arm and write the test that pins it. Do not add a fifth `NotPublishable` member.
6. Write the boundary tests first and watch the copilot-expiry case fail against a shared "expired ⇒ publishable" implementation (constitution §8).

## Test plan

Each criterion below is inherited verbatim from the requirement named in the
row, reflowed onto one line and otherwise unaltered.

| Acceptance criterion (verbatim from REQ) | Test |
|---|---|
| **REQ-057 c2** — Given a page in review, when it publishes, then it publishes under this rule and no other: a page becomes publishable when its veto window has expired or it was explicitly approved, and no edit is unsaved and no claim re-check is outstanding (REQ-053 criterion 5, which fixes when one stands outstanding on a draft and how it clears); it publishes at the first publish time at or after it becomes publishable, and never before. | `tests/publish/publishable/predicate.test.ts` › "a page publishes under this rule and no other" — each of the four conjuncts falsified alone returns its own `NotPublishable` reason; › "it publishes at the first publish time at or after it becomes publishable, and never before" asserts `at` against `nextPublishTimeAtOrAfter`. |
| **REQ-057 c3** — Given copilot mode, when the veto window expires without an explicit approval, then expiry does not make the page publishable — only an explicit approval does — so the page does not publish and remains in review. | `tests/publish/publishable/predicate.test.ts` › "under copilot, expiry is not an approval" — an expired window with no `approvedAt` returns `unapproved`, at the boundary and one millisecond either side. |
| **REQ-057 c4** — Given autopilot mode, when the veto window expires without a veto, then that expiry makes the page publishable and it publishes under criterion 2; and when the customer vetoes inside the window, it never publishes. | `tests/publish/publishable/predicate.test.ts` › "under autopilot, expiry without a veto makes it publishable" and › "a vetoed draft is never publishable" — the veto arrives as `state: 'skipped'`, from which no edge leads to `publishing`. |
| **REQ-057 c5** — Given a page in review, when its veto window is evaluated, then the window that governs it is the one the customer's publishing settings hold at that moment (REQ-073), at whatever length REQ-073 then puts in force for a page already in review; this requirement fixes only what the window's expiry does, never its permitted lengths, its default, or when a saved change to it takes effect. | `tests/publish/publishable/predicate.test.ts` › "the window that governs is the one on the DraftView at the moment of evaluation" — two evaluations of the same draft under two `GoverningPair`s give two answers, and the predicate reads no settings itself. |
| **REQ-057 c6** — Given copilot mode and a page still in review after its window expired, when later days arrive, then it stays in review and approvable until the customer's access ends, it never publishes of its own accord, and it does not stop the next day's page being generated; at the end of the paid-through period the approve action is no longer offered and the draft stays exportable (REQ-076, REQ-078). | `tests/publish/publishable/predicate.test.ts` › "under copilot a page stays in review and approvable across later days" — evaluated at +1, +7 and +30 days it never becomes publishable of its own accord. |
| **REQ-057 c7** — Given autopilot mode and a veto window the customer set to zero, when a page is generated, then it becomes publishable at once and there is no interval in which the customer can stop it; the `draft-ready` mail (REQ-064) names the page, why it was chosen, and the date and time it goes live, states plainly that no window to stop it exists because they set none, and offers taking the page down (REQ-056 criterion 7) in place of an action to stop it. Because that mail is the whole of the telling where no interval exists, it is sent no later than the moment the page publishes, no notification setting the customer holds suppresses it (REQ-075), and it carries no unsubscribe link, because no link would stop it (REQ-075 criterion 5) — unlike the same mail at any longer window, which criterion 1 lets them switch off. | `tests/publish/publishable/predicate.test.ts` › "at a zero window the page is publishable at once and `at` is the next publish time" — the interval-free case; the telling that stands in place of the interval is WO-216's and the absent veto link is WO-217's. |

One further test carries no criterion of its own and exists to hold a guard:
`tests/publish/publishable/predicate.test.ts` › **"the unsaved_edit arm is
present and returns its own reason"** — constructs a `DraftView` with
`hasUnsavedEdit: true` and asserts `because: 'unsaved_edit'`. The arm is
unreachable through any current caller and this test is the only thing that
fails when it is deleted. That is the point: it is REQ-057 criterion 2's third
conjunct, and a predicate that silently drops it is weaker than the criterion it
claims to be.

## Out of scope
- The telling and the re-telling obligation — WO-216.
- The veto token and link — WO-217.
- Taking any transition. This module computes; every state change it implies is taken by BP-045's `transition()`.
- Reading settings. The `GoverningPair` arrives on the `DraftView`; this function never queries for it.
- Any check of active access. BP-045's edge into `publishing` is already closed by BP-017's `hasActiveAccess()`; a second gate here would be two.
