# WO-029 — Theme tokens — the three-state theming and the daisyUI slot mapping

- Branch: wo/WO-029-theme-tokens
- Estimate: ≤1 day
- Preview: sdlc-factory/docs/design/previews/WO-029.html
- Signed-off: 2026-09-03

## Goal
Define every colour, radius, shadow and ring token the product uses, in three
theme states, and map them onto daisyUI's slots so stock daisyUI classes just
work.

## Provenance of this file plan
**This repository holds no `src/`.** Every path is NEW, anchored to
`structure.md`'s row for `src/ui/**` and to BP-018's `code:` globs
(`src/ui/**`, `tailwind.config.ts`, `tests/ui/**`).

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/ui/theme.css` | NEW | The three states BP-018 fixes: bare `:root` = light, carrying **every** token; `@media (prefers-color-scheme: dark)` guarded with `:root:not([data-theme="light"])`; and `:root[data-theme="dark"]` for the explicit toggle. Values transcribed from `BUILD.md` §2.1 exactly — `--bg --surface --sunk --line --ink --ink-2 --ink-3 --accent --on-accent --accent-bg --accent-line --ok --ok-bg --ok-line --warn --warn-bg --warn-line --bad --bad-bg --bad-line --chart-you --chart-rival --chart-goal --r-box --r-field --r-pill --shadow-card --ring-accent`. The six dark `-bg`/`-line` values are derived at 12% / 28% alpha per the clause quoted in `rests-on`, each with that quote as a comment. **No colour is defined only inside a dark block.** |
| `tailwind.config.ts` | NEW | The token-to-daisyUI mapping `BUILD.md` §2.1 states: `base-100`←surface, `base-200`←sunk, `base-300`←line, `base-content`←ink, `primary`←accent, `success/warning/error`←ok/warn/bad. daisyUI 5 plugin registered here; the theme is one named theme reading the CSS variables, never a second copy of the values. |
| `tests/ui/tokens.test.ts` | NEW | The tests below. |

## Interfaces
Exposes (verbatim from BP-018 `## Module / boundary`): `src/ui/theme.css` (the
three-state theming) and `tailwind.config.ts` (the token-to-daisyUI mapping).
Consumes: nothing. BP-018 depends on BP-005 for pins, and this work order uses
none — a colour is not a pinned number under `structure.md` rule 5; it is a token
with one home, which is this file.

## Steps
1. Transcribe the `:root` block from `BUILD.md` §2.1, token by token.
2. Write the guarded dark media query and the explicit `[data-theme="dark"]`
   block, deriving the six `-bg`/`-line` values at 12% / 28%.
3. Write `tailwind.config.ts` with the six slot mappings.
4. Write the tests; watch the "a token missing from `:root` fails" test fail
   first by moving one colour into the dark block only.

      `--color-primary`/`-success`/`-warning`/`-error` but no matching
      `-content` slot. Stock daisyUI classes already named in the registered

      its own, or whether the mapping needs the `-content` slots added
      alongside it.
