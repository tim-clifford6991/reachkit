- Branch: wo/WO-146-setup-submit

## Goal
Build the closed `SetupSubmission` shape, `readSetupState`, and the idempotent
`POST /api/setup` that commits `setup_completed_at` before enqueuing the deep
pass.

```ts
/** The closed shape of the one submit. A field absent from this type cannot be
 *  sent, which is how REQ-025 criterion 1's "and for nothing else" is enforced
 *  rather than reviewed. */
export interface SetupSubmission {
  domain: string                                   // identity, not configuration
  category: string                                 // REQ-026's card supplies it
  competitors: readonly string[]                   // <= 5, REQ-026's card
  mode: 'autopilot' | 'copilot'                    // REQ-028's card
  destination: { kind: 'hosted' } | { kind: 'wordpress'; connectLater: true }
}

export type SetupResult =
  | { ok: true; siteId: string }
  | { ok: false; refused: 'invalid_domain' | 'already_complete' | 'no_active_access' }

// POST /api/setup — the only write path into setup completion.
export async function POST(req: Request): Promise<Response>

/** The one predicate every account route consults. There is no second copy. */
export type SetupState =
  | { complete: false; siteId: string; paidAt: Date }
  | { complete: true;  siteId: string; completedAt: Date }
export function readSetupState(userId: string): Promise<SetupState>
```

## Steps
1. Write the failing tests first (constitution §8, "Watch it fail first").
2. Declare `SetupSubmission` / `SetupResult` exactly as above. Add no field that
   could carry a duration, an estimate or an engine parameter.
3. Implement `readSetupState` as a single read of `sites.setup_completed_at`
   and the payment date.
4. Implement `completeSetup()`: refuse `no_active_access` first, then
   `already_complete` when `setup_completed_at` is non-null, then
   `invalid_domain` with no partial write. On success, set
   `setup_completed_at` and **commit**, then enqueue the deep pass
   at-least-once, idempotent on `(site_id, 'deep')` (BP-033 decision 2). An
   enqueue failure leaves the founder complete.
5. Write the route handler as transport only; log one structured line per
   submit carrying `userId`, `siteId` and whether a pass was enqueued — never
   the payload.
6. Mutation check: delete the `already_complete` branch and confirm the
   idempotency test fails.
