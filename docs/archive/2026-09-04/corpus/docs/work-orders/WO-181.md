## Goal
Create the closed opportunity type surface and the `opportunities` table whose constraints and triggers make a ninth kind, a mismatched evidence shape and a rewritten acceptance test impossible to store.

```ts
// ---- the closed enum (REQ-047 c1; BUILD.md §7) -----------------------------
export type OpportunityType =
  | 'answer_page' | 'keyword_page' | 'comparison_page' | 'format_page'  // Write
  | 'expand_page' | 'answerable_page' | 'refresh_page'                  // Improve
  | 'unblock'                                                           // Fix
export type Family = 'write' | 'improve' | 'fix'
export const FAMILY_OF: Readonly<Record<OpportunityType, Family>>

// ---- evidence: one shape per family, every value Measured (REQ-047 c2) -----
export type Shortfall =
  | { kind: 'position';  position: Measured<number> }
  | { kind: 'thin';      words: Measured<number> }
  | { kind: 'stale';     lastSeenChanged: Measured<Date> }
export type Barrier =
  | 'robots_disallow' | 'noindex' | 'login_wall' | 'js_only' | 'blocked_ai_agent'

export type Evidence =
  | { family: 'write';   query: string; volume: Measured<number>
      rival: { domain: string; url: Measured<string>; position: Measured<number> } }
  | { family: 'improve'; query: string; volume: Measured<number>
      pageUrl: string; shortfall: Shortfall }
  | { family: 'fix';     barrier: Barrier; foundOnUrl: string }

// ---- the acceptance test (REQ-047 c6) --------------------------------------
export type Acceptance =
  | { form: 'top20';       query: string }
  | { form: 'named_on';    question: string }
  | { form: 'gate_cleared'; gate: Barrier }

export type Winnability = 'winnable' | 'reach' | 'not-yet'   // internal handles

export interface Opportunity {
  id: string; siteId: string; scanId: string
  type: OpportunityType; family: Family
  targetQuery: string | null                 // null only for 'unblock'
  targetRef: string                          // proposed slug (write) | page URL (improve) | barrier page URL (fix)
  volume: Measured<number> | null
  evidence: Evidence
  acceptance: Acceptance
  fitBand: Winnability | null                // null only for 'unblock'
  effort: number                             // 0..1, from EFFORT_BY_TYPE
  status: 'open' | 'queued' | 'done' | 'dismissed'
  createdAt: Date
}

export interface RejectionCount {
  not_yet: number            // failed criterion 9
  unmeasured_top10: number   // no measured ranked count in the top ten (see edge behaviour)
  duplicate_open: number     // an equivalent open/queued opportunity already exists
}

export interface Ranked { opportunityId: string; score: number }
```

## Steps
1. Write `tests/opportunities/derive/types.test.ts` and `schema.test.ts` first and run them: both must fail, the first on a missing module and the second on a missing table.
2. Create `src/lib/opportunities/types.ts` with the exposed block above, verbatim. `FAMILY_OF` is `Object.freeze` over the eight, typed `Readonly<Record<OpportunityType, Family>>` so a missing member is a compile error.
3. Write the migration. Order inside the file: table, check constraints, RLS policies, trigger function, trigger, indexes.
4. The `acceptance` immutability trigger is a `before update` trigger raising when `new.acceptance is distinct from old.acceptance` (BP-040 decision 1). It is the invariant; no application code repeats it.
5. The `family` check constraint spells out the mapping the eight types imply, so the stored `family` is a constrained mirror of `FAMILY_OF` rather than a second source of truth.
6. Run the tests: all must now pass. Then delete the trigger locally and confirm the immutability test fails; restore it.

## Test plan
> Watch it fail first (constitution §8): every test below is written and
> run against the absent implementation before the implementation exists.

| Acceptance criterion (verbatim from REQ) | Test |
|---|---|
| **REQ-047 c1** Given a completed scan, when opportunities are derived, then each is of exactly one kind from a fixed set of eight — four that propose writing a new page (answering a question rivals own, a search the customer is absent from, a comparison, a page format the customer lacks), three that propose improving a page the customer already has (expand it, make it answerable, refresh it), and one that asks the customer to remove an access barrier — and an opportunity of any other kind cannot be stored. | `schema.test.ts › a ninth opportunity type cannot be stored` and `types.test.ts › OpportunityType is exactly the eight` |
| **REQ-047 c2** Given an opportunity, when it is stored, then it carries the measured evidence that produced it: for the four that propose writing a new page, the search, its volume, and the rival page or position that shows the gap; for the three that propose improving a page the customer already has, the search, its volume, the page of theirs it names, and the measurement on that page that shows the shortfall — its own position, its thinness, or its staleness — with no rival required; for the one that asks the customer to remove an access barrier, the barrier found and the page of theirs it was found on. Every one of those values is one the product measured and stored, never one it composed (REQ-093 criterion 4). | `schema.test.ts › evidence whose family discriminator disagrees with the row is refused`; `types.test.ts › every Evidence arm carries only Measured values or stored refs` |
| **REQ-047 c5** Given an opportunity that asks the customer to remove an access barrier, when it is presented, then it is presented as an instruction for them to carry out: no page is generated for it, it takes no publishing day and consumes no supply, and it is never actioned automatically in either publishing mode. | `schema.test.ts › an unblock row stores fit_band null and target_query null, and a non-fix row with fit_band null is refused` |
| **REQ-047 c6** Given an opportunity is created, when it is stored, then it carries an acceptance test in exactly one of three forms: the target reaching the top 20 for a named search, the customer being named in the answer to a named question, or a named access barrier being cleared. | `types.test.ts › Acceptance is exactly the three forms`; `schema.test.ts › acceptance is not null` |
| **REQ-047 c8** Given a published page is later judged, when its verdict is produced, then it is judged against the test recorded when its opportunity was created, and that recorded test is never rewritten — including where it can no longer be evaluated. | `schema.test.ts › an update to acceptance raises` (and `… raises for a dismissed row too`) |

**Discriminates (mutation check, constitution §8).**
- Dropping the `before update` trigger makes `schema.test.ts › an update to acceptance raises` fail — the test reads the database, not a service function, so deleting application-level guarding cannot make it pass.
- Widening the `type` check constraint to accept a ninth value makes the c1 test fail; removing the `family`-discriminator check on `evidence` makes the c2 test fail.
- Dropping the partial unique index makes the duplicate-open test fail, which is the index BP-041's idempotent top-up rests on.
