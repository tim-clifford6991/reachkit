# WO-056 — The free-path migration — `network_hash`, `finished_at`, `from_incomplete_rescan`, and the `failed` status

- Branch: wo/WO-056-scans-freepath
- Estimate: ≤1 day

## Goal
Add to `scans` the three columns and the one status value the free path's four
bounds are counted from, so that no rate-limit table is needed and REQ-003
criterion 2's p95 is checkable from stored data.

## File plan

> Every path below is **NEW**. Verified 2026-08-31: this repo carries no
> `supabase/` directory and no `tests/`. Placement per `structure.md` rule 3 and
> 3a: all migrations live in `supabase/migrations/`, and `*_scans_freepath*` is
> BP-023's sub-token of BP-012's `scans` topic. Provisional against a repo with
> no code.

| File | New/Modify | Change |
|---|---|---|
| `supabase/migrations/<timestamp>_scans_freepath.sql` | NEW | Adds exactly three columns to `scans` and widens one enum, per BP-023's data-model delta and nothing else: `network_hash text null` with an index on `(network_hash, created_at desc)`; `finished_at timestamptz null`; `from_incomplete_rescan boolean not null default false`. Adds `failed` to `scans.status` alongside `running / done / degraded`. Creates no table. |
| `tests/scan/free/schema.test.ts` | NEW | Asserts the migrated shape and the index against a live migrated database, and asserts that no new table was created. |

## Interfaces

Consumes: BP-002's `dbAdmin()` for the test harness only. Nothing at runtime.

Exposes: no TypeScript surface. The columns are read by WO-057 (`admitFreeScan`),
written by WO-058 (`claimFreeScanSlot`) and read by BP-022's control derivation
(WO-061). Their contract, verbatim from BP-023 `## Data model delta`:

| Column | Type | Why |
|---|---|---|
| `network_hash` | `text null` | the counter REQ-003 criteria 6 and 7 are evaluated over; null for paid tiers. Indexed `(network_hash, created_at desc)` |
| `finished_at` | `timestamptz null` | REQ-003 criterion 2's p95 is a claim about elapsed time; without an end stamp it cannot be checked from data |
| `from_incomplete_rescan` | `boolean not null default false` | REQ-001 criterion 14's "made once and does not chain", set at claim time and read by BP-022 |

## Steps
1. Write the failing schema test first.
2. Write the migration: the three `alter table` statements, the enum widening,
   and the one index.
3. Confirm the index is the composite `(network_hash, created_at desc)` BP-023's
   NFR budget costs its two aggregates against — not two single-column indexes.
4. Run the migration on a scratch database and the test against it.
5. Confirm no `rate_limits` table, no counter table and no new topic token appear
   anywhere in the diff (BP-023 decision 1, `BUILD.md` §10's bar).

| REQ-003 c2 — "Given any 100 consecutive free scans of reachable domains, counted in the order they started and whichever of criterion 1's ways started each of them, when the time from each scan's start to a readable report is measured, then no more than 5 of those 100 take longer than 60 seconds, and none takes longer than the 90 seconds of criterion 5." | `scan/free/schema · elapsed time is derivable from stored rows alone` — asserts `finished_at` exists and is nullable, and that a query over `scans(created_at, finished_at, tier)` alone computes the p95 for the last 100 free rows without joining another table. | REQ-003 c6 — "Given a visitor who has already started five free scans from the same network within the last hour … when another scan would start for them, then it does not start, they are refused with one written line saying how long until they may scan again, and the refused scan, having never run, produces no report of its own." | `scan/free/schema · the hourly counter is an indexed aggregate over scans` — asserts `network_hash` exists, is nullable, and that the composite index `(network_hash, created_at desc)` is present and is used by the planner for a count over `created_at > now() - interval '1 hour'` (an `explain` assertion). |
