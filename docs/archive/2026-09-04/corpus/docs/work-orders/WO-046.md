# WO-046 — The cold-start fixture, and every derivation running to completion for a domain that ranks for nothing

- Branch: wo/WO-046-coldstart-fixture
- Estimate: ≤1 day

## Goal
Build the two cold-start fixtures BP-021 Decisions 3 fixes and the stage harness
that asserts every scan, derivation, proposal and generation runs to completion
for a domain with no measured rankings and no AI citations of its own.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `tests/presentation/coldstart/fixture.ts` | **NEW** | The two fixture domains BP-021 Decisions 3 fixes: one that resolves in DNS, serves a readable home document, ranks for nothing and is cited in no AI answer; and one degenerate variant whose home document could not be read, which keeps the `no-presence-yet` and `unmeasured` accounts visibly distinct. Exports the seed rows for BP-002's existing tables and the vendor/model stubs. Owns no schema. |
| `tests/presentation/coldstart/stubs.ts` | **NEW** | The module-boundary stubs for BP-007's cache seam and BP-008's closed endpoint list, plus a throwing stub for every export of `src/lib/llm/`. Every stub records its calls so a test can assert a stage made no vendor call. |
| `tests/presentation/coldstart/budget.ts` | **NEW** | `export const COLDSTART_SWEEP_BUDGET_MS = 180_000` — BP-021 Decisions 3's parameter, declared here and nowhere else. A comment records that exceeding it is fixed by sharding on the surface glob, never by raising the number. |
| `tests/presentation/coldstart/stages.ts` | **NEW** | The stage table: one row per engine entry point REQ-091 criterion 1 names — scan, derivation, proposal, generation — each row naming the stage, its module's public entry point, and whether the stage is wired yet. The table is the enumerator; a stage absent from disk is reported as unwired, never silently skipped. |
| `tests/presentation/coldstart/pipeline.test.ts` | **NEW** | Runs every wired stage against both fixtures and asserts each returns. Failing, blocking or being skipped for want of prior presence fails **by stage name**. Emits the coverage statement and asserts the wall clock against the budget. |

## Interfaces
**Consumes** (test-time only — ADR-010 `## Consequences`: reading another node's
tree "creates no import and no cycle; no `depends-on` edge is drawn for it"):
- `PLACES`, `PlaceKey`, `renderPlace`, `account` from WO-045.
- The engine entry points `structure.md` lists as each module's public entry:
  `runScan()` (BP-012), `measureDomain()` (BP-010), `deriveMarketSet()` ·
  `selectTwelve()` · `deriveRivals()` · `sizeRivals()` (BP-011),
  `deriveOpportunities()` (BP-013), `generateDraft()` (BP-014). Each is consumed
  by name through its module's public entry point, not by file path.
- BP-002's tables for the fixture seed; the fixture adds no migration and no
  topic (BP-021 `## Data model delta`).

**Exposes:** `coldStartFixture()`, `degenerateFixture()`,
`COLDSTART_SWEEP_BUDGET_MS` and the stubs to WO-047, which sweeps routes against
the same fixtures and must not define a second one (rule 7.2).

## Steps
1. Create `stubs.ts` first: the cache-seam stub, the endpoint-list stub and the
   throwing `src/lib/llm/` stub, each recording calls.
2. Create `fixture.ts` with the two fixtures. The primary is the exact shape
   REQ-091's user story names — resolves in DNS, readable home document, ranks
   for nothing, cited in no AI answer. The degenerate variant's home document
   could not be read. Neither fixture carries an estimate, a benchmark, a cohort
   average, a manufactured rival, target, question or opportunity: the fixture is
   what criterion 3 is asserted against, so a filler value seeded here would make
   WO-047's provenance assertion vacuous.
3. Create `budget.ts`.
4. Create `stages.ts` as a table, one row per entry point in `## Interfaces`,
   each row `{ stage: string; entry: string; wired: boolean }`. A row whose
   module is not on disk is `wired: false` and is **reported**, never dropped.
5. Write `pipeline.test.ts`: for each fixture, for each wired stage, call the
   entry point with the stubs installed and assert it returned — including
   returning legitimately empty (REQ-029 criterion 4, REQ-047 criterion 3), which
   is a pass, not a failure. A throw, a timeout, or a stage that returns without
   having been reached fails naming the stage. Assert no stub recorded a live
   vendor call. Emit the coverage statement: stages total, stages wired, stages
   run, stages unwired by name.
6. Watch the suite fail first: add a deliberately throwing stage row to the table
   in a temporary commit and confirm the failure names that stage, then remove it.

## Test plan
| Acceptance criterion (verbatim from REQ-091) | Test |
|---|---|
| 1. "Given a domain with no measured rankings and no AI citations of its own, when any scan, derivation, proposal or generation runs for it, then it runs to completion and returns its result — which may legitimately be empty (REQ-029 criterion 4; REQ-047 criterion 3) — and no step fails, blocks, or is skipped for want of prior presence." | `pipeline.test.ts` → **"every wired stage returns for a domain that ranks for nothing"**: each stage in `stages.ts` is invoked against the primary fixture and must return; an empty result passes. Discriminates: a stage that throws, that never resolves within the budget, or that is absent from the run set fails by stage name. |
| 1. (same, verbatim as above) | `pipeline.test.ts` → **"the degenerate variant keeps unmeasured distinct from no-presence-yet"**: against the second fixture, every wired stage still returns, and any absence it produces is a `Measured` whose `kind` is `'unmeasured'`, never a `Cause` of `'no-presence-yet'` — the two vocabularies do not intersect (BP-021 `## Error & edge behavior`, last bullet; REQ-004 criterion 8). |
| 1. (same, verbatim as above) | `pipeline.test.ts` → **"no stage is skipped for want of prior presence"**: the coverage statement names every stage in the table and every stage actually run, and the test fails when the two sets differ for any reason other than `wired: false`. Discriminates: a `continue` on an empty prior measurement drops the stage from the run set and fails. |
| 1. (same, verbatim as above) | `pipeline.test.ts` → **"the run makes no vendor and no model call"**: every stub records zero live calls; the `src/lib/llm/` stub was never invoked without throwing. |

Additional test this WO owns:
- `pipeline.test.ts` → **"the suite states its own coverage"**: the emitted report
  names stages total, wired, run and unwired-by-name; a run with zero wired
  stages reports `0 of N wired` rather than emitting nothing (rule 5.5). This is
  the state on the day this WO lands, and the report is what makes it visible.

## Out of scope
- The route sweep, the per-place assertions and the provenance assertion —
  WO-047. This WO ships the fixture that suite consumes.
- Wiring an engine's stage: each engine's own work order sets its row's `wired`
  to true. This WO ships the table, not the engines.
- Any migration or schema: the fixture seeds through BP-002's existing tables.
- Any CI configuration, branch protection or pre-commit hook.
- A matrix of cold-start shapes — BP-021 Decisions 3 rejects it; two fixtures.
