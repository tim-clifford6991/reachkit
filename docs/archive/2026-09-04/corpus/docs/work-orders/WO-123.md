# WO-123 — purchaseContext and siteMeasurementState — what a purchase carries in, and an account with nothing measured

- Branch: wo/WO-123-purchase-context
- Estimate: ≤1 day

## Goal
Resolve a completed purchase into the domain its report measured — or into
nothing at all — and answer, for every screen, whether this account's current
domain has been measured yet.

## File plan
> **Every path below is NEW.** No `src/` exists. Anchored to
> `registry/structure.md` and BP-031's `code:` glob `src/lib/account/offer/**`.
> Provisional against a repo with no code.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/account/offer/purchase-context.ts` | NEW | Exports `purchaseContext(sessionId)` with BP-031's signature verbatim. Takes **only** a session id. Reads the `CheckoutOrigin` recorded by `recordCheckoutFacts` (WO-119); a `report` origin resolves to that scan's domain and its id; a `pricing` origin resolves to `{ domain: null, fromScanId: null }`. It imports no Stripe customer, address or email field and there is no code path from one to a domain — BP-031: "`purchaseContext` never reads the payer's email domain or billing address." |
| `src/lib/account/offer/measurement-state.ts` | NEW | Exports `siteMeasurementState(siteId)` with BP-031's signature verbatim. One indexed query joining `sites` to the newest completed `scans` row for the same `(site_id, domain)`; returns `nothing-measured-yet` with `sinceDomainSetAt` when there is none, `measured` with the scan id and instant when there is. Derived, never stored (BP-031 decision 1). |
| `tests/account/offer/purchase-context.test.ts` | NEW | A report origin resolves to the scan's domain; a pricing origin resolves to nulls; **the discriminating case for REQ-021 c7:** a pricing-origin session whose paying address is `founder@acme.com` and whose billing address names a country still resolves to `null` — plus a source-level assertion that `purchase-context.ts` references no Stripe email, address or customer field. |
| `tests/account/offer/measurement-state.test.ts` | NEW | No scan → `nothing-measured-yet`; a completed scan for the current domain → `measured`; **a completed scan for a *replaced* domain → `nothing-measured-yet`, and the replaced domain's scan row still exists**; a running scan for the current domain → `nothing-measured-yet`; the query count is one. |

## Interfaces
Consumes (verbatim from BP-030's `## Public interface`):
```ts
export type CheckoutOrigin =
  | { kind: 'report'; scanId: string }
  | { kind: 'pricing' }
```
Exposes (verbatim from BP-031's `## Public interface`):
```ts
export function purchaseContext(sessionId: string):
  Promise<{ domain: string; fromScanId: string } | { domain: null; fromScanId: null }>

export function siteMeasurementState(siteId: string): Promise<
  | { state: 'nothing-measured-yet'; sinceDomainSetAt: Date }
  | { state: 'measured'; scanId: string; measuredAt: Date }
>
```

## Steps
1. Write both test files and watch every case fail.
2. Implement `purchase-context.ts` reading only the recorded origin.
3. Implement `measurement-state.ts` as one join; add the index usage assertion.
4. Add the replaced-domain case last — it is the one that discriminates c12.
