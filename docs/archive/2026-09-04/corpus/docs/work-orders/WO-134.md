# WO-134 — The end of hosting — two notices, then the stop, and never the stop without the notices

- Branch: wo/WO-134-hosting-end-notices
- Estimate: ≤1 day

## Goal
Stamp the hosted-retention clock when access ends, send the two notices REQ-076
c11 requires, and refuse to let a site go dark that is missing either stamp.

## File plan
> **Every path below is NEW.** No `src/` exists. Anchored to
> `registry/structure.md` and BP-060's `code:` glob `src/lib/account/billing/**`.
> Provisional against a repo with no code.
>
> **This work order writes no file under `src/jobs/**`.** BP-003's
> `account/maintenance` tick calls these two queries every 15 minutes; its own
> `JobId` documentation names `REQ-076 c11 BP-060.sitesDueHostingEndNotice` and
> `REQ-076 c10 BP-060.sitesDueHostingStop`. This node owns the rule; BP-003 owns
> the schedule.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/account/billing/hosting-end.ts` | NEW | Exports `sitesDueHostingEndNotice(now)` and `sitesDueHostingStop(now)` with BP-060's signatures verbatim. The first returns sites at two moments — the instant access ends, however it ends (a lapse with no cancellation counts), and `HOSTING_END_REMINDER_DAYS` before serving stops — each guarded by its own stamp so neither is sent twice. Stamping `hosted_serving_ends_at = paid_through + HOSTED_RETENTION_DAYS` happens on the first of these, which is the moment access ends. The second returns sites whose `hosted_serving_ends_at <= now()` **and which carry both stamps**; a site missing either is excluded and raised as an alert (BP-060 decision 3: "A page going dark unannounced is worse than a page served a day longer than promised"). Deleted accounts are excluded from both: deletion sends neither notice and the window never begins. |
| `src/lib/account/billing/hosting-notices.ts` | NEW | Exports `sendHostingEndNotice(siteId, which: 'access_ended' \| 'seven_days')`. One `account` mail per stamp, carrying the day serving stops and a copy key stating that pages remain exportable afterwards. Stamps `hosting_end_notice_at` / `hosting_end_reminder_at` only after `sendEmail` reports `sent: true`. |
| `tests/account/billing/hosting-end.test.ts` | NEW | Fixed-clock cases: due at the instant access ends; due 7 days before the stop; not due twice; a lapse with no cancellation is due exactly as a cancellation is; `sitesDueHostingStop` excludes a site missing either stamp and raises; both queries exclude a deleted account; the stop is idempotent — running the tick twice, late, or not at all still yields the right answer at read time, because `hostedServingState` computes from the timestamp. |
| `tests/account/billing/hosting-notices.test.ts` | NEW | Each notice sends exactly one `account` mail; a failed send leaves the stamp unset so the notice is retried; **the discriminating case for BP-060 decision 3**: a site whose notice send failed is never returned by `sitesDueHostingStop`, so it keeps serving. |

## Interfaces
Exposes (verbatim from BP-060's `## Public interface`):
```ts
export function sitesDueHostingEndNotice(now: Date): Promise<string[]>   // at access end, and 7 days before stop
export function sitesDueHostingStop(now: Date): Promise<string[]>
```
Consumes (verbatim from BP-016's `## Public interface`):
```ts
export function sendEmail(m: {
  kind: MailKind; to: string; subject: CopyKey; blocks: MailBlock[]
  suppressible?: false
}): Promise<{ sent: true; id: string } | { sent: false; reason: 'suppressed' | 'vendor'; retryUntil?: Date }>
```
with `'account': { occasionsFrom: 'REQ-024, REQ-074, REQ-076, REQ-077, REQ-079', stoppable: false }` — unstoppable by its register row.

## Steps
1. Write `tests/account/billing/hosting-end.test.ts` with a fixed clock and watch
   the boundaries fail.
2. Implement `hosting-end.ts`, including the missing-stamp exclusion and its alert.
3. Implement `hosting-notices.ts`, stamping only after a successful send.
4. Add the failed-send case, which is the one that keeps a promise rather than a
   schedule.

## Rollback
Delete two source files and two test files. Sites already stamped keep their
stamps; removing the notices without removing the stop would let a page go dark
unannounced, which is the one outcome BP-060 decision 3 forbids — roll back both
or neither.
