# WO-228 — The hosted adapter — the slug, the live address, the DNS record to set, and cache invalidation

- Branch: wo/WO-228-hosted-adapter
- Estimate: ≤1 day

## Goal
Ship `hostedAdapter`, `dnsRecordFor` and `liveUrlFor`: a delivery that writes no external system, invalidates the hosted cache tags, and a DNS record the founder can set — or a stated pending shape where no domain is known.

> verified to exist, because none can. Placement is anchored to
> `sdlc-factory/docs/registry/structure.md` and to this work order's blueprint
> `code:` globs, and is provisional against a repo with no code: if the

| File | New/Modify | Change |
|---|---|---|
| `src/lib/publish/destinations/hosted/index.ts` | NEW | `hostedAdapter` implementing `DestinationAdapter` with `kind: 'hosted'` and **`servesPublicly: true`**. `deliver` computes the slug and the live address, **returns `madeLive: true` on a successful delivery and `madeLive: false` on a failed one** (ADR-081's discriminator: this adapter is the one place in the product where a page is actually made live, and `madeLive` records what *this call* did — a delivery that failed made nothing live), returns them for BP-045's publication row, and invalidates BP-047's `hosted:site:*` and `hosted:page:*` cache tags — **it writes no external system**, because the page *is* the row and there is no second system to reconcile. Its idempotency is the unique index alone (ADR-080). `unpublish` sets nothing itself, invalidates the same tags — so the address answers 410 at the moment the publication row changes and never waits on a TTL — and returns `{ ok: true, outcome: 'removed' }`, the one arm of BP-045's `UnpublishResult` this destination can take (REQ-056 c15; ADR-081 decision 3). It never reads `made_live_by_us`: the hosted page *is* the row, and removing it is the same act whoever made it live. `health` is the DNS answer (the check itself is WO-226's). |
| `src/lib/publish/destinations/hosted/dns.ts` | NEW | `dnsRecordFor(siteId)` — the `CNAME` record named `content` pointing at the pinned edge hostname from BP-005's `env`, or `{pending: 'no_domain_yet'}` where the site has no address yet. **Two shapes and no third**, so no surface can render a blank. `liveUrlFor({domain, slug})` — one function, the one place a hosted live address is composed. |
| `tests/publish/destinations/hosted/hosted.test.ts` | NEW | `deliver` makes no outbound call (egress seam stubbed to throw) and returns a `liveUrl` on the customer's own domain; `servesPublicly` is true; **`deliver` returns `madeLive: true` on success and `madeLive: false` on a failed delivery** — the second row is what discriminates a real answer from a hardcoded `madeLive: true`, and it is the reason a failed hosted delivery cannot later be unpublished as though ReachKit had made it live; `unpublish` returns `outcome: 'removed'` and no other arm; publishing and unpublishing each invalidate both cache tags at the moment the publication row changes; `dnsRecordFor` returns the record where a domain is known and the pending shape where it is not, and never null or empty; `liveUrlFor` is the only composer of a hosted address (a module-graph assertion). |

## Interfaces

**Consumes**

- `DestinationAdapter`, `DeliveryResult`, `RenderedPage`, `UnpublishResult` — `src/lib/publish/types.ts` (WO-206).
- `tags.site(siteId)` and `tags.page(publicationId)` — BP-047, `src/app/(hosted)/resolve-host.ts` (WO-229). Invalidated by name.
- `env` (the pinned edge hostname the CNAME points at) — BP-005. One pinned hostname, never a string in a card.
- `sites.domain` — BP-002.

**Exposes** — copied exactly from BP-058's `## Public interface`:

The `DestinationAdapter` members this adapter satisfies are BP-045's, including
the two ADR-081 added (`DeliveryResult.madeLive`, required, and the
`UnpublishResult` union); the declarations are WO-206's and are not repeated
here (rule 2.4).


```ts
// src/lib/publish/destinations/hosted/
export const hostedAdapter: DestinationAdapter        // kind: 'hosted'
export interface DnsRecord { type: 'CNAME'; name: 'content'; value: string }
export function dnsRecordFor(siteId: string): Promise<DnsRecord | { pending: 'no_domain_yet' }>
export function liveUrlFor(a: { domain: string; slug: string }): string
```

`servesPublicly: true` is the field WO-206 adds to `DestinationAdapter` — a
field, not a `kind === 'hosted'` test, so a third adapter cannot default into
REQ-063 criterion 1's judged population. The WordPress adapter sets it `false`
(WO-237), which is also what leaves `live_url` null and therefore leaves
`verify_due_at` null (WO-213, BP-049).

**Delivery writes no external system.** That is why this adapter needs no
destination-side marker: the unique index alone is the whole of its at-most-once
guarantee (ADR-080). The marker exists only for WordPress.

## Steps
1. Create `hosted/dns.ts` with `dnsRecordFor` and `liveUrlFor`. Two shapes for the record and no third.
2. `madeLive` follows the delivery's own success, not `servesPublicly` and not `kind`. Do not write `madeLive: true` as a constant on the object: a failed delivery must return `false`, and WO-213's contradictory-fixture test is written against exactly that distinction.
3. Create `hosted/index.ts` with `hostedAdapter`, `servesPublicly: true`.
4. Implement `deliver` as a slug computation, an address composition and two cache-tag invalidations. Assert zero egress.
5. Implement `unpublish` to invalidate the same two tags, so a 410 is never served from a stale cache and a takedown never waits on a TTL, and to return `{ ok: true, outcome: 'removed' }`.
6. Write the "publishing and unpublishing invalidate the tags at the moment the row changes" test first and watch it fail against an implementation that relies on a TTL (constitution §8).
