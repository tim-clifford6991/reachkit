# WO-229 — resolveHost() — the one place a Host becomes a customer, and 410 rather than 404 or a redirect

- Branch: wo/WO-229-resolve-host
- Estimate: ≤1 day

## Goal
Ship `resolveHost()` and the two cache tags: an exact Host resolution that never falls back, one `gone` disposition for all three reasons, and the preview's indexability fixed as a constant of the disposition.

## File plan

> verified to exist, because none can. Placement is anchored to
> `sdlc-factory/docs/registry/structure.md` and to this work order's blueprint
> `code:` globs, and is provisional against a repo with no code: if the
> implementer finds a file already present at one of these paths, they stop and
> log `failed` naming the drift rather than merging into it.

| File | New/Modify | Change |
|---|---|---|
| `src/app/(hosted)/resolve-host.ts` | NEW | `HostDisposition`, `resolveHost`, and the `tags` object BP-058 and BP-045 invalidate by name. Resolution is exact: an unknown or unmapped Host is `{kind:'unknown'}` → 404, and no ReachKit page and no other customer's page is served in its place — a `content.` label on a domain no `sites` row claims is `unknown`, **not** an error page carrying our brand. A publication whose `unpublished_at` is set is `gone:'unpublished'` → **410 Gone, never a redirect**; the two lifecycle reasons (`access_ended`, `account_deleted`) resolve through the same disposition, so there is one `gone` response and not three. `indexable` is a constant of the disposition — `true` for `site`, `false` for `preview` — never a column and never a setting. |
| `tests/hosted/serving/resolve-host.test.ts` | NEW | An unknown Host is `unknown` and never another customer's site; a `content.` label on an unclaimed domain is `unknown`; an unpublished page is `gone:'unpublished'` and the response is 410, not 404 and not a redirect; the two lifecycle reasons produce the same 410; a `gone` disposition is never cached beyond the request; `indexable` is false for every `preview` disposition and no code path can set it true. |

```ts
// src/app/(hosted)/resolve-host.ts
export type HostDisposition =
  | { kind: 'site';     siteId: string; domain: string; indexable: true }
  | { kind: 'preview';  draftId: string;                indexable: false }
  | { kind: 'gone';     reason: 'unpublished' | 'access_ended' | 'account_deleted' }
  | { kind: 'unknown' }

export function resolveHost(host: string): Promise<HostDisposition>

// cache tags this surface reads under; BP-058 and BP-045 invalidate them by name
export const tags: {
  site: (siteId: string) => `hosted:site:${string}`
  page: (publicationId: string) => `hosted:page:${string}`
}
```

**`indexable` is data on the disposition, decided once at the edge.** ADR-002
decision 2: `{slug}.reachkit.app` previews are `noindex` **forever** and no
setting can change it — the site-reputation-abuse guardrail `BUILD.md` §9 and
§14.6 state. This is REQ-059's territory and is *not* the separate report-page
`noindex` of ADR-002 decision 1, which is BP-001's and REQ-001 criterion 8's. Do
not merge the two, and do not look for a settings switch: there is none by
construction.

**This surface writes nothing.** It holds no `POST`, no server action and no
mutation, so no crawler and no visitor can advance BP-045's state machine.

## Steps
1. Read ADR-002 before touching indexability. Removing a `noindex` here reads as an obvious improvement and is a requirement change.
2. Create `resolve-host.ts` with the block above verbatim.
3. Resolve the Host with one indexed lookup on `sites.domain`, cached per Host for 60 s. Never fall back to another site, never to a ReachKit branded page.
4. Make `gone` never cached beyond the request, so a takedown is immediate.
5. Make `indexable` a literal on the disposition type, so a `preview` with `indexable: true` is a type error.
6. Write the "an unknown Host serves nothing of ours and nothing of another customer's" test first and watch it fail against an implementation with a default site (constitution §8).
