**Exposes** — copied exactly from BP-057's `## Public interface`:

```ts
// src/lib/publish/settings/settings.ts
export type Mode = 'autopilot' | 'copilot'

export interface PublishingSettings {
  mode: Mode
  vetoHours: number          // 0..168, always a whole multiple of 24
  publishTime: string        // 'HH:mm', 24-hour, read in `timezone`
  timezone: string           // IANA name
}

export function readPublishingSettings(siteId: string): Promise<PublishingSettings>

/** REQ-073 criterion 2's one written line — the key, never the sentence. */
export type PairCopyKey =
  | 'settings.publishing.pair.autopilotWindow'
  | 'settings.publishing.pair.autopilotZero'
  | 'settings.publishing.pair.copilot'
export function explainPair(s: PublishingSettings): PairCopyKey

/** REQ-073 criterion 1: the zone the browser reported at first sign-in. Writes
 *  `sites.timezone` only while it is null — a zone the customer set is never
 *  overwritten — and validates `reported` with the same IANA check as a patch. */
export function adoptBrowserTimezone(siteId: string, reported: string):
  Promise<{ adopted: true } | { adopted: false; reason: 'already_set' | 'invalid' }>
```

`adoptBrowserTimezone` is the function BP-057's `## Error & edge behavior` names
as "this node does the writing"; the browser-side post and the `src/app/api/**`
adapter that calls it are BP-001's surface and are **WO-273's**.

`savePublishingSettings` is declared by BP-057 in this same file and is **WO-220's**,
because it cannot be written before `newVetoDeadline` exists. This work order
creates `settings.ts` with everything above; WO-220 adds the writer to it. The
two are strictly sequential and share the file on purpose.

`explainPair` is the only place in the product where a mode-and-window pair
becomes a statement (BP-035 decision 1). The setup cards (WO-221) name their own
two keys and do not call this.

## Steps
1. Create `settings/settings.ts` with the block above verbatim.
2. Implement `readPublishingSettings` as one row read with the defaults applied: `VETO.defaultHours` where `veto_hours` is unset, the stored zone otherwise. Never fall back to the server's zone; a missing zone is an error, not a default.
3. Implement the validator as four independent closed checks returning the list of failed field names. An invalid patch is refused whole — nothing is partially saved.
4. Put the days-to-hours conversion here and nowhere else.
5. Implement `explainPair` as a three-way map from the pair to a key. Write no string.
6. Write the "a 36-hour window is refused" and "no export returns a rate" tests first and watch them fail against a permissive validator (constitution §8).
7. Implement `adoptBrowserTimezone` through the validator's IANA check; write its three cases first and watch the "leaves a set zone untouched" case fail without the null guard (§8).
