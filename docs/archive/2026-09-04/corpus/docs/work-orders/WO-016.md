# WO-016 — Job definitions — draft/generate, publish/execute and publish/verify

- Branch: wo/WO-016-content-jobs
- Estimate: ≤1 day

## Goal
Register the three content and publishing jobs with the triggers, idempotency
keys and kill-switch scopes BP-003 fixes.

## Provenance of this file plan
**This repository holds no `src/`.** Every path is NEW under BP-003's `code:`
glob `src/jobs/**`. `src/jobs/index.ts` is modified, and this work order is
sequenced after WO-015 for exactly that reason — the two never run in parallel.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/jobs/draft-generate.ts` | NEW | Daily, evening, per site, **in the site's time zone**, finishing before the veto window would start. Kill-switch guarded (in scope). One call to `generateDraft()`. |
| `src/jobs/publish-execute.ts` | NEW | Triggered on approval or on window expiry. Kill-switch guarded (in scope). Idempotency key `(draft_id, destination_id)`; the enforcing constraint is BP-045's, consumed not written. One call into the state machine. |
| `src/jobs/publish-verify.ts` | NEW | +24h after a publish. **Not** kill-switch guarded — BP-003 puts it outside the scope because it is read-only. One call to `verifyLive()`. |
| `src/jobs/index.ts` | MODIFY | Appends the three definitions. |
| `tests/jobs/content-jobs.test.ts` | NEW | The tests below. |

## Steps
1. Write the three definitions, each a trigger, a bounded loop and one call.
2. Apply the kill-switch guard to the first two only.
3. Register all three.
4. Write the tests; watch the "publish/verify still runs with the switch engaged"
   test fail first by guarding it.
