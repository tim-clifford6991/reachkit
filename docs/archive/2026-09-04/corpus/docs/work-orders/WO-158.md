# WO-158 — The rival gap resolver: absolute at cold start, ratio only at ten ranked searches

- Branch: wo/WO-158-overview-rivals-model
- Estimate: ≤1 day

## Goal
Resolve the rival module into its `absolute` or `ratio` arm from the confirmed
competitor set and the customer's own ranked count, with the cold-start arm
never described as the gap shrinking.

## File plan
> Every path below is **NEW** (no `src/` on disk, checked 2026-08-31). Placement
> follows `structure.md` and BP-038's `code:` globs; provisional.

| File | New/Modify | Change |
|---|---|---|
| `src/app/(account)/app/overview/rivals.ts` | NEW | `RivalGapModule` and the resolver: reads the confirmed competitor set and `sizeRivals()`, returns `absolute` below 10 ranked searches (including `own = 0`, where `lineKey` is **not** the gap-shrinking line) and `ratio` at 10 or more, carrying the previous ratio or, on the crossing measurement, that measurement's absolute counts. |
| `tests/app/overview/rivals.test.ts` | NEW | Arm selection at 0, 9, 10, the crossing case, and the confirmed-set-only property. |

## Interfaces
Consumes: `sizeRivals()` (BP-011/BP-052), the confirmed competitor set
(`sites.competitors`, BP-055/BP-056's write path), `Measured<T>` (BP-010),
`RATIO_UNLOCK` threshold pinned in BP-005 (`BUILD.md` §6.6's ranked ≥ 10).

Exposes (verbatim from BP-038 `## Public interface`):
```ts
export type RivalGapModule =
  | { kind: 'absolute'                                   // criteria 9 and 10
      own: Measured<number>
      rivals: readonly { domain: string; ranked: Measured<number>; series: readonly Measured<number>[] }[]
      lineKey: CopyKey }                                 // NOT the gap-shrinking line
  | { kind: 'ratio'                                      // criterion 11
      rivals: readonly { domain: string; ratio: Measured<number>
                         previous: Measured<number> | { kind: 'first_ratio'; counts: { own: Measured<number>; rival: Measured<number> } }
                         series: readonly Measured<number>[] }[]
      lineKey: CopyKey }
```

## Steps
1. Write the failing tests first (§8).
2. Resolve the arm from the customer's own ranked count: `< 10` → `absolute`,
   `>= 10` → `ratio`. At `own = 0` the arm is `absolute` and what moves over
   time is the rival's own count.
3. Select `lineKey` for the `absolute` arm from a key that is **not** the
   gap-shrinking line; assert that key inequality in a test.
4. On the `ratio` arm, carry the previous ratio; where the customer was below
   the threshold at the previous measurement, carry
   `{ kind: 'first_ratio'; counts }` instead — never a computed previous ratio
   that was never measured.
5. Draw rivals from the confirmed competitor set only; a derived-but-unconfirmed
   candidate must not appear.
6. Mutation check: make the `absolute` arm reuse the gap-shrinking key and
   confirm the criterion 9 test fails.
