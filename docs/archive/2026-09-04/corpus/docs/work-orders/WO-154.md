# WO-154 — The shell model: measured weeks, the waiting count, and the no-publish precedence

- Branch: wo/WO-154-shell-model
- Estimate: ≤1 day

## Goal
Assemble `ShellModel` in one request-cached read — the domain, a week count that
counts measured weeks only, the waiting count, and either the next publish time
or the first-match reason there is none.

## Interfaces
Consumes: `accountForWeek()` and `nextDueOn()` (BP-050, WO-174, WO-175, WO-176, WO-177),
`becomesPublishable()` (BP-015/BP-046), `stoppedWorkStatement` (BP-019/BP-054),

Exposes (verbatim from BP-037 `## Public interface`):
```ts
export type WeekCount =
  | { kind: 'counted'; weeks: number; lastMeasuredOn: Date }   // criterion 6
  | { kind: 'none'; firstDueOn: Date }                         // criterion 7

/** Criterion 4's four causes. Ordered by NO_PUBLISH_PRECEDENCE, not by whichever
 *  test a renderer happens to run first. */
export type NoPublishReason =
  | 'reachkit_stopped' | 'publishing_paused' | 'nothing_approved' | 'nothing_planned'
export const NO_PUBLISH_PRECEDENCE: readonly NoPublishReason[]
// ['reachkit_stopped', 'publishing_paused', 'nothing_approved', 'nothing_planned']

export interface ShellModel {
  domain: string
  weeks: WeekCount
  waiting: number                          // 0 renders no count at all (criterion 2)
  publishing:
    | { mode: 'autopilot' | 'copilot'; next: Date }
    | { mode: 'autopilot' | 'copilot'; next: null; because: NoPublishReason }
}
export function readShell(siteId: string): Promise<ShellModel>

/** Criterion 6's rule, isolated so it has exactly one implementation: the number
 *  of distinct site-local weeks, for the *current* domain, in which a weekly
 *  measurement produced something. Never elapsed weeks, never a stored counter. */
export function weeksMeasured(a: { siteId: string; domain: string }): Promise<WeekCount>
```

## Steps
1. Write the failing tests first (§8).
2. Implement `weeksMeasured` as a distinct count over `scans (site_id, domain,
   week_start)` where the scan produced a measurement; a `not_measured` week
   does not advance it, a partial week does (BP-037 decision 3).
3. Implement the no-publish resolver as a **first match over
   `NO_PUBLISH_PRECEDENCE`**, returning on the first true cause.
4. Assemble `ShellModel` in one request-cached read; assert ≤ 3 index lookups
   and ≤ 40 ms p95 in a budget test.
5. Take the next publish time from `becomesPublishable` only; compute no
   schedule here.
6. Mutation check: reverse the precedence order and confirm the
   (stopped ∧ paused) test fails; replace `weeksMeasured` with elapsed weeks
   and confirm the overstatement test fails.
