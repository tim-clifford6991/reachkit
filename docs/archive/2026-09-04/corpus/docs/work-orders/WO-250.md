# WO-250 — The presentation barrel: `src/lib/presentation/index.ts`, and the boundary test that keeps it the only door

- Branch: wo/WO-250-presentation-barrel
- Estimate: ≤1 day

## Goal
Create `src/lib/presentation/index.ts` so BP-019's declared public interface is
one importable surface, and add the boundary test that fails when a consumer
reaches past it into a leaf or when two leaves claim one name.

> and no `tests/`. Placement follows `registry/structure.md`, whose
> `src/lib/presentation/**` row names this module's public entry points as
> `copy() · renderMeasured() · emptyStateLine() · stoppedWorkStatement() ·
> BAND_LABELS`. This file is the thing that makes that row true.

## Steps
1. Write `tests/presentation/index.test.ts` first and watch every case fail —
   there is no barrel to import (constitution §8).
2. Create `src/lib/presentation/index.ts` as six star re-exports and nothing
   else:

   ```ts
   export * from './copy'
   export * from './generated'
   export * from './place'
   export * from './stopped'
   export * from './bands'
   export * from './measured'
   ```

3. **Decision taken under rule 1.1 — star re-exports, not an enumerated list.**
   Two options. An enumerated list (`export { copy, COPY, COPY_META } from './copy'`, and so on for all six)
   states the surface here, but then every leaf that adds an export must also
   edit this file, which makes the barrel a shared file across six work orders
   and re-creates the collision BP-020 decision 5 was written to remove. Star
   re-exports keep exactly one author per file — the barrel names modules, the
   leaves name symbols — and turn a name claimed by two leaves into a signal
   rather than a silent win: under ES semantics an ambiguous star export is
   *dropped*, so the symbol simply stops resolving from the barrel, which the
   reachability test in step 5 catches by name. That dropped-name behaviour is
   also rule 7.1's "two implementations of one capability" arriving as a test
   failure with both leaves named. **Chosen: star re-exports plus a reachability
   test.** Cost of reversing: rewrite six lines as an enumerated list; no
   consumer changes, because the import specifier is unchanged either way.
4. **The two path notes BP-019 writes, reconciled.** BP-019's interface block
   names `'./stopped/stop'` and `'./stopped/statement'` directly. This barrel
   goes through `./stopped` instead — the leaf's own declared entry point
   (WO-049's file plan). The symbols reaching a consumer are identical; the
   difference is an internal module path, which is the system's under
   constitution §1's rights table, and it means WO-049 can move a symbol between
   `stop.ts` and `statement.ts` without editing a file this WO owns. Cost of
   reversing: two lines. Reported to the architect for BP-019's interface
   comment.
5. Write the reachability test: for each of the six modules, read its own
   `export` list and assert every exported name resolves from the barrel with the
   same binding. This is the assertion that catches an ambiguous star export
   being silently dropped — the one failure mode step 3's choice introduces.
6. Write the no-collision test: assert the six modules' export-name sets are
   pairwise disjoint, and that the union's size equals the barrel's export count.
   A name in two sets fails with both module paths in the message.
7. Write the interface-completeness test: assert each of the fourteen symbols in
   the `## Interfaces` block above resolves from `src/lib/presentation`, by name
   and by kind (value or type). This is the test that fails the day a leaf
   renames an export BP-019 declares.
8. Write the direction and no-logic tests per the test plan.
