# WO-249 — renderMeasured(): the trichotomy rendered, with the two collapses unrepresentable rather than tested for

- Branch: wo/WO-249-render-measured
- Estimate: ≤1 day

## Goal
Create `src/lib/presentation/measured.ts` so the only way a measurement reaches a
screen or a mail is through one function in which rendering an unmeasured value
as a number does not type-check and dashing a measured zero cannot be written as
a local edit.

## Interfaces

**Consumes:** `Measured<T>` and `UnmeasuredReason`, and the three constructors
`measured`, `measuredZero`, `unmeasured`, from `src/lib/measure/measured.ts`
(BP-010/BP-024, WO-052) — the constructors in tests only. The `CopyKey` type and
`copy()` from `src/lib/presentation/copy/` (BP-020, WO-041). Nothing else: no
config, no network, no database, no clock, no `Intl`.

**Exposes** (verbatim from BP-019 `## Public interface`):
```ts
/** REQ-004's trichotomy, rendered. There is no other way to put a measurement on
 *  a screen or in a mail. */
export function renderMeasured<T>(m: Measured<T>, o: {
  format: (v: T) => string
  unmeasuredLine: CopyKey        // differs by reason: undeterminable vs not_attempted
}): { text: string; isDash: boolean; line?: string }
```

For reference, the shape it narrows over (BP-010 / WO-052, not redeclared here):
```ts
export type Measured<T> =
  | { kind: 'measured';   value: T; at: Date }
  | { kind: 'zero';       value: T; at: Date }
  | { kind: 'unmeasured'; reason: 'undeterminable' | 'not_attempted'; at: Date }
```

## Steps
1. Write `tests/presentation/measured.test.ts` first and watch every case fail —
   there is no module to import (constitution §8, "watch it fail first"). Watch
   the three `@ts-expect-error` fixtures fail too: before the source exists they
   error for the wrong reason, and the suite is only meaningful once each errors
   for the reason it names.
2. Add the three keys to `copy/keys/laws.ts` per the file plan. Write no
   sentence: two are empty and owner-owed, the third is REQ-004's own character.
3. Create `src/lib/presentation/measured.ts`. Import `type { Measured }` and
   `type { CopyKey }` as **type-only** imports, and `copy` as the one value
   import.
4. Implement the function as **exactly two branches** — this shape, and not a
   three-arm switch:

   ```ts
   if (m.kind === 'unmeasured') {
     return { text: copy(DASH_KEY), isDash: true, line: copy(o.unmeasuredLine) }
   }
   return { text: o.format(m.value), isDash: false }
   ```

   The two branches are the whole mechanism, and each closes one of the two
   collapses REQ-004 exists to prevent:

   **(a) An unmeasured value cannot become a number.** Inside the guard, `m`
   narrows to the `unmeasured` arm, which carries **no `value` field**. `o.format`
   is the only path from a `T` to a string, `T` is unconstrained, has no default
   and no witness anywhere in scope, and the arm supplies none. So there is no
   expression an implementer could write on that branch that produces `format`'s
   output — "render an outage as 0" is uninhabited, not merely wrong. The
   `@ts-expect-error` fixture in the test plan is the proof, and it is the reason
   this WO does not add a runtime assertion for the same thing: a runtime check
   would be a weaker copy of a compile error (rule 2.4).

   **(b) A measured zero cannot be dashed by a local edit.** The fall-through is
   **one** branch covering `measured` and `zero` together, reached by narrowing
   *by exclusion* — the literal `'zero'` never appears in the file. There is
   therefore no `zero` branch to edit. The only mutation that dashes a zero is
   moving `'zero'` into the guard, which dashes every measured value in the
   product at the same time and fails every case in every consuming suite at
   once. A three-arm `switch (m.kind)` would put a one-line `zero` case in the
   file that a hurried edit could turn into a dash and that nothing but a test
   would catch — which is exactly the "tested for" that BP-019's `## Error & edge
   behavior` says this must not be.
5. Declare `DASH_KEY` as a module-private `const DASH_KEY = 'unmeasured.dash'
   satisfies CopyKey`. It is not exported: a second reader of the dash key is a
   second place a dash can be produced.
6. Set `line` on the unmeasured branch only, and never on the other. `isDash` is
   computed by neither argument nor option — it is the branch. No parameter of
   any kind can set it, which is what makes `isDash === (m.kind ===
   'unmeasured')` a property rather than a convention.
7. Call `o.format` exactly once, with `m.value` and no second argument, no
   fallback and no coercion. `m.at` is read nowhere: the scan date travels with
   the sentence through WO-042's `explain()`, not through this return, and
   reading it here would mint a second date path (rule 2.4).
8. Export `renderMeasured` and nothing else.
