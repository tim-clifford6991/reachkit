## Interfaces
**Consumes:** nothing from another node. This module is pure: no network, no
database, no session, no clock (BP-020 `## Module / boundary`).

**Exposes** (verbatim from BP-020 `## Public interface`):
```ts
// ── src/lib/presentation/copy/keys/<partition>.ts ────────────────────────────
/** The sentences and their metadata are written **one partition file per owning
 *  module** — `report.ts`, `overview.ts`, `calendar.ts`, `draft.ts`,
 *  `settings.ts`, `setup.ts`, `publish.ts`, `danger.ts`, `mail.ts`, `bands.ts`,
 *  `laws.ts` — each exporting a frozen `{ key: [string, CopyMeta] }` block for
 *  its own module and nothing else. See decision 5: this is what keeps two
 *  parallel work orders off one file. */
export const REPORT_COPY: CopyPartition    // and one such export per partition
export type CopyPartition = Readonly<Record<string, readonly [string, CopyMeta]>>

// ── src/lib/presentation/copy/registry.ts ────────────────────────────────────
/** Every sentence the product speaks in its own voice, composed from the closed
 *  partition list. A frozen object literal in the bundle — not a fetch, not a
 *  template store, not an i18n catalogue — so REQ-093 criterion 5 holds with
 *  every model unavailable. This file is written **once**, with every partition
 *  named, and is not appended to block by block. */
export const COPY: Readonly<Record<CopyKey, string>>
export type CopyKey = keyof typeof COPY

/** The parallel, exhaustive metadata map, projected from the same partitions.
 *  `Record<CopyKey, CopyMeta>` is total, so a key added without meta is a
 *  compile error — this is the hook every law in this block is driven off, and
 *  the reason no law has to be remembered. Because both maps are projected from
 *  one partition entry, "a key without meta" is now unrepresentable rather than
 *  merely checked. */
export const COPY_META: Readonly<Record<CopyKey, CopyMeta>>

export interface CopyMeta {
  /** Which cross-cutting law, if any, governs this sentence. The conformance
   *  suites enumerate their own scope from this tag rather than from a list a
   *  developer maintains. */
  law?: 'next-publish' | 'stopped-work' | 'no-presence-yet' | 'unmeasured'
  /** Named text slots and what each accepts. A slot of kind 'measured' may be
   *  filled only through `explain()`; `copy()` refuses such a key. */
  slots: Readonly<Record<string, 'text' | 'date' | 'measured'>>
  /** The requirement clause that fixes what this sentence must say. */
  fixedBy: string           // e.g. "REQ-092 c4"
}

// ── src/lib/presentation/copy/copy.ts ────────────────────────────────────────
/** A sentence carrying no measurement. Signature is BP-019's, verbatim. */
export function copy(key: CopyKey, vars?: Record<string, string | number>): string
```

## Decision taken under rule 1.1
**The empty-value-plus-throw representation.** `COPY`'s declared type is
`Readonly<Record<CopyKey, string>>`, so a key whose string the owner has not yet
supplied has no representable "absent" value. Three options: omit the key (then
every downstream module referencing it fails to compile and cannot be built or
tested at all), give it a placeholder sentence (forbidden — the owner owns
customer-visible strings, and a placeholder is the thing REQ-091 criterion 2
forbids on a screen), or give it `''` and make reading it throw. **Chosen: `''`
plus `OWNER_OWED` plus a throw.** Derivation: the key is an internal name (the
system's, per constitution §1), the empty value is not a string a reader can ever
see because `copy()` refuses it, and the failure is loud at the call site rather
than blank on a screen. Cost of reversing: one line per key — delete the
`OWNER_OWED` entry and paste the owner's sentence in; no consumer changes.

**The twelfth partition, `offer.ts`.** BP-020 decision 5 names eleven partitions
by module. The seven BP-001-owned surfaces cut on 2026-08-31 (WO-241..WO-247)
include `/pricing`, whose sentences are BP-030's `PRICE_COPY_KEYS` and BP-031's
`OfferTerms` keys — a module with no partition in that list, because the list was
written before those work orders existed. Options: put them in `settings.ts` or
`setup.ts` (wrong module, and the next reader looking for the price sentence has
two places to look), let WO-241 add a partition (then WO-241 modifies
`registry.ts`, which decision 5 bounds to one line but which is still a second
work order writing this file), or declare the twelfth here. **Chosen: declare it
here**, where the partition list is written once anyway, so `registry.ts` still
has exactly one author. The two opt-out lines WO-247 renders go in `mail.ts` —
BP-029 owns the opt-out and lives in `src/lib/mail/leads/**`, so that partition
is already the right module and no thirteenth is needed. Cost of reversing: one
import and one spread line. Reported to the architect for BP-020's interface
comment, which lists eleven.
