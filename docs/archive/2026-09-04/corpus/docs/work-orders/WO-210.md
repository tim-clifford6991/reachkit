# WO-210 — The publishing switch — instant stop, the held-page set, and resume order

- Branch: wo/WO-210-publishing-switch
- Estimate: ≤1 day

## Goal
Ship the read and record of `sites.publishing_enabled`, the derived held-page set, and the oldest-first resume order — so that switching off takes effect at the moment it is recorded and loses no page.

## File plan

> This repository carries no `src/`, no `tests/`, no `supabase/` and no
> `package.json` (verified 2026-08-31). **Every path below is NEW** — none was
> verified to exist, because none can. Placement is anchored to
> `sdlc-factory/docs/registry/structure.md` and to this work order's blueprint
> `code:` globs, and is provisional against a repo with no code: if the
> implementer finds a file already present at one of these paths, they stop and
> log `failed` naming the drift rather than merging into it.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/publish/switch/index.ts` | NEW | `isPublishingOn`, `setPublishing`, `heldPages`, `resumeOrder`. `heldPages` is **derived**, never stored: `state ∈ {approved, in_review, failed} ∧ publishable ∧ ¬published` (BP-045 decision 2 — a held page is the absence of an edge, not an eleventh state). `resumeOrder` sorts by `drafts.publishable_since` ascending, tiebreak `drafts.id`. `setPublishing` records the moment and returns it; it moves no page and takes no transition. |
| `tests/publish/switch/switch.test.ts` | NEW | Recording the switch changes no draft's state; `heldPages` counts the four kinds REQ-056 c10 names and reads no column named `held`; `resumeOrder` is stable and oldest-first across a backlog; switching off and on again returns the same set in the same order. |

## Interfaces

**Consumes**

- `Actor`, `State` — `src/lib/publish/types.ts` (WO-206).
- `sites.publishing_enabled` — BP-002's declared addition on the `sites` topic. Read and written here; no column is added by this work order.
- `db()` under RLS — BP-002.

**Exposes** — copied exactly from BP-045's `## Public interface`:

```ts
// src/lib/publish/switch/index.ts
export function isPublishingOn(siteId: string): Promise<boolean>
export function setPublishing(siteId: string, on: boolean, by: Actor): Promise<{ recordedAt: Date }>
/** REQ-056 c14: the count a surface shows without opening Settings. */
export function heldPages(siteId: string): Promise<{ count: number; draftIds: string[] }>
/** REQ-056 c13: held pages in the order they were held, oldest first. */
export function resumeOrder(siteId: string): Promise<string[]>
```

## Steps
1. Create `switch/index.ts` with the four functions above.
2. Implement `heldPages` as a single derived query. Assert in test that no column named `held` exists and none is written.
3. Implement `resumeOrder` on `drafts.publishable_since` ascending with `drafts.id` as tiebreak, so the order is total and stable.
4. Write the tests and watch "recording the switch moves no page" fail against a stub that skips held pages (constitution §8).

## Test plan

Each criterion below is inherited verbatim from the requirement named in the
row, reflowed onto one line and otherwise unaltered.

| Acceptance criterion (verbatim from REQ) | Test |
|---|---|
| **REQ-056 c9** — Given the customer switches publishing off — the switch on the closed settings list, REQ-070 criterion 1 — when they do so, then it takes one action and no publish attempt begins for any page after the moment the switch is recorded — including for one already approved or already in review — until they switch it back on; the only page that can still reach a destination is one whose attempt was already under way at that moment, which criteria 11 and 12 govern. | `tests/publish/switch/switch.test.ts` › "no attempt begins after the moment the switch is recorded" — a claim started before and reaching the switch read after is refused; the assertion is on `setPublishing`'s returned `recordedAt` boundary. |
| **REQ-056 c10** — Given publishing is switched off, when a page that would otherwise have gone to a destination is held by it — one already approved, one whose veto window expired while the switch was off, one whose publish time arrived, or one whose retry fell due — then it stays in the state it holds, the move to `publishing` is not taken for it, and it is never skipped, discarded or moved to `needs_attention` on account of publishing being off; every such page is one of the held pages criterion 13 resumes. | `tests/publish/switch/switch.test.ts` › "a held page keeps the state it holds" — each of the four kinds REQ-056 c10 names is present in `heldPages` and none has moved to `skipped` or `needs_attention`. |
| **REQ-056 c13** — Given pages were held while publishing was switched off, when the customer switches it back on, then those pages resume under the ceilings in criterion 8, in the order they were held, and none is dropped. | `tests/publish/switch/switch.test.ts` › "resume order is the order they were held, oldest first, and drops none" — a backlog of thirty returns thirty ids in `publishable_since` order. |
| **REQ-056 c14** — Given publishing is switched off, when the customer opens the app, then that state, its effect on the schedule, and how many pages are held by it are visible without opening Settings. | `tests/publish/switch/switch.test.ts` › "heldPages returns a count and the ids without any settings read" — the function makes exactly one query and reads no settings table. |
