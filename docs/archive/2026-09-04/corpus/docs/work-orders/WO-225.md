# WO-225 — The destination registry — the read model a surface may see, and connect / disconnect / reconnect

- Branch: wo/WO-225-destination-registry
- Estimate: ≤1 day

## Goal
Ship `adapterFor`, `DestinationView`, `listDestinations`, `connect`, `disconnect` and `reconnect` — the whole of what a surface may see about a destination, carrying copy keys and never a vendor string.

> `code:` globs, and is provisional against a repo with no code: if the

| File | New/Modify | Change |
|---|---|---|
| `src/lib/publish/destinations/index.ts` | NEW | The registry. `adapterFor(kind)` is total over the closed two-member union and returns WO-228's `hostedAdapter` or WO-237's `wordpressAdapter`. `DestinationView` is **the whole of what a surface may see** — an id, a kind, a state, a reason token, a date, a count, an action and two copy keys, and there is no field on it that can hold a vendor string. `connect` with `config: null` creates the deferred connection (`expired` / `never_connected`, `last_checked_at` set at creation, no network call, result `ok`); a non-null config is validated by the adapter's `health`. `disconnect` calls `destroyConfig` and sets `deleted_at`, calls no `unpublish` and touches no publication row. `reconnect` sets `ok`, returns the number of pages waiting, and releases **only where publishing is on** — it never publishes anything itself, it clears a guard. |

**Exposes** — copied exactly from BP-058's `## Public interface`:

```ts
// src/lib/publish/destinations/index.ts
export type DestinationKind = 'hosted' | 'wordpress'
export type DestinationHealth = 'ok' | 'expired' | 'error'         // BUILD §10's enum, unchanged
export type HealthReason =
  | 'never_connected' | 'dns_unset' | 'dns_elsewhere'
  | 'credentials_expired' | 'credentials_invalid' | 'unreachable' | 'destination_rejected'

export interface DestinationView {          // everything a surface may see, and nothing more
  id: string
  kind: DestinationKind
  health: DestinationHealth                 // rendered as working / needs reconnecting / failing
  reason: HealthReason | null
  lastCheckedAt: Date
  heldPages: number
  action: 'none' | 'reconnect' | 'set_dns'
  copy: { state: CopyKey; line: CopyKey | null }   // keys only — never a sentence, never a payload
}

export function adapterFor(kind: DestinationKind): DestinationAdapter
export function listDestinations(siteId: string): Promise<DestinationView[]>
/**
 * `config: null` is a **deferred connection** (REQ-028 criteria 3 and 5): the row
 * is created `expired` / `never_connected`, no network call is made, and the
 * result is `ok`. A non-null config is validated by the adapter's `health`.
 */
export function connect(a: { siteId: string; kind: DestinationKind; config: unknown | null; by: Actor }):
  Promise<{ ok: true; destinationId: string; health: DestinationHealth } | { ok: false; reason: HealthReason }>
export function disconnect(destinationId: string, by: Actor): Promise<{ ok: true; credentialsDestroyed: true }>
export function reconnect(a: { destinationId: string; config: unknown; by: Actor }):
  Promise<{ ok: true; held: number; releasing: boolean } | { ok: false; reason: HealthReason }>
```

**`listDestinations` in this work order does not yet refresh health.** The
in-line 24-hour refresh REQ-074 criterion 1 promises is `ensureFreshHealth`, and
WO-226 adds the call to this file. The two work orders share
`destinations/index.ts` on purpose and are strictly sequential: `health/` imports
`adapterFor` from here, so this file must exist first. (Both files are inside one
module, `src/lib/publish/`; structure.md rule 6 governs cycles *between*
`src/lib/` modules, and none is created.)

**Reason selects the line; state selects the band** (BP-058 decision 2). A
destination that was never connected is `expired` with reason `never_connected`,
because REQ-074 criterion 2's offer is exactly what REQ-028 criterion 5 asks for
at setup — one state machine for brokenness, one Reconnect action, one held-queue
mechanism.

## Steps
1. Create `destinations/index.ts` with the block above verbatim.
2. Make `adapterFor` total over the closed union with no default arm, so adding a third kind is a type error rather than a silent fallthrough.
3. Implement `connect`: `config: null` writes the deferred row and returns `ok` without a network call; a non-null config is validated by the adapter's `health` before the row lands `ok`.
4. Implement `disconnect`: `destroyConfig` plus `deleted_at`, in one transaction. Call no `unpublish`. Touch no publication row — deleting one is exactly the tidy-up ADR-080 forbids.
5. Implement `reconnect`: set `ok`, clear `broken_mail_sent_at`, return `held` from `heldPages`, and set `releasing` from `isPublishingOn`. Publish nothing here.
6. Build `DestinationView` from a `select` list that does not include `config`. Assert in test that the type has no field able to hold a vendor string.
7. Write the "disconnect deletes no publication row" test first and watch it fail against an implementation that cleans up (constitution §8).
