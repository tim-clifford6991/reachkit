## Goal
Pursue a month of unused supply from evidence the pass already measured, stop on one of three reasons, and add every qualifying opportunity a weekly re-measurement produces — buying nothing either time.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/lib/opportunities/supply/pursue.ts` | NEW | `pursueDepth(c, { siteId, scanId, report, ownRanked, target? })` — loops BP-040's derivation over evidence already in the report until `supplyDepth().unused >= target` (`target_met`), until that evidence is spent (`evidence_spent`), or until `c.capHit()` (`pass_ended_early`). Defaults `target` to BP-005's `SUPPLY_TARGET_DEPTH`. Makes no vendor call and no fetch of its own; returns `{ unused, stop, created }` and throws only on a database error, so no caller can read a shortfall as a failure. |
| `src/lib/opportunities/supply/topup.ts` | NEW | `topUp(c, { siteId, scanId, report, ownRanked })` — calls the same derivation once for a completed weekly re-measurement and returns `{ added, unused }`. Additive only: it dismisses nothing, deletes nothing and re-derives nothing that already exists, relying on WO-181's partial unique index for idempotency. Returns `{ added: 0 }` without deriving where `hasActiveAccess()` is false. |
| `tests/opportunities/supply/pursue.test.ts` | NEW | A report with evidence for 40 candidates stops at exactly `target` with `target_met`; a report with evidence for 4 stops at `evidence_spent` with `unused: 4` and does not throw; a `CostContext` whose `capHit()` flips mid-loop stops at `pass_ended_early`; no vendor or fetch stub is called in any of the three; the target is read from the constant, not a literal. |
| `tests/opportunities/supply/topup.test.ts` | NEW | A weekly report producing three new qualifying targets adds three within the same call; re-running the same top-up adds nothing and leaves `unused` unchanged; a report re-deriving an existing open target adds nothing; a site without active access derives nothing. |

```ts
export type DepthStop = 'target_met' | 'evidence_spent' | 'pass_ended_early'

/** Drives BP-040's derivation over evidence the pass has already measured until
 *  the target is met or that evidence is spent. Buys nothing (REQ-095 non-goal:

export function pursueDepth(c: CostContext, a: {

  siteId: string; scanId: string; report: StoredReport; ownRanked: Measured<number>
}): Promise<{ added: number; unused: number }>
```

## Steps
1. Write both test files first and run them; both must fail on a missing module.
2. Implement `pursue.ts`. Assert in the test that no vendor stub and no `safeFetch` stub is reachable from it — REQ-095's non-goal bars "Buying more data, raising a cap, or lowering the winnability bar", and the way that is kept is that this module has no such call to make.
3. The three stop reasons are exhaustive and mutually exclusive; return the reason, never a boolean, so BP-003's observability can distinguish a spent market from a spent cap (BP-041's NFR budget: the distribution of `stop` is where REQ-095's open yield assumption is first dischargeable).
4. Implement `topup.ts`. Idempotency is the index, not a guard in this file: run the same top-up twice in the test and assert the row count.
5. Run the tests. Then mutate: lower the winnability bar inside the loop to reach the target and confirm nothing changes in this module's tests but WO-182's property test fails — which is why the bar is not reachable from here at all.
