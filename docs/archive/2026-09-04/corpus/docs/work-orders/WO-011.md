# WO-011 — The two Postgres clients — db(), dbAdmin() and the generated Database type

- Branch: wo/WO-011-db-clients
- Estimate: ≤1 day

## Goal
Expose exactly two ways to reach Postgres — a request-scoped client that carries
the caller's identity and a server-only administrative one — so no other module
chooses how it reaches the database.

## Provenance of this file plan
**This repository holds no `src/`.** Every path is NEW, anchored to
`structure.md`'s row for `src/lib/db/**` and BP-002's `code:` globs.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/lib/db/index.ts` | NEW | The two clients, exactly BP-002's public interface. `dbAdmin()` reads `SUPABASE_SERVICE_ROLE` through `env` and throws at import time if evaluated in a client bundle. `db()` is request-scoped and constructed per request. |
| `src/lib/db/types.generated.ts` | NEW | Generated from the applied schema by `supabase gen types typescript`. Checked in, never hand-edited; a header states so. |
| `tests/db/clients.test.ts` | NEW | The tests below. |

## Interfaces
Exposes (verbatim from BP-002 `## Public interface`):
```ts
// src/lib/db/index.ts — the only two ways to reach Postgres
export function db(): SupabaseClient<Database>        // request-scoped, RLS applies
export function dbAdmin(): SupabaseClient<Database>   // server-only, bypasses RLS
                                                      // throws if imported in a client bundle
export type { Database } from './types.generated'
```
Consumes (verbatim from BP-005 `## Public interface`):
```ts
export const env: Readonly<Env>
```

## Steps
1. Generate `types.generated.ts` with `npm run db:types` (the script WO-001
   declares) from the schema WO-009 and WO-010 applied.
2. Write the two clients.
3. Add the client-bundle guard to `dbAdmin()`.
4. Write the tests; watch the "generated types are stale" test fail first by
   adding a column and not regenerating.
