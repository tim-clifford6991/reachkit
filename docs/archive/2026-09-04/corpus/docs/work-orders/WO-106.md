# WO-106 — sendEmail() — the seam, and the one store each kind's stoppability chooses

- Branch: wo/WO-106-mail-send-seam

- Estimate: ≤1 day

## Goal
Ship `sendEmail()` so that every mail composes once, consults exactly one
stoppability store chosen by its register row, and reaches the vendor only if that
store says send.

## Provisional against an empty repo
**No `src/` exists.** All files NEW. `src/lib/mail/send.ts` is named explicitly in
BP-053's `code:` list and in ADR-040 point 3.

Reuse check (rule 7.2): `registry/capabilities.md` gives `sendEmail()` to BP-053
(declared by BP-016) and to no one else. This WO consumes four existing-by-plan
seams and mints none: `composeMail()` (WO-103), `MAIL_KINDS` (WO-104),
`sendViaVendor()` (WO-105), `stoppedByPreference()` (WO-107, BP-059) and
`isSuppressed()` (WO-112, BP-029). It writes **no** suppression logic of its own —
ADR-042's whole subject.

## Read ADR-042 before touching this file
`MAIL_KINDS[kind].stoppable` is the dispatch, not documentation. Exactly one store
is consulted per send: `'toggle'` → BP-059's `users.notify`; `'opt-out'` →
BP-029's `email_suppressions`; `false` → neither. There is no call that asks both
and no helper that unifies them. Merging them takes a magic-link customer's
sign-in mail away, silently (ADR-042 `## Context`).

## Interfaces
**Exposes** (verbatim from BP-053 `## Public interface`):
```ts
// src/lib/mail/send.ts — BP-016's declared seam, realised
export function sendEmail(m: {
  kind: MailKind; to: string; subject: CopyKey; blocks: MailBlock[]
  optOut?: { href: string }
  measurement?: MeasurementState
  userId?: string                       // required when MAIL_KINDS[kind].stoppable === 'toggle'
  suppressible?: false                  // REQ-057 c7's one send
}): Promise<
  | { sent: true; id: string }
  | { sent: false; reason: 'suppressed' | 'preference-off' | 'preference-unreadable' | 'vendor'
      retryUntil?: Date }>
```
**Consumes**:
```ts
export function composeMail(m: { kind: MailKind; subject: CopyKey; blocks: readonly MailBlock[]
  optOut?: { href: string }; measurement?: MeasurementState
}): { html: string; text: string; omitted: readonly number[] }          // WO-103
export const MAIL_KINDS: Readonly<Record<MailKind, KindRow>>            // WO-104
export function sendViaVendor(v: VendorSend): Promise<VendorResult>     // WO-105
export function stoppedByPreference(a: {
  userId: string; kind: MailKind          // type-only import from the register
}): Promise<'send' | 'stopped' | 'unreadable'>                          // WO-107 (BP-059)
```
and BP-029's address-wide suppression read (WO-112).

## Steps
1. Write the three test files first and watch them fail.
2. Implement the compose step, then the dispatch, then the vendor call — in that
   order, so a partial implementation never sends before it has consulted.
3. Map `VendorResult` to the public union; `retriable: false` still surfaces as
   `reason: 'vendor'` with no `retryUntil`, so BP-029's window can end early.
4. Log kind, recipient hash, suppression/preference outcome, vendor id, retry
   count, and the count of omitted blocks. Never a body, never an address.
5. Mutation check: move the suppression consult before `composeMail` and confirm
   nothing fails (it should not — ordering there is free); then move it to
   schedule time by caching the result and confirm `stoppability.test.ts` fails.
