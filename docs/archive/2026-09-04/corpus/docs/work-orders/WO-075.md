# WO-075 — phraseQuestions — the second nano call, and the template fallback that never drops a question

- Branch: wo/WO-075-phrase-questions
- Estimate: ≤1 day

## Goal
Implement `src/lib/market/questions/phrase.ts` so each selected search gains a wording
through the `'question-phrasing'` nano call while carrying its own search unchanged, and a
failed phrasing degrades to a template rather than removing a question from the denominator.

## Context an implementer needs
No source code exists on disk; both paths below are NEW.

**This is the second of the free path's two nano calls.** BUILD §6.7 step 4 reads "Phrase
as questions (nano, **same call as step 1**)", which is arithmetically impossible: step 3 —
deterministic selection — sits between step 1 and step 4, so step 4's input is step 3's
output and cannot exist when step 1 is issued. BP-025 decision 2 settles it: two nano calls
per scan, ≈0.6¢ rather than ≈0.3¢, against `CAPS.FREE_C` 12¢. Do not "optimise" the two
calls back into one; doing so would let the model see the candidate set before selection
runs, which is the coupling §6.7 forbids.

## Interfaces
**Consumes**: `SelectedSearch` (WO-074), `Measured<T>` (BP-010), `CostContext` (BP-007), and

```ts
// BP-009 — the call site, verbatim from its LlmCallSite union
  | 'question-phrasing'  // nano · a selected search -> a question's wording (step 4)
export function llm<T>(c: CostContext, call: {
  site: LlmCallSite
  input: unknown
  schema: ZodType<T>          // output is parsed or the call failed
  tier: 'nano' | 'haiku'
}): Promise<Measured<T>>
```

**Exposes** — copied exactly from BP-025's `## Public interface`:

```ts
// src/lib/market/questions/phrase.ts — step 4
export interface Question {
  id: string                            // stable within a scan; the matrix keys on it
  text: string                          // the wording only
  search: SelectedSearch                // carried, never returned by the model
  phrasing: 'template' | 'model'
}
export function phraseQuestions(c: CostContext, a: { selected: SelectedSearch[] }): Promise<Measured<Question[]>>
```

## Steps
1. Derive a stable `id` per selected search from its `rank` (stable within a scan, which is
   all `Question.id` promises). The id is assigned before the call and is the key the model's
   response is matched back on.
2. Issue **one** `llm()` call with `site: 'question-phrasing'`, `tier: 'nano'`, whose input is
   the ids and keywords of the selected searches and whose schema parses an array of
   `{ id, text }` and nothing else — no keyword, no volume, no intent, no rank.
3. Build one `Question` per input `SelectedSearch`, in input order, `search` carried by
   reference from the input. Where the model supplied a parseable `text` for that id, set
   `phrasing: 'model'`; otherwise apply the template and set `phrasing: 'template'`.
4. A whole-call failure (`unmeasured` from `llm()`) yields every question at
   `phrasing: 'template'` and a `measured` outcome — the questions exist, so the set is
   measured. Nothing is dropped: dropping one would change criterion 1's denominator, which
   every other number on the card is read against (BP-025 decision 3).
5. `phraseQuestions` returns `Measured<Question[]>` whose length always equals
   `selected.length`.
6. Emit the observability field BP-025 names: phrasing fallbacks.
7. Write the tests; watch each fail first.

Cost shape, from BP-025 decision 2:
`phraseQuestions/issues-exactly-one-nano-call` — one `llm()` invocation per call, `site`
`'question-phrasing'`, `tier` `'nano'`; and the phrasing call's input contains no member of
the raw market set beyond the selected searches handed in.

Discrimination: widening the schema to admit a `keyword`, or dropping an unphrased question
from the array, must each fail a named test above.
