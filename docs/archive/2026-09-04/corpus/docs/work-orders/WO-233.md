# WO-233 — bodyCoverage() — the one operational definition of "returns its whole page content"

- Branch: wo/WO-233-body-coverage
- Estimate: ≤1 day

## Goal
Ship `bodyCoverage()`: multiset containment of the draft's tokens in the fetched document, against one pinned floor, so the AI-readable check discriminates a JavaScript-gated page from a correct one — and decides **readability alone**, never whether the document is our page.

## Interfaces

**Consumes**

- `VERIFY.coverageFloor` — BP-005, `src/lib/config/constants.ts`, asserted in `tests/pins.test.ts`. Read by WO-234, not by this file.
- `drafts.body_md` — BP-002 and BP-014. Passed in by the caller; this function reads nothing.

**Exposes** — copied exactly from BP-049's `## Public interface`:

```ts
// src/lib/publish/verify/coverage.ts
/** The one definition of REQ-062 criterion 1's "whole page content". */
export function bodyCoverage(fetchedHtml: string, draftBodyMd: string): number  // 0..1
```

`VERIFY.coverageFloor = 0.95` belongs in BP-005 (config over constants, rule 7)
and is applied by WO-234, not here. BP-049 states the derivation: the floor is
chosen so that template chrome, typographic substitution and markdown-to-HTML
differences cannot fail a page whose content is wholly present, while a page
gated behind client JavaScript fails decisively. Reversal is one pin; the risk of
raising it is false failures on a customer's own domain, and of lowering it is
calling a JavaScript-gated page AI-readable.

**This function does not decide identity, and a second floor on it is forbidden**
(BP-049 decision 4, 2026-09-01). REQ-062 criterion 4's third outcome includes
"what came back was not the page ReachKit published", and criterion 1's fourth
check asks whether the page "returns its whole page content to a crawler that
runs no scripts". Decided from this number alone those are **the same
measurement at two thresholds**: a parked page, a soft-404 and a login wall
return almost none of the draft's tokens — and so does a correctly published page
whose body is behind client JavaScript, which is exactly the failure `aiReadable`
exists to find. One threshold cannot serve both, and whichever way it is set one
of the two promises breaks silently. **Identity is `isOurPage`** — a canonical
link or `og:url` resolving to the fetched address, or a normalised `<title>`
match — and it lives in `answer.ts` (WO-261). BP-049 rejects "a second, much
lower coverage floor for identity" in terms: it is one measurement with two pins
and the gap between them is unfalsifiable. The indistinguishability row in the
file plan is what records that, so a later reader proposing the second floor
meets the evidence before the temptation.

## Steps
1. Create `verify/coverage.ts` as one pure function.
2. Normalise both sides to lowercase alphanumeric tokens; measure multiset containment of the draft's tokens in the document.
3. Build the two fixtures — a correct rendered page and a JavaScript-gated one — before writing the function, and watch the containment measure separate them where a byte-length ratio does not (constitution §8).
4. Build the third fixture — a parked page — and assert that this function **cannot** tell it from the JavaScript-gated one. That is the point: identity is decided elsewhere, from a different part of the document.
5. Add no threshold, no I/O and **no second threshold** to this file. A function in this file that returns a boolean, or a caller that compares this number against anything but `VERIFY.coverageFloor`, is the identity/readability merge BP-049 decision 4 rejects.

## Out of scope
- Fetching anything — WO-234.
- The floor itself — BP-005's pin.
- **Deciding whether the document is the page ReachKit published.** That is `isOurPage` in `answer.ts` — WO-261 — and it reads the canonical link, `og:url` or `<title>`, never this number (BP-049 decision 4). Nothing in this file returns a boolean.
- Any arm of `VerifyOutcome`. This function feeds one `Measured<boolean>` inside the `found` arm and decides no arm at all.
- Running a headless browser. Rejected in BP-049 decision 3: it would defeat the check's purpose, which is precisely to look without one.
