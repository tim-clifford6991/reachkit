# WO-082 — categoryOnReport and correctionOffer — what the report's face shows and whether the control is drawn

- Branch: wo/WO-082-correction-offer
- Estimate: ≤1 day

## Goal
Implement `src/lib/market/coherence/offer.ts` so a reader always gets a route: the category
the report measured on its face or a plain statement that none was reached, and a correction
control whose availability is decided from one stored report and a clock — never from the
scan pipeline.

```ts
// src/lib/market/coherence/offer.ts
/** What this node needs from a stored report, supplied by its caller.
 *  Deliberately not BP-012's `StoredReport`: even a type-only import of it would
 *  put a src/lib/market → src/lib/scan edge into the build graph and close the
 *  cycle rule 6 forbids (Decisions 3). */
export interface ReportFacts {
  scanId: string
  measuredAt: Date
  category: string | null                    // null where the scan never reached one
  correctionState: CorrectionState
  domainRemoved: boolean
}
export type CategoryOnReport =
  | { shown: true; category: string }
  | { shown: false; reason: 'not_reached' }        // REQ-004 c6/c9's line stands there instead
export function categoryOnReport(report: ReportFacts): CategoryOnReport

export type CorrectionOffer =
  | { offered: true;  as: 'first' | 'retry' }
  | { offered: false; because: 'used' | 'exhausted' | 'in_progress' | 'report_too_old' | 'domain_removed' }
export function correctionOffer(a: { report: ReportFacts; now: Date }): CorrectionOffer
```

## Steps
1. `categoryOnReport`: `category === null` ⇒ `{ shown: false, reason: 'not_reached' }`;
   otherwise `{ shown: true, category }`. Nothing is guessed, and no default category exists
   anywhere in this file. The category is shown on the face of a report of **any** age —
   only the *control* expires.
2. `correctionOffer`, evaluated in this order so a reader is always told the most specific
   true reason:
   - `report.domainRemoved` ⇒ `{ offered: false, because: 'domain_removed' }`.
   - `correctionState === 'running' || correctionState === 'running_retry'` ⇒
     `{ offered: false, because: 'in_progress' }`. Both running members take this arm and it
     is written as one condition, not two branches — a retry in flight is in progress, and
     splitting it here would be the second reading BP-028 decision 2a's alternative (b)
     rejects.
   - `correctionState === 'used'` ⇒ `'used'`; `'exhausted'` ⇒ `'exhausted'`.
   - `now - report.measuredAt >= CORRECTION.offerMaxAgeDays` ⇒ `'report_too_old'`.
   - `correctionState === 'failed_once'` ⇒ `{ offered: true, as: 'retry' }`.
   - `correctionState === 'none'` ⇒ `{ offered: true, as: 'first' }`.
3. The offer is computed at render time from the stored report and a clock **only**. It never
   queries the scan pipeline, so a report renders its offer correctly even when scanning is
   switched off — the refusal happens at submission, where the reason exists (BP-028's
   `## Error & edge behavior`), and it is BP-012's `Admission` that tells the reader which
   limit was met, not this file.
4. Where the scan never reached a category, the control is **still offered** on the same terms:
   correcting supplies the category the scan never reached. `categoryOnReport` and
   `correctionOffer` share no branch.
5. Age is compared in whole days against `CORRECTION.offerMaxAgeDays`; the literal 7 does not
   appear in this file (`structure.md` rule 5).
6. Emit the observability field BP-028 names: offer outcome.
7. Write the tests; watch each fail first.

Totality over the six states: `offer/covers-every-correction-state` — a table-driven test over
all six `CorrectionState` members at a fixed age, asserting each returns a value of the
`CorrectionOffer` union, so a state added to the machine cannot silently fall through this
function. `offer/running-retry-is-in-progress-not-exhausted` — named separately, because a
reader who assumes `running_retry` is a terminal state would take the reader's retry away
while it is still running.

Discrimination: reordering the offer branches so `report_too_old` precedes `used`, mapping
`running_retry` to anything but `in_progress`, letting `categoryOnReport` suppress a category
past 7 days, or reading `Date.now()` instead of the supplied `now`, must each fail a named
test above.

Purity, from BP-028's `## NFR budget` ("**0¢ and no I/O**… the verdict is computed at render
time, so moving a threshold re-renders correctly against every report already stored"):
covered by `offer/never-reads-the-pipeline` above.
