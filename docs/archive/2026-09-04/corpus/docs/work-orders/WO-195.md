## Goal
Implement the one fixed recorded similarity measure and the near-duplicate rule that compares a candidate against this customer's published, measured and queued pages.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/lib/generate/rules/similarity.ts` | NEW | `similarity(a: string, b: string): number` — exact Jaccard over the set of 5-word shingles of the rendered text, lowercased with punctuation stripped and stop-words kept. Two strings in, one number out: no options parameter, no threshold argument and no configuration, so there is no argument through which a per-customer threshold could arrive (BP-042 decision 3). `SHINGLE_SIZE` is read from BP-005. |
| `src/lib/generate/rules/nearduplicate.ts` | NEW | `ComparisonSet` verbatim from BP-042's public interface, and `checkNearDuplicate(a: { rendered: string; comparison: ComparisonSet }): RuleFailure | null` — fails at or above `NEAR_DUPLICATE_MAX` against any member of the published, measured or queued sets, carrying `{ rule: 'near_duplicate', duplicateOf: { kind, ref, title }, similarity }`. All three sets are this customer's; nothing compares against another customer's page. No stored score and no shingle table. |
| `tests/generate/rules/similarity.test.ts` | NEW | The measure is symmetric (`similarity(a, b) === similarity(b, a)`), returns 1 for identical text and 0 for disjoint text, is stable across runs and processes for the same pair, and is unchanged by punctuation or letter case; a fixture pair is asserted to a fixed value so a change of shingle size is visible as a changed number rather than a changed verdict. |
| `tests/generate/rules/nearduplicate.test.ts` | NEW | A candidate at 0.86 against a queued draft fails and carries that draft as `duplicateOf` with `kind: 'queued'`; at 0.84 it passes; the same candidate compared against another customer's page is never considered (the set has no such member and no code path fetches one); a candidate failing against a measured page carries `kind: 'measured'`. |
| `tests/generate/rules/similarity-shape.test.ts` | NEW | Compile-time assertion under `tsc --noEmit`: `typeof similarity` is exactly `(a: string, b: string) => number` (a hand-rolled `Equals<A, B>`), so adding an options parameter or a threshold argument fails the type-check. |

```ts
/** One fixed recorded measure: Jaccard over 5-gram word shingles of the
 *  rendered text, lowercased, punctuation stripped. No options, no threshold
 *  argument, no configuration — the same pair always returns the same number. */
export function similarity(a: string, b: string): number

export interface ComparisonSet {
  published: Array<{ ref: string; title: string; rendered: string }>
  measured:  Array<{ ref: string; title: string; rendered: string }>
  queued:    Array<{ ref: string; title: string; rendered: string }>
}
```

## Steps
1. Write the three test files first and run them; each must fail on a missing module.
2. Implement `similarity.ts` as a set operation, so symmetry and order-independence hold by construction rather than by test.
3. Implement `nearduplicate.ts`. The three sets are the argument; this module fetches nothing and knows no other customer exists.
4. Run the tests. Then mutate: add an `opts` parameter to `similarity` and confirm `similarity-shape.test.ts` fails at compile time; change `SHINGLE_SIZE` locally and confirm the fixed-value fixture fails while the verdict tests still pass — which is why the fixed value is asserted.
5. Do not add a cache, a MinHash sketch or a stored score (BP-042 decision 3 rejects all three).

| **REQ-050 c13** Given any two comparisons, when similarity is computed, then it is computed by the same single recorded measure, so the same pair of pages always returns the same verdict. | `similarity.test.ts › the same pair always returns the same number` (symmetry, stability across processes, punctuation and case invariance) and `similarity-shape.test.ts › similarity takes exactly two strings` |

**Discriminates (mutation check, constitution §8).**
- Adding an options or threshold parameter breaks the compile-time shape assertion — a runtime test would still pass, and a per-customer threshold is exactly what c13 forbids.
- Dropping the queued set from the comparison makes the 0.86-against-queued case pass; the requirement names all three sets and the test asserts each.
- Replacing Jaccard with an embedding similarity keeps most verdicts and fails `… asserted to a fixed value`, which is the test that holds "one fixed recorded measure".
