**Exposes** (verbatim from the blueprint):
```ts
export type Verdict = 'working' | 'too_early' | 'not_working'   // the three

/** **ADR-072 (landmine, superseding ADR-071) — every one of these is terminal.**
 *  There is no lift condition for any of them and no code computes one. Read that
 *  file before writing the branch that judges a page again once its search comes
 *  back into the tracked set: it is the change that will present as a *bug
 *  report* rather than a tidy-up, and REQ-063 criterion 6 forbids it in terms —
 *  "A page marked no longer judgeable stays so, and nothing restores it". */
export type NotJudgeableCause =
  | 'search_untracked'   // its target search is no longer measured
  | 'unpublished'        // REQ-056 c7 — and `unpublished` is itself a terminal state
  | 'page_not_found'     // BP-049 recorded REQ-062 c4's second outcome, and nothing
                         // else: this node never fetches a page's address (ADR-085)
  | 'question_left_set'  // REQ-071 c7
  | 'domain_changed'     // REQ-071 c14

/** REQ-063 c1's two verification outcomes that sit **beside** a verdict without
 *  qualifying it: a check the page failed (REQ-062 c3) and a check that could not
 *  be confirmed (REQ-062 c4's third outcome). Read from BP-049's stored
 *  `VerifyOutcome`; never re-derived and never re-fetched.
 *
 *  **`could_not_confirm` is deliberately here and deliberately not a
 *  `NotJudgeableCause`** — ADR-085 Decision 4 and ADR-072 Decision 5b. It and
 *  `page_not_found` render as the same grey line and have opposite consequences:
 *  one leaves the page fully judged, the other retires it forever. Merging them
 *  is the cleanup those two files exist to stop. */
export type VerifyNote =
  | { note: 'checks_failed';     failed: readonly CheckId[]; checkedAt: Date }
  | { note: 'could_not_confirm'; checkedAt: Date }

/** A page's standing for one week. Four shapes, and they never collapse into
 *  three (ADR-071, carried forward unchanged by ADR-072). */
export type WeekStanding =
  | { kind: 'verdict';       verdict: Verdict
      measuredAt: Date
      movement: Movement | null
      verifyNote: VerifyNote | null }      // c1: shown beside, never in place of
  | { kind: 'not_judgeable'; cause: NotJudgeableCause
      lastJudgedWeek: WeekStart | null }   // null = never judged (c6)
  | { kind: 'not_measured' }               // c5, second half — transient, no row
  | { kind: 'no_week' }                    // c5, first half — the week was not measured at all

export interface Movement {
  previousWeek: WeekStart
  spansWeeks: number          // 1 unless a week was missed (c4)
  from: Measured<number>; to: Measured<number>
  declined: boolean           // c3 — carried, never smoothed away
}

export type WeekStart = string   // ISO date of Monday in the site's own time zone
```

## Steps
1. Write both test files first and run them; the schema test must fail on a missing table and the types test on a missing module.
2. Write the migration. `week_start` is a date, stored as Monday **in the site's time zone** (BP-051 decision 3); the job's UTC schedule never appears in a stored week.
3. Make insert-only a permission: revoke update and delete for the request-scoped role rather than relying on application code. The series is the record c6's "date of the last verdict it did receive" is derived from.
4. Create `types.ts`. The four arms are a discriminated union, not an enum with a reason field: ADR-071 point 1 (carried forward by ADR-072 Decision 2) requires a consumer to destructure, so the three "cannot tell you" cases are unavoidable at every call site rather than optional at one.
5. Declare `NotJudgeableCause` with **five** members and `VerifyNote` as a **separate** union. Write the two declarations in that order and read ADR-085's warning block before either: `could_not_confirm` belongs to `VerifyNote` and to nothing else, and adding it to `NotJudgeableCause` "beside `page_not_found`" is the tidy-up ADR-085 exists to stop.
6. Add the exhaustiveness fixture: a `switch` over `WeekStanding` missing one arm must fail `tsc --noEmit`, and the same for `NotJudgeableCause`'s five members. That fixture is the test that survives the reviewer who proposes collapsing two grey rows into one.
7. Write `landmine.test.ts` last and run it against the finished `types.ts`. Its (a) case is a negative assertion — `@ts-expect-error` on an assignment of `'could_not_confirm'` to `NotJudgeableCause` — so it goes green only while the merge has *not* happened, and goes red the day it does. A positive test cannot express that.
8. Run the tests. Then mutate: give `not_measured` a row shape and confirm the schema test's constraint cases no longer describe the table; then add `'could_not_confirm'` to `NotJudgeableCause` and confirm `landmine.test.ts` fails while every other test in this work order still passes — that is the whole point of it.

**Discriminates (mutation check, constitution §8).**
- Merging `not_measured` into `not_judgeable` — the tidy-up ADR-071 exists to prevent — fails the four-arm assertion and the exhaustiveness fixture; every screen would still render correctly, which is why the test is a type-level one.
- **Adding `could_not_confirm` to `NotJudgeableCause`** fails `landmine.test.ts` case (a) and nothing else in the corpus. It is the change ADR-085's warning block says will be proposed as a tidy-up, it passes every runtime test that exists, and its effect is that a page retired from judgement forever by a 502 goes on looking correct on every screen, week after week (ADR-072 Decision 5 makes that unrecoverable by design).
- **Replacing `VerifyNote` with a `Date`** — the `verifyFailedAt` this file carried until 2026-09-01 — fails the `verifyNote` member assertion. A `Date` cannot say *which* checks failed, and cannot distinguish "the page failed a check" from "the check did not settle at all", which is REQ-062 c4's third outcome and the arm that asserts nothing.
- Making `lastJudgedWeek` optional passes every runtime test and fails the required-member assertion; c6 needs the null that means never judged, which an absent field cannot express.
- Permitting updates on `page_verdicts` makes the update-refused case fail, and would let a later week rewrite an earlier verdict — the history c6 reads.
