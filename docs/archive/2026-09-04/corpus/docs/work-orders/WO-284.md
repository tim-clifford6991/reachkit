# WO-284 — Bind the boot environment to the deployment — SUPABASE_SERVICE_ROLE_KEY end to end, NANO_API_KEY optional, DATABASE_URL out of Env

- Branch: wo/WO-284-boot-environment
- Estimate: ≤1 day (one schema, one reader, six fixtures, one example file)

## Goal
Move `env.ts`'s boot schema and every reader and fixture of it onto BP-005
decision 6's three bindings in one commit, so a deployment on the Vercel
project `reachkit` boots on the names that project holds and an environment
carrying the retired names fails loudly instead of half-configuring.

> **Read `blueprints/BP-005.md` decision 6 (6a, 6b, 6c) before writing a
> line.** It holds the derivation and the reversal cost of each of the three
> bindings, and the standing fact about write-only secrets they follow from.
> None of that is restated here (rule 2.4).

**Risk: high — seam: access control.** `SUPABASE_SERVICE_ROLE_KEY` is the binding that bypasses RLS, held behind `dbAdmin()` and server-only by the charter's stack row ("Supabase — Postgres, RLS default-deny … `dbAdmin` server-only"). A boot-schema test that survives deletion of a required binding lets an environment half-configure, or lets the `dbAdmin()` guard stop guarding, with no visible symptom until something reads past a policy. Mutation-tested (doctrine 0.13.2, rule 2b).

## Provenance of this file plan
Every path below exists; every one is MODIFY. **Type fan-out (rule 1b):** the
two type-shape edits — schema key renamed, `DATABASE_URL` row deleted — were
applied alone on a scratch copy of `src/`, `tests/` and `tsconfig.json` (whose
`include` covers `tests/**`) and `npm run typecheck` run against it. Baseline
exit 0; after the edit, exactly one error — `src/lib/db/index.ts(58,64): error
TS2551: Property 'SUPABASE_SERVICE_ROLE' does not exist on type
'Readonly<{ … }>'. Did you mean 'SUPABASE_SERVICE_ROLE_KEY'?` — so that file is
the only type-change row. What did *not* error is the finding: every other
consumer names the binding as a **string literal** in a `process.env` fixture
where no compiler can see it, so the six test files and `.env.example` are grep
rows, not type rows. Separately: `tests/config/env.test.ts` falls under no
blueprint's `code:` globs (BP-005 globs `src/lib/config/**` and
`tests/pins.test.ts` only) — flagged to the architect, not repaired here.
