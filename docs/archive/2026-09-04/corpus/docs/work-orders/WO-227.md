# WO-227 — One mail per breakage — for the customer who has not signed in since it broke

- Branch: wo/WO-227-breakage-mail-occasion
- Estimate: ≤1 day

## Goal
Ship `breakageMailDue()`: the occasion for exactly one `account` mail per breakage, evaluated inside `draft/generate`'s existing per-site daily loop.

## File plan

> This repository carries no `src/`, no `tests/`, no `supabase/` and no
> `package.json` (verified 2026-08-31). **Every path below is NEW** — none was
> verified to exist, because none can. Placement is anchored to
> `sdlc-factory/docs/registry/structure.md` and to this work order's blueprint
> `code:` globs, and is provisional against a repo with no code: if the
> implementer finds a file already present at one of these paths, they stop and
> log `failed` naming the drift rather than merging into it.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/publish/destinations/health/breakage-mail.ts` | NEW | `breakageMailDue(siteId, now)`. Returns due at most once per breakage, on the conjunction BP-058 states: `health <> 'ok'` ∧ `now - health_changed_at ≥ 24 h` ∧ `broken_mail_sent_at is null` ∧ `lastSignInAt < health_changed_at`. Returns the destination id, the held count and the copy key `mail.account.destinationBroken` — the occasion and the payload, never a sentence. Marks `broken_mail_sent_at` when the caller reports the send. |
| `src/lib/publish/destinations/health/index.ts` | MODIFY | Re-export `breakageMailDue`. |
| `tests/publish/destinations/health/breakage-mail.test.ts` | NEW | Each of the four conjuncts falsified alone makes it not due; at 24 hours exactly it is due; a customer who signed in after the breakage is never mailed; a second evaluation on the following day is not due; reconnecting and breaking again makes it due once more; the payload carries a copy key and a count and no sentence. |

## Interfaces

**Consumes**

- `health_changed_at`, `broken_mail_sent_at`, `health` — WO-223.
- `heldPages(siteId)` — BP-045, WO-210.
- The moment the customer last signed in — BP-017, `src/lib/account/`. See `rests-on`.
- `sendEmail()` and `MAIL_KINDS` — BP-016. **Called by `draft/generate`, not by this module**: this module returns the occasion and the payload.
- `copy()` — BP-019, for the key `mail.account.destinationBroken`. The sentence is the owner's.

**Exposes** — copied exactly from BP-058's `## Public interface`:

```ts
/** REQ-074 c6's occasion; returns at most one per breakage. */
export function breakageMailDue(siteId: string, now: Date): Promise<
  { due: false } | { due: true; destinationId: string; held: number; copy: 'mail.account.destinationBroken' }
>
```

**The mail rides an existing job** (BP-058 decision 1). Criterion 6 needs an
occasion when the customer has *not* signed in, so a read cannot supply it;
`breakageMailDue` is evaluated inside `draft/generate`'s per-site daily
invocation — the same site loop that would otherwise be preparing the page that
is now being held. BP-003's kill switch stops `draft/generate`, so a breakage
mail can be delayed by a stop, during which REQ-092 already makes the product say
its work stopped.

Whether a mail may be sent at all is REQ-064 criterion 6's rule, not this work
order's; `account` is the registry kind this occasion carries.

## Steps
1. Create `health/breakage-mail.ts` with the four-conjunct predicate exactly as BP-058 states it.
2. Read the last sign-in moment through BP-017. If that read is not available when the implementer starts, they stop and log `failed — next: wait on BP-017's identity work order` — do not mint a column on the `users` topic, which is BP-017's under structure.md rule 3.
3. Return the copy key and the held count. Write no sentence.
4. Mark `broken_mail_sent_at` when the send is reported. WO-226 already clears it on every transition back to `ok`.
5. Write the "no further mail about that destination until it is reconnected and breaks again" test first and watch it fail against an implementation that re-evaluates daily without the guard (constitution §8).
