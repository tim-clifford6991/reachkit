# WO-063 — `GET /api/scan/{scanId}/progress` — the SSE transport over the stage stream

- Branch: wo/WO-063-progress-route
- Estimate: ≤1 day

## Goal
Serve BP-023's stage stream as server-sent events and nothing more — one thin
adapter that adds no stage, no estimate and no figure of its own, and that closes
after the one ending.

## File plan

> Every path below is **NEW**. Verified 2026-08-31: this repo carries no `src/`.
> Placement per `structure.md` (`src/app/api/**` is BP-001's container, rule 1:
> transport only; BP-022 anchors this route). Provisional against a repo with no
> code.

| File | New/Modify | Change |
|---|---|---|
| `src/app/api/scan/[scanId]/progress/route.ts` | NEW | The `GET` handler. Opens an SSE response over WO-060's `progress(scanId)`, serialising each `StageEvent` as one event, closing the stream after the `ending` event. Sets `Cache-Control: no-store` and `X-Robots-Tag: noindex`. Holds no timer, no stage list and no ending logic of its own. |
| `tests/app/scan-address/progress-route.test.ts` | NEW | The transport, heartbeat, termination and unknown-id suites named in the test plan. |

## Interfaces

Consumes: WO-060's `progress`, `StageEvent`, `STAGES`; WO-059's `Ending`.

Exposes (verbatim from BP-022 `## Public interface`):

```
Routes
  GET  /api/scan/{scanId}/progress          SSE; the stream is BP-023's `progress()`
```

## Steps
1. Write the failing suite first.
2. Implement the `GET` handler returning a streaming response with
   `text/event-stream`, `no-store` and `noindex`.
3. Serialise each `StageEvent` verbatim as the event payload — no renaming, no
   added field, no percentage.
4. Close the response after the single `ending` event and release the iterator.
5. Handle a disconnected client by cancelling the iterator: no background
   continuation for a visitor who closed the page (REQ-003's non-goal).
6. An unknown or malformed `scanId` responds 404 on this API route — the promise
   that a *report address* never 404s is REQ-001 criterion 5's and binds
   `/scan/{domain}`, not this transport path.

## Test plan

> Criteria are copied verbatim from `requirements/REQ-003.md`; line breaks are
> normalised to fit the table and no word is changed.

| Acceptance criterion (verbatim from REQ) | Test |
|---|---|
| REQ-003 c1 — "Given a scan is running — however it started … when the visitor watches the page, then it shows named stages that advance as work completes, never an unlabelled spinner or an indeterminate bar alone." | `progress-route/stream · every stage event reaches the client, in order` — driving a fixture scan through all six stages, the SSE body carries the same sequence of `StageEvent`s the iterable produced, in order, with no event added or dropped. |
| REQ-003 c1, "never an unlabelled spinner" | `progress-route/stream · heartbeats pass through unaltered` — a stalled stage produces `{heartbeat:true}` events on the wire at ≥30 s intervals, each asserted to carry no stage field, and the connection stays open across them. |
| REQ-003 c4 — "Given a scan that cannot complete at all, when it ends, then the visitor is told in one written line that the measurement failed and is offered a manual retry (the retry window is REQ-001's)." | `progress-route/stream · the ending is the last event and the stream closes` — for each `Ending` shape, the ending is serialised once, is last, and the response ends; the client observes end-of-stream rather than a hang. |
| REQ-003 c5 — "… No visitor waits on a running scan beyond 90 seconds." | `progress-route/stream · the response ends inside the ceiling` — a scan stopped at the time ceiling closes the SSE response within the ceiling, asserted against a frozen clock. |
| REQ-003's non-goal — "No background continuation for a visitor who closes the page mid-scan." | `progress-route/stream · a disconnect cancels the iterator` — aborting the request cancels the underlying iterable, asserted by spy on its `return`. |
| REQ-003's non-goal — "No spend, cost or cap figure shown to a visitor." | `progress-route/stream · nothing is added on the wire` — every serialised event is asserted equal to the event the iterable produced; a source assertion that `route.ts` contains no percentage, ETA, cents or cap identifier. |
