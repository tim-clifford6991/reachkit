# WO-170 — The autosave: last write wins, the badge drops, and no unchecked text publishes

- Branch: wo/WO-170-draft-autosave
- Estimate: ≤1 day

## Goal
Accept `PATCH /api/drafts/{id}` as the draft's only text write — last write
wins, the grounded fact re-tested against the saved text, the claim outcome
cleared to outstanding, and `claim_checked_body_hash` cleared so unchecked text
cannot publish.

export interface SaveBody { bodyMd: string }

## Steps
1. Write the failing tests first (§8).
2. Implement the save as last-write-wins: no merge, no conflict prompt, no
   version list (REQ-045's non-goals exclude all three).
3. Recompute `grounded.present` by testing the recorded verbatim passage against
   the saved text. Never rewrite the fact to match the edit.
4. On every successful save, set `claim: { state: 'outstanding' }` and clear
   `claim_checked_body_hash`, so no claim-check outcome is shown for that draft
   until a check completes against the text as saved.
5. Enqueue one claim re-check per save that changed the text, debounced so a
   burst of saves produces one check, never one per save.
6. Treat `store_unavailable` as a **retryable refusal** — never a redirect — so
   the client keeps the buffer and retries on the next tick.
7. Assert the server-observable predicate for criterion 10:
   `hash(body_md) != claim_checked_body_hash` is what BP-015 reads as
   `claim_recheck`; nothing in this WO releases a page earlier.
8. Mutation check: leave `claim_checked_body_hash` untouched on save and confirm
   the unchecked-text test fails.
