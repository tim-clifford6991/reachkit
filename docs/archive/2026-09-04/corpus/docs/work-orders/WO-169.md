# WO-169 — The draft read: every word, its grounding, its claim outcome, and what happens if you do nothing

- Branch: wo/WO-169-draft-read
- Estimate: ≤1 day

## Goal
Assemble `DraftView` — the full body, the two-state authorship label, the
grounded fact with its URL and read date, the claim state in every case
including the empty list, and the do-nothing outcome from
`becomesPublishable`.

## Interfaces

Exposes (verbatim from BP-044 `## Public interface`):
```ts
export type ClaimState =
  | { state: 'passed'; at: Date }
  | { state: 'failed'; matchedEntry: string; at: Date }      // criterion 11
  | { state: 'outstanding' }                                 // criterion 9 — nothing shown yet
  | { state: 'nothing_to_check' }                            // criterion 3 — empty list

/** Criterion 1 and REQ-093 criterion 2: what ReachKit wrote is labelled as this
 *  page's generated content, and the label never presents the customer's own
 *  words as text ReachKit generated. Two states, page-level (decision 1). */
export type Authorship = { edited: false } | { edited: true; firstEditedAt: Date }

export interface DraftView {
  draftId: string
  title: string
  bodyMd: string                                             // every word that would publish
  authorship: Authorship
  grounded: { fact: string; url: string; readAt: Date; present: boolean }  // criteria 2 and 8
  claim: ClaimState
  doNothing: { key: CopyKey; publishesAt: Date | null }      // criterion 4, from becomesPublishable
  lastSavedAt: Date | null
}
export function readDraft(draftId: string): Promise<DraftView>
```

## Steps
1. Write the failing tests first (§8, "Watch it fail first").
2. Return `bodyMd` in full — assert in test that the returned body equals the
   stored body byte for byte, so no truncation can be introduced later.
3. Read the grounded fact with `url` and `readAt`, and `present` as last
   recomputed by the save path (WO-170); never rewrite the fact to match an edit.
4. Return `nothing_to_check` where the do-not-claim list is empty, `outstanding`
   where `claim_checked_body_hash` does not match the current body's hash,
   `failed` with its `matchedEntry`, and `passed` otherwise.
5. Take `doNothing` from `becomesPublishable` only; compute no schedule here.
6. Refuse a draft the customer does not own, and an id that does not exist, with
   one written line — never a stack trace or a vendor payload.
7. Mutation check: return a summarised body and confirm the full-body test
   fails; return `passed` for an empty list and confirm the
   `nothing_to_check` test fails.
