# WO-172 — The draft read view: the whole page, its grounding, its claim badge, and what happens if you do nothing

- Branch: wo/WO-172-draft-read-view
- Estimate: ≤1 day
- Preview: sdlc-factory/docs/design/previews/WO-172.html
- Signed-off: <date>

## Goal
Render every word that would publish, the grounded fact marked in the text with
its source line, the claim outcome in every case, the generated-content label,
and the do-nothing box with approve, edit and veto available without leaving the
view.

## File plan
> Every path below is **NEW** (no `src/` on disk, checked 2026-08-31). Placement
> follows `structure.md` and BP-044's `code:` globs; provisional.

| File | New/Modify | Change |
|---|---|---|
| `src/app/(account)/app/draft/[draftId]/page.tsx` | NEW | Server component: reads `readDraft`, renders the full body, the authorship label through BP-019's `generatedLabel`, the grounded-fact mark with its URL and read date, the claim badge for all four states, and the do-nothing box. |
| `src/app/(account)/app/draft/[draftId]/DraftRead.tsx` | NEW | The read surface: the marked grounded passage, the claim badge, and the action row — approve and veto post to the publishing node's routes and this view re-reads; which are offered follows the same projection from BP-015's `TRANSITIONS` that BP-039 decision 2 describes, so the two surfaces cannot offer different actions for one state. |
| `tests/app/draft/read-view.test.tsx` | NEW | Full body, the label in both states, the grounding line, the four claim states, the do-nothing box, the offered actions. |

## Interfaces
Consumes (verbatim from BP-044 `## Public interface`):
```ts
export interface DraftView {
  draftId: string
  title: string
  bodyMd: string                                             // every word that would publish
  authorship: Authorship
  grounded: { fact: string; url: string; readAt: Date; present: boolean }  // criteria 2 and 8
  claim: ClaimState
  doNothing: { key: CopyKey; publishesAt: Date | null }      // criterion 4, from becomesPublishable
  lastSavedAt: Date | null
}
export function readDraft(draftId: string): Promise<DraftView>
```
and `generatedLabel()` / `copy()` (BP-019), the registered component set
(BP-018), `TRANSITIONS` (BP-015/BP-045) for the action projection.

Exposes: the `/app/draft/{id}` route. No new engine interface.

## Steps
1. **Precondition (rule 7.3):** signed preview. As of 2026-08-31
   `sdlc-factory/docs/design/tokens.md` is `Status: ready` and `components.md`
   registers 24 components, every row `proposed` and reaching `approved` only
   when a preview carrying it is signed off. The claim badge, the generated-
   content label and the source chip are all `Badge`, each with its required
   text child (`components.md` §4, "not gaps"); this WO mints no component.
2. Write the failing tests first (§8).
3. Render `bodyMd` in full: no truncation, no "show more" on the body.
4. Mark the grounded passage inside the text and render its URL and read date
   beside it; where `present` is false, the mark is absent — the fact is not
   rewritten to fit.
5. Render the claim badge for `passed`, `failed` (naming the matched entry),
   `outstanding` (no outcome shown) and `nothing_to_check`.
6. Render the authorship label from `Authorship` — two states, page-level; it
   never presents the customer's own words as text ReachKit generated.
7. Render the do-nothing box from `doNothing`, and the approve / edit / veto
   controls from the transition projection, all without leaving the view.
8. Mutation check: truncate the body at a character budget and confirm the
   full-body test fails; render `passed` while `claim` is `outstanding` and
   confirm the badge test fails.
