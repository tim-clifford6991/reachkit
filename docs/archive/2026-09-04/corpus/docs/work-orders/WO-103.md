# WO-103 — The branded shell, its plain-text twin, and composeMail()

- Branch: wo/WO-103-mail-shell-compose
- Estimate: ≤1 day
- Preview: sdlc-factory/docs/design/previews/WO-103.html
- Signed-off: (pending — design-guardian)

## Goal
Assemble one branded frame and one plain-text frame around a rendered block list,
choose the one whole-mail line a mail with nothing left to say carries, and
return both bodies plus the omitted indexes from a single `composeMail()` call.

## Provisional against an empty repo
**No `src/` exists.** All files NEW, inside BP-053's `src/lib/mail/shell/**`
glob (ADR-040 point 3: "the shell, the block model and its renderer, the register
itself, the send seam and the vendor call — is BP-053's").

**Placement choice (rule 1.1).** BP-053's `## Public interface` prints
`composeMail` under the comment header `// src/lib/mail/blocks/types.ts`. This WO
places it at `src/lib/mail/shell/compose.ts` instead. Derivation: ADR-040 point 3
names the shell as the thing that frames every mail, `composeMail` is the
shell-plus-blocks assembly, and a `types.ts` that exports a function is a file
whose name lies. Both paths are inside BP-053's own `code:` globs, so no owner
changes. Cost of reversing: one file move and one import edit; no behaviour, no
schema, no interface change. Flagged, not asked (rule 1.1). `MeasurementState`
follows the function on the same ground (2026-09-03): it is `composeMail`'s
parameter type and nothing a template speaks, so it is declared in `compose.ts`
beside the function; WO-101's `types.ts` stays "the only vocabulary a template
may speak". Same reversal cost.

**Hold released 2026-09-03.** The `MeasurementState` behaviour — the
nothing-to-report notice and its two exceptions — was held from 2026-08-31 on
REQ-064's third `REVIEW` line. That line is closed: REQ-064's `## Open questions`
is empty, and BP-053's discharge section names the history file
(`requirements/history/REQ-029-041-060-064-071-2026-09-01-review-lines-closed.md`,
whose item 3 finds criterion 3 "already excepts" the double line the review
feared). BP-053 decision 2 and the `composeMail` signature this order transcribes
say the same thing — `measurement` "required for 'weekly', rejected for every
other kind" is the signature's own comment — so no blueprint conflict is raised;
the one residual is the `rests-on` row on how the type-level half is expressed.
The rows land here because the line is a whole-mail decision made after every
block has rendered, which is the shell's, not a block renderer's.

Reuse check (rule 7.2): `registry/capabilities.md` gives `composeMail()` to
BP-053 and nothing else. No shell exists.

## Interfaces
**Exposes** (verbatim from BP-053 `## Public interface`):
```ts
/** Every value that can be absent enters as a Measured<T>. A template holds no
 *  conditional and cannot format a number itself, so no template can forget
 *  criterion 1. */
export function composeMail(m: {
  kind: MailKind
  subject: CopyKey
  blocks: readonly MailBlock[]
  optOut?: { href: string }            // BP-029's lead mail; BP-059's toggle mail
  measurement?: MeasurementState       // required for 'weekly', rejected for every other kind
}): { html: string; text: string; omitted: readonly number[] }

export type MeasurementState =
  | { state: 'complete' }
  | { state: 'partial'; unmeasured: readonly CopyKey[] }   // REQ-065 c4 → criterion 1's line
  | { state: 'none'; nextDueOn: Date }                     // REQ-065 c3 → its own line
```
**Consumes**: `MailBlock`, `renderBlocksHtml`, `renderBlocksText`,
`omittedIndexes` (WO-101, WO-102); `MailKind` (WO-104); `copy()` (BP-019);
`src/ui/theme.css` tokens (BP-018).

## Steps
1. Write all three tests first and watch them fail.
2. `frame.ts` and `text-frame.ts`, section-for-section identical in structure,
   the whole-mail line slot included.
3. `compose.ts`: assemble, return, no branching on kind beyond the type-level
   `measurement` requirement.
4. The whole-mail line, chosen from the union and the omitted/empty count and
   never from a flag (BP-053 decision 2's rejected alternative).
5. Mutation check: delete the text-frame call and confirm `compose.test.ts`
   fails; delete the `'partial'` branch and confirm the criterion 1 case fails;
   delete the nothing-to-report branch and confirm the empty-mail case fails.
