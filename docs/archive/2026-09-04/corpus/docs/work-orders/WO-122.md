# WO-122 — admitSiteAddress and setSiteDomain — reaching means resolving in DNS, and nothing more

- Branch: wo/WO-122-admit-site-address
- Estimate: ≤1 day

## Goal
Admit or refuse the address the account's site will use — on a DNS test and no
other — and make the one write that fixes it.

## File plan
> **Every path below is NEW.** No `src/` exists. Anchored to
> `registry/structure.md` and BP-031's `code:` glob `src/lib/account/offer/**`.
> Provisional against a repo with no code.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/account/offer/normalise.ts` | NEW | Exports `normaliseDomain(input: string)`, which strips scheme, path, port, userinfo and a leading `www.`, lowercases and IDNA-encodes, and fails `not_a_domain` for `localhost`, a bare IPv4 or IPv6 literal, and any label without a public suffix — **before any DNS lookup** (BP-031: "an unresolvable-by-construction address must never reach it"). |
| `src/lib/account/offer/admit.ts` | NEW | Exports `admitSiteAddress` with BP-031's signature verbatim. Normalises, then calls BP-006's `resolvesInDns()` **and no other check** — no HTTP fetch, no status-code test, no content test, no robots read (BP-031 decision 2). A DNS error retries once; a second failure returns `does_not_resolve` with `lineKey: 'setup.domain.unreachable'`. Hard ceiling 4 s. |
| `src/lib/account/offer/set-domain.ts` | NEW | Exports `setSiteDomain` with BP-031's signature verbatim. Re-admits the domain (never trusts a caller's admission), then writes `sites.domain` and stamps `sites.domain_set_at = now()` in one statement, returning `measurementReset: true` when the domain differs from the previous value. Idempotent per site: setting the same domain twice does not re-stamp `domain_set_at` and returns `measurementReset: false`. Deletes no `scans` row and touches no other column. |
| `tests/account/offer/admit.test.ts` | NEW | Normalisation cases (scheme, path, port, userinfo, `www.`, uppercase, IDN); the `not_a_domain` set (`localhost`, `127.0.0.1`, `::1`, `example`, an empty string); the DNS branch with a stubbed `resolvesInDns` (true, false, error-then-true, error-then-error); the ceiling. **The discriminating test for BP-031 decision 2:** a domain that resolves but returns 404, 503 and an empty body on HTTP is admitted in all three cases — this fails the moment somebody adds a liveness check. |
| `tests/account/offer/set-domain.test.ts` | NEW | The write, the re-stamp rule, `measurementReset` both ways, idempotency, the refusal path, and a column-set assertion that nothing but `domain` and `domain_set_at` changed. Plus: a `scans` row for the replaced domain still exists afterwards. |
| `tests/account/offer/no-setup-gate.test.ts` | NEW | REQ-021 c10's structural half: a source-level assertion that `src/lib/account/offer/**` exports no function whose name or return type expresses setup completion, and that no exported function of this module is imported by `src/lib/account/billing/**`, `src/lib/account/export/**` or `src/lib/account/lifecycle/**` — the three modules behind Settings, cancellation and export. BP-031: "this node exposes no gate that Settings, cancellation or export consult". |

## Interfaces
Consumes (verbatim from BP-006's `## Public interface`):
```ts
export function resolvesInDns(host: string): Promise<boolean>
```
Exposes (verbatim from BP-031's `## Public interface`):
```ts
export function admitSiteAddress(input: string): Promise<
  | { ok: true; domain: string }                                  // registrable, lowercased, no scheme/path
  | { ok: false; reason: 'not_a_domain' | 'does_not_resolve'; lineKey: 'setup.domain.unreachable' }
>

export function setSiteDomain(siteId: string, domain: string):
  Promise<{ ok: true; domain: string; measurementReset: boolean }
        | { ok: false; reason: 'does_not_resolve' | 'not_admitted' }>
```
