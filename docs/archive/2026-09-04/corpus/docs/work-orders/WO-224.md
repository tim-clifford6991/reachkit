# WO-224 — The sealed credential — encrypted at rest, plaintext for one call, destroyed on disconnect

- Branch: wo/WO-224-destination-config-seal
- Estimate: ≤1 day

## Goal
Ship `withConfig()`: the only place a destination credential is ever in plaintext, for the duration of one call, returning nothing that outlives it — and the destruction path that nulls the ciphertext.

## File plan

> This repository carries no `src/`, no `tests/`, no `supabase/` and no
> `package.json` (verified 2026-08-31). **Every path below is NEW** — none was
> verified to exist, because none can. Placement is anchored to
> `sdlc-factory/docs/registry/structure.md` and to this work order's blueprint
> `code:` globs, and is provisional against a repo with no code: if the
> implementer finds a file already present at one of these paths, they stop and
> log `failed` naming the drift rather than merging into it.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/publish/destinations/config/seal.ts` | NEW | Authenticated symmetric encryption with a key from BP-005's `env`. `seal(cfg)` and the internal `unseal(ciphertext)`. The ciphertext never leaves the database except into `withConfig`'s callback. |
| `src/lib/publish/destinations/config/index.ts` | NEW | `withConfig<T, R>(destinationId, fn)`. Reads the row, decrypts, invokes `fn(cfg)`, and returns **the callback's value, never the config**. No read path used by any surface returns the config, and the `select` list for `DestinationView` does not include it. Also `destroyConfig(destinationId)` — overwrite `config` with null in the same transaction that sets `deleted_at`. |
| `tests/publish/destinations/config/seal.test.ts` | NEW | A sealed config round-trips; the stored value is not the plaintext; `withConfig` returns the callback's value and never the config; a callback that tries to return the config is a type error; `destroyConfig` nulls the ciphertext and leaves the row; **no log line, error message, thrown stack or serialised value anywhere in this module contains any part of the credential**, asserted by seeding a recognisable token and grepping every emitted string. |

## Interfaces

**Consumes**

- `env` (the encryption key binding) — BP-005, `src/lib/config/env.ts`.
- `db()` / `dbAdmin()` under RLS — BP-002.
- The `config` and `deleted_at` columns — WO-223.

**Exposes** — copied exactly from BP-058's `## Public interface`:

```ts
// src/lib/publish/destinations/config/
/** Decrypts for the duration of one call and returns nothing that outlives it. */
export function withConfig<T, R>(destinationId: string, fn: (cfg: T) => Promise<R>): Promise<R>
```

`destroyConfig` is internal to this module and is called by `disconnect`
(WO-225); it is not part of BP-058's published surface. Splitting it out here is
a file-plan choice (rule 1.1) so that "the only place a credential is in
plaintext" is one directory rather than a convention. Cost of reversing: move one
function.

## Steps
1. Create `config/seal.ts` with authenticated symmetric encryption keyed from BP-005's `env`. If the binding is absent when the implementer starts, they stop and log `failed — next: wait on BP-005's env work order`.
2. Create `config/index.ts` with `withConfig` typed so the callback's return type is unrelated to the config type — a callback that returns the config must not type-check.
3. Implement `destroyConfig` as one statement that nulls the ciphertext and sets `deleted_at` together.
4. Write the credential-leak test first — seed a recognisable token as the application password, exercise every path in this module, and assert the token appears in no emitted string. Watch it fail against an implementation that logs the row (constitution §8).
