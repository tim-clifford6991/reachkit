# WO-015 — Job definitions — scan/run and weekly/refresh

- Branch: wo/WO-015-scan-jobs
- Estimate: ≤1 day

## Goal
Register the two scan-triggering jobs with their triggers, concurrency,
idempotency keys and kill-switch guards — each a trigger, a bounded loop and one
call into the engine, and nothing more.

## Provenance of this file plan
**This repository holds no `src/`.** Every path is NEW under BP-003's `code:`
glob `src/jobs/**`.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/jobs/scan-run.ts` | NEW | Trigger: on demand. Tier is a parameter (`free` \| `deep` \| `weekly`). Kill-switch guarded (in scope). Calls `runScan()` once and records the outcome. Holds no scan logic. |
| `src/jobs/weekly-refresh.ts` | NEW | **Hourly tick**, due-ness computed per site's own local Monday and local hour from `WEEKLY_DUE_HOUR_LOCAL` — never `Mon 06:00 UTC`. Idempotency key `(site_id, week_start)`; the enforcing `unique (site_id, week_start) where tier = 'weekly'` belongs to BP-050's migration and is consumed, not written here. Fixed fan-out concurrency so a slow site never starves the rest of Monday. |
| `src/jobs/index.ts` | MODIFY | Appends the two definitions to `jobs`. |
| `tests/jobs/scan-run.test.ts` | NEW | The tests below. |
| `tests/jobs/weekly-refresh.test.ts` | NEW | The tests below. |

## Interfaces
Consumes (verbatim from BP-012's row in `registry/capabilities.md`, which is
"the blueprint's `## Public interface` verbatim"):
```
`runScan()` · `admitFreeScan()` · `readCurrentReport()`
```
Consumes (verbatim from BP-003 `## Public interface`): `killSwitchEngaged()`.
Consumes (BP-005 `constants.ts`): `WEEKLY_DUE_HOUR_LOCAL`, `WEEK_START`, `CAPS`.
Exposes: two `JobDefinition` values, registered in `jobs`.

## Steps
1. Write `scan-run.ts` with the kill-switch guard before any call.
2. Write `weekly-refresh.ts` with the hourly tick and site-local due-ness.
3. Register both.
4. Write the tests with `runScan()` doubled; watch the "not `Mon 06:00 UTC`" test
   fail first by scheduling on a UTC hour.

## Test plan
> **Criterion source: the blueprint, not a requirement.** BP-003 carries
> `satisfies: []`. REQ-065 criterion 1 (every active site re-measured inside the
> customer's own Monday) is the requirement-side promise; the engine half is
> BP-050's. Cited, not inherited.

| Acceptance criterion (source quoted) | Test |
|---|---|
| BP-003 NFR budget: "**The tick is hourly and due-ness is per site's own local Monday and local hour — `Mon 06:00 UTC` is not the trigger**" | `tests/jobs/weekly-refresh.test.ts` — a site at UTC−7 is due on its own Monday 06:00 local and not on 06:00 UTC. Scheduling on a UTC hour fails it. ADR-060 is cited, not restated. |
| BP-003 error behaviour: "Every job is idempotent by a natural key stated in its own feature node — … `(site_id, week_start)` for the weekly refresh" | Same file — two deliveries for one `(site_id, week_start)` produce one run. |
| BP-003 error behaviour: "No job fans out across customers inside one invocation past a fixed concurrency; a slow site never starves the rest of Monday." | Same file — asserts a fixed concurrency bound and that one slow site does not delay the rest past it. |
| BP-003 responsibility: "each job is a trigger, a bounded loop and one call into the engine" | `tests/jobs/scan-run.test.ts` — parses both files and asserts each imports exactly one engine module and calls one exported function from it. |
| BP-003 error behaviour: "A job that exceeds its own budget stops and marks its subject `degraded` rather than throwing" | `tests/jobs/scan-run.test.ts` — a doubled `runScan()` that exceeds budget yields a `degraded` outcome and no thrown error. |
