# WO-139 — exportEverything — complete or nothing, and never a check on whether they still pay

- Branch: wo/WO-139-export-everything
- Estimate: ≤1 day

## Goal
Stream a complete archive of every page ReachKit wrote for a site, decided
complete before the first byte leaves, to an active, cancelled or lapsed customer
alike — and make the absence of the access check enforceable rather than
remembered.

## File plan
> **Every path below is NEW.** No `src/` exists. Anchored to
> `registry/structure.md` and BP-062's `code:` glob `src/lib/account/export/**`.
> Provisional against a repo with no code.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/account/export/archive.ts` | NEW | Exports `exportEverything(siteId)` and `ExportFailure` with BP-062's signatures verbatim. **Resolves the manifest, every page body and every asset byte before the first byte of the zip reaches the response** (decision 2); only then streams. A failure before streaming returns `{ ok: false, reason, lineKey: 'export.failed' }`; a failure during streaming aborts the HTTP response without a zip trailer, so the client sees a broken download rather than a short archive presented as complete. A page whose asset cannot be read fails the **whole** export (`asset_unreadable`) — skipping it is exactly the partial archive c5 forbids. Past 120 s the export fails with `timeout` rather than trickling. Asset bytes are streamed through and never buffered whole; peak heap ≤ 64 MB regardless of site size. |
| `src/lib/account/export/frontmatter.ts` | NEW | Writes each file's front-matter: title, state, publish date, live URL and take-down date, with explicit nulls where they do not apply. **File bodies are the stored `body_md` verbatim** — nothing is regenerated, re-rendered or model-touched at export time; a copy that differs from what was published is a defect. |
| `tests/account/export/archive.test.ts` | NEW | Every page in all four states appears as a Markdown file with its assets; a site with zero pages yields an archive containing the manifest and no page files; an unreadable asset fails the whole export and the retry returns `ok: false` again; a timeout returns `timeout` and no archive; a failure during streaming yields no valid zip trailer; bodies are byte-identical to `body_md`; time to first byte ≤ 10 s for a 500-page fixture. |
| `tests/account/export/frontmatter.test.ts` | NEW | The five fields per file; a never-published page carries explicit nulls; nothing in a file body was re-rendered. |
| `tests/account/export/no-access-gate.test.ts` | NEW | BP-062 decision 1, made enforceable two ways: (a) a source-level assertion that no file under `src/lib/account/export/**` imports from `src/lib/account/billing/**`, the message naming REQ-078 c2; (b) a behavioural case — a site whose `paid_through` is in the past exports a **complete** archive. The mutation case: adding an `hasActiveAccess` call fails (a). **The lint half of the same rule is not written here.** BP-001 decision 2 (2026-08-31) adds BP-062's rule verbatim to `eslint.config.mjs`, which is BP-001's file and another planner's work order; case (a) above is this node's own copy of the check and stays, because a lint config can be skipped in a worktree and case (b) is behavioural anyway (rule 3.3: a refusal blocks only where something enforces it). |

## Interfaces
Exposes (verbatim from BP-062's `## Public interface`):
```ts
export function exportEverything(siteId: string): Promise<
  | { ok: true; archive: ReadableStream<Uint8Array>; filename: string; pages: number }
  | { ok: false; reason: ExportFailure; lineKey: 'export.failed' }
>
export type ExportFailure = 'asset_unreadable' | 'record_unreadable' | 'timeout' | 'internal'
```
Consumes: `buildManifest(siteId)` (WO-138); `currentSession()` (BP-061) at the
route, which is BP-001's; `db()` (BP-002).

Does **not** consume `hasActiveAccess` — BP-062: "**This node never consults
BP-060's access gate** — that is the whole of REQ-078 criterion 2 and there is a
test that asserts the import does not exist."

## Steps
1. Write `tests/account/export/no-access-gate.test.ts` first and watch both halves
   fail.
2. Write `frontmatter.ts`.
3. Write `archive.ts` with resolve-then-stream ordering.
4. Add the failure cases: unreadable asset, timeout, mid-stream abort.
5. Run the mutation check on the import assertion.
