# WO-167 — The month grid and its stage filter

- Branch: wo/WO-167-calendar-grid
- Estimate: ≤1 day
- Preview: sdlc-factory/docs/design/previews/WO-167.html
- Signed-off: <date>

## Goal
Render the month as BP-018's `CalendarGrid` — one page or one written line per
date, its stage where there is a page — with a stage filter that narrows the
view and shows each stage's count.

## File plan
> Every path below is **NEW** (no `src/` on disk, checked 2026-08-31). Placement
> follows `structure.md` and BP-039's `code:` globs; provisional.

| File | New/Modify | Change |
|---|---|---|
| `src/app/(account)/app/calendar/page.tsx` | NEW | Server component: reads `readMonth` for the site-local month, renders the grid and the filter, and selects today on open. |
| `src/app/(account)/app/calendar/MonthGrid.tsx` | NEW | Renders BP-018's `CalendarGrid`: each cell carries either the page with its stage chip or the one written line from its `EmptyAccount`. Weekends are ordinary dates and nothing filters them. Passes data, not CSS. |
| `src/app/(account)/app/calendar/StageFilter.tsx` | NEW | The All-plus-five filter, each with its count from the same `readMonth` result; selecting one narrows the grid. |
| `tests/app/calendar/grid.test.tsx` | NEW | One page or one line per cell, the stage chip, weekends, filter narrowing and counts. |

## Interfaces
Consumes (verbatim from BP-039 `## Public interface`):
```ts
export interface DayCell {
  date: Date                                                          // site-local day
  page: { draftId: string; title: string; stage: Stage } | null
  empty: EmptyAccount | null                                          // exactly one of page / empty
}
export function readMonth(a: { siteId: string; month: string /* YYYY-MM, site-local */ }):
  Promise<{ days: readonly DayCell[]; counts: Readonly<Record<Stage | 'all', number>> }>
```
and `CalendarGrid` (BP-018 — `repeat(7, minmax(0, 1fr))`), `copy()` and
`stoppedWorkStatement` (BP-019).

Exposes: the `/app/calendar` route. No new engine interface.

## Steps
1. **Precondition (rule 7.3):** signed preview. As of 2026-08-31
   `docs/design/tokens.md` is `Status: ready` and `components.md` registers 24
   components including `CalendarGrid` — every row `proposed`, reaching
   `approved` only when a preview carrying it is signed off. Its registered
   contract already carries this grid's two hard rules: `label` is required, so
   "a day can never render as a coloured cell alone", and it "performs no
   padding" — an empty day is an absent entry this WO decides about, never a
   padded placeholder.
2. Write the failing tests first.
3. Render each cell from `DayCell`: a page with its stage chip, or the one
   written line for its `EmptyAccount` — never both and never neither.
4. Render the filter with counts taken from the same `readMonth` result, so the
   filter can never disagree with the grid.
5. Never render a cell with a page and no stage.
6. Mutation check: render a second page on a date and confirm the one-page test
   fails; render the exhausted-supply line for an `unattributed` account and
   confirm the ADR-061 guard test fails.

## Test plan
| Acceptance criterion (verbatim from REQ-043) | Test |
|---|---|
| 1. Given a month view, when it renders, then every date it shows that is today or later carries a page while any opportunity a page can be written from remains that no page has yet been created from — a date is left empty only where that supply is exhausted, never because the day was not reached for; no date carries more than one page; any day of the week may carry one, weekends included; and no page is created to occupy a date that no such opportunity backs. | `tests/app/calendar/grid.test.tsx › every future date renders a page while supply remains, weekends included`, `(same file) › no cell renders two pages`, `(same file) › the grid render creates nothing` |
| 2. Given a date carrying a page, when it renders, then it states which stage that page is in — Live, Your review, Scheduled, Planned or Needs you — and no page renders without a stage. | `tests/app/calendar/grid.test.tsx › every rendered page carries its stage chip, and a page without a stage cannot be rendered` |
| 6. Given pages spread across several stages, when the customer selects a stage, then the view narrows to that stage, and every stage shows how many items it holds. | `tests/app/calendar/grid.test.tsx › selecting a stage narrows the grid to it`, `(same file) › All and each of the five stages render a count drawn from the same read as the grid` |

Additional discriminating test: `tests/app/calendar/grid.test.tsx › an
unattributed empty date renders the stopped-work line and never the
exhausted-supply line` (ADR-061).
