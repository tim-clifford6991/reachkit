## Goal
Judge one site's week once, idempotently, from that week's measurement alone — and expose the week's standings to a surface and to the weekly mail without ever recomputing a verdict.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/lib/opportunities/verdicts/judge.ts` | NEW | `judgeWeek({ siteId, week })`. **The first thing it does for each publication is ask whether a `not_judgeable` row already exists for it, and short-circuit** — same cause, same `lastJudgedWeek`, before any evaluation whatever (ADR-072 Decision 5, 5c). Then: BP-050's account for the week — `not_measured` writes **no rows at all** and every page's standing is `no_week`; a partial week judges each page whose recorded test `evaluateAcceptance` can decide from what that week did measure and leaves every other page `not_measured` with no row. This function supplies the three causes `evaluateAcceptance` cannot: `unpublished` from the publication's state (REQ-056 c7, itself a terminal state), `domain_changed` by comparing `WeekMeasurements.domain` with the publication's own, and `page_not_found` **read from BP-049's stored `VerifyOutcome` and from nothing else** — it makes no request of any kind (ADR-072 Decision 5a, ADR-085). For each judged page it composes the verdict (WO-204), the movement (WO-204) and `verifyNote`, and inserts one row. `verifyNote` is composed by destructuring the stored outcome: `found` with one or more failed checks gives `{ note: 'checks_failed', failed, checkedAt }`; `could_not_confirm` gives `{ note: 'could_not_confirm', checkedAt }` **and the page is judged this week and every week exactly as though the check had passed**; `page_not_found` gives no note at all, because it is a cause and the page carries `not_judgeable` instead. Idempotent per `(site_id, week)` on WO-203's unique key: a re-run inserts nothing further and mints no second verdict. |
| `tests/opportunities/verdicts/terminal.test.ts` | NEW | **The ADR-072 pin, and the test that has to exist before somebody files the bug report.** A page marked `not_judgeable` in week 1 for `search_untracked` reads `not_judgeable` in weeks 2 through 12 with the **same cause and the same `lastJudgedWeek`**, while that search is back in the tracked set from week 2 and the page is live throughout — the exact fixture ADR-072's warning block describes, asserted as correct behaviour and not as a defect. The same for `question_left_set` with the question rejoining the set, and for `unpublished`, `page_not_found` and `domain_changed`. One further case: the short-circuit runs **before** evaluation, asserted by a fixture whose week's measurements would decide the test — the row is still `not_judgeable`, so a later re-ordering that evaluates first and checks the row second fails here rather than in production. And a source-level assertion that no file under `src/lib/opportunities/verdicts/**` writes to a column named `is_judgeable` or clears a cause: ADR-072 Decision 5c's whole content is that no such writer exists. |
| `src/lib/opportunities/verdicts/read.ts` | NEW | `readWeek({ siteId, week })` — one indexed read on `(site_id, week_start)`, scoped to that week alone, returning a `WeekStanding` per publication and recomputing no verdict. `weeklyDigest({ siteId, week })` returns the same standings plus `weekMeasuredAt` for BP-016's mail. Neither writes anything; a week with no rows returns `no_week` or `not_measured` standings from the account, never an earlier week's verdict. |
| `tests/opportunities/verdicts/judge.test.ts` | NEW | An unmeasured week writes zero rows and every page reads `no_week`; a partial week judges the decidable pages and leaves the rest `not_measured` with no row; a re-run of the same week inserts nothing; **a WordPress page is judged exactly as a hosted one is, from the same `servesPublicly` rule and with no destination-kind test anywhere in the module** (ADR-084); a page with no publication row gets no standing, by the absence of the row and not by a rule; two sites in different time zones judged in one run carry `week_start` values a day apart; and — the two fixtures that carry ADR-085's whole cost — **a page whose stored outcome is `could_not_confirm` receives an ordinary verdict with `verifyNote` beside it, identical in every other respect to a page whose check passed**, while **a page whose stored outcome is `page_not_found` receives `not_judgeable` with that cause and no `verifyNote` at all**. Two fixtures differing only in the stored outcome, asserted to go opposite ways. |
| `tests/opportunities/verdicts/no-look.test.ts` | NEW | A source-level assertion that no file under `src/lib/opportunities/verdicts/**` imports BP-006's `safeFetch`, `fetch`, or any module under `src/lib/egress/**`, and that `judgeWeek` completes against a fixture whose network is stubbed to throw on any call. REQ-063's non-goal — "Any look at a published page's address" — and ADR-072's second `rests-on` row, which is what makes the terminality of `page_not_found` safe rather than merely stated. The failure message names the non-goal in the requirement's own words. |
| `tests/opportunities/verdicts/read.test.ts` | NEW | A read for a week with no rows never returns a neighbouring week's verdict; a page that received a verdict in week 1 and became unjudgeable in week 3 reads `lastJudgedWeek` as week 1; a page that never received one reads null; the digest carries `weekMeasuredAt` and the same standings the surface reads; the digest carries `verifyNote` on the standings that have one, so BP-016's mail renders it beside the verdict and never in place of one; a site whose access ended is judged for no new week while every verdict already recorded stays readable with the date it was taken. |

## Steps
1. Write both test files first and run them; both must fail on a missing module.
2. Implement `judge.ts`. **Write the terminality short-circuit first, before any other line of it**: for each publication, one indexed read for an existing `not_judgeable` row, and where there is one, emit the same cause and the same `lastJudgedWeek` and evaluate nothing. Writing it later means writing an evaluation path that has to be un-run. Then read the scan for the named week and no other — a verdict is a fact about the week it was taken, and reading any other measurement is what REQ-063's first non-goal forbids.
2a. **Do not write a lift condition for any cause, and do not write the code that judges a page again once its search comes back into the tracked set.** It will present as a bug report — the page is live, the search is back, the customer is paying, and the screen says no longer judgeable — and it is forbidden in REQ-063 criterion 6's own terms. REQ-063 criterion 7, the resumption path, was withdrawn outright on 2026-09-01 and its number was not reused, so a citation to it dangles rather than pointing at a softer promise. Read ADR-072 before touching this file.
3. Write `no_week` and `not_measured` as returned shapes only. ADR-071 point 2: they are represented by the absence of a row, so a transient miss cannot be written down as a permanent state, because there is nowhere to write it.
4. Return `no_week` per page for uniformity of type, and record in the module's header comment that it is a property of the week, not of the page — BP-019 and BP-016 must render it once per week, never once per page (ADR-071 point 3).
5. Compose `verifyNote` by **destructuring the stored `VerifyOutcome`**, never by testing a boolean or a date. `found` with failed checks → `checks_failed` with the ids and `checkedAt`; `could_not_confirm` → `could_not_confirm` with `checkedAt`; `page_not_found` → **no note**, because that outcome is a `NotJudgeableCause` and the page carries `not_judgeable` instead. `verifyNote` is never consulted when composing a verdict. Assert it with two fixtures differing only in the stored outcome.
5a. **`could_not_confirm` and `page_not_found` come from the same fetch, render as the same grey line, and go opposite ways in this file.** One leaves the page fully judged with a note beside its verdict; the other retires it from judgement forever and nothing restores it. Do not retry the first, do not fold it into `reachable: false`, and do not add it to `NotJudgeableCause` beside the second — all three read as tidying an obviously incomplete union and all three pass every test that exists before they are proposed. ADR-085 is the file; `terminal.test.ts` and `landmine.test.ts` (WO-203) are the tests.
6. Make idempotency the unique key, not a guard: run `judgeWeek` twice in the test and assert the row count.
7. Run the tests. Then mutate, four ways: write a row for `not_measured` and confirm the partial-week test fails; fall back to the latest verdict when the requested week has none and confirm `… never returns a neighbouring week's verdict` fails; **route `could_not_confirm` to `not_judgeable` and confirm the two-fixture case fails while every screen would still have rendered correctly**; and **remove the short-circuit so a returning search lifts `search_untracked`, and confirm `terminal.test.ts` fails** — that mutation is the change a future reader will propose as a bug fix.

**Discriminates (mutation check, constitution §8).**
- **Lifting a cause when its condition lifts** — restoring a page to judgement once its search is back in the tracked set — fails `terminal.test.ts` and nothing else. It is the mutation ADR-072 exists to stop, it will be proposed as a *bug report* rather than a tidy-up, and its effect is a resumed verdict presented to a customer as continuous with verdicts taken before the gap, against a test written for a market position ReachKit stopped measuring, on a screen whose own line says the page is no longer judged.
- **Routing `could_not_confirm` to `not_judgeable`** — completing the union the obvious way — fails the two-fixture case in `judge.test.ts` and nothing else. In production it retires a page from judgement forever on the strength of ReachKit's own 502, and ADR-072 Decision 5 makes that unrecoverable by design. Both grey lines still render correctly.
- **Retrying a `could_not_confirm`** fails `no-look.test.ts` (the network stub throws) and is the most defensible version of the forbidden thing: a transport error at 24 hours *is* a flake, and there is no second look, so a retry that succeeds an hour later records a different day's fact under the check's own date (REQ-062's non-goal).
- Falling back to the most recent verdict when the requested week has no row makes `… never returns a neighbouring week's verdict` fail — and is the change that would show a customer last week's verdict as this week's.
- Writing a row for `not_measured` makes the partial-week test fail, and in production would let one missed measurement retire a paying customer's page from judgement permanently while every screen still rendered correctly.
- Letting `verifyNote` downgrade or withhold a verdict makes the two-fixture verification test fail — c1 says it is shown beside a verdict and never in place of one.
- Judging in UTC weeks makes the two-time-zone test fail; BP-051 decision 3 is why the stored week is the site's own Monday.
