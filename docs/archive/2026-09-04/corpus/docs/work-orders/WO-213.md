# WO-213 — publish() — the delivery call after the commit, and the outcome written exactly as it happened

- Branch: wo/WO-213-publish-attempt
- Estimate: ≤1 day

## Goal
Ship `publish()`: claim, call the destination adapter after the transaction has committed, and write the outcome — including `verify_due_at` on a delivery that has a live address.

## File plan

> This repository carries no `src/`, no `tests/`, no `supabase/` and no
> `package.json` (verified 2026-08-31). **Every path below is NEW** — none was
> verified to exist, because none can. Placement is anchored to
> `sdlc-factory/docs/registry/structure.md` and to this work order's blueprint
> `code:` globs, and is provisional against a repo with no code: if the
> implementer finds a file already present at one of these paths, they stop and
> log `failed` naming the drift rather than merging into it.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/publish/attempt/index.ts` | NEW | `publish()` in BP-045's declared shape, the `FailureReason` re-export and `RETRYABLE`. Order: `claim()` (WO-212); on `alreadyPublished` return without calling the adapter; otherwise commit, then call `adapterFor(kind).deliver(page, cfg, draftId)` with a 20 s hard timeout; then one outcome write — `delivery_state`, `published_at`, `live_url`, `remote_id`, `failure_reason`, **`made_live_by_us = result.madeLive`, copied straight off the `DeliveryResult` the adapter returned and derived from nothing else** (ADR-082 Decision 2, carried forward by ADR-084 Decision 4), and `verify_due_at = published_at + 24h` where `live_url` is non-null and null where it is null (BP-049's column, BP-049's rule, **which reads the address and never `destination.kind`**). Then `transition()` to `published` or `failed`. A timeout is the retryable `timeout` reason and the delivery is reconciled by the idempotency key on the next attempt. |
| `tests/publish/attempt/publish.test.ts` | NEW | The adapter is never called before the claim transaction commits (asserted by an adapter that inspects transaction state); an attempt already under way at the moment the switch is recorded runs to a known outcome and that outcome is written exactly as it happened; **`verify_due_at` is set on a delivery that returned an address and left null on one that did not — asserted from the address and against three adapter kinds, `hosted`, `wordpress` and a hypothetical third, so the rule cannot be re-derived from the kind**; a 20 s timeout produces `timeout` and no second delivery on the following attempt. **Four `made_live_by_us` rows:** a stub adapter returning `madeLive: true` with a `liveUrl` stores `true`; a stub returning `madeLive: false` with no `liveUrl` stores `false`; and — the discriminating pair — **a stub returning `madeLive: true` with `liveUrl: undefined` still stores `true`, and one returning `madeLive: false` with a `liveUrl` set still stores `false`.** The last pair fails against any implementation that derives the column from `live_url != null` or from `servesPublicly`, and passes against every other implementation including the wrong ones — which is why the fixtures are contradictory on purpose, and why the pair matters more now than when it was written: `live_url` used to be null for every WordPress row and is now non-null for every one of them, so the wrong predicate has stopped under-classifying and started over-classifying. |

**Exposes** — copied exactly from BP-045's `## Public interface`:

```ts
// src/lib/publish/attempt/index.ts
export type { FailureReason } from '../types'      // declared in the leaf; re-exported here
export const RETRYABLE: readonly FailureReason[]

export function publish(a: { draftId: string; destinationId: string; by: Actor }): Promise<
  | { ok: true; publicationId: string; liveUrl?: string; alreadyPublished: boolean }
  | { ok: false; reason: FailureReason; retryable: boolean; attemptNo: number }
  | { ok: false; reason: 'held'; heldBy: 'switch_off' | 'ceiling_day' | 'ceiling_week'
                                        | 'destination_not_working' | 'not_publishable' | 'telling_owed' }
>
```

`FailureReason` is *declared* in `src/lib/publish/types.ts` (WO-206) and
**re-exported from this file**, which is BP-045's own text as of 2026-08-31:
"Declared **here**, in the leaf, not in `attempt/`. `DeliveryResult.reason` names
it and `types.ts` imports nothing from `src/lib/publish/`, so declaring it under
`attempt/index.ts` made this file uncompilable as specified. `attempt/index.ts`
re-exports it, which is why every caller's spelling is unchanged. `RETRYABLE`
stays in `attempt/` — it is policy, not shape." So no importer's spelling
changes: `import { FailureReason } from '.../attempt'` still resolves. `RETRYABLE`
is defined here and is the first four members.

## Steps
1. Create `attempt/index.ts` with the block above. `FailureReason` is re-exported from `../types`, never re-declared here — a second declaration would compile and would be the copy rule 2.4 forbids.
2. Call the adapter strictly after the claim transaction has committed. Assert it in test, not in a comment.
3. Write the outcome in one statement. `liveUrl` is `result.liveUrl` — the address the adapter returned, and **since ADR-084 both adapters return one on every successful delivery**, so a WordPress row carries a `live_url` exactly as a hosted one does. `made_live_by_us` is `result.madeLive` and **nothing else** — not `servesPublicly`, not `hostedByUs`, not `liveUrl != null`, not `kind === 'hosted'`. ADR-084 Decision 4: `madeLive` is a fact about what this call did to this page; the others are facts about the destination, and `liveUrl != null` in particular is the substitution ADR-081 alternative 4 rejected and ADR-084 records as **still wrong with the sign reversed** — it is now non-null for every WordPress row and would classify every WordPress page as made-live-by-us.
4. Set `verify_due_at = published_at + 24h` on a delivered publication with a non-null `live_url`, and null otherwise — BP-049's stated rule, landing on this write because this is where `delivery_state` becomes `delivered`. **Read the address, never the kind.** Since ADR-084 that means every delivery at both destinations is due for the 24-hour check, and WordPress joined the verified population with no second destination rule written anywhere — which is the seam BP-049 decision 2 built and this step must not undo.
5. Map a hard timeout at 20 s to `timeout`, retryable, and take no edge other than `publishing → failed`.
6. Write the "adapter is not called inside the transaction" test first and watch it fail against an implementation that calls it inside (constitution §8).
