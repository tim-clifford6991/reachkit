# WO-088 — swapOffer — a destination handle for a rival out of the customer's league, and no way to change the set

- Branch: wo/WO-088-swap-offer
- Estimate: ≤1 day

## Goal
Implement `src/lib/market/sizing/offer.ts` so a `far`-banded rival produces an offer naming
where the customer can replace it — and so "the product removed my rival" is not a bug that
can be written in this module at all.

## Context an implementer needs
No source code exists on disk; both paths below are NEW.

**The three band words are ruled; criterion 6's sentence is not.** BP-019's
`BAND_LABELS.rivalSize` now carries `band.rivalSize.near` → "Similar size",
`band.rivalSize.middle` → "Larger" and `band.rivalSize.far` → "Much larger" (BP-019 decision
6, owner ruling of 2026-08-31), and the disjointness assertion passes on them. The written
line criterion 6 requires — the one saying the rival is far beyond what they could catch and
why the distance will not move — was **not** part of that ruling and is still owed. Neither
fact changes this WO: `swapOffer` returns a state and a destination handle, and the
`offer/writes-no-string` guard below stands over both the ruled band words and the unwritten
line.

**The swap offer names a destination; it never changes the set** (BP-052 decision 3). REQ-096
criterion 7 forbids the product narrowing the set on its own judgement, and REQ-096's non-goal
forbids suggesting a specific replacement rival. This module therefore exports **no** mutation
of the rival set: the change happens at REQ-071's competitors card, on that requirement's
terms, and the actual mutation is BP-034's `addRival`/`removeRival` (WO-083) persisted by
BP-056's `saveRivals` (WO-090).

## Interfaces
**Consumes**: `RivalSize` from `./size` (WO-087, quoted verbatim there). Nothing else.

**Exposes** — copied exactly from BP-052's `## Public interface`, comment included:

```ts
// src/lib/market/sizing/offer.ts
export type SwapOffer =
  | { offered: false }
  | { offered: true; rival: string; destination: 'settings.competitors' }
export function swapOffer(s: RivalSize): SwapOffer            // offered iff state==='sized' && band==='far'
```

## Steps
1. `swapOffer(s)` returns `{ offered: true, rival: s.domain, destination: 'settings.competitors' }`
   when and only when `s.state === 'sized' && s.band === 'far'`; otherwise `{ offered: false }`.
   An `unsized` rival and a stale (`current: false`) `far` rival are handled by that one
   condition — a stale `far` band is still a `far` band, and criterion 4 requires the date to
   travel with it, which `RivalSize` already carries.
2. `destination` is the literal type `'settings.competitors'` — a handle, not a URL and not a
   sentence. Route resolution is the surface's.
3. Export nothing else. In particular export no function that takes a `RivalSize[]` or a
   `RivalSet` and returns a modified one, and no function that suggests a replacement.
4. Emit the observability field BP-052 names: whether the swap offer fired.
5. Write the tests; watch each fail first.
