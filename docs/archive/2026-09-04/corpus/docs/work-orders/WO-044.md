# WO-044 — The string-literal sweep and the generated-text flow gate over the surface globs

- Branch: wo/WO-044-copy-sweep
- Estimate: ≤1 day

## Goal
Build ADR-010 point 1: a suite whose scope is a path glob over the surface tree,
failing on a product sentence written as a string literal in a surface and on a
`GeneratedColumn` value reaching a surface except through `renderGenerated` or
`renderQuestion`.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `tests/presentation/copy/surface-tree.ts` | **NEW** | The file enumerator: walks `src/app/**`, `src/app/(hosted)/**`, `src/lib/mail/**` and `src/ui/**` with `node:fs` recursive read, returns every `.ts`/`.tsx` path found, and returns the counts it walked per glob. Takes a root parameter so the fixture tree can be swept with the same code. **This is the one file enumerator in the corpus; WO-047's route enumerator is a different thing and lives in BP-021's tree.** |
| `tests/presentation/copy/allowlist.ts` | **NEW** | The declared allow-list of non-voice string positions ADR-010 point 1 names — attribute values, `aria-*`, test ids, class names — as an explicit, reviewable data structure with one comment per entry saying why it is not the product's voice. Nothing else is allowed. |
| `tests/presentation/copy/budget.ts` | **NEW** | `export const COPY_SWEEP_BUDGET_MS = 120_000` — BP-020 Decisions 3's parameter, declared here and nowhere else. A comment records that exceeding it is fixed by sharding on the surface glob, never by raising the number. |
| `tests/presentation/copy/string-literal-sweep.test.ts` | **NEW** | Parses each enumerated file with the TypeScript compiler API and fails on a string literal in a JSX text position, in a text-bearing prop, or in a mail template body, unless the position is on the allow-list. Emits the coverage statement. Asserts the wall clock against the budget. |
| `tests/presentation/generated/flow-gate.test.ts` | **NEW** | Fails on a value read from one of `GeneratedColumn`'s seven columns reaching a surface other than through `renderGenerated` or `renderQuestion`; and fails on a `GeneratedText` reaching a slot whose `PageIdentity` is absent (BP-020 `## Error & edge behavior`, tenth bullet). Emits its own coverage statement. |
| `tests/presentation/copy/__fixtures__/surfaces/**` | **NEW** | The synthetic surface tree: one clean file per governed glob that must pass, and one violating file per rule that must be flagged by name — a JSX text literal, a text-bearing prop literal, a mail body literal, an allow-listed attribute literal (must pass), a direct `drafts.body` read into JSX, and a `GeneratedText` rendered with no `PageIdentity`. |

## Interfaces
**Consumes** (test-time only — ADR-010 `## Consequences`: "The suites read other
nodes' source trees. That is a **test-time** relationship and creates no import
and no cycle; no `depends-on` edge is drawn for it"):
- `COPY`, `COPY_META`, `CopyKey`, `OWNER_OWED` from WO-041.
- `GeneratedColumn`, `renderGenerated`, `renderQuestion` from WO-043.
- The source trees under `src/app/**`, `src/app/(hosted)/**`, `src/lib/mail/**`
  and `src/ui/**`, read from disk. No import of any module in those trees.

**Exposes:** `surfaceTree()` and `COPY_SWEEP_BUDGET_MS` to the other two suites
in this block (WO-047 and WO-050 may import the enumerator; neither may copy it).

## Steps
1. Create `surface-tree.ts`. Walk the four globs from a supplied root using
   `node:fs`'s recursive directory read; return `{ files: string[]; perGlob:
   Record<string, number> }`. Skip nothing silently — a directory that does not
   exist yet contributes `0` and is reported as `0`, never omitted (rule 5.5).
2. Create `allowlist.ts` and `budget.ts`.
3. Create the fixture tree under `tests/presentation/copy/__fixtures__/surfaces/`
   mirroring the four glob shapes, with the six files listed in the file plan.
4. Write `string-literal-sweep.test.ts`. Parse each file with
   `ts.createSourceFile` and walk the AST: flag `JsxText` with non-whitespace
   content, a `StringLiteral` or `NoSubstitutionTemplateLiteral` in a JSX
   attribute whose name is text-bearing, and a string literal in a mail template
   body. Compare against `allowlist.ts`. Two describes: one over the fixture tree
   (must flag exactly the known violations, by file and position, and must not
   flag the clean files or the allow-listed attribute) and one over the real
   surface globs (must flag nothing). Emit the coverage statement:
   files walked per glob, literals inspected, violations found, allow-list hits.
5. Write `flow-gate.test.ts`. For each enumerated file, flag any identifier or
   property access naming one of the seven `GeneratedColumn` strings, or a value
   typed `GeneratedText`, that reaches a JSX text position or a text-bearing prop
   without passing through a call to `renderGenerated` or `renderQuestion` in the
   same expression. Same two describes over fixture tree and real tree; same
   coverage statement.
6. Assert the wall clock of each describe against `COPY_SWEEP_BUDGET_MS`.

## Test plan
| Acceptance criterion (verbatim from REQ-093) | Test |
|---|---|
| 1. "Given any text the product renders or sends to a person — whether or not they are a customer: a verdict, an explanation, a label, a heading, an empty state, an alert, or anything else it says in its own voice — when they read it, then it is a written string in the product and no part of it was produced by a language model, unless criterion 2 or criterion 3 admits it. The kinds named here are illustrative, not a closed list: the criterion holds for every text the product renders or sends, on every surface it speaks on — a screen and a mail alike — including surfaces added after this requirement." | `string-literal-sweep.test.ts` → **"a product sentence written in a surface is flagged by file and position"** (fixture describe) and **"no surface holds a product sentence"** (real describe). Discriminates: deleting the JSX-text rule makes the fixture describe pass with the violation present, which fails the fixture describe's expected-violation list. The "surfaces added after this requirement" clause is carried by the scope being a glob, not a list: `surface-tree.ts` holds no file names. |
| 2. "Given text a language model produced — the body, title, slug or description of a page ReachKit wrote, or the title or slug of one it has proposed and not yet written — when it appears on any surface the product renders or sends, a screen and a mail alike, to any reader whether or not they are a customer, whoever the page was written or proposed for and whether or not that person is a customer either, including before that page exists, then it appears as that page's content, identified as the page it belongs to and, where the page is not yet written, identified as proposed; and never as the product's own statement about the reader or their market." | `flow-gate.test.ts` → **"a stored model column reaches a surface only through renderGenerated"** (fixture + real describes), and **"a GeneratedText reaching a slot with no PageIdentity is flagged"**. Discriminates: the fixture's direct `drafts.body` read must be flagged by file and position; removing the rule fails the fixture describe. |
| 3. "Given the wording of one of the twelve tracked questions, which a language model produced, when it renders on any surface — the report and the app alike, and a set re-derived after a category change (REQ-071 criterion 7) as much as the first — then it is admitted on condition that the search it was derived from is shown with it, in the fuller form REQ-006 criterion 9 fixes wherever that requirement governs, and it is never presented as the product's own verdict about the reader or their market." | `flow-gate.test.ts` → **"questions.wording reaches a surface only through renderQuestion"**: `questions.wording` is one of the seven columns and its only sanctioned sink is `renderQuestion`; a fixture file rendering it through `renderGenerated` is flagged. |

Additional test this WO owns:
- Both suites → **"the sweep states its own coverage"**: the emitted report names
  the count per glob, and a run over an empty root reports `0` per glob rather
  than emitting nothing. Discriminates: an early return on an empty tree makes
  the report absent and fails (constitution rule 5.5).

## Out of scope
- Any CI configuration, branch protection or pre-commit hook. ADR-010 point 6 and
  constitution rule 3.3: these suites are recorded, not enforced, and creating
  the enforcement is a platform decision this WO does not make.
- An ESLint rule — ADR-010 alternative 2 rejects it as the gate; it remains
  available later as ergonomics derived from `allowlist.ts`.
- The cold-start route sweep (WO-047) and the stopped-state sweep (WO-050).
- Type-level enforcement at the `src/ui/` boundary — ADR-010 alternative 3
  rejects it on `structure.md` rule 6 grounds.

## Decision taken under rule 1.1
The sweep parses with the TypeScript compiler API (`ts.createSourceFile`) and
walks the tree with `node:fs`, rather than adding a glob or AST dependency.
Derivation: both are already present in any TypeScript project and neither needs
a repo-root config file, which ADR-010 alternative 2 rejects on ownership
grounds. Cost of reversing: one file (`surface-tree.ts`) and the parser call in
each suite.

## Rollback
Delete the five files and the fixture directory. Nothing in `src/` imports them.
