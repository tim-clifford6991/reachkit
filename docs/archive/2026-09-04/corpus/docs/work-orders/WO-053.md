# WO-053 — The partition — `classify`, `FEEDS`, and `sectionOutcome`

- Branch: wo/WO-053-partition
- Estimate: ≤1 day

## Goal
Ship the exhaustive classification of every scan outcome into one arm of
`Measured`, the transitively closed map from input to the factors it feeds, and
the section-level present/absent verdict — so that no call site ever answers
those questions for itself.

## File plan

> Every path below is **NEW**. Verified 2026-08-31: this repo carries no `src/`.
> Placement per `structure.md`; provisional against a repo with no code.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/measure/partition.ts` | NEW | The whole public interface below. `classify` is one function over one closed input union with one arm each, implementing BP-024's six-row classification table exactly. `FEEDS` is the transitively closed dependency map of BP-024's `FEEDS` table. `sectionOutcome` returns `{ present: false; reason }` only when every input the section is made of is `unmeasured`, and the reason is the fold of those reasons under `worseReason`. |
| `tests/measure/verdict/partition.test.ts` | NEW | The suite named in the test plan, including the exhaustiveness tests over both closed unions. |

## Interfaces

Consumes (from WO-052, `src/lib/measure/measured.ts`): `Measured<T>`,
`UnmeasuredReason`, `measured`, `measuredZero`, `unmeasured`, `worseReason`.

Exposes (verbatim from BP-024 `## Public interface`, `src/lib/measure/partition.ts`):

```ts
/** The exhaustive classification REQ-004's last non-goal hands to the blueprint.
 *  One function, one closed input union, one arm each — a new input cannot ship
 *  without a classification. */
export type ScanInput =
  | 'home_document' | 'pricing_document' | 'access_rules'
  | 'business_profile' | 'market_suggestions'
  | 'own_ranked_rows' | 'question_serps'
export type InputOutcome =
  | { read: true;  empty: boolean }        // we read it; `empty` = it contained none of what we counted
  | { read: false; because: 'undeterminable' }
  | { read: false; because: 'not_attempted' }
export function classify(input: ScanInput, o: InputOutcome, at: Date): Measured<null>

/** REQ-004 criterion 6's second sentence — "an input no driver depends on never
 *  withholds the score" — is this map, not a judgement at each call site. */
export const FEEDS: Readonly<Record<ScanInput, readonly ScoreFactorName[]>>

/** Section-level outcome, for REQ-004 criterion 10. A section whose data could
 *  not be retrieved is absent and named; it is never an empty card. */
export type SectionName = 'verdict' | 'ai_answers' | 'google_presence' | 'problems' | 'first_page'
export function sectionOutcome(s: SectionName, inputs: Readonly<Record<ScanInput, InputOutcome>>):
  { present: true } | { present: false; reason: UnmeasuredReason }
```

`ScoreFactorName` is WO-054's export from `src/lib/measure/score.ts`. To keep the
dependency direction acyclic, declare `ScoreFactorName` in `score.ts` and
`import type` it here; `partition.ts` imports no value from `score.ts`.

## Steps
1. Write the failing suite first.
2. Declare `ScanInput`, `InputOutcome` and `SectionName`.
3. Implement `classify` as a total switch over `InputOutcome` per BP-024's
   classification table: `{read:true, empty:false}` → `measured(null, at)`;
   `{read:true, empty:true}` → `measuredZero(null, at)`; `{read:false,
   because:'undeterminable'}` → `unmeasured('undeterminable', at)`;
   `{read:false, because:'not_attempted'}` → `unmeasured('not_attempted', at)`.
   Reading is the whole of the line: no arm inspects the input name to decide.
4. Write `FEEDS` from BP-024's table, transitively closed: `home_document` →
   `['foundations','answerability']`; `pricing_document` → `['answerability']`;
   `access_rules` → `['foundations']`; `business_profile` → `['presence']`;
   `market_suggestions` → `['presence']`; `own_ranked_rows` → `['presence']`;
   `question_serps` → `['presence']`. Freeze it.
5. Implement `sectionOutcome` over a per-section input list held in this file.
6. Add the exhaustiveness guards: a `never` check on both unions so a new member
   fails the build until it has a row.

## Test plan

| Acceptance criterion (verbatim from REQ) | Test |
|---|---|
| REQ-004 c7 — "Given an input the scan did read that contained none of what was counted — including a site's access rules, read successfully, that gate nothing — when the report renders and the result is stored, then the value is shown as 0 with its denominator and recorded as a measured zero, never as '—', 'unknown', a missing section, or a measurement that could not be taken. Access rules read successfully that do gate are a measured result too and are likewise never '—' … Reading is what divides this criterion from criterion 6." | `partition/classify · read-and-empty is a zero, for every input` — over all seven `ScanInput` members, `classify(input, {read:true, empty:true}, at)` is `kind: 'zero'`, and `classify(input, {read:true, empty:false}, at)` is `kind: 'measured'`. Neither is ever `unmeasured`. |
| REQ-004 c6 — "Given an input whose existence the scan could not determine — it could not tell whether a gate or an input is there at all, because nothing was returned, the answer was unreadable, or a data source did not answer — when the report renders and the result is stored, then every driver depending on it is shown and recorded as '—', one written line names which driver was missing or, where no driver depended on that input, names what could not be measured, and the score is shown as '—' only where a driver it is composed of depended on that input. An input no driver depends on never withholds the score." | `partition/classify · unread is undeterminable, never zero` — over all seven inputs, `{read:false, because:'undeterminable'}` classifies `unmeasured/undeterminable` and is asserted not equal to any `zero` value. And `partition/FEEDS · closed, total and transitive` — every `ScanInput` has a row; `business_profile` and `market_suggestions` reach `presence` (the transitive closure BP-024 fixes); no row is empty for an input BP-024's table gives a factor to. |
| REQ-004 c9 — "Given a measurement the scan never attempted because it stopped early — at the 90-second ceiling (REQ-003 criterion 5) or the free path's spend ceiling (REQ-003 criterion 11) — when the report renders and the result is stored, then everything depending on it is shown and recorded as '—', one written line states it was not measured because the scan stopped early, and it is never shown or recorded as 0." | `partition/classify · not_attempted is never zero` — over all seven inputs, `{read:false, because:'not_attempted'}` classifies `unmeasured/not_attempted`, and a mutation test asserts that swapping this arm for `measuredZero` fails the suite (the vacuity guard constitution §8 requires). |
| REQ-004 c10 — "Given a section whose data could not be retrieved, when the report renders, then that section is absent and one written line names the missing section and states that it could not be measured — never an empty card, a persistent spinner, or placeholder content." | `partition/sectionOutcome · absent only when nothing behind it was read` — for each of the five `SectionName`s: all its inputs unread → `{present:false}` with the folded reason; any one input read → `{present:true}`. Plus `partition/sectionOutcome · problems is present whenever its inputs were read` — the case BP-027 leans on, so a `—` count never removes the problems section. |
| REQ-004 c6, second sentence, as a property | `partition/FEEDS · an input no factor depends on never withholds the score` — asserts that the question wording and the rival derivation are not `ScanInput` members at all, so no failure in either can reach `FEEDS`; a new member added without a row fails to compile. |
