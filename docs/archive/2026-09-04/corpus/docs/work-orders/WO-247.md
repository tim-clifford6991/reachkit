# WO-247 — `GET /opt-out/{token}` — address-wide follow-up suppression, and the one line that says so

- Branch: wo/WO-247-opt-out
- Estimate: ≤1 day
- Preview: sdlc-factory/docs/design/previews/WO-247.html
- Signed-off: <date>

## Goal
Apply an opt-out token on arrival and tell the person, in one written line,
that follow-up to their address has stopped — or that the link is not one of
ours — with nothing else on the page and nothing asked of them.

## Provenance of this file plan
**This repository holds no `src/`.** Both paths are NEW. `GET /opt-out/{token}`
is on BP-001's public route list ("address-wide follow-up suppression") and is
anchored by this container's glob `src/app/(public)/**` and by no leaf's.
BP-001's delegation table names the target: "BP-029's address-wide suppression",
behind it REQ-011. WO-004 named this surface as one it does not cut.

**Why `ui: yes`.** BP-001's prose counts this among "six transport-only
adapters", but its own route table lists it under *Routes (public)*, not under
*Adapters (transport only)* — that block names exactly two, the Stripe webhook
and the Inngest endpoint — and this route renders a page a person reads. Rule
7.3 binds "a WO touching customer-visible surface", so it carries a preview and
a sign-off. Marking it `ui: no` on the strength of the prose would let a
customer-visible page ship with no preview, which is the one thing that gate
exists to prevent. Reported with this block's return.

## File plan

## Interfaces

Consumes (verbatim from BP-029 `## Public interface`):
```ts
// src/lib/mail/leads/optout.ts
export function optOutTokenFor(email: string): string                 // signed, no expiry
export function applyOptOutToken(token: string): Promise<
  | { email: string }
  | { error: 'invalid' }>                                             // idempotent
```
Also consumes: BP-019's `copy()` (WO-041) and BP-018's registered components.
`suppressAddress` is **not** consumed: `applyOptOutToken` is the token path and
calls it, and a second caller would be two entry points to one capability.

Exposes (verbatim from BP-001 `## Public interface`):
```
  GET  /opt-out/{token}                 address-wide follow-up suppression
```
`PUBLIC_PATHS` already carries `/opt-out/{token}` (WO-003 writes that allow-list
from BP-001's public route list); this work order does not touch
`src/middleware.ts`.

## Steps
1. Produce the preview artifact at the path in the display bullets above and hold
   in draft until it is signed off (constitution rule 7.3). This WO does not
   proceed to implementation before that.
2. Write the failing suites first, the idempotence case among them.
3. Call `applyOptOutToken` once per request and switch totally over its two arms;
   there is no third rendering and no default arm.
4. Render the confirmation line by key. **Do not render the returned address.**
   The arm carries it because the caller may need it; this page shows it to
   whoever holds the link, which is not necessarily the person who owns it, so
   echoing it would state one person's address to another.
5. Render no control of any kind: the suite enumerates the rendered controls and
   asserts the set is empty.

unreachable — so revert this only together with whatever stops those mails being
sent.
