# WO-028 — Hosted-edge container — the unknown-Host 404 and immediate cache invalidation

- Branch: wo/WO-028-hosted-container
- Estimate: ≤1 day
- Preview: sdlc-factory/docs/design/previews/WO-028.html
- Signed-off: <date>

## Goal
Create the hosted route group as a container that returns 404 for a Host it does
not know and never serves a stale 410, so a takedown does not wait on a TTL.

## Provenance of this file plan
**This repository holds no `src/`.** Every path is NEW, anchored to
`structure.md`'s row for `src/app/(hosted)/**` and to the remainder of BP-004's
glob after BP-047's five narrower ones (see `rests-on`).

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/app/(hosted)/not-found.tsx` | NEW | The unknown-or-unmapped-Host response: HTTP 404, and **never a ReachKit page** — no ReachKit name, no ReachKit link, no ReachKit navigation, nothing that identifies the operator of a stranger's domain. Renders BP-018's tokens only, no copy from the product's own registry. |
| `src/app/(hosted)/revalidate.ts` | NEW | The cache-invalidation port: `invalidateHosted({ host, slug })`, called by the publish and unpublish paths (BP-045, outside this block) and by nothing on this surface. Invalidation is immediate; there is no TTL path to a 410. |
| `tests/hosted/container/not-found.test.ts` | NEW | The 404 tests below. `tests/hosted/**` is BP-004's; BP-047 globs `tests/hosted/serving/**` and `tests/hosted/indexing/**`, so `tests/hosted/container/**` is free. |
| `tests/hosted/container/revalidate.test.ts` | NEW | The invalidation tests below. |

## Interfaces
Exposes:
```ts
// src/app/(hosted)/revalidate.ts
export function invalidateHosted(a: { host: string; slug?: string }): Promise<void>
```
Consumes (verbatim from BP-002 `## Public interface`): `db()` · `dbAdmin()`.
Consumes (BP-018): `src/ui/theme.css`.
**Not consumed and not implemented here** — BP-047's `resolveHost()`, `robots.txt`,
`sitemap.xml` and `tags()`.

## Steps
1. Create the route group with `not-found.tsx` only.
2. Write `revalidate.ts` as a port with no caller on this surface.
3. Write the two test files; watch the "no ReachKit page" test fail first by
   rendering the product's name.

## Test plan

| Acceptance criterion (source quoted) | Test |
|---|---|
| BP-004 error behaviour: "An unknown or unmapped Host returns 404 and never a ReachKit page." | `tests/hosted/container/not-found.test.ts` — an unmapped Host yields 404; the body contains no ReachKit name, link or navigation. Rendering the product's name fails it. |
| BP-004 public interface: "an unknown Host is 404, never a fallback to another customer's content" | Same file — an unmapped Host never renders any published page, including when exactly one site exists. |
| BP-004 NFR budget: "Cache invalidation on publish and on unpublish is immediate; a 410 must not be served from a stale cache and a takedown must not wait on a TTL." | `tests/hosted/container/revalidate.test.ts` — after `invalidateHosted`, the next read misses the cache; a fixture asserting a TTL-based expiry fails. |
| BP-004 error behaviour: "Serving is read-only: nothing on this surface can change a publication's state, so a crawler cannot advance the state machine." | Same file — parses every file in `src/app/(hosted)/` and asserts none exports a `POST`, a server action or a mutation. |
| BP-004 NFR budget: "no customer identifier in a log line served from a customer's own domain" | Same file — asserts the request log record carries Host, slug, status and cache disposition, and no user or site id. |

## Out of scope

  all BP-047's under `structure.md` rule 2.

  account deleted) — BP-047 consumes them from BP-017.
- The DNS record the customer sets and the hosted destination's delivery half —
  BP-058.

container to sit in, so revert them first or together.
