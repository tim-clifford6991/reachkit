# WO-085 — suggestRivals and settleSetup — two suggestion sources by path, and the one idempotent write

- Branch: wo/WO-085-setup-suggest-settle
- Estimate: ≤1 day

## Goal
Complete `src/lib/market/setup/index.ts` with the two functions that touch the world: rival
suggestions, whose source differs by whether a report backs the account, and the single
idempotent write that settles the market and the rival set.

## Context an implementer needs
No source code exists on disk; `src/lib/market/setup/index.ts` exists only as WO-084 leaves
it. **This WO modifies that file — it must never run in parallel with WO-084.**

The first `rests-on` row above is inherited verbatim from BP-034's own front-matter. It is
open and does not block planning: it bounds whether `none_found` can be distinguished from a
vendor failure, and BUILD §16 milestone 2 is the first point at which it can be measured.

**BP-034 decision 2 reconciles BUILD §4.3 with §6.6** and is the rule this WO implements:
where a completed report backs the account, suggestions are BP-026's market-derived rivals
read from that report (0¢, already bought). Where no report backs it and the founder states
their market, the market-derived list cannot exist — it requires twelve SERPs only a scan
produces — so the single source is `competitorsDomain()`.

**Setup is never held on suggestions.** BP-034's `## NFR budget`: the call is bounded at 3 s
and, on timeout, leaves `SuggestionState` at `none_found` rather than holding the screen.

## Steps
1. `suggestRivals(c, s)` branches on the market card, not on the purchase:
   - `s.market.state === 'empty'` ⇒ return `{ kind: 'zero', value: [], at }` without any call.
     The caller keeps `suggestions.state` at `'awaiting_market'`; a card with no market says it
     is waiting on the market and never that none were found.
   - `s.market.state === 'inferred'` ⇒ the candidates are the report-derived rivals the caller
     holds in `ReportFacts.rivals` (BP-026's `deriveRivals` output, already paid for at 0¢).
     **Make no vendor call on this path.**
   - `s.market.state === 'stated'` ⇒ one `competitorsDomain(c, { domain: s.siteDomain })` call.
2. Normalise every returned row through `registrableDomain`, drop nulls, drop the account's own
   domain, drop anything already in `s.rivals`, and cap the list at `BATTERY.COMPETITORS_MAX`.
3. Bound the vendor call at 3 s. A timeout, a vendor error, or an empty result all return a
   `Measured` the caller maps to `'none_found'` — setup is released either way. Do **not** hold,
   retry or block on this call.
4. No rival found for a *replaced* domain may be offered: `suggestRivals` reads only
   `s.siteDomain` and the `ReportFacts` the caller currently holds, both re-keyed by
   `onDomainChanged` (WO-084), so a stale report cannot reach this function.
5. `settleSetup({ siteId, category, rivals })` writes `sites.category` (text) and
   `sites.competitors jsonb` through `db()`, storing each rival as `{ domain, origin }` so
   "clear the suggested, keep the typed" survives a reload and a later domain change (BP-034
   decision 3: origin is stored, never inferred). One statement, idempotent on `siteId` — a
   resubmitted form cannot produce two rival sets.
6. `settleSetup` writes **only** those two columns. It adds no column, no table and no
   migration: `supabase/migrations/*_sites*.sql` is not this node's glob (BP-034's
   `## Data model delta`).
7. Emit the observability fields BP-034 names: suggestion source and count, and submit outcome.
8. Write the tests; watch each fail first.
