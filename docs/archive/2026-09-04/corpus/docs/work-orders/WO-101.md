# WO-101 — Mail block vocabulary, the omission rule, and the HTML rendering of all eight blocks

- Branch: wo/WO-101-mail-blocks-html
- Estimate: ≤1 day
- Preview: sdlc-factory/docs/design/previews/WO-101.html
- Signed-off: (pending — design-guardian)

## Goal
Ship the eight-member `MailBlock` union and the HTML renderer that drops an
unmeasured block entirely, prints a measured zero as zero, states a measured-empty
list in one written line, and lets model text through exactly one door.

## Provisional against an empty repo
**This repo carries no `src/`.** Every path below is NEW — none was verified to
exist, because none does. Placement follows `structure.md`'s row for
`src/lib/mail/**` (BP-016) narrowed by BP-053's `code:` globs and ADR-040 point 3,
which puts the block model at `src/lib/mail/blocks/**`.

Reuse check (rule 7.2): `registry/capabilities.md` names "The register of nine
mail kinds, the omission rule and the shell" as BP-053's, entry points
`MAIL_KINDS · composeMail() · sendEmail()`; no block renderer exists anywhere in
the index or on disk. `renderMeasured()` (BP-019) and `generatedLabel()` (BP-020)
are indexed and are **consumed**, not re-implemented — this module contains no
formatter for a `Measured<T>` of its own.

Type fan-out check (rule 1b): not runnable. `factory.config.json` carries no
`typeCheck` key (`{"schema": null}`), there is no `package.json`, no `tsconfig`
and no source tree, so there is no compiler to invoke and no exported type to
widen. This WO **creates** the type every later mail WO consumes; the fan-out
appears in WO-102, WO-103, WO-113 and is recorded there as a `depends-on`.

## Interfaces
**Exposes** (verbatim from BP-053 `## Public interface`):
```ts
// src/lib/mail/blocks/types.ts — the only vocabulary a template may speak
export type MailBlock =
  | { block: 'heading';   text: CopyKey; vars?: CopyVars }
  | { block: 'paragraph'; text: CopyKey; vars?: CopyVars }
  | { block: 'stat';      label: CopyKey; value: Measured<number>
                          format: 'integer' | 'delta' | 'perMonth'
                          note?: CopyKey }                        // travels with its value or not at all
  | { block: 'list';      label: CopyKey; items: Measured<readonly ListRow[]>; emptyLine: CopyKey }
  | { block: 'verdicts';  label: CopyKey; items: Measured<readonly VerdictRow[]>; emptyLine: CopyKey }
  | { block: 'action';    label: CopyKey; href: string }
  | { block: 'notice';    text: CopyKey; vars?: CopyVars }
  | { block: 'pageBody';  pageTitle: string; written: boolean; markdown: string }
```
Plus, chosen by this WO under rule 1.1 (internal names are the system's) and
bounded to BP-053's `blocks/**` glob:
```ts
export function omittedIndexes(blocks: readonly MailBlock[]): readonly number[]
export function renderBlocksHtml(blocks: readonly MailBlock[]): { html: string; omitted: readonly number[] }
```
Derivation: BP-053 declares `composeMail` returning `omitted`, but not the
function that computes it; splitting it out is what lets the HTML and plain-text
renderers (WO-102) share one omission decision rather than hold two. Cost of
reversing: inline it into each renderer — one edit, two copies of rule 2.4's
second copy.

**Consumes**: `Measured<T>` (BP-010, `src/lib/measure/`); `copy()` and
`renderMeasured()` (BP-019, `src/lib/presentation/`); `generatedLabel()` (BP-020,
`src/lib/presentation/generated/`); BP-018's theme tokens (`src/ui/theme.css`).

## Out of scope
- The plain-text rendering of these blocks (WO-102) and the shell (WO-103).
- `composeMail()`, the nothing-to-report notice, and `MeasurementState` — WO-103,
  which also carries the exception clauses of c1 and c3 since 2026-09-03.

  that assert a key resolves; the sentences are BP-019's registry and the owner's
  (REQ-093 c1, constitution §1's "Customer-visible strings" row).
- Any template. Templates are their owning nodes' (ADR-040 point 2).
