# WO-285 — The `GeneratedText` brand

- Branch: wo/WO-285-generated-text-brand
- Estimate: ≤1 day (measured: two source lines, one test file section)

## Goal
Make `GeneratedText`'s boundary nominal — a brand only `fromStored` can set —
so BP-020's "`fromStored()` is the only constructor of `GeneratedText`" stops
being a statement about this module's manners and becomes one about the
compiler, and hold it there with a fixture that fails by name when the brand is
deleted.

## Placement (rule 1.1 — the planner's call, stated with its reasoning)
**Not W3. The next wave, first order in it, `Must`.** `wave:` is left absent
here; `/wave propose` and the librarian assign it (constitution §4).

Grounds:
1. **W3's goal sentence cannot cite this order.** W3 delivers JN-001 steps 3
   and 4 — the free report screen. No W3 surface renders a `GeneratedText`;
   WO-279's own `## Rollback` says "No surface imports them until the
   AI-answers card is cut", and that card is not in W3. An order the wave's
   goal cannot cite is not in the wave.
2. **W3 already holds ten against a cap of eight.** Adding an eleventh that
   fails ground 1 is exactly the move the cap exists to prevent.
3. **Its only dependency is unmerged and currently `failed` in validation.**
   WO-279 is being fixed for two TST-028 findings, one of them in the very file
   this order's test row rewrites. Two strictly serialized orders inside one
   wave's remaining time is a scheduling claim nothing supports.
4. **Waiting lands the brand before the hazard, not after, at no measured
   cost.** The hazard opens when a second author writes a surface holding a
   `GeneratedText` — first in the wave that cuts the AI-answers card. The
   conversion cost stays zero until then (`rests-on` row 1, re-measured).

If the owner overrides and wants it in W3 anyway, the honest trade is to defer
one order, not to accept eleven: **WO-284 (Should)** — a boot-environment
binding whose absence blocks no W3 surface. Deferring WO-279 is not available
as the trade, because this order depends on it.

## Merge test (rule 2.6) — passes
The goal and stop condition above cite BP-020's declared interface, ADR-012 and
REQ-093 criterion 1, and quote TST-028 as evidence; none of those is WO-279's
goal or stop condition, and WO-279 is already 57/57 on its own test plan, which
this order neither completes nor changes. The overlap is two files and a merge
order — a `depends-on`, not a merge. WO-279 is also `started`, which the
consolidation rule puts out of reach, and the brand is a change to BP-020's
*declared interface* decided in ADR-012 after WO-279 was cut; ADR-012
`## Consequences` names it as a separate order on §4 grounds.

## Reuse check (rule 7.2) and what it discharges
`registry/capabilities.md` row "Identifying generated text as page content"
(`src/lib/presentation/generated/`, owner BP-020) already owns this capability;
this order **extends** it in place, creating no capability, no consumer and no
index row (rule 7.1). The brand is declared and consumed inside that one
module, crosses no edge and adds no import, so `structure.md` rule 6 is
untouched (ADR-012 point 5).

Landing this order discharges **BP-020 `rests-on` row 4** ("Until the brand of
Decisions 7 / ADR-012 lands in `src/lib/presentation/generated/text.ts`…"),
currently `open` and the only `open` row on that node — its validator
dispositions it (rule 2.3b). Row 5 is `undischargeable` and untouched here.

The construction the fixture holds, quoted from `WO-279.md` `## TST-028` →
`### Criterion 1's rule-4.2 substitution — judged, and disproven as written`
(rule 5.3 — the quote is the claim):

```ts
// No `as GeneratedText`, no `as unknown as`, no call to fromStored.
const handWritten: GeneratedText = {
  source: "model",
  text: "This sentence was never read from storage — the author typed it directly.",
};
const result = renderGenerated(handWritten, { state: "written", pageId: "p", title: handWritten, slug: handWritten, body: handWritten });
```

The `@ts-expect-error` goes on the `const handWritten` declaration — measured:
the brand raises exactly one error, `TS2741 Property '[brand]' is missing in
type '{ source: "model"; text: string; }' but required in type
'GeneratedText'`, at that line and nowhere else.

lands, a revert that keeps the fixture fails the typecheck by name instead of
passing green.
