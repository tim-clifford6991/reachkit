## Goal
Declare REQ-043 criterion 12's `WayThrough` union with its three refusal grounds
and no fourth, and decide the first way through — the page at its public address,
as a visitor sees it — from the stored page record alone, with no request of any
kind.

## Interfaces
**Consumes** (verbatim from BP-045's `## Public interface`, `src/lib/publish/types.ts`, WO-206):
```ts
export type AddressLabel =
  | 'record.address.publiclyReadableAt'   // while the page stands `published`
  | 'record.address.wasPublishedAt'       // from the moment it moves to `unpublished`

export type RecordedAddress =
  | { offered: true;  label: AddressLabel; url: string }
  | { offered: false; because: 'never_made_live'; copy: 'record.address.neverMadeLive' }

export type VerifyOutcome =
  | { outcome: 'found';             checks: VerifyChecks; checkedAt: Date }
  | { outcome: 'page_not_found';    status: 404 | 410;    checkedAt: Date }
  | { outcome: 'could_not_confirm'; why: NotConfirmed;    checkedAt: Date }
export type VerifyDisposition =
  | { kind: 'not_yet'; dueAt: Date }
  | { kind: 'due' }
  | { kind: 'done';    result: VerifyOutcome }
  | { kind: 'never';   because: 'taken_down_first' | 'no_live_address' }

export interface PageRecord {
  draftId: string
  state: State
  opportunityId: string
  targetQuery: string
  measuredAt: Date                 // the measurement behind the page (c6)
  mode: 'approved' | 'autopilot'   // c6's "approved or published automatically"
  address: RecordedAddress
  /** REQ-056 c6 and c16: the outcome c15 or c16 named for this page, and **no
   *  other account of what is at that address**. Non-null exactly when
   *  `state === 'unpublished'`. */
  unpublishOutcome: UnpublishResult['outcome'] | null
  /** REQ-062 c7. BP-049's whole `VerifyOutcome`, `checkedAt` included, or the
   *  disposition where no check has run. **Not optional, and not separable from
   *  `state`** — a surface cannot obtain the state without it, which is how
   *  criterion 7's "no surface presents the page as live without also carrying
   *  what ReachKit saw when it looked" holds on surfaces that do not exist yet
   *  (ADR-085 Decision 5). */
  verification: VerifyDisposition
}
```

## Steps
1. Write `tests/app/calendar/ways.test.ts` and `tests/app/calendar/ways-landmine.test.ts` first and run them; both must fail on a missing module (§8, "Watch it fail first").
2. Add the three owner-owed keys to `src/lib/presentation/copy/keys/calendar.ts` and to `OWNER_OWED`. Write **no sentence** — the strings are the owner's (constitution §1's decision table, "Customer-visible strings"), and `copy()` throwing on an owner-owed key is the mechanism that keeps a blank off the customer's screen (WO-041).
3. Declare `WayThrough` by copying BP-039's block character-for-character, comment included. Three grounds, no fourth.
4. Implement `wayAsVisitor` in the precedence criterion 12 states: ReachKit's own act first, then what the one check recorded, then offered. **Read ADR-085 before writing the second branch.** `page_not_found` is the only outcome that refuses a way; `could_not_confirm` is the arm whose whole content is *ReachKit does not know*, and refusing on it takes a page the record says nothing against and tells the customer the way leads nowhere.
5. Destructure `verification`; never test it with a boolean and never reach for a date. A `verifyFailed !== null` style test cannot tell "the page failed a check" from "the check did not settle", and those two go opposite ways here.
6. Close the `never_made_live` address arm with `const _never: never = record.address` inside the narrowed branch, with a comment naming this work order's second `rests-on` row. The arm has no members in production since ADR-084 Decision 1; the day it gains one, this file must stop compiling rather than hand a component an offered way with an undefined `href`.
7. Run the tests. Then mutate, three ways: refuse on `could_not_confirm` and confirm `ways-landmine.test.ts` fails while every other test passes; reverse the precedence of the first two grounds and confirm the both-at-once case fails; add a `HEAD` request before returning the offered arm and confirm the source-level import assertion fails.

**Discriminates (mutation check, constitution §8).**
- **Refusing on `could_not_confirm`** — completing the union the tidy way —
  fails `ways-landmine.test.ts` and nothing else in the corpus. Its effect is
  that a page ReachKit reached a 502 against is presented to its owner as a way
  that leads nowhere, on the one screen where the two grey lines actually sit
  side by side, and the requirement's own words for that outcome are that
  "neither the four outcomes nor the page's absence is asserted".
- **A `HEAD` or `GET` before returning the offered arm** fails the source-level
  import assertion and nothing else. It reads as making the link trustworthy; it
  is a second look at a published page, which REQ-062's non-goal forbids
  outright, and a transport failure would render to the customer as a page that
  is gone.
- **Reversing the first two grounds' precedence** fails the both-at-once case
  only. It is invisible in every other fixture, and it tells a customer who took
  the page down themselves that ReachKit's check could not find it.
- **Defaulting the `never_made_live` address arm into the offered branch** —
  the natural `else` — compiles today only because the arm is empty; the
  `const _never: never` is what makes it a build failure the day it is not.
