# WO-022 — The cost context — cache-first, ledger-always, cap-degrades

- Branch: wo/WO-022-cost-context
- Estimate: ≤1 day

## Goal
Run every vendor and model call inside a per-scan context that reads cache first,
ledgers what was spent whether or not the call succeeded, and returns a value at
the cap instead of throwing.

## Provenance of this file plan
**This repository holds no `src/`.** Every path is NEW, anchored to
`structure.md`'s row for `src/lib/costs/**` and BP-007's `code:` globs.

`reserved_cents` (BP-007 data-model delta, added by ADR-094 decision 3a) is **not** this
order's migration: the 2026-09-03 ruling recorded in WO-021's `## Provenance` folds the
column into WO-021's create-table, both orders being unbuilt and `fetches` having no rows
anywhere. This order consumes the column and asserts it from the seam's side; the file that
declares it is WO-021's.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/lib/costs/index.ts` | NEW | `withCostContext()` and the `CostContext` implementation, exactly BP-007's interface. Opens the context, runs the body, and at close writes the roll-up (`spentCents`, `degraded`) to `scans.cost_cents` and `scans.status`. `recordFetch` **reserves** `costCents` before the call — the cap is checked against the reservation — and, where the call site supplied `settleCents`, **settles** the ledgered figure from the payload afterwards, clamped to the reservation and logged when it would exceed it. `spentCents()` sums settled figures. |
| `src/lib/costs/cache.ts` | NEW | The cache read keyed `source + cacheKey + policyVersion`: the newest row on that key inserted within `freshnessDays`, **excluding a row whose payload is the vendor's own zero-result shape** (BP-007 decision 3 — the exclusion is at the read, not the write). Nothing is ever deleted — a bumped `policyVersion` is how a changed derivation invalidates. |
| `src/lib/costs/ledger.ts` | NEW | `recordFetch`'s write half: a row is written for every call that reached the vendor, including one that succeeded at the vendor and failed on parse. Every row carries both figures — `reserved_cents` (what the cap was checked against) and `cost_cents` (the settled figure where one settled, the reservation otherwise). |
| `tests/costs/context.test.ts` | NEW | The tests below. |

## Interfaces
Exposes (verbatim from BP-007 `## Public interface`):
```ts
export type CapName = 'FREE' | 'DEEP' | 'WEEKLY' | 'DRAFT'

export function withCostContext<T>(
  ctx: { scanId: string; cap: CapName; policyVersion: number },
  body: (cost: CostContext) => Promise<T>
): Promise<T>

export interface CostContext {
  /** Cache-first, ledger-always. `fresh` false means the payload came from cache
   *  and cost nothing. An empty payload is always a miss; there is no negative
   *  cache. */
  recordFetch<P>(call: {
    source: string           // vendor endpoint or model id
    cacheKey: string
    freshnessDays: number
    /** The **reservation**: the most this call can cost, known before it runs.
     *  The cap is checked against this, so no call is made against money the
     *  context has not got. */
    costCents: number
    /** Optional **settlement** (ADR-094 decision 3a). Where a vendor's own
     *  documented rule makes the final charge a function of the response, the
     *  call site supplies it and the ledger records the settled figure instead
     *  of the reservation. `settled <= reserved` is enforced here, not trusted:
     *  a closure returning more is clamped to the reservation and logged, since
     *  the excess would be money the cap never authorised. One call site uses
     *  it today — BP-008's flagged `serpOrganic`. Omitting it is the ordinary
     *  case and behaves exactly as before this argument existed. */
    settleCents?: (payload: P) => number
    run: () => Promise<P>
  }): Promise<{ payload: P; fresh: boolean; costCents: number } | { skipped: 'cap' }>
  // The returned `costCents` is the settled figure where one was supplied, the
  // reservation otherwise — one number, and it is the one the row carries.

  capHit(): boolean          // re-checked between calls in any multi-call step
  spentCents(): number
  degraded(): boolean
}
```
Consumes: `db()`/`dbAdmin()` (BP-002), `CAPS` and `CACHE_WINDOWS_D` (BP-005).

## Steps
1. Write `cache.ts` and prove the no-negative-cache rule by test.
2. Write `ledger.ts` and prove the spend-then-fail case; each row carries both figures.
3. Write `index.ts` with the three-armed `recordFetch` return, the cap checked against the
   reservation before `run()`, and the settlement applied after it where a closure was
   supplied — clamped at the reservation, never above it.
4. Write the tests; watch the cap case fail first by throwing a `CapExceeded`
   instead of returning `{ skipped: 'cap' }`, and the settlement case fail first by
   ledgering the reservation regardless of the closure's return.

## Out of scope
- The free-path short-circuit BP-007 names — "A free scan of a domain measured
  less than 7 days ago serves the stored report and opens no context at all" — is
  BP-012/BP-023's admission control, which decides not to open a context. This
  work order opens the context it is given.
- Every caller: BP-008 (WO-023 to WO-025) and BP-009 (WO-026, WO-027).
- The vendor rule that computes a settlement. `settleCents` is a closure the call site
  supplies; BP-008's flagged `serpOrganic` is the one that supplies it today (ADR-094
  decision 3a, BP-007 decision 4: "the **rule** that computes a settlement is vendor
  knowledge and stays at the call site"). This seam learns nothing about AI Overviews and
  carries no endpoint-specific branch.
- The `fetches` table itself — its create-table statement, both indexes, `reserved_cents`
  and its RLS policy are WO-021's (see `## Provenance` and the `rests-on` row). This order
  writes and reads rows; it declares no column.
- Rendering any cost figure; none is ever rendered.

## Rollback
Delete `src/lib/costs/**` and its test. The schema is untouched by this order, so
nothing is dropped. No vendor or model call can be made, which is the safe
direction.
