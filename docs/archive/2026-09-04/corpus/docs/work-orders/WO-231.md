# WO-231 — Two robots policies that share no helper, and a sitemap of exactly this site's live pages

- Branch: wo/WO-231-hosted-robots-sitemap
- Estimate: ≤1 day

## Goal
Ship the `robots.txt` and `sitemap.xml` we serve on the customer's own domain — blocking no general crawler, naming BP-005's six AI agents by pin — and the separate preview document, produced by a function that shares no helper with it.

## File plan

> This repository carries no `src/`, no `tests/`, no `supabase/` and no
> `package.json` (verified 2026-08-31). **Every path below is NEW** — none was
> verified to exist, because none can. Placement is anchored to
> `sdlc-factory/docs/registry/structure.md` and to this work order's blueprint
> `code:` globs, and is provisional against a repo with no code: if the
> implementer finds a file already present at one of these paths, they stop and
> log `failed` naming the drift rather than merging into it.

| File | New/Modify | Change |
|---|---|---|
| `src/app/(hosted)/robots.ts` | NEW | Two documents, two functions, **sharing no helper and no partial** (BP-047 decision 1, ADR-002's consequence: the two policies must never be merged). The customer-domain document blocks no general search engine crawler, has no blanket `Disallow`, and names BP-005's `AI_CRAWLERS` list with `Allow` — the list is a pin, so adding or removing an agent is a pins-test change and not an edit to a template string. The preview host is served a different document that disallows everything. |
| `src/app/(hosted)/sitemap.ts` | NEW | `sitemap.xml` listing exactly the live hosted pages of the site the Host resolved to — never another site's, never a page in any other state, never a preview address, and never a ReachKit-addressed URL. |
| `tests/hosted/indexing/robots.test.ts` | NEW | The customer-domain document contains no blanket `Disallow` and no rule blocking a general crawler; each of the six `AI_CRAWLERS` members appears by name with `Allow`; the preview document disallows everything; **the two documents are produced by two functions that share no helper**, asserted as a module-graph check so a later "tidy-up" that merges them fails. |
| `tests/hosted/indexing/sitemap.test.ts` | NEW | The sitemap lists exactly the site's delivered, non-unpublished hosted publications; a second site's pages are absent; an unpublished page is absent the moment its row changes; no preview address and no ReachKit address appears; a site with no live pages yields a valid empty sitemap rather than an error. |

## Interfaces

**Consumes**

- `resolveHost`, `HostDisposition` — WO-229.
- `AI_CRAWLERS` — BP-005, `src/lib/config/constants.ts`, asserted in `tests/pins.test.ts` against `BUILD.md` §9's quoted clause. **The list is a pin, not a string in a template** (BP-047 decision 3): it appears here and in BP-049's user-agent decision, and a literal here would be a second copy.
- `publications` and `sites.domain` — BP-002, WO-208.

**Exposes** — copied exactly from BP-047's `## Public interface`:

```ts
GET  https://content.{customer-domain}/robots.txt   we serve it, on their domain
GET  https://content.{customer-domain}/sitemap.xml  every live page of that site, and nothing else
```

**The six agents are GPTBot, ClaudeBot, OAI-SearchBot, Claude-SearchBot,
PerplexityBot and Google-Extended** — quoted in `BUILD.md` §9 and in REQ-059
criterion 4, held in BP-005's `AI_CRAWLERS`. Do not type them here; import the
pin.

**A little duplication between the two robots documents is kept on purpose.** A
merged helper is one edit away from serving the wrong policy on the wrong host,
and that edit reads as a tidy-up — which is why the module-graph assertion above
is a test and not a comment.

## Steps
1. Read ADR-002 before writing either document.
2. Create `robots.ts` with two exported functions, one per disposition, importing `AI_CRAWLERS` from BP-005. Share no helper between them, not even a line-joining utility.
3. Create `sitemap.ts` selecting the resolved site's delivered, non-unpublished hosted publications and nothing else.
4. Write the module-graph assertion that the two robots functions share no callee, and watch it fail against a single parameterised template (constitution §8).

## Out of scope
- The page render and its head — WO-230.
- Host resolution — WO-229.
- ReachKit's own public pages, including report pages and their sitemap policy — ADR-002 decision 1 and REQ-001 criterion 8, BP-001's.
- Adding or removing an AI agent — a pin change in BP-005 with a failing pins test until the quote is updated.

## Rollback
Delete the four files. The hosted page still renders; only the two policy documents disappear, which means crawlers see no explicit policy — acceptable briefly, not indefinitely.
