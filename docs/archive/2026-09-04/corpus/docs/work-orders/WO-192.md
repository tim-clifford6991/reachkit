## Goal
Implement the three rules about where a figure or a fact came from — the grounded statement, the rival figure that must link its source, and the figure only ReachKit holds.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/lib/generate/rules/sentences.ts` | NEW | A deterministic sentence splitter over rendered text and a link index per sentence — shared by the two sentence-scoped rules so there is one notion of "in the same sentence" in the product, not two. |
| `src/lib/generate/rules/grounding.ts` | NEW | `checkGrounding(a: { grounded: GroundedFact | null; fetchedToday: string }): RuleFailure | null` — fails where there is no grounded fact at all, or where the recorded passage does not occur word for word in the content fetched that day. There is no fallback: the report, a rival's page and the model's knowledge are not admissible sources, and no branch in this file reads any of them. |
| `src/lib/generate/rules/rivals.ts` | NEW | `checkRivalSource(a: { rendered: string; rivals: string[] }): RuleFailure | null` — a sentence naming a rival domain or rival name and containing a numeral must carry a link in that same sentence. Sentence-scoped, not paragraph-scoped (BP-042: a paragraph-wide scope lets one sourced figure legitimise three unsourced ones). Failure carries `{ rule: 'rival_source', figure }`, the numeral as it appears — a stored value, not a sentence. |
| `src/lib/generate/rules/figures.ts` | NEW | `buildPrivateFigureRegister(a: { report: StoredReport; opportunities: Opportunity[] }): string[]` and `checkPrivateFigure(a: { rendered: string; register: string[] }): RuleFailure | null` — deterministic, no model call: a numeral in the rendered text that matches a register member and carries no link in the same sentence fails, with `{ rule: 'no_private_figure', figure }`. |
| `tests/generate/rules/grounding.test.ts` | NEW | No grounded fact fails; a passage altered by one character fails; a passage present verbatim passes; a passage found only in the report or only on a rival's page fails. |
| `tests/generate/rules/rivals.test.ts` | NEW | A rival figure with a link in the same sentence passes; the same figure with the link in the next sentence of the same paragraph fails; a rival named without a numeral passes; a numeral without a rival passes. |
| `tests/generate/rules/figures.test.ts` | NEW | A ranking position drawn from the register fails unsourced and passes when the sentence links a source; a volume that happens to match a register member fails (the register is a register, not a judgement); a numeral absent from the register passes; an empty register fails nothing. |

## Steps
1. Write the three test files first and run them; each must fail on a missing module.
2. Implement `sentences.ts` first — both scoped rules import it, so "the same sentence" is defined once (rule 2.4).
3. Implement `grounding.ts`. It takes the day's fetched content as an argument and makes no network call of its own; the fetch is the pipeline's (WO-198).
4. Implement `rivals.ts` and `figures.ts`. Both run over `rendered` — the words the published page shows — and both are deterministic: no `llm()` import appears in this directory.
5. Run the tests. Then mutate: widen the rival scope to the paragraph and confirm `rivals.test.ts › the link in the next sentence fails` fails; delete the register and confirm every `figures.test.ts` case passes vacuously, which is the mutation the register test is written to catch.

## Test plan
> Watch it fail first (constitution §8): every test below is written and
> run against the absent implementation before the implementation exists.

| Acceptance criterion (verbatim from REQ) | Test |
|---|---|
| **REQ-050 c1** Given a draft is generated, when it is queued for review, then it carries at least one statement of fact drawn from a page on the customer's own live site, stored with that page's URL, the date it was read and the passage it was drawn from copied word for word from the content fetched that day; the passage is kept unchanged from then on, so the statement can still be read against it after the customer's own page has moved on. | `grounding.test.ts › a draft with no statement drawn from the customer's own live page fails` and `… a passage altered by one character fails` |
| **REQ-050 c2** Given a draft states any figure or claim about a competitor, when it is queued, then that statement links the public page it was read from, and no competitor figure appears that has no such page to link. | `rivals.test.ts › a rival figure links its source in the same sentence` and `… a rival figure with no linkable page fails` |
| **REQ-050 c3** Given a draft is queued for review, when it is checked, then it states no figure that only ReachKit holds — a ranking position, a search volume, a visibility or answer count the product measured — so every figure a reader meets on the published page is one they can open a source for. | `figures.test.ts › a figure only ReachKit holds fails unsourced` and `… the same figure passes when the sentence links a source` |

**Discriminates (mutation check, constitution §8).**
- Deleting `buildPrivateFigureRegister` and returning an empty register makes every c3 case pass — the test asserts a specific failure on a register-derived numeral, so the vacuous version fails.
- Replacing the verbatim passage comparison with a fuzzy or normalised one makes `… a passage altered by one character fails` fail.
- Broadening the link scope from sentence to paragraph fails the c2 next-sentence case.
