# WO-161 — The pages-published tile: its delta, or its goal of 30 and what reaching it means

- Branch: wo/WO-161-overview-pages-published
- Estimate: ≤1 day
- Preview: sdlc-factory/docs/design/previews/WO-161.html
- Signed-off: <date>

## Goal
Render the pages-published tile so that it leads with exactly one headline
number carrying its change since the previous measurement, or — where there is
none — its goal of 30 with the meaning key beside it, and never appears bare.

## File plan
> Every path below is **NEW** (no `src/` on disk, checked 2026-08-31). Placement
> follows `structure.md` and BP-038's `code:` globs; provisional.

| File | New/Modify | Change |
|---|---|---|
| `src/app/(account)/app/overview/PagesPublishedTile.tsx` | NEW | Renders `Module<number>` for pages published: the headline through `renderMeasured` with its delta since the previous measurement, and where there is no previous measurement, `GOALS.pages_published` — the value `30` read from BP-005's `GOAL_VALUES` through WO-156's `GOALS`, with its `meansKey` rendered through `copy()`. The number is **read, never written here**: this file contains no numeric literal for the goal, so a change to the pin moves the tile and a change to the tile cannot move the pin. |
| `tests/app/overview/pages-published.test.tsx` | NEW | Delta rendering; the goal-and-meaning render where no previous measurement exists; the never-bare property; and the discriminating case that the rendered goal equals `GOAL_VALUES.pages_published` rather than any literal in this file — change the pin and the assertion follows it. |

## Interfaces
Consumes (verbatim from BP-038 `## Public interface`):
```ts
export type GoalKey = 'searches_appeared_in' | 'ai_answers' | 'score' | 'pages_published'
/** The pairing lives here; the numbers are BP-005's `GOAL_VALUES` and are never
 *  written in this module. All four now carry a value: `pages_published` was
 *  ruled by the owner on 2026-08-31 at **30**, meaning a month of daily pages,
 *  so `value` is no longer optional and no tile renders a goalless headline. */
export const GOALS: Readonly<Record<GoalKey, { value: number; meansKey: CopyKey }>>
```
and `renderMeasured()` / `copy()` (BP-019).

Exposes: `PagesPublishedTile` inside the overview module; no new cross-node
interface.

## Steps
1. **Precondition (rule 7.3):** signed preview. As of 2026-08-31
   `docs/design/tokens.md` is `Status: ready` and `components.md` registers 24
   components, every row `proposed` and reaching `approved` only when a preview
   carrying it is signed off. The preview, not the registration, is the gate.
2. Write the failing tests first.
3. Render the headline with its delta since the previous measurement.
4. Where there is no previous measurement, render `GOALS.pages_published.value`
   beside the headline with `copy(GOALS.pages_published.meansKey)`. **Still do
   not write the number or the sentence in this file**: the value is BP-005's
   pin (`GOAL_VALUES.pages_published`, ruled 30 on 2026-08-31) and the sentence
   is the owner's, in BP-019's registry. What the ruling changed is that the
   value exists; where it lives did not change.
5. Add the discriminating test: the rendered goal is read from
   `GOAL_VALUES.pages_published`, so changing the pin changes the render and a
   literal `30` anywhere under `src/app/(account)/app/overview/` fails the test.
6. Assert the never-bare property directly: with no delta and the goal stubbed
   away the tile must not render, because `HeadlineNumber.goal` is required and
   `GOALS`' `value` is not optional (WO-156).
