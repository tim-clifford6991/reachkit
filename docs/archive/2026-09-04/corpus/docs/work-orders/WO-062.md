# WO-062 — `POST /api/scan` — the canonicaliser and starter, with a no-JavaScript path

- Branch: wo/WO-062-api-scan
- Estimate: ≤1 day

## Goal
Turn one submitted value into the canonical report address and, where admission
allows, one claimed scan — responding with a location the client navigates to,
and never with a rendered report.

## File plan

> Every path below is **NEW**. Verified 2026-08-31: this repo carries no `src/`.
> Placement per `structure.md` (`src/app/api/**` is BP-001's container and every
> file in it is transport-only, rule 1; BP-022 anchors this route). Provisional
> against a repo with no code.

| File | New/Modify | Change |
|---|---|---|
| `src/app/api/scan/route.ts` | NEW | The `POST` handler and `StartScanResponse`. A thin adapter: parse the body, call WO-051's `parseDomain`, call WO-057's `networkKeyOf` over `x-forwarded-for`, call WO-058's `claimFreeScanSlot`, and return a location. It contains no admission logic, no SQL and no rendering. Content negotiation: a JSON request gets `StartScanResponse` (422 on a malformed value); a form submission with no JavaScript gets 303 to the canonical address on success and 303 back to the landing page carrying the problem handle and the submitted value on failure. |
| `tests/app/scan-address/api-scan.test.ts` | NEW | The response, idempotence, no-JS and no-session suites named in the test plan. |

## Interfaces

Consumes: WO-051's `parseDomain` and `DomainProblem`; WO-057's `networkKeyOf`;
WO-058's `claimFreeScanSlot`.

Exposes (verbatim from BP-022 `## Public interface`):

```
Routes
  POST /api/scan                            { value: string } — start, or name what is wrong
```

```ts
// src/app/api/scan/route.ts
export type StartScanResponse =
  | { ok: true;  location: string; scanId: string }
  | { ok: false; problem: DomainProblem }                                // REQ-001 c3, HTTP 422
```

## Steps
1. Write the failing suite first.
2. Parse and validate the request body to `{ value: string }`; anything else is a
   400 with no problem handle, since it is not a visitor's typed value.
3. `parseDomain(value)`. On failure respond 422 with `{ ok: false, problem }`
   (JSON) or 303 back to the landing page with the handle and the value
   preserved (form).
4. Derive the network key from `x-forwarded-for`'s first entry and claim the
   slot. On a claim, respond `{ ok: true, location, scanId }` (JSON) or 303 to
   `location` (form).
5. On a refusal, respond `{ ok: true, location, scanId: '' }`? **No** — respond
   with the canonical location and no scan id: the refusal is shown at the report
   address on load, by WO-061's resolver and WO-069's view (REQ-003 c12). Model
   this as `{ ok: true, location }` with `scanId` present only when a scan was
   claimed, and keep the union shape BP-022 declares by returning the running
   scan's id where admission returned `in_flight` with `sameDomain: true`.
6. Make the post idempotent on the canonical domain: a double mount, a refresh
   mid-scan and two tabs all join the one running scan through
   `claimFreeScanSlot`'s in-flight arm rather than starting a second.
7. Read no session and set no cookie anywhere in the handler.
