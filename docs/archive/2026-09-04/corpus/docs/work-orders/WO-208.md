# WO-208 — The publications migration — the unique index that is the at-most-once guarantee

- Branch: wo/WO-208-publications-migration
- Estimate: ≤1 day

## Goal
Add the `publications` columns and the `unique (draft_id, destination_id)` index that make REQ-056 criterion 5 an invariant of the schema rather than a code path, with no `on delete cascade` reaching the table (ADR-080).

## File plan

> This repository carries no `src/`, no `tests/`, no `supabase/` and no
> `package.json` (verified 2026-08-31). **Every path below is NEW** — none was
> verified to exist, because none can. Placement is anchored to
> `sdlc-factory/docs/registry/structure.md` and to this work order's blueprint
> `code:` globs, and is provisional against a repo with no code: if the
> implementer finds a file already present at one of these paths, they stop and
> log `failed` naming the drift rather than merging into it.

| File | New/Modify | Change |
|---|---|---|
| `supabase/migrations/<migration-timestamp>_publications_core.sql` | NEW | The whole delta. `unique (draft_id, destination_id)`; `delivery_state text not null` constrained to `claimed | delivered | failed`; `attempt_no int not null default 0`; `claimed_at timestamptz not null`; `failure_reason text null`; `remote_id text null`; **`made_live_by_us boolean not null default false`** (ADR-082's discriminator, retained unchanged by ADR-084 Decision 4 — see the note below the interface block); **`unpublish_outcome text null`** constrained to the five members of `UnpublishResult`'s `outcome` (ADR-082 Decision 6, carried forward by ADR-084 Decision 4); `verify_due_at timestamptz null`; index `(site_id, published_at)`; partial index `(verify_due_at) where verify is null`. Every foreign key into `publications` from `drafts`, `destinations` and `sites` is declared **without** `on delete cascade` (ADR-080 decision 3), with the ADR cited in a SQL comment on each. Timestamp prefix is generated by the migration tool at authoring time; the topic token is `publications`, BP-045's under structure.md rule 3. |
| `tests/publish/attempt/schema.test.ts` | NEW | Schema assertions against a migrated test database: the unique index exists on exactly `(draft_id, destination_id)`; a second insert for the same pair is rejected by the database, not by application code; no constraint into `publications` carries `ON DELETE CASCADE`; `delivery_state` refuses a fourth value; `verify_due_at` accepts null; **`made_live_by_us` exists, is `boolean not null`, defaults to `false`, and accepts both `true` and `false`** — the `false` clause is now the one no production write path exercises (ADR-084 Decision 4 inverted which is the constant), so a column that silently refused it would never be caught by any other test; **`unpublish_outcome` accepts each of the five `UnpublishResult` outcomes and refuses a sixth**, including `named_for_removal`, which no production path can write today and which is therefore the value a narrowed constraint would quietly reject. |

**`made_live_by_us` will read as a dead column, and the reason has inverted —
read ADR-084's warning block before dropping it.** Until 2026-09-01 it was
`false` for every WordPress row and `true` for every hosted one. Since the
owner's ruling that content is published complete at every destination, the
WordPress adapter sets `status: 'publish'` on every create and returns
`madeLive: true`, so the column is now **`true` for every row this product
writes, at both destinations** — a column with one value, which is exactly what
it looks like and exactly what it is not. It is what keeps REQ-056 criterion
16's second outcome renderable at all, and it is the reason `unpublish` never
writes into a post ReachKit did not make live.

The substitution `live_url is not null` is **still wrong and has changed sign**.
ADR-081 rejected it because `live_url` was null for every WordPress row, so the
predicate classified every WordPress page as never-live. `live_url` is now
non-null for every WordPress row, so the same predicate would classify every
WordPress page as made-live-by-us — including any page a future draft-delivery
option produced, whose post ReachKit would then write into. Same substitution,
opposite failure, both wrong. Removing the column breaks no test that this
migration does not write.

**`unpublish_outcome` is not derivable and is added by this file.** ADR-082
Decision 6, carried forward unchanged by ADR-084 Decision 4: `made_live_by_us`
and `unpublished_at` together cannot separate REQ-056 criterion 16's outcomes 2,
3 and 4, because those are facts about what the last call *found* at a
destination ReachKit does not own — the post still there, the post already gone,
the site not reached. It is what the page record's written line is rendered from
(WO-263) and what the retry action reads to decide whether it is offered.
Adding it deletes nothing and is the shape ADR-080 decision 2 prescribes
("outcomes are recorded by updating …"), not an exception to it.

`verify_due_at` is BP-049's column and lands here because
`supabase/migrations/*_publications*.sql` is BP-045's glob under structure.md
rule 3 — BP-049 says so in its own data-model delta. It is created by this work
order, written by WO-213 and read by WO-232. **It is now set on every delivery
at both destinations**: the rule that sets it reads `live_url`, and since
ADR-084 a WordPress row has one (BP-045's data-model delta says so in terms).
This file creates the column and the partial index; nothing about the column
itself changed.

## Steps
1. Read ADR-080 in full before writing a line of this file. It is a landmine: every change this work order forbids reads as housekeeping and breaks no test.
2. Write the migration with the columns and indexes above.
3. Add a SQL comment on the unique index and on each foreign key naming ADR-080 and REQ-056 criterion 5, so the next reader of the schema meets the reason before the temptation.
4. Write `tests/publish/attempt/schema.test.ts` against a freshly migrated database and watch the duplicate-insert assertion fail before the unique index exists.
5. Confirm no `on delete cascade` anywhere in the file, and that no other migration in the repository adds one into `publications`.

## Test plan

Each criterion below is inherited verbatim from the requirement named in the
row, reflowed onto one line and otherwise unaltered.

| Acceptance criterion (verbatim from REQ) | Test |
|---|---|
| **REQ-056 c5** — Given a page and a destination for which a publish has already been attempted, when a publish is attempted again — including a retry of an attempt whose outcome was never confirmed, and an attempt made after the page was unpublished — then at most one post for that page exists at that destination, and a page in `unpublished` gains no post. | `tests/publish/attempt/schema.test.ts` › "a second publication row for the same (draft_id, destination_id) is refused by the database" — the insert is made directly in SQL, bypassing every application path, so the test discriminates the index and not a code branch. |
| _(not a REQ criterion)_ ADR-080 decision 3 — "No foreign key into `publications` carries `on delete cascade`". | `tests/publish/attempt/schema.test.ts` › "no constraint into publications cascades on delete" — reads `pg_constraint` and asserts `confdeltype` is never `c`. Deleting the guard makes this fail, which is the mutation check §8 requires. |
| _(not a REQ criterion)_ ADR-084 Decision 4 — the discriminator is a stored fact on the publication row, and it is now the constant-looking column. | `tests/publish/attempt/schema.test.ts` › "made_live_by_us is boolean not null default false and accepts both values" — reads `information_schema.columns` for the type, nullability and default, then inserts one row with `true` and one with `false` and reads both back. Dropping the column, or making it a generated expression over `live_url`, fails this test; nothing else in the corpus would notice, which is the whole reason the row is here. |
| _(not a REQ criterion)_ ADR-082 Decision 6, carried forward by ADR-084 Decision 4 — the last unpublish's outcome is stored, because it is not derivable. | `tests/publish/attempt/schema.test.ts` › "unpublish_outcome accepts each of the five outcomes and refuses a sixth" — five inserts and one rejection. The `named_for_removal` insert is the discriminating one: no production path writes it, so a constraint narrowed to today's reachable population would pass every other test in the corpus and fail only this. |

## Out of scope
- Any `*_drafts*.sql` file. `drafts.transitions` and `drafts.publishable_since` are BP-014's migration under structure.md rule 3 and must not be written here.
- The `destinations` topic — WO-223.
- Writing `made_live_by_us` or `unpublish_outcome`. This work order creates both columns; `publish()` writes `made_live_by_us` from `DeliveryResult.madeLive` (WO-213), the WordPress adapter reads it to choose an arm (WO-239), and `unpublish()` records the arm it got back into `unpublish_outcome` (WO-214).
- Row-level security policies — BP-002's `*_rls*.sql`.
- Any code that reads or writes these columns.

## Rollback
A down migration dropping the added columns and indexes. Note that dropping the unique index re-arms the duplicate post REQ-056 criterion 5 forbids; a rollback of this file is only safe while no publish path exists, i.e. before WO-212 lands.
