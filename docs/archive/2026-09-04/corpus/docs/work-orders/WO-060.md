# WO-060 — `stages.ts` — the six named stages, the heartbeat, and exactly one ending on the stream

- Branch: wo/WO-060-stages
- Estimate: ≤1 day

## Goal
Name every stage a running free scan advances through, emit them as work
completes rather than on a timer, keep the stream alive while a third party is
slow, and close it after exactly one ending.

## File plan

> Every path below is **NEW**. Verified 2026-08-31: this repo carries no `src/`.
> Placement per `structure.md`; `src/lib/scan/stages.ts` is BP-023's file inside
> BP-012's container. Provisional against a repo with no code.

| `src/lib/scan/stages.ts` | NEW | `StageName`, `STAGES`, `StageEvent`, `progress`. Six handles, one per dataset boundary of `BUILD.md` §6.3's free-scan list (BP-023 decision 7), ordered. A stage the ceilings cut off emits no `done:true`. No word a visitor reads appears in this file — every handle is internal. |

Exposes (verbatim from BP-023 `## Public interface`, `src/lib/scan/stages.ts`):

```ts
/** Internal handles. Every word a visitor reads is BP-019's (REQ-093 c1). */
export type StageName =
  | 'reading_your_site'        // own fetches: home + detected pricing page
  | 'reading_access_rules'     // robots.txt and the home document's reader rules
  | 'reading_your_market'      // profile + keyword_suggestions → market set + the 12 questions
  | 'checking_your_presence'   // ranked_keywords@50
  | 'asking_the_twelve'        // 12 live organic SERPs, with their AI overviews
  | 'scoring'                  // drivers, score, band, problems, first page
export const STAGES: readonly StageName[]      // exactly the six above, in order

export type StageEvent =
  | { stage: StageName; done: boolean }
  | { heartbeat: true }                                   // ≥ every 30 s
  | { ending: Ending }                                    // terminal; the stream then closes
export function progress(scanId: string): AsyncIterable<StageEvent>
```

`progress` is the narrowing of BP-012's declared
`progress(scanId: string): AsyncIterable<{ stage: StageName; done: boolean }>` —
BP-023's union adds the heartbeat and the ending arms. That refinement is
BP-023's contract and is not re-decided here.

## Steps
1. Write the failing suites first.
2. Declare `StageName` and freeze `STAGES` in order. Assert at module load that
   `STAGES.length === 6` and that every `StageName` member appears exactly once.
3. Implement `progress(scanId)` as an async iterable over the scan's recorded
   stage transitions, emitting entry and exit events per stage.
4. Add the heartbeat: if no event has been emitted for `TIMING.progressHeartbeatS`,
   emit `{ heartbeat: true }`. The heartbeat never advances a stage and never
   carries a stage name.
5. Emit exactly one `{ ending }` and then close the iterable. After the ending,
   the iterable is done — no further event of any kind.
6. On a stage the ceilings cut off, emit no `done: true` for it; the outputs are
   recorded `unmeasured / not_attempted` by the pipeline (WO-052's arm), never 0
   and never simply absent.
7. Emit the one structured log line per stage transition BP-023's NFR budget
   specifies.

| REQ-003 c5 — "Given a scan still running past 60 seconds — including when the delay is the scanned domain's own server answering slowly — when it reaches 90 seconds, then measuring stops and the visitor is shown the report of everything measured by that point, with the rest reported as unmeasured (REQ-004). | REQ-003 c11 — "… all remaining work is skipped, and the visitor is shown the report of everything measured up to that point, the skipped parts reading as not measured and the score reading as REQ-004 criterion 9 requires …" | `stages/cutoff · the spend ceiling ends the stream the same way` — the same assertions with `stoppedReason: 'spend_ceiling'`, and an assertion that no stage after the cut-off emits any event at all. |
| REQ-003 c4 — "Given a scan that cannot complete at all, when it ends, then the visitor is told in one written line that the measurement failed and is offered a manual retry (the retry window is REQ-001's)." | `stages/ending · exactly one ending, then the stream closes` — over all four `Ending` shapes: exactly one `{ending}` event is emitted, it is the last event, and pulling the iterable again yields done.
