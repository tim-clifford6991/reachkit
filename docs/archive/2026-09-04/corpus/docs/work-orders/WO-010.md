# WO-010 — RLS default-deny policies and the two policy invariants CI holds

- Branch: wo/WO-010-rls
- Estimate: ≤1 day

## Goal
Write the row-level policies that make every table default-deny and make a
tombstoned account unreachable through `db()` — and the two checks that fail when
either guarantee is removed.

## Provenance of this file plan
**This repository holds no `supabase/`.** Every path is NEW, anchored to BP-002's
`code:` glob `supabase/migrations/*_rls*.sql`.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `supabase/migrations/00000000000002_rls.sql` | NEW | Adds `users.deleted_at timestamptz` (see `rests-on`), then one policy set per table created in WO-009. Every request-scoped policy restricting a row to its owning user also carries the condition that the owning user's `deleted_at` is null. No policy grants anon read of `scans`. |
| `tests/db/rls.test.ts` | NEW | The two invariants below, asserted against the applied schema rather than against the SQL text. |

## Interfaces
Consumes: the schema WO-009 applied. Exposes: no code interface — the guarantee
is the schema. BP-002's `## Public interface` (`db()`, `dbAdmin()`) is WO-011's.

## Steps
1. Add the `deleted_at` column.
2. Write one policy per table per operation, each naming the owning user.
3. Add the `deleted_at is null` condition to every request-scoped policy.
4. Write the two invariant tests. Watch each fail first: drop one table's policy
   for the first, remove the condition from one policy for the second.

| BP-002 error behaviour: "A policy that lacks the `deleted_at is null` condition is a CI failure, not a review comment: the guarantee has one point of failure and the test fails when the condition is removed from **any** policy, not merely when the happy path passes." | Same file — enumerates every request-scoped policy and asserts the condition is present in each; then, behaviourally, tombstones a fixture user and asserts every owned row is invisible through the request-scoped client across select, insert, update and delete. |
| BP-002 error behaviour: "The public report is served by `dbAdmin()` from the server, never by an anon read of `scans` — `scans` carries `cost_cents` and the raw report blob, neither of which a stranger may read." | Same file — an anon-key select on `scans` returns zero rows and no error text naming a column. |

## Out of scope
- Setting `deleted_at`, the 30-day purge, and every rule about when an account is
  tombstoned — BP-063.
- ADR-051's reasoning. It is cited, never restated (rule 2.4).
- `domain_blocks` policies — WO-012 writes the table and its policy together.

## Rollback
Reverting this migration returns every table to "RLS on, no policy", which is
unreadable rather than open — the safe direction. Do not revert WO-009 without
also reverting this one.
