# WO-164 — The month read: ten states onto five stages, one page a date, and the stage counts

- Branch: wo/WO-164-calendar-month
- Estimate: ≤1 day

## Goal
Map the ten publish states onto the five stages by one total table, and read a
month of site-local day cells with exactly one page or one empty account each,
plus the per-stage counts.

## File plan
> Every path below is **NEW** (no `src/` on disk, checked 2026-08-31;
> `00-project.md`: "Greenfield. No source code on disk yet"). Placement follows
> `structure.md` and BP-039's `code:` globs; provisional.

| File | New/Modify | Change |
|---|---|---|
| `src/app/(account)/app/calendar/stages.ts` | NEW | `Stage` and `STAGE_OF` — the exhaustive map over REQ-056's ten states, `null` meaning the state occupies no date. `failed` maps to Scheduled; `needs_attention` is the only state mapping to Needs you (BP-039 decision 1). |
| `src/app/(account)/app/calendar/month.ts` | NEW | `DayCell` and `readMonth()` — the month's drafts joined to their opportunities, resolved into day cells in `sites.time_zone`, plus `counts` for All and each of the five stages from the same result. ## Interfaces
Consumes: `TRANSITIONS` and `PublishState` (BP-015/BP-045), `nextForDay()` and
`supplyDepth()` (BP-013/BP-041), `accountFor()` (WO-165), `sites.time_zone`
(BP-002's `sites`), `Measured<T>` (BP-010).

Exposes (verbatim from BP-039 `## Public interface`):
```ts
/** REQ-043 criterion 2's five stages. Closed. */
export type Stage = 'live' | 'your_review' | 'scheduled' | 'planned' | 'needs_you'

/** The exhaustive map from REQ-056 criterion 1's ten states. Total over the
 *  union: `null` means the state carries no page on a date, and the date is
 *  resolved by `accountFor` instead. REQ-043's non-goal hands this mapping here. */
export const STAGE_OF: Readonly<Record<PublishState, Stage | null>>
// planned -> planned          generating -> planned
// in_review -> your_review    approved -> scheduled     publishing -> scheduled
// failed -> scheduled         needs_attention -> needs_you
// published -> live           skipped -> null           unpublished -> null

export interface DayCell {
  date: Date                                                          // site-local day
  page: { draftId: string; title: string; stage: Stage } | null
  empty: EmptyAccount | null                                          // exactly one of page / empty
}
export function readMonth(a: { siteId: string; month: string /* YYYY-MM, site-local */ }):
  Promise<{ days: readonly DayCell[]; counts: Readonly<Record<Stage | 'all', number>> }>
```

## Steps
1. Write the failing tests first (§8).
2. Declare `STAGE_OF` exactly as the comment above; add an exhaustiveness check
   so a new `PublishState` fails compilation here rather than defaulting.
3. Implement `readMonth` as two queries — the month's drafts with their
   opportunity join, and one supply-depth count — plus one stopped-work lookup;
   budget p95 ≤ 300 ms.
4. Compute day boundaries in `sites.time_zone` once per request; never render a
   grid against UTC days.
5. Assert `DayCell` carries exactly one of `page` / `empty`; a second draft on a
   date is surfaced as a data defect, not rendered.
6. Assert this module writes nothing: there is no code path here that creates a
   draft.
7. Mutation check: map `failed` to `needs_you` and confirm the stage test fails;
   drop the time-zone conversion and confirm the UTC+13 day test fails.
