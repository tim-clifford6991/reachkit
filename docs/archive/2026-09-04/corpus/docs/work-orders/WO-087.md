# WO-087 — sizeRivals and dueForResizing — one entry per rival, a date on every band, and two unsized states

- Branch: wo/WO-087-size-rivals
- Estimate: ≤1 day

## Goal
Implement `src/lib/market/sizing/size.ts` so every tracked rival gets exactly one entry in
input order — sized with its counts, its date and whether that measurement is current, or
unsized for one of two named reasons — and never disappears from the array.

## Context an implementer needs
No source code exists on disk; both paths below are NEW.

The first `rests-on` row above is inherited verbatim from BP-052's front-matter and is open:
it bounds `rankedCount`'s ceiling, not whether this WO may be built. If refuted, the fix is
shared with REQ-041 and is not owned here.

**No new spend site** (BP-052's `## NFR budget`): sizing reads the rows the paid deep and
monthly passes already buy — `rankedKeywords(rows: 100)` per rival, inside `CAPS.DEEP_C` 150¢
and `CAPS.WEEKLY_C` 40¢. **Paid path only.** BUILD §6.4's never-pull list forbids per-rival
`ranked_keywords` on the free path, and BP-052's `## Error & edge behavior` holds that by the
module graph rather than a runtime check: nothing here is reachable from BP-026's free-report
card, and the test plan asserts the absence of that import edge in both directions.

**No band is ever stored as an independent column** (BP-052 decision 1). `report.rivalSizes`
stores the counts, the date and the derived band together, and re-derivation from the stored
counts must reproduce the stored band.

plus `Measured<T>` (BP-010), `CostContext` (BP-007), `RivalSizeBand` and `bandRivalSize`

**Exposes** — copied exactly from BP-052's `## Public interface`:

```ts
// src/lib/market/sizing/size.ts
export type RivalSize =
  | { domain: string; state: 'sized'
      rankedCount: number; band: RivalSizeBand; at: Date; current: boolean }
  | { domain: string; state: 'unsized'
      because: 'awaiting_deep_pass' | 'added_since_last_sizing' }
export function sizeRivals(c: CostContext, a: { rivals: string[]; ownRanked: number }):
  Promise<Measured<RivalSize[]>>            // one entry per input rival, in input order
export function dueForResizing(a: { lastMeasuredAt?: Date; now: Date }): boolean
```

## Steps
1. `sizeRivals` returns **exactly one entry per input rival, in input order**. There is no code
   path in this module that filters, reorders, excludes, hides or truncates one — that absence
   is how criterion 7 is held, and the test asserts the array's length and order over every
   arm, including failures.
2. Per rival: `rankedKeywords(c, { domain, rows: RANKED_RIVAL_ROWS })`, then
   `rankedCount` from the returned rows' total count, then
   `band = bandRivalSize({ rivalRanked: rankedCount, ownRanked: a.ownRanked })`.
3. `ownRanked` is the customer's own measured count from the **same pass** and is handed in
   with the rivals. Stamp one `at` for the whole call, so a band can never mix a rival's count
   from one pass with a customer count from another.
4. `current` is `true` for a count measured in this call. A rival whose rows could not be
   fetched **keeps its previous `sized` entry with the earlier date and `current: false`** — it
   never falls back to `unsized`, which would read as "we have never measured this" about a
   rival we have. The caller supplies the previous entry; where it does, this function carries
   it forward unchanged but for `current`.
5. The two unsized reasons: `'awaiting_deep_pass'` for a rival settled at setup before the pass
   completed, `'added_since_last_sizing'` for one added afterwards. The `unsized` arm carries
   **no** band and **no** count, so a surface cannot print a band for a rival that has none.
6. `dueForResizing({ lastMeasuredAt, now })` is true when `lastMeasuredAt` is absent or is
   `CACHE_WINDOWS_D.rival` days or more before `now` — one number, not two; the literal 30 does
   not appear in this file.
7. Emit the observability fields BP-052 names: per rival, the two counts, the derived band, the
   measurement date, and whether it was a re-measurement or a first sizing.
8. Write the tests; watch each fail first.
