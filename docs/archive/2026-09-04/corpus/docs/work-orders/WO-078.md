# WO-078 — deriveRivals — the §6.6 partition, the score, and a total tie-break

- Branch: wo/WO-078-derive-rivals
- Estimate: ≤1 day

## Goal
Implement `src/lib/market/rivals/derive.ts` so the rival set is counted over the twelve
SERPs the scan already bought — at zero extra cost, identical at 0 and at 10,000 ranked
searches for the customer, and in a byte-identical order on every run.

## Context an implementer needs
No source code exists on disk; both paths below are NEW. **This module buys nothing.**
BUILD §6.6: "Zero extra cost". It must never call BP-008, and the test plan asserts the
absence of that import path. Cold start is the path, not a branch: the derivation counts
over the market's SERPs and never reads the customer's own rankings.

## File plan
| File | New/Modify | Change |
|---|---|---|

## Interfaces
**Consumes**: `SerpResult` (BP-008), `registrableDomain` / `isPlatformDomain` /
`isOwnDomain` (WO-077, quoted there verbatim), `BATTERY.COMPETITORS_MAX` (BP-005).

**Exposes** — copied exactly from BP-026's `## Public interface`:

```ts
// src/lib/market/rivals/derive.ts — BUILD §6.6, zero extra cost
export interface RivalCandidate {
  domain: string
  top10Appearances: number
  aiCitations: number
  score: number                    // top10Appearances + 2 × aiCitations
}
export function deriveRivals(a: { serps: SerpResult[]; ownDomain: string }):
  { rivals: RivalCandidate[]; sources: string[] }   // rivals: top 5 by score; sources: platform hits
```

## Steps
1. For each SERP, walk the organic top ten and the `ai_overview` references, mapping every
   host through `registrableDomain`; drop nulls.
2. Drop every domain for which `isOwnDomain(domain, ownDomain)` — before scoring, so a
   customer's own hosted page never becomes their own rival.
3. Partition: `isPlatformDomain` ⇒ the domain accumulates into `sources` and **never** into
   `rivals`. `sources` is the de-duplicated list of platform domains hit, in first-seen order.
4. Count `top10Appearances` (once per SERP per domain, never twice for two results on one
   SERP) and `aiCitations` (once per SERP per domain).
5. `score = top10Appearances + 2 * aiCitations`.
6. Sort by the four-key total order BP-026 decision 3 fixes: `score` desc, then `aiCitations`
   desc, then `top10Appearances` desc, then `domain` ascending. Take the first
   `BATTERY.COMPETITORS_MAX`.
7. Emit the observability fields BP-026 names: candidate count before and after the platform
   partition, and rival count kept.
8. Write the tests; watch each fail first.

Determinism, required by BP-026's `## NFR budget` ("identical `SerpResult[]` in,
byte-identical card and rival order out"):
`deriveRivals/total-order-under-ties` — six domains with an identical `score` return in the
order the four-key comparator dictates, and a shuffled input produces the identical output.

Zero cost, required by BUILD §6.6 and BP-026's `## NFR budget` ("**0¢.** Nothing here buys
anything"): `deriveRivals/buys-nothing` — `derive.ts` resolves no import into
`src/lib/vendors/`, `src/lib/costs/` or `src/lib/llm/`, and the signature takes no
`CostContext`.

Discrimination: dropping the `domain` tie-break, counting a domain twice on one SERP, or
letting a platform domain into `rivals`, must each fail a named test above.
