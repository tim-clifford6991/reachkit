## Goal
Implement the three rules about the text itself: the brand's absence from the opening a reader meets, the markup a reader would never see, and the sentence written for a machine.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/lib/generate/rules/brandgap.ts` | NEW | `checkBrandGap(a: { rendered: string; businessName: string | null; domain: string }): RuleFailure | null` — fails where the business name or the domain appears, in any letter case, within the first 300 characters of the rendered text. Runs over `rendered` (the words the published page shows), never over the Markdown that produces them. The 300 is REQ-050's own number, carried in its first `rests-on`. |
| `src/lib/generate/rules/hidden.ts` | NEW | `checkHiddenText(a: { markdown: string }): RuleFailure | null` — runs over the Markdown **and the markup embedded in it**, because the rule is about what would be handed to the destination: off-screen positioning, zero sizing, background-matching colour, comments, and alt/caption/title text carrying anything but a description of what it labels. A hyperlink and its address are exempt (c2 and c4 both require links). |
| `src/lib/generate/rules/machine.ts` | NEW | `checkMachineAddress(a: { rendered: string }): RuleFailure | null` — applies BP-005's `MACHINE_ADDRESS_PATTERNS` to the rendered text. Config, not constants in code, so a form found later is added in one file; no `llm()` import appears here (BP-042 decision 1 bars a model judge as the enforcement). |
| `tests/generate/rules/brandgap.test.ts` | NEW | The name at character 299 fails and at 301 passes; upper, lower and mixed case all fail; the domain fails as the name does; a Markdown link whose visible words do not name the brand passes though the URL contains the domain — the rule reads what the reader reads. |
| `tests/generate/rules/hidden.test.ts` | NEW | Each embedded form fails on its own fixture; an ordinary hyperlink with its address passes; alt text describing its image passes and alt text carrying a sentence about the brand fails; an HTML comment fails. |
| `tests/generate/rules/machine.test.ts` | NEW | One fixture per pinned pattern, each failing; a sentence addressed to a reader that mentions an assistant passes; the pins are read from `constants.ts` and an empty pattern list makes the suite fail rather than pass vacuously. |

## Steps
1. Write the three test files first and run them; each must fail on a missing module.
2. Implement `brandgap.ts` and `machine.ts` over `rendered`; implement `hidden.ts` over `markdown`. Which text each rule reads is a promise, not an implementation detail: c6 says "the words the published page shows, not the Markdown syntax that produces them" and c7 says "the text ReachKit would hand to the destination".
3. `machine.test.ts` asserts `MACHINE_ADDRESS_PATTERNS.length > 0` before its cases, so an empty pin list fails the suite instead of making every case pass.
4. Record no new pattern in code. A form found later is added to BP-005's pin list by BP-005's work order, not here.
5. Run the tests. Then mutate: run `brandgap` over the Markdown instead of the rendered text and confirm the link-URL case fails.

| Acceptance criterion (verbatim from REQ) | Test |

| **REQ-050 c6** Given a draft is generated, when it is checked, then the customer's brand — the business name and the domain recorded for their site — is not named, in any letter case, within the first 300 characters of the page as a reader reads it: the words the published page shows, not the Markdown syntax that produces them. | `brandgap.test.ts › the brand named at character 299 fails, at 301 passes`, `… any letter case fails`, `… the rule reads the rendered words, not the Markdown` |
| **REQ-050 c7** Given a draft is generated, when it is checked, then the text ReachKit would hand to the destination — the draft's Markdown and any markup embedded in it — carries nothing a reader of the published page would not see: no embedded markup positioning text off-screen, sizing it to zero or colouring it to match its background, no comment, and no alternative text, caption or title text carrying anything but a description of what it labels. A hyperlink and the address it points at are not text this criterion restricts — criteria 2 and 4 both require a draft to carry links. | `hidden.test.ts › each embedded form fails` and `… a hyperlink and its address pass` |
| **REQ-050 c8** Given a draft is generated, when it is checked, then it carries no sentence addressed to a machine reader rather than a human one — no instruction, directive or assertion aimed at an assistant, a crawler or a ranking system about how to treat, cite, rank or recommend the page. | `machine.test.ts › one fixture per pinned pattern fails` and `… a sentence addressed to a reader passes` |
| **REQ-050 c12** Given the customer edits a draft, when the edited text names their brand within its first 300 characters, then the edit is saved and neither held nor stopped for it: criteria 6 to 8 bind what ReachKit generates, not what the customer writes on their own site. | `brandgap.test.ts › the module exports only a check over generated text and is not reachable from an edit path` — the saving of an edit is REQ-045's and BP-044's; this row records the boundary these three rules must not cross |

**Discriminates (mutation check, constitution §8).**
- Emptying `MACHINE_ADDRESS_PATTERNS` makes `machine.test.ts` fail at its guard assertion rather than passing every case — the vacuity this rule is most exposed to.
- Swapping `rendered` for `markdown` in `brandgap` makes the link-URL case fail; swapping the other way in `hidden` makes the comment case pass and its test fail.
- Exempting alt text wholesale makes `hidden.test.ts › alt text carrying a sentence about the brand fails` fail.
