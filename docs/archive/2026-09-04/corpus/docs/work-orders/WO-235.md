# WO-235 — The published message — the live address and all four outcomes, sent whether they passed or failed

- Branch: wo/WO-235-published-telling
- Estimate: ≤1 day

## Goal
Ship `tellingFor()`: the occasion and payload for the `published` message, sent on the same occasion whichever of the three outcomes the one check recorded — with a failed check, an absent page and an unconfirmed check none of them a reason to send nothing.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/publish/verify/telling.ts` | NEW | `PublishedTelling`, `tellingFor(publicationId)`. Returns the live address, the whole recorded `VerifyOutcome`, `failed: readonly CheckId[]`, the `SiteCondition` where criterion 6 recorded one, and **one of three copy keys** — `mail.published.verified`, `mail.published.notFound`, `mail.published.notConfirmed` — selected by the outcome's arm and by nothing else. `failed` is **non-empty only under `found`, and possibly empty then**; under the other two arms it is empty **because there are no check outcomes at all**, which the mail states in their place and never alongside them (criterion 5's last sentence). **Exposes** — copied exactly from BP-049's `## Public interface`:

```ts
// src/lib/publish/verify/telling.ts
/** REQ-062 criterion 5. One message on the same occasion whichever of the three
 *  outcomes was recorded — a failed check, an absent page and an unconfirmed
 *  check are none of them a reason to send nothing. */
export interface PublishedTelling {
  publicationId: string
  liveUrl: string
  result: VerifyOutcome
  /** Non-empty only under `found`; possibly empty then. Never a reason not to
   *  send. Under the other two arms it is empty **because there are no check
   *  outcomes at all**, which the mail states in their place and never
   *  alongside them (criterion 5's last sentence). */
  failed: readonly CheckId[]
  /** Criterion 5: named separately from the page's own outcomes, and only where
   *  criterion 6 recorded one. */
  siteCondition: SiteCondition | null
  copy: 'mail.published.verified' | 'mail.published.notFound' | 'mail.published.notConfirmed'
}
export function tellingFor(publicationId: string): Promise<PublishedTelling>
```

**Three keys, and two of them must stay two — ADR-085 (landmine).**
`page_not_found` and `could_not_confirm` render as the same grey line and have
opposite consequences everywhere else in the product: one retires the page from
weekly judgement forever, the other leaves it fully judged and shown as it was
(ADR-085 Decision 4's table). A reviewer looking at two nearly identical mail
lines will propose one key. The one-key-per-arm assertion in the file plan is
what fails when they do; nothing else in this module would notice, because both
arms carry the same fields except the discriminant.

**The recorded outcome goes in place of the four outcomes, never alongside
them.** Criterion 5's last sentence says so in terms. Carrying an empty `failed`
list beside a `page_not_found` result would read to a template as "four checks,
none failed" — which is the opposite of what was recorded. `failed` is empty
under those arms **because there is nothing to report**, and the payload carries
no `checks` field at all for a template to reach for.

## Steps
1. Create `verify/telling.ts` with the block above verbatim.
2. Select the copy key from the outcome's arm and from nothing else. **Three arms, three keys.** Do not derive one key with a variable in it.
3. Compute `failed` as the checks whose value is a measured `false`, **inside `found` only**. An `unmeasured` check is not a failure — it was not observed. Under the other two arms `failed` is empty and there is no `checks` field.
4. Carry `siteCondition` only where criterion 6 recorded one; `null` otherwise, and never rendered as "the site is fine" (WO-262).
5. Return the same shape and the same occasion in all four fixtures. Add no branch that suppresses on any outcome.
6. Write the "sent on the same occasion in all three arms" test first and watch it fail against an implementation that returns nothing when a check failed or when no page was found (constitution §8).
7. Mutate: give `page_not_found` and `could_not_confirm` the same copy key, and confirm the one-key-per-arm row — and only that row — fails.
