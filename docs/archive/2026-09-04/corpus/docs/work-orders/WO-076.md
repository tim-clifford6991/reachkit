# WO-076 — buildAiAnswersCard — the answer matrix, its denominator and its five invariants

- Branch: wo/WO-076-ai-answers-card
- Estimate: ≤1 day

## Goal
Implement `src/lib/market/questions/matrix.ts` so the AI-answers card's view model is
assembled from SERPs the scan already bought, with one cell per question, two counts that
can only be read against what was measured, and no field an instruction or a severity could
be written into.

## Context an implementer needs
No source code exists on disk; both paths below are NEW. This module **buys nothing**: it
reads the `Measured<SerpResult>[]` the scan already paid for. Citation matching uses
BP-026's `registrableDomain` (WO-077) — one implementation of domain normalisation in the
product, not two (rule 7.1); `capabilities.md` names BP-026 as its owner.

**Exposes** — copied exactly from BP-025's `## Public interface`:

```ts
// src/lib/market/questions/matrix.ts — REQ-006's card, assembled from SERPs already bought
export type AnswerCell =
  | { kind: 'answered'; citedDomains: readonly string[]; namesCustomer: boolean }
  | { kind: 'no_answer' }
  | { kind: 'unmeasured'; reason: 'undeterminable' | 'not_attempted' }
export interface AiAnswersCard {
  measuredSearches: number              // n — REQ-006 criterion 1's denominator
  answeredSearches: number              // m of n — AI answers appeared on m
  customerCitations: number             // over m, never over n
  rows: readonly { question: Question; cell: AnswerCell }[]
}
export function buildAiAnswersCard(a: {
  questions: Question[]; serps: Measured<SerpResult>[]; ownDomain: string
}): AiAnswersCard
```

## Steps
1. Pair each `Question` with the `Measured<SerpResult>` for its `question.search.keyword`,
   in question order. `rows.length === questions.length` always.
2. Cell derivation, one arm each:
   - the `Measured` arm is `unmeasured` ⇒ `{ kind: 'unmeasured', reason }`, carrying BP-010's
     own reason (`'undeterminable' | 'not_attempted'`). It lowers `n` and is **never** counted
     as a place the customer was ignored.
   - the SERP returned no `ai_overview` ⇒ `{ kind: 'no_answer' }`, excluded from both counts.
   - otherwise `{ kind: 'answered', citedDomains, namesCustomer }`, where `citedDomains` is
     the `references` payload mapped through `registrableDomain` (nulls dropped, order
     preserved, exact duplicates collapsed once) and `namesCustomer` is true when any
     reference `isOwnDomain(host, ownDomain)`. An `ai_overview` citing no domain is
     `answered` with `citedDomains: []` — the card says the answer named no brand; it does
     not become `no_answer`.
3. `measuredSearches` = rows whose cell is not `unmeasured`.
   `answeredSearches` = rows whose cell is `answered`.
   `customerCitations` = rows whose cell is `answered` and `namesCustomer` — so it is
   counted over `m`, never over `n`.
4. Add no field to `AiAnswersCard` and to `AnswerCell` beyond the union above. There is no
   severity, no warning level, no advice, no tip and no recommendation field, so a surface
   cannot render one (the same structural guarantee BP-026 decision 1 records for its card).
5. Emit the observability field BP-025 names: per-cell outcome kind.
6. Write the tests; watch each fail first.
