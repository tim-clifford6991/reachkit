# WO-120 — sites provisioning columns — the domain, the report behind the purchase, and when the domain was set

- Branch: wo/WO-120-sites-provisioning-migration
- Estimate: ≤1 day

## Goal
Add the three additive `sites` columns and the one-site-per-account index BP-031's
data-model delta names, under the `sites_provisioning` sub-token.

## File plan
> **Every path below is NEW.** No `supabase/` exists in this repository. Anchored
> to `registry/structure.md` rule 3a (`*_sites_provisioning_*` inside BP-017's
> `*_sites*`) and BP-031's `code:` globs. Provisional against a repo with no code.

| File | New/Modify | Change |
|---|---|---|
| `supabase/migrations/<ts>_sites_provisioning_columns.sql` | NEW | `alter table sites add column domain text null` (null until setup for a scanless purchase), `provisioned_from_scan_id uuid null references scans(id)` **with no `on delete cascade`** (ADR-051 point 2), `domain_set_at timestamptz null`. Add `create unique index sites_one_per_user on sites (user_id)` — the partial unique index BP-031 names as "one site per account". Add an index on `(id, domain)` supporting `siteMeasurementState`'s read. `<ts>` is the implementer's `YYYYMMDDHHMMSS`; the filename carries exactly one sub-token. |
| `tests/account/offer/schema.test.ts` | NEW | Asserts the three columns exist with the stated types and nullability; that a second `sites` row for one `user_id` is refused; that the `provisioned_from_scan_id` foreign key carries no cascade; and that no column named anything like `has_measurement` or `measured` exists on `sites` (BP-031 decision 1: "No `measured` boolean exists to be left true" — the test makes the absence enforceable rather than remembered). |

## Interfaces
Consumes: `db()` · `dbAdmin()` (BP-002). Consumes the `scans` table, which is
BP-012's topic — this migration references it and does not alter it.

Exposes: no TypeScript surface. The columns are the substrate for WO-122 and
WO-123.

## Steps
1. Write the migration.
2. Write `tests/account/offer/schema.test.ts` and watch it fail.
3. Apply and re-run; regenerate BP-002's `Database` types as a side effect.

## Out of scope
- Writing any of the three columns — WO-122 and WO-123.
- `sites` columns owned by other sub-tokens: `*_sites_hosting_*` (WO-130),
  `*_sites_erasure_*` (WO-140).
- The baseline `sites` table and its RLS policies — BP-002's.

## Rollback
Drop the index and the three columns in a follow-up migration. Reversing after
WO-122 has run in an environment discards recorded site domains — the account's
identity, not a cache.
