# WO-104 — The register of nine mail kinds as a typed constant

- Branch: wo/WO-104-mail-kinds-register

- Estimate: ≤1 day

## Goal
Land `MAIL_KINDS` and `MailKind` as the typed constant BP-016 declares, so that a
send on an unregistered occasion does not compile.

## Provisional against an empty repo
**No `src/` exists.** Both files NEW. `src/lib/mail/kinds.ts` is named
explicitly in BP-053's `code:` list and in ADR-040 point 3.

Reuse check (rule 7.2): `registry/capabilities.md` row "The register of nine mail
kinds, the omission rule and the shell — `src/lib/mail/` — BP-053 (register
declared by BP-016) — `MAIL_KINDS` · `composeMail()` · `sendEmail()`". BP-016
declares the rows; this WO is the leaf that ships them, which is exactly the
declaring/implementing relation the index's preamble describes. Nothing to reuse;
one thing to transcribe.

## Scope note — the two halves of criterion 6
REQ-064 criterion 6 has two halves, and this order carries both. The
**compile-time** half — "a mail on any other occasion is never sent", enforced by
`MailKind` being the keys of this constant — is `register-shape.test.ts`. The
**corpus-legality** half — every `occasionsFrom` names a requirement that exists
and is `approved` (BP-053 decision 4; BP-016 decision 1's "a test asserts every
row names at least one approved requirement") — is `register-legality.test.ts`.
It was held on REQ-064's second `REVIEW` line from 2026-08-31; that line is
closed (REQ-064's `## Open questions` is empty; BP-053 is `blocked-by: []` and
its discharge section names the history file), and the test lives in
`tests/mail/kinds/**`, the directory this order already writes. Released
2026-09-03.

## Interfaces
**Exposes** (verbatim from BP-016 `## Public interface`):
```ts
export const MAIL_KINDS = {
  'magic-link':     { occasionsFrom: 'REQ-024, REQ-077', stoppable: false },
  'first-page':     { occasionsFrom: 'REQ-010 criterion 3', stoppable: false },
  'first-page-unavailable':
                    { occasionsFrom: 'REQ-010 criteria 7 and 8', stoppable: false },
  'nurture':        { occasionsFrom: 'REQ-010 criterion 9',  stoppable: 'opt-out' },
  'draft-ready':    { occasionsFrom: 'REQ-057',          stoppable: 'toggle',
                      unsuppressibleWhen: 'autopilot at a veto window of zero (REQ-057 criterion 7)' },
  'published':      { occasionsFrom: 'REQ-062',          stoppable: 'toggle' },
  'weekly':         { occasionsFrom: 'REQ-063, REQ-065', stoppable: 'toggle' },
  'setup-reminder': { occasionsFrom: 'REQ-025',          stoppable: false },
  'account':        { occasionsFrom: 'REQ-024, REQ-074, REQ-076, REQ-077, REQ-079', stoppable: false },
} as const
export type MailKind = keyof typeof MAIL_KINDS
```
And (verbatim from BP-053 `## Public interface`):
```ts
export type KindRow = {
  occasionsFrom: string                 // requirement ids; asserted approved by test
  stoppable: false | 'toggle' | 'opt-out'
  unsuppressibleWhen?: string
}
```
**Consumes**: nothing. This file must import nothing — `structure.md` rule 6 and
BP-059 decision 1 both depend on it being importable type-only without creating a
cycle.

## Steps
1. Write `register-shape.test.ts` first and watch it fail.
2. Write `register-legality.test.ts` against the requirements corpus and watch it
   fail on a fixture row whose `occasionsFrom` names an id no file carries.
3. Transcribe the constant. Change no string in it; the `occasionsFrom` values are
   BP-016's and any edit is drift the librarian logs.
4. Confirm the file has zero imports (a lint assertion or a test on the source
   text is acceptable; the property is what matters).
5. Mutation check: delete a row and confirm the shape test fails on the key count
   and the key set, not only on the count; point a fixture row at a `draft`
   requirement and confirm the legality test fails on status, not only on
   existence.

## Out of scope
- The register-to-directory bijection — ADR-040 point 1's "a directory with no
  register row, or a register row with no directory, fails BP-053's register
  test", and decision 4's "every `MailKind` reachable from a template appears in
  the register". With no `src/lib/mail/templates/<kind>/` on disk every row
  would fail it, and six of the nine directories have no work order yet
  (BP-016's `rests-on` row). It joins `register-legality.test.ts` when the ninth
  directory lands; the trigger is BP-016's, not a `REVIEW` line.
- The send seam (WO-106).
- Adding, renaming or removing a row. `MAIL_KINDS` is BP-016's declaration; a
  tenth kind is a change to that node.
