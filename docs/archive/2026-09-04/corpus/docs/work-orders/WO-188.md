## Goal
Add the one column supply needs and implement `supplyDepth` — days of pages, which is open non-`fix` rows, and the date supply hit zero.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `supabase/migrations/20260901091000_opportunities_supply.sql` | NEW | Adds `status_changed_at timestamptz not null default now()` to `opportunities` and the `before update` trigger that maintains it when `status` changes. That is the only new column: no counter, no `supply_depth` column, no materialised view (BP-013 decision 2), and no `sites.supply_arrival_told_scan_id` (BP-041's data-model delta says why). |
| `src/lib/opportunities/supply/depth.ts` | NEW | `supplyDepth(siteId)` — `unused` is `count(*) where status = 'open' and family <> 'fix'`, served off WO-181's partial index; `exhaustedSince` is `max(status_changed_at)` over that site's opportunities when `unused` is 0, falling back to the completion time of the site's most recent completed scan where the site has never held one, and `null` whenever `unused > 0`. One indexed count, plus one `max()` in the exhausted case only. |
| `tests/opportunities/supply/depth.test.ts` | NEW | Against a migrated database: four open `unblock` rows and no others give `unused: 0`; a mix gives the non-`fix` count; `exhaustedSince` is null while `unused > 0`; it is the moment the last non-`fix` row left `open` when `unused` is 0; a site that never held one falls back to its latest completed scan's time; the count issues one query. |

## Steps
1. Write `depth.test.ts` first and run it: it must fail on a missing column and a missing module.
2. Write the migration. The trigger sets `status_changed_at = now()` only when `new.status is distinct from old.status`, so an unrelated update does not move the date `exhaustedSince` reads.
3. Implement `depth.ts`. The predicate `status = 'open' and family <> 'fix'` appears once in this file and is imported by everything else that reads depth (BP-041 decision 1; BP-013 decision 2's amendment).
4. Run the tests. Then mutate: drop `and family <> 'fix'` and confirm the all-`unblock` fixture reports four days of pages instead of zero.

**Discriminates (mutation check, constitution §8).**
- Counting every open row makes the all-`unblock` fixture report four days of pages — the precise failure REQ-095 was written against, and the test asserts zero.
- Setting `status_changed_at` on every update rather than on a status change makes the `exhaustedSince` date move under an unrelated edit; the test updates a non-status column and asserts the date did not move.
- Adding a cached counter column would leave every test green until it drifted, which is why BP-013 decision 2 forbids one and the file plan states its absence.
