# WO-255 — `assembleReport` and `storeCurrentReport`

- Branch: wo/WO-255-assemble-store
- Estimate: ≤1 day

## Goal
Compose a `StoredReport` from a scan's stage outputs so that no section can be
omitted, and land it in one transaction that inserts the scan row and moves the
current-report pointer, so that a failed pass leaves the previous report and its
date exactly where they were.

## Provenance of this file plan
**This repository holds no `src/`.** All three paths are NEW. `src/lib/scan/` is
BP-012's row in `structure.md` and `store.ts` is claimed by no leaf (BP-023's
`code:` names four files, BP-036's is `deep/**`, BP-050's is `weekly/**`);
`tests/scan/report/**` likewise.

**Why the write half is its own file and its own work order.** BP-013's
`deriveOpportunities(c, { siteId, scanId, report: StoredReport, ownRanked })`
takes the **assembled** report as an argument, so `runScan` must compose in
memory before it can derive and must store after. Assembly is therefore a pure
function with its own totality contract, and storage is a transaction with its
own concurrency contract; splitting them is what lets WO-256 be an
orchestration and nothing else.

**Reuse check (rule 7.2).** No file-plan row in the corpus names
`src/lib/scan/store.ts` or any composer of the blob, and `capabilities.md` has
no row for it — the nearest, "One current stored report per domain", is the read
(WO-254). This work order creates the write half of that same capability, in the
same module, under the same owning node; it mints no second seam.

**Status.** Left `status: draft` — written and not self-certified in the same
pass. A later audit sets the status against §3's gate list.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/lib/scan/store.ts` | **NEW** | `ReportSections`, `assembleReport` and `storeCurrentReport` (below). `assembleReport` is **pure and total**: it takes one argument object with a required member per `StoredReport` section, so a section a stage never produced is a compile error rather than a missing key, and the caller must pass the `Measured` arm that says why. It computes nothing — no score, no rate, no count, no band — and re-derives no figure (BP-012 decision 3: "This node composes and stores; it defines none of the section shapes and re-derives no figure"). It derives exactly two fields from what it is given: `complete`, which is `stoppedReason === 'complete'`, and `version`, the one blob version this build writes. `storeCurrentReport` runs **one** transaction: insert or update the scan row with its `report jsonb`, `score`, `drivers`, `stopped_reason`, `correction_state` and `supersedes_scan_id`; clear `is_current` on the domain's previous current row; set `is_current` on this one. The flip is the commit point. A `stoppedReason` of `'failed'` **never** sets `is_current` and never clears the previous one — the previous report and its date are untouched. No trigger, no advisory lock, no `select … for update`: the partial unique index is the constraint (BP-012 decision 1). |
| `tests/scan/report/assemble.test.ts` | **NEW** | The totality, no-re-derivation and never-omitted suites. |
| `tests/scan/report/store.test.ts` | **NEW** | The transaction, pointer-flip, failed-scan and concurrency suites. |

## Interfaces

**Consumes:** `StoredReport`, `Tier` and `readCurrentReport` from WO-254's
`src/lib/scan/report.ts`; `Measured<T>` and its combinators from WO-052;
`db()` / `dbAdmin()` from BP-002 (WO-008). Every section type is imported
through `report.ts` and re-declared nowhere.

**Exposes:**
```ts
/** One required member per section of BP-012's `StoredReport`. Required, not
 *  optional, and that is the whole point: BP-012's own comment on the type says
 *  "A section that could not be measured is present with its `Measured` arms
 *  saying so — a section is never omitted, because an absent key and a
 *  `not_attempted` value read the same to a consumer and REQ-004 forbids that."
 *  An optional member here would make that sentence a convention; a required
 *  one makes it a compile error. */
export interface ReportSections {
  scanId: string
  domain: CanonicalDomain
  measuredAt: Date
  tier: Tier
  stoppedReason: 'complete' | 'time_ceiling' | 'spend_ceiling' | 'failed'
  fromIncompleteRescan: boolean
  verdict: Verdict
  market: Measured<SuggestionRow[]>
  questions: Measured<Question[]>
  answers: AiAnswersCard
  serps: readonly Measured<SerpResult>[]
  rivals: Measured<RivalCandidate[]>
  rivalSizes: Measured<RivalSize[]>
  onPage: OnPageFacts
  robots: Measured<RobotsPolicy>
  correctionState: CorrectionState
}

/** Pure and total. Derives `version` and `complete` and copies the rest. No
 *  arithmetic, no clock, no I/O. */
export function assembleReport(s: ReportSections): StoredReport

/** BP-012 decision 1's "single transaction that inserts the new scan and flips
 *  the pointer". Returns the status the pipeline reports. A `failed` report
 *  never becomes current. */
export function storeCurrentReport(a: {
  report: StoredReport
  siteId?: string
  supersedesScanId?: string          // a correction supersedes the scan it corrects
  degraded: boolean                  // BP-007's `CostContext.degraded()`, carried not recomputed
}): Promise<{ scanId: string; status: 'done' | 'degraded' | 'failed' }>
```

## Steps
1. Write both test files first and run them; every case must fail on a missing
   module (constitution §8, "Watch it fail first").
2. Declare `ReportSections` with every member required. Do not give any member a
   default and do not accept a partial: the type is the enforcement.
3. Implement `assembleReport` as a copy plus the two derived fields. Assert at
   source that the file contains no arithmetic operator applied to a section
   value, no `Date.now`, no `new Date()` with no argument and no `await`.
4. Implement `storeCurrentReport` as one transaction in the order BP-012
   decision 1 fixes: write the row, clear the previous pointer, set this one.
   Branch on `stoppedReason === 'failed'` **before** touching either pointer.
5. Derive `status` totally: `'failed'` where `stoppedReason` is `'failed'`;
   `'degraded'` where the pass was degraded or `complete` is false; `'done'`
   otherwise. One expression, no `default` arm that swallows a fourth case.
6. Mutate to prove the suite discriminates: (a) make one `ReportSections` member
   optional and confirm the totality row fails to compile; (b) clear the
   previous pointer before writing the new row and confirm the crash-between
   case leaves the domain with no current report; (c) set `is_current` for a
   `failed` report and confirm the REQ-001-c17 row fails.

| BP-012 `## Public interface`: "`measuredAt: Date // one date; every figure under it is this scan's`" | `… › the report carries exactly one date and it is the caller's` — the assembled blob's `measuredAt` equals the argument's, and a source assertion that `store.ts` reads no clock. | BP-012 decision 1: "`unique (domain) where is_current` plus **a single transaction** that inserts the new scan and flips the pointer." | `tests/scan/report/store.test.ts › the insert and the flip are one transaction` — a doubled db asserts exactly one `begin`/`commit` pair and that the row write precedes both pointer statements; a fault injected after the row write and before the flip leaves the domain's previous current report intact and no new current row. |
| BP-012 decision 1 `## Consequences`: "the flip is the commit point; anything that fails before it leaves the customer's report untouched, which is exactly the promise." | `… › a failed pass changes nothing a reader can see` — storing a report with `stoppedReason: 'failed'` for a domain that already has a current report leaves that report, its `measuredAt` and its `is_current` flag unchanged, and `readCurrentReport` returns the old one. Discriminates: setting `is_current` unconditionally replaces a good report with a failed one. |
| BP-012 `## Error & edge behavior`: "The current-report pointer moves only when a new scan has produced a report, so a failed re-scan or a failed correction leaves the previous report and its date exactly where they were (REQ-001 criterion 17). **The partial unique index makes \"two current reports for one domain\" unrepresentable.**" | `… › two concurrent stores for one domain leave exactly one current` — two `storeCurrentReport` calls for one domain run against the real index; one commits, the other is rejected by the constraint and is retried or reported, and exactly one `is_current` row exists afterwards. A source assertion that no advisory lock and no `for update` appears — the index is the enforcement, not the code. |
| BP-012 `## Error & edge behavior`: "Both ceilings end in a stored report whose outstanding work is `unmeasured / not_attempted`, never 0." — **the storage half** | `… › a ceiling stores a report and marks it incomplete` — a `time_ceiling` and a `spend_ceiling` report each store, each become current, each carry `complete: false`, and each return `status: 'degraded'`. A ceiling report is stored, not discarded: the customer gets back what was measured. |
| BP-012 `## Public interface`: "`export function runScan(…): Promise<{ scanId: string; status: 'done' \| 'degraded' \| 'failed' }>`" — **the status this file derives for it** | `… › the three statuses are total and exclusive` — a table over `stoppedReason` × `degraded` asserting the status for every combination, with no combination unreachable and no fourth value. Discriminates: a `default` arm returning `'done'` hides a case rather than failing on it. |
