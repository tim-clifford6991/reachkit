# WO-148 — The incomplete-setup gate: one allow-list, and the way out is never gated

- Branch: wo/WO-148-setup-gate
- Estimate: ≤1 day

## Goal
Expose `SETUP_INCOMPLETE_ALLOWLIST` and the one gate predicate that redirects an
unfinished founder to `/setup` while keeping Settings, cancel, resume, export,
invoices, sign-out and delete reachable — and takes a finished founder onward.

## File plan
> Every path below is **NEW** (no `src/` on disk, checked 2026-08-31). Placement
> follows `structure.md` and BP-033's `code:` globs; provisional.

| File | New/Modify | Change |
|---|---|---|
| `src/app/(account)/setup/allowlist.ts` | NEW | `SETUP_INCOMPLETE_ALLOWLIST` as a readonly tuple, and `isAllowedWhileIncomplete(path)` — a first-match over it, with `/api/account/*` matched as a prefix. The default for an unlisted account route is blocked (BP-033 decision 4). |
| `src/app/(account)/setup/gate.ts` | NEW | `setupRedirectFor({ userId, path })` — returns `'/setup'`, `'/app'` or `null` from `readSetupState` plus the allow-list. One place, consulted by the `(account)` layout; it contains no per-route branch. |
| `tests/app/setup/gate.test.ts` | NEW | Redirect matrix over complete/incomplete × allow-listed/not; cancellation path parity. |

## Interfaces
Consumes (verbatim from BP-033 `## Public interface`):
```ts
export type SetupState =
  | { complete: false; siteId: string; paidAt: Date }
  | { complete: true;  siteId: string; completedAt: Date }
export function readSetupState(userId: string): Promise<SetupState>
```

Exposes (verbatim from BP-033 `## Public interface`):
```ts
/** REQ-025 criterion 5's exception, expressed as data rather than as an `if`
 *  repeated in every route. Anything not matched here redirects to /setup while
 *  setup is incomplete. */
export const SETUP_INCOMPLETE_ALLOWLIST: readonly string[]
// ['/setup', '/app/settings', '/api/settings', '/api/export', '/api/account/*', '/api/stripe/portal']
```

## Steps
1. Write the failing redirect-matrix test first.
2. Declare the allow-list verbatim as the six entries above.
3. Implement `setupRedirectFor`: complete + `/setup` → `/app`; incomplete +
   allow-listed → no redirect; incomplete + anything else → `/setup`.
4. Assert that the cancellation taken from Settings with setup unfinished runs
   the identical BP-017 call a finished customer's does — the test asserts the
   same function is reached with the same arguments, so there is no
   setup-aware branch to add later.
5. Mutation check: remove `/app/settings` from the tuple and confirm the
   "Settings stays reachable" test fails.
