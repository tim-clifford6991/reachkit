### 3. Mutation gap found — criterion 4's test does not discriminate removal of the `type.css` import

One mutation did **not** fail: **removing `import "@/ui/type.css";` from `src/app/layout.tsx`** leaves the entire suite green — `npm test` 395/395, `npm run typecheck` clean, `npm run build` clean, and `tests/app/layout.test.ts` itself 6/6. Reproduced twice, independently.

This matters because it is the exact deviation the implementer's own report flags as load-bearing (Deviation 2, disposed below): `src/ui/fonts.ts` only loads font bytes and exports the class name `"rk-fonts"`; the `--font-ui`/`--font-mono` custom-property *bindings* live solely in `src/ui/type.css`'s `.rk-fonts` rule, and `grep -rn "type.css"` across `src/` and `tests/` shows `src/app/layout.tsx` is the only file in the tree that imports it. If that one import line is deleted, the class `"rk-fonts"` still lands on `<html>` (nothing binds it to any CSS in the compiled output) and, in a real browser, neither font variable would actually be bound — yet no test in the suite would catch the regression.

The test suite proves two things separately — (a) `<html>` carries the class named `fontVariables`, and (b) `type.css`, read directly off disk, has a `.rk-fonts` rule binding both variables — but never proves the third fact that makes (a) and (b) compose into the criterion: that `layout.tsx` actually imports `type.css`. The file-plan-imports `describe` block in `tests/app/layout.test.ts` checks this exact pattern for `theme.css` and for `fonts.ts` (both regex-asserted against `layoutSource()`, both independently reproduced failing when I removed them, §2 above) but has no equivalent row for `type.css`.

This is a vacuous-test finding under constitution §8 / the validator's own charge ("a test that survives deletion of its feature is vacuous and is itself a finding") — not a defect in the shipped code (`type.css` **is** imported today, so the criterion holds as built) but a real, demonstrated gap in the regression protection for acceptance-criterion row 4 of this WO's own test plan.

**Fix:** add one more assertion to the `layoutSource()` `describe` block in `tests/app/layout.test.ts`, of the same shape as the existing `theme.css`/`fonts.ts` checks — `expect(layoutSource()).toMatch(/import\s+["']@\/ui\/type\.css["']/)` — so a future removal of the import fails loudly instead of silently.
