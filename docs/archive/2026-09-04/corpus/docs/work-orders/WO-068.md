# WO-068 — The report arm — the verdict strip, the one notice, the one control, and the module order

- Branch: wo/WO-068-report-view
- Estimate: ≤1 day
- Preview: sdlc-factory/docs/design/previews/WO-068.html
- Signed-off: <date>

## Goal
Render the `report` arm of the address union: one verdict strip at the top, at
most one written notice, exactly one control or none, the report's modules in
`BUILD.md` §4.1's order, and the removal address at the foot.

## File plan

> Every path below is **NEW**. Verified 2026-08-31: this repo carries no `src/`.
> Placement per `structure.md`; `_address/` is BP-022's private folder inside
> BP-001's `src/app/(public)/**`. Provisional against a repo with no code.

| File | New/Modify | Change |
|---|---|---|
| `src/app/(public)/scan/[domain]/_address/report-view.tsx` | NEW | `ReportView`, over WO-061's `{ kind: 'report' }` arm. Renders (1) the verdict strip: domain, measurement date, score and band through `renderMeasured` and `SCORE_BANDS`, and the three factor mini-bars, each named and each with its own value or a dash; (2) at most one `AddressNotice`, as a total switch; (3) exactly one `AddressControl`, as a total switch, `none` rendering nothing; (4) the module slots in `BUILD.md` §4.1's order, with modules 3 and 4 filled by WO-066 and modules 2, 5 and 6 as named slots; (5) the copy-link control; (6) `RemovalAddressLine` at the foot. Contains no string literal a person reads and no branch on payment, session or tier. |
| `tests/app/scan-address/report-view.test.tsx` | NEW | The verdict, notice, control, order and no-paywall suites named in the test plan. |

## Interfaces

Consumes: WO-061's `AddressState`, `AddressControl`, `AddressNotice`; WO-055's
`Verdict`, reached through BP-012's declared `StoredReport.verdict` (decision 3,
2026-08-31 — the blob has a shape now, and this file reads it by field rather
than through a reader interface of its own); WO-053's `sectionOutcome`; WO-066's
cards and `MethodSections`; WO-067's `RemovalAddressLine`; BP-019's `copy()`,
`renderMeasured()`, `SCORE_BANDS`; BP-018's registered components. Per
`design/components.md`, the strip is a composition over registered rows and
mints nothing: the band is `Badge` (required text child), the three driver
mini-bars are `Progress` ("not a sixth chart"), the copy-link control is `Btn`,
and `ReportView` is named there as a screen composition that "must not become" a
registry row.

Exposes:

```tsx
// src/app/(public)/scan/[domain]/_address/report-view.tsx
export function ReportView(p: {
  state: Extract<AddressState, { kind: 'report' }>
  slots: {                                  // sibling nodes' modules, absent-safe
    aiAnswers?: JSX.Element
    googlePresence?: JSX.Element
    freePage?: JSX.Element
    pricing?: JSX.Element
  }
}): JSX.Element
```

The module order, verbatim from `BUILD.md` §4.1: "1. **Header strip** (card):
domain · date · category · score (big mono, band badge) · three driver mini-bars ·
Copy link. 2. **Two equal cards, side by side** … 3. **Three problem cards**
(grid) … 4. **DIY collapses** (3) … 5. **Free page card** … 6. **Pricing card**".

## Steps
1. Produce the preview artifact at the path in the display bullets above and hold
   in draft until it is signed off (rule 7.3).
2. Write the failing suites first.
3. Render the verdict strip from the stored `Verdict`: `scoreAndBand` through
   `renderMeasured`, the band word from `SCORE_BANDS[handle]`, the three factors
   each named and each rendered through `renderMeasured`. On the `unmeasured`
   arm render the dash, render no band element at all, and render the one line
   naming every missing factor with its reason's key.
4. Render `notice` as a total switch over `AddressNotice | null` — at most one
   line, ever.
5. Render `control` as a total switch over `AddressControl` — `none` renders
   nothing; every other arm renders exactly one control.
6. Render the modules in order, omitting a slot that is absent and rendering a
   section that `sectionOutcome` reports `present: false` as absent with one
   written line naming it — never an empty card and never a spinner.
7. Render the copy-link control, whose value is the canonical address and which
   carries no token and no expiry.
8. Render `RemovalAddressLine` at the foot of every report.
