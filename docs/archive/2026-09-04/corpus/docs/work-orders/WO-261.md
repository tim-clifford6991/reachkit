# WO-261 — classify() — a whitelist of two statuses, never a blacklist, and identity decided apart from readability

- Branch: wo/WO-261-verify-answer
- Estimate: ≤1 day

## Goal
Ship `src/lib/publish/verify/answer.ts`: the one place an answer from a page's own public address becomes one of REQ-062 criterion 4's three outcomes, decided by a whitelist of exactly two statuses, plus the identity test that separates "not our page" from "our page whose body we cannot read".

| File | New/Modify | Change |
|---|---|---|
| `src/lib/publish/verify/answer.ts` | NEW | `classify` and `isOurPage`. **`classify` is a whitelist of two statuses and never a blacklist of failures** (ADR-085 Decision 2): `404` and `410` — and no other status — return `page_not_found`; **every other answer returns `could_not_confirm`, including one this function does not recognise**, because the default arm must be the one that asserts nothing. `status: null` (no HTTP answer at all) is `could_not_confirm` with `why: 'unreachable'`; a 5xx is `'server_error'`; a `finalUrl` that is not this page's address after redirects is `'redirected_away'`; a 2xx whose document fails `isOurPage` is `'not_our_page'`; a 2xx whose document passes returns `{ outcome: 'found', html }`. **Pure** — no fetch, no clock, no database; it takes the answer and returns an arm. `isOurPage` decides identity from a canonical link or `og:url` resolving to `requestedUrl`, or, where the document declares neither, a normalised `<title>` match against the published title — **and never from `bodyCoverage`** (BP-049 decision 4). |
| `tests/publish/verify/answer.test.ts` | NEW | **The whitelist rows:** `404` and `410` are `page_not_found`; **a table of every other status the fixtures cover — `200` non-page, `301`, `302`, `403`, `418`, `451`, `500`, `502`, `503`, `599` and `null` — is `could_not_confirm`**, asserted as a table rather than case by case so a new status cannot be added to the wrong arm by omission; **an unrecognised status falls to `could_not_confirm`** — the property assertion, run over a generated sweep of every integer status in `100..599` outside `{404, 410}`. **The blacklist mutation:** rewriting `classify` as "anything that is not a 2xx is `page_not_found`, except this list" passes the two whitelist rows and fails the sweep. **The identity rows:** a document whose canonical link resolves to `requestedUrl` is ours; one whose `og:url` does is ours; one declaring neither but whose normalised `<title>` matches is ours; one declaring none of the three is `not_our_page`. **The identity/readability split rows:** a **JavaScript-gated fixture that declares a matching canonical link is `found`** — not `not_our_page` — so the `aiReadable` check that exists to catch it can actually run; and a **parked-page fixture with no canonical, no `og:url` and a rewritten title is `not_our_page`**, though its body coverage is identical to the JavaScript-gated one's. That pair is the whole of BP-049 decision 4 and neither half passes without the other. **A source assertion that this module never imports `bodyCoverage`.** |

## Interfaces

**Consumes**

- `NotConfirmed` — `src/lib/publish/types.ts` (WO-206), declared in BP-045's leaf and re-exported by BP-049's `verify.ts` (BP-045 decision 9).
- Nothing else. This module makes no fetch, reads no row and holds no clock.

**Exposes** — copied exactly from BP-049's `## Public interface`:

```ts
// src/lib/publish/verify/answer.ts
/** ADR-085 Decision 2: a **whitelist of two statuses**, never a blacklist of
 *  failures. An answer this function does not recognise is `could_not_confirm`,
 *  because the default arm must be the one that asserts nothing. */
export function classify(a: {
  status: number | null            // null = no HTTP answer at all
  finalUrl: string | null          // after redirects
  requestedUrl: string
  html: string | null
  publishedTitle: string
}): { outcome: 'found'; html: string } | { outcome: 'page_not_found'; status: 404 | 410 }
 | { outcome: 'could_not_confirm'; why: NotConfirmed }

/** decision 4. Is this document the page we published, independently of whether
 *  we can read its body? Canonical link or `og:url` resolving to `requestedUrl`
 *  is sufficient; where the document declares neither, a normalised `<title>`
 *  match. This is what keeps a JavaScript-gated page in `found` — failing
 *  `aiReadable`, which is the whole point of that check — instead of
 *  disappearing into `not_our_page`. */
export function isOurPage(html: string, a: { requestedUrl: string; publishedTitle: string }): boolean
```

**A whitelist, and the reason is the direction of the default — ADR-085
(landmine).** A blacklist admits an unclassified answer into `page_not_found` by
default, and `page_not_found` is the arm with the expensive consequence: it stops
the page being shown as live (REQ-060 criterion 2) and **retires it from weekly
judgement forever** (REQ-063 criterion 6, ADR-072 — nothing restores it).
`could_not_confirm` asserts nothing and costs nothing. So the default arm must be
the one that asserts nothing, and the two statuses that mean "no such page" are
enumerated rather than everything else being enumerated. The generated sweep in
the file plan is what makes that a property rather than a preference: it is not
possible to write a blacklist that passes it.

**`could_not_confirm` is final, not pending, and is never retried.** REQ-062's
non-goal says it in terms. Nothing in this module schedules anything — it is
pure — and `dueNow` (WO-232) selects only rows with no recorded outcome, which is
where that promise is actually held. Named here because a reader of this file is
exactly the person who will think a `could_not_confirm` deserves a second look.

**Identity is not readability, and one number cannot decide both** (BP-049
decision 4). A parked page, a soft-404 and a login wall return almost none of the
draft's tokens — and **so does a correctly published page whose body is behind
client JavaScript, which is exactly the failure `aiReadable` exists to find**. One
threshold cannot serve both, and whichever way it is set, one of the two promises
breaks silently. So identity is decided from the document's *own declaration of
itself* — canonical, `og:url`, title — which a CMS emits in server-rendered
markup even where it withholds the body, and readability is `bodyCoverage`
(WO-233), evaluated only after identity holds. BP-049 rejects "a second, much
lower coverage floor for identity" in terms: it is one measurement with two pins
and the gap between them is unfalsifiable.

The failure direction is chosen and recorded: a page whose CMS emits no
canonical, no `og:url` and a rewritten title reads as `not_our_page` when it is in
fact ours. **That is the safe direction — it asserts nothing.**

## Steps
1. Read **ADR-085** in full, warning block first, then BP-049 decision 4. Every simplification this module invites is one of that file's landmines.
2. Create `answer.ts` with the block above verbatim. Keep it pure: no import of `safeFetch`, no clock, no database.
3. Write `classify` as an explicit two-member whitelist. **Write the `could_not_confirm` return as the function's final, unconditional fall-through**, so an unhandled answer reaches it structurally and not by a `default:` somebody can reorder.
4. Write `isOurPage` reading canonical link, then `og:url`, then normalised `<title>`. **Do not import `bodyCoverage` into this file** — assert its absence in test.
5. Order the checks in `classify` so identity is asked only of a 2xx that answered: status first, then `finalUrl`, then `isOurPage`.
6. Write the generated status sweep first and watch it fail against a blacklist implementation (constitution §8). Then write the JavaScript-gated / parked-page pair and watch the second fail against an implementation that decides identity from coverage.
7. Mutate, and confirm each fails: swap the whitelist for a blacklist (sweep fails); decide identity from `bodyCoverage` (the JavaScript-gated fixture becomes `not_our_page` and that row fails); give `page_not_found` a third status (the sweep fails).

## Out of scope
- Fetching anything. `verifyLive` makes the one `safeFetch` and hands the answer here — WO-234. This module is pure.
- Producing the four checks. They are the `found` arm's and are WO-234's; `bodyCoverage` is WO-233's.
- `checkedAt`, and the serialisation of `VerifyOutcome` into `publications.verify` — WO-234.
- Deciding whether a check is due, and never running one twice — WO-232.
- The site condition — WO-262. This module never looks at a sitemap or a robots document.
- **Retrying, rescheduling or re-running anything.** Forbidden, not merely out of scope (ADR-085 Decision 3, REQ-062's non-goal): "not confirmed" is a final outcome for that page, not a pending one.
- **What the two not-measured arms do downstream.** `page_not_found` retires the page from weekly judgement forever; `could_not_confirm` does not, and the page goes on being judged with the outcome shown beside the verdict. ADR-085 Decision 4's table states both and BP-051 holds them; this module records neither consequence.
- Every customer-visible string. ADR-085's Open questions record that the `page_not_found` line and the `could_not_confirm` line are **two sentences, not one, and neither may name a cause** — owner-owed, and nothing here mints them. This module returns an arm and a `NotConfirmed` token for the log and the copy key.
- The WordPress REST error mapping. BP-048's `errors.ts` (WO-236) maps answers about **a post id ReachKit holds**; this maps an answer about **a page a reader went to**. BP-048 says it in terms: the two look alike, run against the same host, mean different things, and **must not be merged**.

## Rollback
