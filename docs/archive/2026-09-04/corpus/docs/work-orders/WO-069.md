# WO-069 — `GET /scan/{domain}` — the route, the total view switch, `noindex`, and the 308

- Branch: wo/WO-069-report-route
- Estimate: ≤1 day
- Preview: sdlc-factory/docs/design/previews/WO-069.html
- Signed-off: <date>

## Goal
Serve the one public report address: resolve it, redirect a non-canonical form,
render exactly one arm of the closed union, mark every response `noindex`, and
never answer with a blank page, a 404 or an unhandled error.

## File plan

> Every path below is **NEW**. Verified 2026-08-31: this repo carries no `src/`.
> Placement per `structure.md`; `page.tsx` and `_address/` are BP-022's inside
> BP-001's `src/app/(public)/**`. Provisional against a repo with no code.

| File | New/Modify | Change |
|---|---|---|
| `src/app/(public)/scan/[domain]/page.tsx` | NEW | The route: derive the network key from `x-forwarded-for`, call `canonicalRedirect` and issue a 308 where it returns a target, otherwise call `resolveAddress` and hand the state to the view switch. Sets `noindex` as both a meta tag and an `X-Robots-Tag` header on every response, and sets no CDN cache. Serves the `removed` arm with HTTP 200. Renders no module itself. |
| `src/app/(public)/scan/[domain]/_address/view.tsx` | NEW | The total switch over `AddressState`: `malformed`, `scanning`, `starting`, `refused` and `cooldown` are rendered here; `report` delegates to WO-068's `ReportView` and `removed` to WO-067's `RemovedView`. The `starting` arm renders the progress shell and posts `/api/scan` on first frame — never during server render. The `scanning` and `starting` arms subscribe to WO-063's SSE stream and swap in the report without a reload. Every line is a `CopyKey`. |
| `tests/app/scan-address/route.test.tsx` | NEW | The status, header, redirect and no-session suites. |
| `tests/app/scan-address/view.test.tsx` | NEW | The totality, per-arm rendering and progress-swap suites. |

## Interfaces

Consumes: WO-061's `resolveAddress`, `canonicalRedirect`, `AddressState`;
WO-057's `networkKeyOf`; WO-063's SSE route; WO-067's `RemovedView`; WO-068's
`ReportView`; BP-019's `copy()`; BP-018's registered components.

Exposes (verbatim from BP-022 `## Public interface`):

```
Routes

```

## Steps
1. Produce the preview artifact at the path in the display bullets above and hold
   in draft until it is signed off (rule 7.3).
2. Write the failing suites first.
3. Implement the route: network key, `canonicalRedirect` → 308, else
   `resolveAddress` → view switch.
4. Set `noindex` as a meta tag and as an `X-Robots-Tag` header on every response
   of this route, including the redirect, the removal line, the malformed line,
   the refusal, the cooldown and the progress shell. Read `decisions/ADR-002.md`
   before touching this: the `noindex` policy and the absent sitemap are that
   decision's, and this node implements them.
5. Implement the switch as a total `switch` over `AddressState.kind` with a
   `never` default, so a new arm fails the build.
6. Implement the `starting` arm: render the progress shell server-side, and post
   `/api/scan` from the client on first frame. Nothing is posted during server
   render.
7. Implement the progress swap: subscribe to `/api/scan/{scanId}/progress`, and
   on the `ending` event replace the progress view with the report without a
   reload.
8. Set no CDN cache header on this route: the `refused` and `scanning` arms
   depend on the visitor, so the render is not shared.

## Test plan

> Criteria are copied verbatim from `requirements/REQ-001.md`,
> `requirements/REQ-002.md` and `requirements/REQ-003.md`; line breaks are
> normalised to fit the table and no word is changed.

| Acceptance criterion (verbatim from REQ) | Test |
|---|---|
| REQ-001 c5 — "Given a report address for a well-formed domain, when a visitor opens it directly, then what loads is always one of three readable things — a stored report, a scan in progress, or one written line saying why there is no report for them to read — and never a blank page, a 404, or an unhandled error." | `route/status · every arm answers 200 with a body` — over every `AddressState` arm, the route responds 200 (or 308 on the redirect path) with a non-empty rendered body; no fixture produces a 404, a 500 or an empty document. And `view/switch · the switch is total` — a `never` default makes an unmapped arm a build failure, asserted by a compile-error fixture. |
| REQ-001 c4 — "Given a report address whose domain segment is not a well-formed public domain name, when it is opened, then one written line names what is wrong with it and the visitor is offered the landing field — never a blank page, an unhandled error, or a scan." | `view/malformed · one line and the landing field` — for each `DomainProblem`, the page renders one written line resolved from that problem's key and a landing field; asserted no scan was claimed, by spy. |
| REQ-001 c2 — "… then they arrive at the single public report address for that domain; no two of those forms produce different addresses or different stored reports." | `route/redirect · a non-canonical segment 308s once` — each non-canonical written form responds 308 to the canonical address; following the redirect once reaches a 200 and no second redirect. |
| REQ-001 c8 — "Given any report address, when a search engine or other crawler requests it, then the page tells it not to index the page, and no sitemap the product publishes lists any report address; the report stays reachable by its link to anyone who has it." | `route/noindex · every response carries noindex twice` — every arm's response carries the `X-Robots-Tag: noindex` header *and* the meta tag, including the 308; and `route/noindex · no sitemap names a report address` — a repository-wide assertion that no sitemap source under `src/` emits a `/scan/` path. And `route/noindex · the link still works` — a request carrying no referrer and no cookie still receives the report. |
| REQ-001 c6 — "Given the report address for a domain, when a visitor with no session, no cookie, and no prior visit opens it, then the full report is readable without signing in or paying." | `route/no-gate · no session, no cookie, no gate` — the route sets no `Set-Cookie`, reads no session, and renders the full report for a bare request; a source assertion that neither file imports an auth or account module. |
| REQ-001 c9 — "… then a scan for that domain is already underway with no further action from the visitor …" | `view/starting · the post happens on first frame, never on the server` — server-rendering the `starting` arm makes no call to `/api/scan`, asserted by spy; mounting the client component issues exactly one post; mounting it twice issues one further post that joins the running scan rather than starting a second. |
| REQ-003 c1 — "Given a scan is running — however it started … when the visitor watches the page, then it shows named stages that advance as work completes, never an unlabelled spinner or an indeterminate bar alone." | `view/scanning · named stages, never a bare spinner` — the `scanning` arm renders one labelled element per `StageName` from copy keys, advancing on stage events; a heartbeat event changes no stage label; asserted that no indeterminate progress element renders without a stage label beside it. |
| REQ-003 c3 — "Given a scan that completes while the visitor is watching, when it finishes, then the report replaces the progress view without the visitor reloading." | `view/scanning · the ending swaps in the report in place` — feeding the SSE stream a `report` ending replaces the progress view with `ReportView` in the same document, with no navigation and no reload, asserted by watching for a location change and finding none. |
| REQ-003 c12 — "Given a visitor refused under criterion 6 or 7 at the report address of a domain with no stored report, when the address loads, then it shows that refusal in writing and starts no scan — never a blank page, a 404, or an error (REQ-001 criterion 5) …" | `view/refused · the refusal is written at the address, and nothing starts` — for each refusal reason, the `refused` arm renders one line from that reason's key, with an elapsed duration where the refusal carries one and none where it does not; asserted 200, and asserted by spy that no scan was claimed. |
| REQ-001 c16 — "Given a domain whose scan failed without producing a report less than 24 hours ago, when its report address is opened, then one written line says what happened and a manual retry control is offered, and no scan starts by itself." | `view/cooldown · one line, one retry, nothing automatic` — the `cooldown` arm renders one line and exactly one retry control; asserted that no scan is claimed on load and that no timer re-attempts. |
| REQ-002 c3 — "Given a domain whose report has been removed, when its report address is opened, then it shows the removed report to nobody and starts no scan for anyone …" | `route/removed · 200, the line, and no scan` — the `removed` arm responds HTTP 200 (never 404 and never 410), renders WO-067's `RemovedView`, and claims no scan; asserted also that the response carries `noindex`. |
