# WO-017 — Job definitions — lead/nurture and account/maintenance

- Branch: wo/WO-017-lifecycle-jobs
- Estimate: ≤1 day

## Goal
Register the follow-up sequencer and the fifteen-minute maintenance tick — the
seventh id BP-003 decision 1 added — so the four clock-triggered obligations no
read path can serve have a trigger.

## Provenance of this file plan
**This repository holds no `src/`.** Every path is NEW under BP-003's `code:`
glob `src/jobs/**`. `src/jobs/index.ts` is modified, and this work order is
sequenced after WO-016 for that reason.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/jobs/lead-nurture.ts` | NEW | Event plus delay: 24h / 72h / 168h from `NURTURE_H`. Idempotency key `(lead_id, touch_index)` — **per-touch dedupe inside a sequence, not the sequence key**; the sequence key `(lower(email), domain)` and its partial unique index are BP-029's and are consumed, never re-implemented here. Not kill-switch guarded (outside the scope). |
| `src/jobs/account-maintenance.ts` | NEW | Every 15 minutes from `MAINTENANCE_TICK_MINUTES`. One tick, five due-work queries, **no domain logic**: each returned subject is handed straight back to the node that owns the rule. Not kill-switch guarded — BP-003 states halting it would hold a purge, withhold a hosting notice and strand a paid founder. |
| `src/jobs/index.ts` | MODIFY | Appends the two definitions; `jobs` now holds exactly seven. |
| `tests/jobs/lifecycle-jobs.test.ts` | NEW | The tests below. |
