# WO-179 — The settings read: the fourteen values, destination health, and the mail-kind register

- Branch: wo/WO-179-settings-read
- Estimate: ≤1 day

## Goal
Assemble `SettingsModel` from one read of `sites`, `destinations` and `users`,
with notification toggles projected from the stoppable subset of `MAIL_KINDS`
rather than hand-written.

## File plan
> Every path below is **NEW** (no `src/` on disk, checked 2026-08-31). Placement
> follows `structure.md` and BP-055's `code:` globs; provisional.

| File | New/Modify | Change |
|---|---|---|
| `src/app/(account)/app/settings/read.ts` | NEW | `SettingsModel` and `readSettings(siteId)` — one read of `sites`, `destinations` and `users`; no measurement, no vendor call, no model call. Carries the market `effectKey`, the publishing `outcomeKey` for the selected pair, competitor suggestions from BP-011, and destination health as a **state** (`ok` / `expired` / `error`), never an error. |
| `src/app/(account)/app/settings/notifications.ts` | NEW | Projects the notification rows from BP-016's `MAIL_KINDS`, filtered to the kinds that register as stoppable. A mail kind added without a stoppability flag cannot render a toggle; a stoppable kind cannot go unlisted (BP-055 decision 4). |
| `tests/app/settings/read.test.ts` | NEW | The model's fields, the read budget, health as a state. |
| `tests/app/settings/notifications.test.ts` | NEW | Projection from the register; an unstoppable kind never appears; a new stoppable kind appears with no code change here. |

## Interfaces
Consumes: `MAIL_KINDS` (BP-016/BP-053), `deriveRivals()` for suggestions
(BP-011), `listDestinations()` / `checkHealth()` (BP-015/BP-058),
`billingSummary()` (BP-017/BP-060), `db()` (BP-002).

Exposes (verbatim from BP-055 `## Public interface`):
```ts
export function readSettings(siteId: string): Promise<SettingsModel>
export interface SettingsModel {
  market: { category: string; suggestions: readonly string[]; effectKey: CopyKey }
  competitors: readonly string[]                       // <= 5
  domain: string
  publishing: { mode: 'autopilot' | 'copilot'
                /** A whole multiple of 24 in [0, 168] — whole days 0 to 7
                 *  (REQ-073 c1). BP-057 is the validator and the one home of
                 *  the rule; this field is the value it produced. The comment
                 *  here read `0..168`, which admits 37 hours — a value the rule
                 *  refuses and no screen can render. */
                vetoHours: number
                publishTime: string; timeZone: string; enabled: boolean
                outcomeKey: CopyKey }                  // REQ-073 c2's written line for the selected pair
  destinations: readonly { id: string; kind: 'hosted' | 'wordpress'; health: 'ok' | 'expired' | 'error' }[]
  voice: { text: string }
  doNotClaim: readonly string[]
  notifications: readonly { kind: MailKind; on: boolean }[]   // from BP-016's MAIL_KINDS, stoppable only
  account: { name: string; email: string }
}
```

## Steps
1. Write the failing tests first (§8).
2. Assemble the model from one read of each of the three tables; assert p95
   ≤ 400 ms and no measurement, vendor call or model call.
3. Project the notification rows over the stoppable subset of `MAIL_KINDS` —
   **not** the three hard-coded toggles of `BUILD.md` §4.7 (BP-055 decision 4):
   a second copy of the register is the copy that goes stale, and a stoppable
   mail with no toggle is a customer who cannot stop a mail the product says
   they can.
4. Return destination health as a state; `expired` carries a Reconnect action
   (BP-015) and is not an error.
5. Return `publishing.vetoHours` as read from `sites.veto_hours`. This module
   validates nothing about it: the rule is BP-057's and the write path is
   WO-178's. A read that "corrects" a stored value would hide the very state
   BP-057's validator exists to prevent from ever being stored.
6. Return the market `effectKey` and the publishing `outcomeKey` as keys only.
7. Mutation check: hard-code three toggles and confirm the register-projection
   test fails when a fourth stoppable kind is added.
