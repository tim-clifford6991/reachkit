# WO-286 — The stored report read and what a visit resolves to — StoredReport declared once, one indexed read, the eight-row order and the one control

- Branch: wo/WO-286-stored-report-read
- Estimate: ≤1 day

## Goal
Declare `StoredReport` once and read the current one off the partial unique index, and turn a visit to a report address into exactly one arm of a closed union with at most one control and at most one notice.

**Risk: high — seam: data leaving the system.** The removal arm: REQ-002 criterion 3 promises a removed report is shown to nobody, and the only thing holding a withdrawn report off a public address is row 3's precedence in a first-match table. A test that survives reordering that table leaves a taken-down report served, and nobody but the domain owner who asked would see it. This order's own test plan already demands that mutation; `risk: high` is what makes the validator run it (doctrine 0.13.2, rule 2b).

**Why the split holds the merge test.** WO-280's remaining half states its goal
and stop condition — "two current reports for one domain are unrepresentable in
the database, and every written form of a domain redirects to the one address for
it", decided by `tests/scan/report/schema.test.ts` and

`tests/app/scan-address/resolve.test.ts` — naming WO-280 only as a column it
reads, the way it names WO-051's `parseDomain` and WO-057's `admitFreeScan`. That
is a one-way `depends-on`, not the mutual citation rule 2.6's merge test forbids.
Verified in the shipped code: `canonical.ts` imports `parseDomain` and nothing
else, and BP-022's `AddressState` union has no redirect arm — the 308 is issued
from `canonicalRedirect`'s result at the route (WO-282), never from
`resolveAddress`.

**Why it is blocked, and by what.** `StoredReport` composes ten section types
and re-declares none of them (BP-012 decision 3). Eight of the ten do not exist
(sixth `rests-on` row, confirmed by independent grep on 2026-09-04); only
`Verdict` (WO-277) and `RobotsPolicy` (WO-018) do. Inventing a substitute shape
for a type another node owns is the second copy rule 2.4 exists to prevent and
would defeat this order's own "declares no section shape" criterion. `blocked-by`
names the nine owning orders; none of them carries a wave.

**What ADR-095 moved (2026-09-04, after this order was cut).** Two members of
`StoredReport` change shape and one owning order joins the block. `market`
becomes `Measured<MarketSet>` — the leaf's shape, declared by BP-025 in
`src/lib/market/questions/market-set.ts`, which is **WO-072's** file, so the
existing `blocked-by` edge on WO-072 now carries the type as well as the
function. `coherence: CoherenceVerdict` is a new member, BP-028's type in
`src/lib/market/coherence/check.ts`, which is **WO-080's** file and no other's —
that is the one edge this decision adds, and `blocked-by` gains WO-080.
`WO-071` joins `depends-on` (not `blocked-by`): `MarketSet` composes `Profile`,
which WO-071 declares, but this file imports `MarketSet` alone and never
`Profile`, so the edge is transitive, not direct. Nothing else in this order
moves: the eight-row resolution order, the five-row control derivation and every
acceptance criterion below are untouched.

export type Tier = 'free' | 'deep' | 'weekly'

/** The versioned report blob `BUILD.md` §10 names ("report jsonb(versioned blob:
 *  measurements, questions, answers, market set)"), declared here because this
 *  node assembles it and is the only writer. Five blueprints named this type and
 *  none declared it; consumers were reading it through locally-invented reader
 *  interfaces, which is the second copy rule 2.4 exists to prevent.
 *
 *  Every section is a type its own node already owns. This node composes and
 *  stores; it defines none of the section shapes and re-derives no figure. A
 *  section that could not be measured is present with its `Measured` arms
 *  saying so — a section is never omitted, because an absent key and a
 *  `not_attempted` value read the same to a consumer and REQ-004 forbids that. */
export interface StoredReport {
  version: number                        // the blob is versioned; readers branch on nothing else
  scanId: string
  domain: CanonicalDomain                // ADR-020's one canonical key
  measuredAt: Date                       // one date; every figure under it is this scan's
  tier: Tier
  complete: boolean                      // false where `stopped_reason` is a ceiling or a failure
  stoppedReason: 'complete' | 'time_ceiling' | 'spend_ceiling' | 'failed'
  fromIncompleteRescan: boolean          // REQ-001 c14's re-scan control reads this
  verdict: Verdict                       // BP-024 — score, band, factors, missing, blockedReaders
  market: Measured<MarketSet>            // BP-025 — profile, suggestions, total volume (ADR-095)
  questions: Measured<Question[]>        // BP-025 — the twelve, or as many as the market yielded
  answers: AiAnswersCard                 // BP-025 — REQ-006 c1's denominator lives in here
  serps: readonly Measured<SerpResult>[] // BP-026 — the bought top-tens, per target search
  rivals: Measured<RivalCandidate[]>     // BP-026
  rivalSizes: Measured<RivalSize[]>      // BP-052 — absent on the free path by REQ-096's non-goal
  onPage: OnPageFacts                    // BP-010
  robots: Measured<RobotsPolicy>         // BP-006's type, BP-010's measurement
  coherence: CoherenceVerdict            // BP-028 — total union, unwrapped; ADR-095 decision 3
  correctionState: CorrectionState       // BP-028's value domain, stored on the scan row too
}
export function readCurrentReport(domain: string): Promise<StoredReport | null>

## Steps
1. Write both test files first and run them; the schema suite must fail on a
   missing migration and the read suite on a missing module (constitution §8).
2. Declare `Tier` and `StoredReport` in `report.ts`, importing all ten section
   types. Re-declare none of them, not even structurally.
3. Implement `readCurrentReport` as one indexed read. A domain with no current
   row returns `null`; there is no second query and no latest-scan fallback —
   BP-012 decision 1 rejected exactly that ("a 'latest scan wins' read-side
   query — rejected, a failed re-scan then becomes the report").
4. Implement the version guard: an unknown `version` throws naming the version
   and the scan id, rather than returning a value with fields missing. BP-012's
   own comment fixes the rule — "readers branch on nothing else".
5. Mutate to prove the suite discriminates: (a) drop the `where is_current`
   predicate from the index and confirm the two-current-rows case passes an
   insert it should reject; (b) make the version guard return `null` instead of
   throwing and confirm the guard row fails, since `null` is indistinguishable
   from "no report" at every call site.
6. Declare the three unions exactly as above.
7. Implement `resolveAddress` as the eight rows in order, each an early return.
   Row 3's `removed` comes from WO-057's `admitFreeScan` returning
   `{ refuse: 'removed' }` — that is the only way this module learns a domain is
   removed, and it holds no `domain_blocks` query of its own.
8. Implement the control derivation as a separate first-match function over the
   stored report, returning exactly one `AddressControl`. Row 3 reads
   `StoredReport.measuredAt` against `FREE_RESCAN_WINDOW_D`; row 4 reads
   `StoredReport.complete` and `StoredReport.fromIncompleteRescan` — the blob's
   own field, which BP-012 notes "REQ-001 c14's re-scan control reads" — rather
   than `scans.from_incomplete_rescan` directly or a walk of a predecessor
   chain; row 1 reads `StoredReport.correctionState`, BP-028's value domain.
9. Implement the notice derivation: at most one `AddressNotice`, or `null`.
   `measurement_failed` and `refused` are notices on a `report` arm whenever a
   report exists — never states of their own (BP-022's rows 5 above 6 and 7).
10. Add the exhaustiveness guard: a `never` check over each union so a new arm
   fails the build until every table maps it.
11. Emit the one structured line per resolution BP-022's NFR budget specifies:
   route id, `AddressState.kind`, `AddressControl.kind`, domain, and the scan id
   where one exists. Never a payload, never an IP.
