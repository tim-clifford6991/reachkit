# WO-005 — Environment bindings — env.ts, parsed and validated at boot

- Branch: wo/WO-005-env
- Estimate: ≤1 day

## Goal
Parse and validate every environment binding the product reads, once, at module
load, so a deployment cannot start half-configured.

## Provenance of this file plan
**This repository holds no `src/`.** Both paths are NEW, anchored to
`structure.md`'s row for `src/lib/config/**` and to BP-005's `code:` globs.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/lib/config/env.ts` | NEW | A Zod schema over `process.env` covering exactly `BUILD.md` §15's list — `DATABASE_URL SUPABASE_URL SUPABASE_ANON_KEY SUPABASE_SERVICE_ROLE STRIPE_SECRET_KEY STRIPE_WEBHOOK_SECRET STRIPE_PRICE_ID RESEND_API_KEY DATAFORSEO_LOGIN DATAFORSEO_PASSWORD ANTHROPIC_API_KEY NANO_API_KEY IP_HASH_SALT KILL_SWITCH OWNER_EMAILS NEXT_PUBLIC_APP_URL` — plus `HOSTED_EDGE_CNAME_TARGET`, the one binding BP-005 adds and states the derivation for. Parsed at module load; a missing or malformed binding throws. No default, no fallback. `SUPABASE_SERVICE_ROLE`, `STRIPE_SECRET_KEY`, `RESEND_API_KEY`, `DATAFORSEO_PASSWORD`, `ANTHROPIC_API_KEY`, `NANO_API_KEY` and `IP_HASH_SALT` are marked server-only and their access throws if the module is evaluated in a client bundle. |
| `tests/config/env.test.ts` | NEW | The tests below. `structure.md` rule 4 puts a module's tests at `tests/<module>/**`; `tests/pins.test.ts` is the one named exception and is WO-007's. |

## Steps
1. Write the `Env` type as the union of `BUILD.md` §15's names plus
   `HOSTED_EDGE_CNAME_TARGET`, each with its parse rule (URL, non-empty string,
   boolean-ish for `KILL_SWITCH`, comma-separated list for `OWNER_EMAILS`).
2. Parse at module load and freeze.
3. Add the client-bundle guard on the secret bindings.
4. Write the tests; watch the "missing binding throws at boot" test fail first by
   supplying a default, then remove the default.

### Edge probes (run against a scratch test file, then removed — never fixed)

- `KILL_SWITCH` accepted spellings: `"1"`, `"yes"`, `"TRUE"`, `"on"` all parse to boolean `true` via `z.stringbool()` (case-insensitive, several truthy tokens) — consistent with WO-005 step 1's "boolean-ish"; no defect.
- `KILL_SWITCH=""` (empty string): throws — correctly rejected rather than coerced to a default falsy value.
- `OWNER_EMAILS=""` (empty string): throws (`.min(1)` on the raw string before the split) — an empty owner list is rejected, not silently allowed.
- `OWNER_EMAILS` with exactly one address: accepted, one-element array — the floor is one, not two.
- `OWNER_EMAILS` with whitespace around entries (`" a@x.com , b@x.com "`): both entries trimmed correctly by the transform's `.trim()`, both parse — no defect.
- `OWNER_EMAILS` with a trailing comma (`"a@x.com,b@x.com,"`): throws — the trailing empty segment fails `z.email()`, so a trailing separator is rejected rather than silently dropped.
- `NEXT_PUBLIC_APP_URL` with a trailing slash (`"https://app.example.com/"`): accepted, preserved verbatim — not a defect against any of the 4 rows (none asks for normalization), but worth naming for later WOs: a module concatenating a path onto `env.NEXT_PUBLIC_APP_URL` must not assume the absence of a trailing slash.
- `DATABASE_URL` / `SUPABASE_URL` / `NEXT_PUBLIC_APP_URL` padded with leading/trailing whitespace: accepted, with the whitespace silently trimmed. Isolated the cause with a direct probe of the library, not `env.ts`: `z.url().safeParse('  https://example.com  ')` → `{success:true, data:'https://example.com'}` (zod 4.5.4, confirmed via `node_modules/zod/package.json`). This is inherited `z.url()` behaviour (its underlying `new URL()` parse trims per the WHATWG URL spec), not something `env.ts` added, and no test-plan row addresses it — not a defect of this WO, but a corpus fact worth recording since later modules may assume `env.*` URL strings are exactly what the process env set.
