# WO-110 — firstPageOffer() — what is on offer, and the arm where nothing is

- Branch: wo/WO-110-first-page-offer

- Estimate: ≤1 day

## Goal
Return the six facts the report card and the giveaway mail both read, and the
`{ offered: false }` arm that makes "no page is offered" the absence of a card
rather than a card with an empty slot.

## Provisional against an empty repo
**No `src/` exists.** Both files NEW, inside BP-029's `src/lib/mail/leads/**`
glob (`structure.md` rule 2: "BP-029 owns `src/lib/mail/leads/**`").

Reuse check (rule 7.2): `registry/capabilities.md` gives `readCurrentReport()` to
BP-012, `deriveOpportunities()` and the closed type enum to BP-013/BP-040, and
`generateDraft()` to BP-014/BP-042. This WO **consumes** all three and derives no
opportunity, no title and no volume of its own. It mints one thing: the offer
projection, which the index does not carry and which BP-029 decision 5 puts here
rather than in the surface.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/lib/mail/leads/offer.ts` | NEW | `firstPageOffer(scanId)` verbatim from BP-029's signature. Reads the current report (BP-012), takes the top-ranked open opportunity (BP-013's ranking, not a ranking of its own), and projects the six facts. `volume` and `rival` stay `Measured<T>` all the way out — this function never coalesces, never substitutes and never invents a rival (REQ-091 c3). `{ offered: false }` when the scan derived no page worth writing. |
| `tests/mail/leads/offer.test.ts` | NEW | The `offered: false` arm, the six facts, `Measured` passthrough, and the negative property that the offer gates nothing else in the report. |

## Interfaces
**Exposes** (verbatim from BP-029 `## Public interface`):
```ts
// src/lib/mail/leads/offer.ts
/** What the report's free-page card states, and whether it renders at all.
 *  Criterion 6's "no page is offered" is the { offered: false } arm — the card
 *  is absent and no control renders, rather than a card with an empty slot. */
export function firstPageOffer(scanId: string): Promise<
  | { offered: false }
  | { offered: true
      title: string                    // BP-014's proposed title — model text (REQ-093 c2)
      pagesFound: number               // the N of "page 1 of N"
      targetQuery: string
      volume: Measured<number>         // omitted from card and mail when unmeasured
      rival: Measured<string>          // REQ-091 c3: unmeasured renders as its written line
      format: OpportunityType }>       // BP-013's closed enum
```
**Consumes**: `readCurrentReport()` (BP-012, `src/lib/scan/`);
`deriveOpportunities()` / `rankOpen()` and `OpportunityType` (BP-013, BP-040,
`src/lib/opportunities/`); `Measured<T>` (BP-010).

## Steps
1. Write `offer.test.ts` first and watch it fail.
2. Implement the read and the projection. No formatting: this function returns
   data, never a rendered string (BP-029 decision 5 — "the card and the mail read
   the same offer").
3. Assert this module imports nothing from `src/app/**` (`structure.md` rule 6).
4. Mutation check: coalesce an `unmeasured` volume to 0 and confirm the
   `Measured` passthrough test fails.
