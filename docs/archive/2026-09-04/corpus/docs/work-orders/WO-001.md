# WO-001 — Next.js toolchain, build configuration and the repo's root files

- Branch: wo/WO-001-toolchain
- Estimate: ≤1 day

## Goal
Stand up the greenfield Next.js (App Router) + TypeScript toolchain BP-001 is the
deployable unit of, so that every later work order in the corpus has a compiler,
a test runner, a lint pass and a place to put a file.

## Provenance of this file plan
**This repository holds no `src/`.** Every path below is NEW; none was verified
against an existing file, because there is none to verify against. The paths are
anchored to `sdlc-factory/docs/registry/structure.md` ("Top level"), which is the
only authority on where code lives, and to BP-001's `code:` globs. The plan is
provisional in exactly that sense and in no other.

## Steps
1. Initialise `package.json` with the dependency set above, pinned to exact
   versions (no `^`) so a pinned corpus is not moved by an install. Declaring the
   whole set here is deliberate: it is the single file every other foundation
   work order would otherwise have to modify, and it is what lets WO-011,
   WO-013, WO-026, WO-029 and WO-030 run in parallel.
2. Write `tsconfig.json`; confirm `npm run typecheck` exits 0 on an empty `src/`.
3. Write `next.config.ts`, `postcss.config.mjs`, `eslint.config.mjs`. For each
   of the four lint rules, write the fixture that must be reported before the
   rule exists, and watch it go unreported (constitution §8).
   **ADR-050's other half is not recast here.** Point 3 of that ADR — "BP-003,
   BP-012, BP-015 and BP-063 call it and compute no access predicate of their
   own" — is enforced by ADR-050 point 4's three mutation tests in
   `tests/account/billing/`, and stays there. "Computes no access predicate" is
   not a lexical property an import rule can decide: a rule claiming to enforce
   it would report nothing on a hand-rolled `paid_through > now()` comparison in
   a job body and would read, in CI, exactly like a rule that holds. A check
   that looks like it holds and does not is worse than an absent one, so this
   file takes the import fence and nothing more.
4. Write `vitest.config.ts` and `tests/setup.ts`; confirm `npm test` exits 0 with
   zero test files.
5. Write `.env.example` from `BUILD.md` §15, names only.
6. Extend `.gitignore`.
