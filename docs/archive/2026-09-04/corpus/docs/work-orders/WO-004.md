# WO-004 — The api adapter convention, request logging, and the job-runner transport adapter

- Branch: wo/WO-004-api-adapters
- Estimate: ≤1 day

## Goal
Fix the shape every `src/app/api/**` route handler in the corpus takes — read the
request, call one exported function on the owning component, map the result to a
response — and ship the first adapter written to it.

## Provenance of this file plan
**This repository holds no `src/`.** Every path is NEW, anchored to BP-001's
`code:` glob `src/app/api/**`.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/app/api/_adapter.ts` | NEW | The convention as code: `adapter(handler)` wraps a route handler, emits BP-001's one structured request log line, and maps a component's typed failure to a status plus a copy key. It **imports no engine module**, so it cannot become a place logic accumulates. |
| `src/app/api/_log.ts` | NEW | The single request log line: route id, status, duration and — where one exists — scan id. Never a payload, never a body, never a header value. |
| `src/app/api/jobs/[[...slug]]/route.ts` | NEW | Transport only: `export const { GET, POST, PUT } = jobs.serve()` per BP-001's interface line `ALL /api/jobs/[[...slug]] -> jobs.serve()`. Registers nothing itself (`structure.md` rule 1). |
| `tests/app/adapter.test.ts` | NEW | Convention tests. |
| `tests/app/jobs-route.test.ts` | NEW | Asserts the jobs route re-exports `serve()` and adds no logic. |

## Interfaces
Consumes (verbatim from BP-003 `## Public interface`):
```ts
// src/jobs/index.ts
export function serve(): { GET: Handler; POST: Handler; PUT: Handler }
```
Exposes (verbatim from BP-001 `## Public interface`):
```
Adapters (transport only)
  ALL  /api/jobs/[[...slug]] -> jobs.serve()
```
plus, for every later adapter in the corpus:
```ts
// src/app/api/_adapter.ts
export function adapter<T>(h: (req: Request) => Promise<T>): (req: Request) => Promise<Response>
```

## Steps
1. Write `_log.ts` and prove by test that it drops anything not in its four-field
   allow-list.
2. Write `_adapter.ts`.
3. Write the jobs route as a re-export.
4. Write both tests; watch the "an adapter importing an engine module fails lint"
   test fail before the rule exists.
