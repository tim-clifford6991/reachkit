# WO-049 — stoppedWorkStatement(), nextPublishStatement() and dayAccount() — ADR-011's precedence, implemented literally

- Branch: wo/WO-049-stopped-statements
- Estimate: ≤1 day

## Goal
Create `src/lib/presentation/stopped/statement.ts` so every surface that says
ReachKit stopped its own work says it through one function, every statement of
when the next page publishes renders through one function, and a stopped day
reaches BP-021's arbiter as one `Cause` rather than a placed line.

**Exposes** (verbatim from BP-054 `## Public interface`):
```ts
// ── src/lib/presentation/stopped/statement.ts ────────────────────────────────
/** REQ-092 criteria 1, 2, 4 and 8. The one statement that ReachKit did not do
 *  the work. Every surface that says so says it through this function.
 *
 *  Replaced BP-019's withdrawn `stoppedWorkLine(a: { resumesOn?: Date })`, which
 *  this node does not ship; BP-019 decision 4 records the withdrawal and
 *  re-exports this signature. See Decisions 1. */
export function stoppedWorkStatement(stop: WorkStop): {
  /** "ReachKit did not do the work" — never "there was nothing worth publishing". */
  line: string
  /** REQ-092 criterion 2, always present: the action, or that nothing is needed. */
  needsLine: string
  /** REQ-092 criterion 4, always present: the resumption date, or that no time
   *  is promised. Never absent. */
  resumesLine: string
}

/** REQ-092 criterion 7. Every statement of when the next page publishes — the
 *  navigation's, the footer autopilot card's next-publish time, a mail's
 *  statement of what publishes next — renders through this one function.
 *  While `stop` is non-null it names ReachKit's stop and nothing else, whatever
 *  else is also true of the account. ADR-011 is why. */
export function nextPublishStatement(a: {
  stop: WorkStop | null
  /** The causes REQ-040 criterion 4 admits when ReachKit has not stopped —
   *  paused, nothing approved, no page planned. Ignored entirely when `stop` is
   *  non-null; that is the point, and it is asserted, not documented. */
  otherwise: { tag: 'paused' | 'nothing-approved' | 'none-planned' } | { tag: 'scheduled'; at: Date }
}): { line: string }

/** REQ-092 criteria 1 and 6, as the single account a date carries. Returns the
 *  `Cause` BP-021's `account()` arbitrates, never a line placed directly on a
 *  screen — so a stopped day cannot end up with two accounts. */
export function dayAccount(stop: WorkStop, pageProduced: boolean):
  | { tag: 'reachkit-stopped'; line: string }               // no page that day
  | { tag: 'reachkit-stopped'; line: string; partialPass: true }  // c6: page produced, pass incomplete
```

## Steps
1. Create `statement.ts`. Implement `stoppedWorkStatement(stop)`:
   `line` is `copy('stopped.work.line')`; `needsLine` is
   `copy(stop.needs.key)` on the `action` arm and
   `copy('stopped.work.needs-nothing')` on the `nothing` arm; `resumesLine` is
   `copy('stopped.work.resumes-on', { date: … })` on the `{ on }` arm and
   `copy('stopped.work.no-time-promised')` on the `{ promised: false }` arm. All
   three fields are always returned; none is conditional and none is `undefined`.
   The function takes no session, reader or persona argument.
2. Implement `nextPublishStatement(a)` **in this order and no other**:
   ```
   if (a.stop !== null) return { line: copy('next-publish.stopped') }
   switch (a.otherwise.tag) { … }
   ```
   The early return reads `a.otherwise` nowhere. Do not add an `else if`, do not
   append a second clause, do not pass `otherwise` as a slot. Place a comment on
   the early return citing **ADR-011 point 5** — "Not 'prefers'; ignores" — and
   ADR-011's consequence that this will be reported as a bug at least once and is
   not one. The `otherwise` switch maps `scheduled` → `next-publish.scheduled`
   with its `at` date, `paused` → `next-publish.paused`, `nothing-approved` →
   `next-publish.nothing-approved`, `none-planned` → `next-publish.none-planned`,
   and closes with a `never` exhaustiveness check. This node adds no cause to
   REQ-040 criterion 4's set.
3. Implement `dayAccount(stop, pageProduced, instructionOutstanding)` — see the
   rule 4.2 objection below for the third parameter. Returns
   `{ tag: 'reachkit-stopped', line: copy('stopped.work.line') }` when
   `pageProduced` is false, and
   `{ tag: 'reachkit-stopped', line: copy('stopped.work.partial-pass'), partialPass: true }`
   when `pageProduced` is true and `stop.partial` is true. Before either, **throw**
   when `instructionOutstanding` is true and `stop.needs.kind === 'nothing'` —
   ADR-011 point 4: "an assertion, not a silent merge, because a silent merge is
   how the instruction disappears." The error message names neither the
   instruction's text nor any internal cause.
4. `dayAccount` returns a `Cause`, never a placed line: the returned object is
   handed to BP-021's `account()` by the caller. This module calls `account()`
   nowhere and places nothing on a screen.
5. Create `index.ts` re-exporting exactly the symbols in `## Interfaces`.
6. Write `tests/presentation/stopped/statement.test.ts`. Watch it fail before
   `statement.ts` exists.

## Rule 4.2 objection — `dayAccount`'s third parameter
**The objection.** BP-054 `## Error & edge behavior` and ADR-011 point 4 both
require `dayAccount` to reject the pair where a stop is arbitrated over an
outstanding instruction while `stop.needs.kind === 'nothing'`. BP-054's declared
signature is `dayAccount(stop: WorkStop, pageProduced: boolean)` — it is handed
no fact about an outstanding instruction and cannot make that assertion.
**For the declared signature:** it is an approved interface and a planner does not
widen a contract. **For the third parameter:** without it the assertion ADR-011
calls load-bearing is unreachable in the function the ADR names, and moving it
into BP-021's `account()` puts one rule in two homes (rule 2.4) and gives BP-021
a dependency on BP-054's semantics that BP-054's own boundary section forbids.
**Taken:** `dayAccount(stop, pageProduced, instructionOutstanding: boolean)`,
required rather than optional — an optional flag makes the assertion reachable by
omission, which is exactly the failure mode BP-019 decision 4 withdrew a
signature over. Cost of reversing: one parameter and its call sites. Reported to
the architect; not fixed in the blueprint by this WO.
