# WO-175 — Due sites: an hourly selection on each site's own local Monday

- Branch: wo/WO-175-weekly-due
- Estimate: ≤1 day

## Goal
Select, on each hourly tick, every site whose own local week has begun, whose
local hour has reached the due hour, that has active access, and that has no
scan row for `(site_id, week_start)`.

## File plan
> Every path below is **NEW** (no `src/` on disk, checked 2026-08-31). Placement
> follows `structure.md` and BP-050's `code:` globs; provisional.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/scan/weekly/due.ts` | NEW | `dueSites(now)` — one indexed query on `(active, time_zone)` joined against `scans (site_id, week_start)`, filtered by the site's own local weekday and hour and by `hasActiveAccess`. Returns `{ siteId, weekStart }` pairs. Logs one line per due-selection carrying the count and the local hour band. |
| `tests/scan/weekly/due.test.ts` | NEW | Selection across offsets, the active-access gate, the already-measured exclusion, the retry-inside-the-week property, the 10⁴-site budget. |

## Interfaces
Consumes: `weekStartFor()` and `WEEKLY_DUE_HOUR_LOCAL` (WO-174),
`hasActiveAccess()` (BP-017 — the single gate; this node holds no second
definition of active), `db()` (BP-002).

Exposes (verbatim from BP-050 `## Public interface`):
```ts
/** Every site whose local week has begun, whose local hour has reached the due
 *  hour, that has active access, and that has no row for (site_id, week_start).
 *  Called by BP-003's hourly tick — see ADR-060 for why the tick is hourly. */
export function dueSites(now: Date): Promise<readonly { siteId: string; weekStart: string }[]>
```

## Steps
1. **Read ADR-060 first.** The tick is hourly and due-ness is site-local; a
   weekly cron at `Mon 06:00 UTC` silently re-files every measurement west of
   UTC−6 into the previous customer-week.
2. Write the failing tests first (§8).
3. Implement the query: local weekday Monday or later within the current
   site-local week, local hour at or past `WEEKLY_DUE_HOUR_LOCAL`, active
   access, and no `scans` row for `(site_id, week_start)` with `tier = 'weekly'`.
4. Assert the budget: one indexed query, under 50 ms at 10⁴ sites.
5. Assert retry is free — a site whose run failed has no row and is selected
   again on the next tick **inside the same site-local week**; a site whose run
   completed (`done` or `degraded`) has a row and is not selected again.
6. Mutation check: drop the active-access predicate and confirm the ended-access
   test fails; select on UTC weekday and confirm the UTC−8 test fails.

## Test plan
| Acceptance criterion (verbatim from REQ-065) | Test |
|---|---|
| 1. Given a site with active access, when a week beginning on Monday in the time zone the customer set arrives, then its market is re-measured exactly once within that week and never before it begins, without the customer asking; it is due on that week's Monday, and it carries the date it was taken in that same time zone. | `tests/scan/weekly/due.test.ts › a site is selected only once its own local Monday and due hour have arrived, for every offset tested`, `(same file) › a site already carrying a weekly scan row for the week is never selected again`, `(same file) › a site whose run failed is selected again on the next hourly tick inside the same site-local week` |
| 5. Given a site whose access has ended, when the week begins, then it is not re-measured, no week is stated to that customer as unmeasured and no next measurement is announced to them, and every measurement already taken stays readable with the date it was taken. | `tests/scan/weekly/due.test.ts › a site without active access is never selected, whatever its local weekday` |
