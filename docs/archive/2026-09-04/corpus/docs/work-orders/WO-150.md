# WO-150 — The deep pass and its named stages, with a progress frame that cannot carry a duration

- Branch: wo/WO-150-deep-pass-stages
- Estimate: ≤1 day

## Goal
Run `runScan({ tier: 'deep' })` behind `runDeepPass`, and project BP-012's
pipeline stage onto the closed `DeepStage` union as a `ProgressFrame` that has
no field a duration could travel in.

## File plan

> `00-project.md`: "Greenfield. No source code on disk yet"). Placement follows
> `structure.md` and BP-036's `code:` globs; provisional.

|---|---|---|
| `src/lib/scan/deep/stages.ts` | NEW | The `DeepStage` union and the **total** map from BP-012's `progress()` stage onto it. A pipeline stage with no entry is a compile error; a `DeepStage` no pipeline stage maps to is a test failure. |
| `src/lib/scan/deep/run.ts` | NEW | `runDeepPass()` — calls BP-012's `runScan({ tier: 'deep' })`, returns `{ scanId, status }`. It branches nothing about the pipeline; the deep tier's parameters are passed, not reimplemented. |

## Interfaces
Consumes: `runScan()` and `progress()` (BP-012), `WEEKLY`-independent deep tier
ceilings (BP-012), `HEARTBEAT` pin (BP-005, 15 s — BP-036 decision 5).

Exposes (verbatim from BP-036 `## Public interface`):
```ts
/** The named steps REQ-029 criterion 1 promises in written words. Closed: a step
 *  the pipeline runs that is not here cannot be shown, and a step shown that is
 *  not running is a test failure. */
export type DeepStage =
  | 'reading_site' | 'building_market' | 'asking_questions'
  | 'measuring_rivals' | 'finding_opportunities'

export function runDeepPass(a: { siteId: string; domain: string }):
  Promise<{ scanId: string; status: 'done' | 'degraded' | 'failed' }>

/** REQ-029 criterion 1 made structural: this frame has no field a duration,
 *  estimate, countdown, clock or percentage could travel in. The heartbeat
 *  timestamp is the server's own send time and is never rendered. */
export interface ProgressFrame { stage: DeepStage; running: true; heartbeatAt: Date }
export type ProgressEvent = ProgressFrame | { running: false; reason: ReleaseReason }
export function progressStream(siteId: string): AsyncIterable<ProgressEvent>
```

## Steps
1. Write the failing tests first (§8).
2. Declare `DeepStage` as the five names above, closed.
3. Implement the stage map as total over BP-012's stage union, with an
   exhaustiveness check that fails compilation if BP-012 adds a stage.
4. Implement `runDeepPass` as a thin call into `runScan({ tier: 'deep' })`.
5. Implement `progressStream` with a 15 s heartbeat (pinned in BP-005), a
   resume that is indistinguishable from an unbroken stream, and an 11-minute
   close.
6. Add the structural test: the keys of `ProgressFrame` are exactly
   `{ stage, running, heartbeatAt }` — no elapsed, no total, no percentage, no
   ETA (BP-036 decision 2).
7. Mutation check: add an `elapsedMs` field and confirm the structural test
   fails.
