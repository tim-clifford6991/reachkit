## Goal
Return at most one supply notice, derived on every read, with a total precedence order — so that one statement rather than two is a property of the return type.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/lib/opportunities/supply/notice.ts` | NEW | `supplyNotice({ siteId, firstArrivalAfter? })` returning `SupplyNotice | null` — a single value, never an array. Precedence is total and stated once here: `exhausted` > `short` > `arrival_shortfall`. `exhausted` where `unused` is 0, carrying `days: 0` and `since` from `supplyDepth().exhaustedSince`; `short` where `unused` is 1..6, carrying `days`; `arrival_shortfall` where the caller names a scan the customer is first arriving after and the pass fell short, carrying `days`; `null` where `unused >= SUPPLY_SHORT_BELOW` and no arrival telling is outstanding. No stored flag, no dismissal state, no expiry — the value is computed from the current count on every call. |
| `tests/opportunities/supply/notice.test.ts` | NEW | `unused: 0` with an arrival outstanding returns `exhausted` and nothing else; `unused: 3` with an arrival outstanding returns one notice carrying `days: 3`; `unused: 7` returns null and `unused: 6` returns `short`; the `short` notice stops on the read after supply reaches 7, with no job and no clearing step; a repeated read while supply stays at zero returns the same `since`; a top-up that adds supply makes the next read return null. |
| `tests/opportunities/supply/shape.test.ts` | NEW | Compile-time assertions under `tsc --noEmit`: `Awaited<ReturnType<typeof supplyNotice>>` is exactly `SupplyNotice | null` (a hand-rolled `Equals<A, B>`, so widening it to `SupplyNotice[]` or adding a second value fails the type-check), and `SupplyNotice` has exactly three arms. Plus a runtime assertion that the return is never an array. |

## Steps
1. Write both test files first and run them; both must fail on a missing module.
2. Implement `notice.ts`. The precedence chain is a single `if/else if/else` in one function — there is no second producer and no surface-side choice to make (BP-041 decision 3).

5. Run the tests. Then mutate: return an array of applicable notices and confirm `shape.test.ts` fails at compile time before any runtime test runs.

**Discriminates (mutation check, constitution §8).**
- Returning every applicable notice makes `shape.test.ts`'s `Equals` assertion fail under `tsc --noEmit` — a runtime-only test would pass, since both notices would be individually correct, which is exactly how "one statement, not two" dies quietly.
- Storing the notice as a dismissible row makes `… the short notice stops on the read after supply reaches 7` fail without any clearing step, because there would be one.
- Reordering the precedence so `short` outranks `exhausted` makes the `unused: 0` case report `days: 0` under the wrong kind and loses `since` — the test asserts the kind and the date together.
