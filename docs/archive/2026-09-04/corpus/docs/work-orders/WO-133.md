# WO-133 — Cancel, resume, and the subscription events that move the paid-through date

- Branch: wo/WO-133-cancel-resume
- Estimate: ≤1 day

## Goal
Let the customer cancel and resume without contacting anyone, return the exact
date access ends, and advance the paid-through date from Stripe's own events —
cutting nothing off before that date.

## File plan
> **Every path below is NEW.** No `src/` exists. Anchored to
> `registry/structure.md` and BP-060's `code:` glob `src/lib/account/billing/**`.
> Provisional against a repo with no code.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/account/billing/cancel.ts` | NEW | Exports `cancelSubscription(userId)` with BP-060's signature verbatim. Cancels at period end, stamps `cancelled_at`, leaves `paid_through` untouched, and returns `accessEndsAt` (the unchanged `paid_through`) and `hostedServingEndsAt` — `paid_through + HOSTED_RETENTION_DAYS` where the site has pages served at the hosted destination, `null` where it has none. Cuts nothing off now. |
| `src/lib/account/billing/resume.ts` | NEW | Exports `resumeSubscription(userId)` with BP-060's signature verbatim. Works before **and** after the paid-through date: after it, creates a new Stripe subscription against the existing customer. Advances `paid_through`, clears `cancelled_at`, `hosted_serving_ends_at`, `hosting_end_notice_at` and `hosting_end_reminder_at`. **Touches `sites.domain`, category and competitors not at all** — asserted by a column-set check, since c6's promise is that the customer returns to what they left. |
| `src/lib/account/billing/events.ts` | NEW | Exports `onSubscriptionEvent(event)` with BP-060's signature verbatim, called by WO-125's router. Advances `paid_through` from the subscription's period end, records `plan_status` as what Stripe last said, and does nothing else. **Invents no behaviour for `past_due`, a failed renewal, a refund or a chargeback** (REQ-076 non-goal, owner ruling); the handler records the status and returns. |
| `tests/account/billing/cancel.test.ts` | NEW | Cancellation stamps `cancelled_at`, leaves `paid_through` unchanged, returns that date as `accessEndsAt`, and returns `hostedServingEndsAt` as exactly 30 days later where hosted pages exist and `null` where they do not; a second cancel returns `already_cancelled`; **the discriminating case**: after cancelling, `hasActiveAccess` is still true. |
| `tests/account/billing/resume.test.ts` | NEW | Resume before the date and resume after it, both without any support path; both clear the three stamps; a column-set assertion that no `sites` column changed; `not_cancelled` for a subscription that was never cancelled. |
| `tests/account/billing/events.test.ts` | NEW | A renewal advances `paid_through`; a `past_due` event records the status and changes `paid_through` by nothing and triggers no mail, no retry and no dunning of any kind (the mutation case: adding any behaviour to the `past_due` branch fails this test); an unrelated subscription event is a no-op. |

## Interfaces
Exposes (verbatim from BP-060's `## Public interface`):
```ts
export function cancelSubscription(userId: string):
  Promise<{ ok: true; accessEndsAt: Date; hostedServingEndsAt: Date | null }
        | { ok: false; reason: 'already_cancelled' | 'vendor' }>

export function resumeSubscription(userId: string):
  Promise<{ ok: true; paidThrough: Date } | { ok: false; reason: 'not_cancelled' | 'vendor' }>

export function onSubscriptionEvent(event: Stripe.Event): Promise<void>
```
Consumes: `STRIPE_EVENTS`'s `'subscription'` rows (WO-125); BP-005's
`HOSTED_RETENTION_DAYS = 30`.

## Out of scope
- The cancellation confirmation screen and every sentence on it — BP-001's
  surface, BP-019's registry, the owner's words. Nothing a customer reads about
  money is written by this work order.
- Refunds, chargebacks and dunning — deferred by owner ruling; ADR-050's
  consequence section is explicit that none may be added without a requirement.
- Stamping `hosted_serving_ends_at` at access end and sending the two notices —
  WO-134.
- Deletion's immediate `paid_through = now()` — WO-143.

## Rollback
Delete three source files and three test files. A Stripe subscription already
cancelled at period end is not restored by a rollback; resuming it is the
customer's own action (c6).
