# WO-125 — handleStripeWebhook and STRIPE_EVENTS — signature is the whole of the trust boundary

- Branch: wo/WO-125-stripe-webhook
- Estimate: ≤1 day

## Goal
Verify a Stripe signature before parsing anything, route the verified event
through one closed map, and create nothing at all for an event that does not
verify.

## File plan
> **Every path below is NEW.** No `src/` exists. Anchored to
> `registry/structure.md` (rule 1: "A Stripe webhook adapter verifies nothing
> itself: it hands the raw body and signature to BP-017") and BP-032's `code:`
> glob `src/lib/account/provisioning/**`. Provisional against a repo with no code.

| File | New/Modify | Change |
|---|---|---|
| `src/lib/account/provisioning/events.ts` | NEW | Exports `STRIPE_EVENTS` with BP-032's signature verbatim — a closed `Record<string, 'provision' \| 'subscription' \| 'ignore'>` with `checkout.session.completed` mapped to `provision`, every `customer.subscription.*` and `invoice.*` row we handle mapped to `subscription`, and the rest absent. |
| `src/lib/account/provisioning/webhook.ts` | NEW | Exports `handleStripeWebhook(rawBody, signature)` with BP-032's signature verbatim. **Verifies against `env.STRIPE_WEBHOOK_SECRET` before parsing**; a body that does not verify returns `{ handled: false, reason: 'signature' }` and touches no table and no other module. A verified event whose type is absent from `STRIPE_EVENTS` returns `{ handled: false, reason: 'unknown_event' }` — never a throw, never a 500. A `provision` row calls `provisionFromPayment` (WO-126, imported behind a narrow function type so this work order can land first with a stub); a `subscription` row calls BP-060's `onSubscriptionEvent` (WO-133, same). Introduces **no** event table: BP-032's data-model delta rules out both `payments` and `provisioning_attempts`, so the durable record that lets the adapter answer 2xx is the `users` row the provisioning branch writes (`checkout_session_id`, WO-116), and this file's own record of an event is the structured event stream. |
| `tests/account/provisioning/webhook.test.ts` | NEW | A tampered body, a wrong secret, a replayed-but-stale signature timestamp and an empty signature each return `reason: 'signature'`, write no row and call no downstream module (asserted by spy, not by absence of error); a verified unknown event type returns `unknown_event`; a verified `checkout.session.completed` routes to `provision` exactly once; verification happens before `JSON.parse` (asserted by handing a body that is valid-signature/invalid-JSON and a body that is invalid-signature/valid-JSON and observing which fails first). A test asserts no table is created or written by this module. |
| `tests/account/provisioning/redaction.test.ts` | NEW | No log call in `src/lib/account/provisioning/**` receives the raw body, the signature header, the webhook secret or a magic-link URL (BP-032's NFR budget). |

## Interfaces
Exposes (verbatim from BP-032's `## Public interface`):
```ts
export function handleStripeWebhook(rawBody: Buffer, signature: string): Promise<
  | { handled: true; event: string }
  | { handled: false; reason: 'signature' | 'unknown_event' }
>

export const STRIPE_EVENTS: Readonly<Record<string, 'provision' | 'subscription' | 'ignore'>>
```
Consumes: `provisionFromPayment` (WO-126) and `onSubscriptionEvent` (WO-133),
both by their blueprint signatures.
