## Goal
Build the only path into a generation prompt as a closed struct carrying the customer's current voice text verbatim — so that "nothing is learned about them" is a property of a type rather than an audit of a pipeline.

## File plan
| File | New/Modify | Change |
|---|---|---|
| `src/lib/generate/voice/inputs.ts` | NEW | `DraftPromptInputs` verbatim from BP-042's public interface, and `buildPromptInputs(a: { siteId: string; opportunityId: string; grounded: GroundedFact }): Promise<DraftPromptInputs>` — reads `sites.voice_text` now, carries it in full and unaltered, and carries the opportunity with its evidence. No earlier version is read, copied, cached or stored; the voice text is not written onto the draft and never appears in a log line. | `tests/generate/voice/inputs-shape.test.ts` | NEW | Compile-time assertions under `tsc --noEmit`: `keyof DraftPromptInputs` is exactly `'businessName' | 'domain' | 'category' | 'voiceText' | 'opportunity' | 'grounded'` (a hand-rolled `Equals<A, B>`), so adding a `profile`, `summary`, `embedding` or `history` member fails the type-check; plus a runtime assertion that the object handed to `llm()` has exactly those keys. |

## Steps
1. Write both test files first and run them; both must fail on a missing module.
2. Implement `inputs.ts`. The read of `voice_text` is a single column read at build time; there is no cache and no memo, because a memo is an earlier version stored for reuse (c2).
3. The compile-time `Equals` assertion is the test of record for c4. BP-042 decision 4: the struct is what makes "nothing learned" checkable by reading a type rather than auditing a pipeline.
4. Assert in the test that the build performs no insert or update — the module holds no write path at all.
5. Run the tests. Then mutate: add an optional `styleProfile?: string` member and confirm `inputs-shape.test.ts` fails at compile time before any runtime test runs.

| **REQ-055 c3** Given the customer has written no description, when a draft is generated, then it is generated without one and no substitute is inferred. | `inputs.test.ts › a site with no description yields voiceText null and no substitute` |
| **REQ-055 c4** Given any number of edited or published pages, when a draft is generated, then the only inputs shaping its voice are that description and the page's own evidence; no profile, summary or embedding derived from the customer's edits, drafts or publishing history is stored or sent. | `inputs-shape.test.ts › DraftPromptInputs has exactly the six members` and `… the object handed to llm() has exactly those keys` |

**Discriminates (mutation check, constitution §8).**
- Adding any member to `DraftPromptInputs` fails the compile-time assertion; a runtime test that merely checked the voice text would survive that mutation, which is why c4's test of record is the type.
- Caching the voice text between builds makes `… changing the description carries only the current text` fail on the second build.
- Trimming or normalising the voice text makes the byte-for-byte assertion fail — "in full and unaltered" is exactly what the test holds.
