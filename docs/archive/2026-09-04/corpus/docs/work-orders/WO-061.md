# WO-061 — `resolveAddress` and `canonicalRedirect` — the closed address union, the eight-row order, the one control

- Branch: wo/WO-061-address-resolver
- Estimate: ≤1 day

## Goal
Turn a visit to a report address into exactly one arm of a closed union, in one
fixed order with removal above everything, producing at most one control and at
most one notice — so that two controls on one report is unrepresentable rather
than reviewed.

## Interfaces

Consumes: WO-051's `parseDomain`, `CanonicalDomain`, `DomainProblem`; WO-057's
`admitFreeScan`, `Admission`, `NetworkKey`; BP-012's `readCurrentReport` and its
**declared** `StoredReport` (decision 3, 2026-08-31 — imported, not re-shaped),
of which this module reads exactly `measuredAt`, `complete`,
`fromIncompleteRescan`, `correctionState` and `verdict`; BP-005's

Exposes (verbatim from BP-022 `## Public interface`):

```ts
// src/app/(public)/scan/[domain]/_address/resolve.ts
// Exactly one arm. REQ-001 criterion 5's "never a blank page, a 404 or an
// unhandled error" is discharged by the union being closed and total.
export type AddressState =
  | { kind: 'malformed';  problem: DomainProblem }                       // REQ-001 c4
  | { kind: 'removed' }                                                  // REQ-002 c3, REQ-001 c18
  | { kind: 'scanning';   scanId: string }                               // REQ-001 c9, REQ-003 c1/c7
  | { kind: 'starting';   startOnFirstFrame: true }                      // REQ-001 c9 + BUILD §3
  | { kind: 'refused';    refusal: Refusal }                             // REQ-003 c12, no stored report
  | { kind: 'cooldown';   failedAt: Date }                               // REQ-001 c16, no stored report
  | { kind: 'report'
      report: StoredReport                                               // REQ-001 c11/c12
      control: AddressControl                                            // exactly one, or none
      notice: AddressNotice | null }                                     // at most one written line

/** REQ-001 criterion 16: "exactly one control that starts a new measurement is
 *  offered beside it … never a second control alongside it." A sum type, so two
 *  controls on one report is unrepresentable rather than tested for. */
export type AddressControl =
  | { kind: 'none' }
  | { kind: 'rescan';           because: 'incomplete' | 'age' }          // REQ-001 c14 / c15
  | { kind: 'retry' }                                                    // REQ-001 c16
  | { kind: 'correction_retry' }                                         // REQ-094 c7 — that node's arm

/** At most one line beside the report. REQ-094 c7 forbids a second line beside
 *  REQ-001 c16's, so this is a sum too. */
export type AddressNotice =
  | { kind: 'incomplete';  unmeasured: readonly UnmeasuredPart[] }       // REQ-001 c14
  | { kind: 'measurement_failed'; failedAt: Date }                       // REQ-001 c16
  | { kind: 'refused';     refusal: Refusal }                            // REQ-003 c12, stored report

export function resolveAddress(a: {
  rawDomain: string
  network: NetworkKey                    // BP-023
}): Promise<AddressState>

// src/app/(public)/scan/[domain]/_address/canonical.ts — routing only
/** 308s any non-canonical written form of a domain to the one address for it
 *  (REQ-001 c2). The parse itself is BP-023's `parseDomain`; this is the
 *  redirect policy that keeps one address per domain. */
export function canonicalRedirect(rawSegment: string): { redirectTo: string } | null
```

`Refusal` is the refusing half of WO-057's `Admission` — the union minus its
`{ admit: true }` arm — and is derived from it by a type operator in this file,
never restated as a second literal union. `UnmeasuredPart` is likewise derived,
not invented: `StoredReport.verdict` is BP-024's `Verdict`, whose `missing` and
`unmeasuredElsewhere` arrays carry the parts that were not measured, so
`UnmeasuredPart` is the element type of those two arrays and is written as a
type operator over them. Nothing in this file re-declares a `StoredReport`
field.

The resolution order, verbatim from BP-022 `## Error & edge behavior`,
evaluated top to bottom, first match wins:

| # | Condition | State | Grounds |
|---|---|---|---|
| 1 | the address segment does not parse (`parseDomain` fails) | `malformed` | REQ-001 c4 |
| 2 | the segment parses but is not the canonical form | 308 to the canonical address | REQ-001 c2 |
| 3 | a `domain_blocks` row exists for the domain | `removed` | REQ-002 c3, REQ-001 c18 |
| 4 | a scan of this domain is running | `scanning` | REQ-001 c9, REQ-003 c7 |
| 5 | a current stored report exists | `report` (+ control, + notice) | REQ-001 c12 |
| 6 | a scan of this domain failed producing no report < 24 h ago | `cooldown` | REQ-001 c16 |
| 7 | admission refuses | `refused` | REQ-003 c12 |
| 8 | otherwise | `starting` | REQ-001 c9 |

The control derivation, verbatim from the same section, first match wins:

| # | Condition on the stored report | Control |
|---|---|---|
| 1 | a correction of this report ran and produced no report, and its one retry is unspent | `correction_retry` |
| 2 | a measurement of this domain failed producing no report < 24 h ago | `retry` |
| 3 | age ≥ `FREE_RESCAN_WINDOW_D` | `rescan{ because: 'age' }` |
| 4 | incomplete, and this scan was not itself started from an incomplete report's offer (`scans.from_incomplete_rescan` false) | `rescan{ because: 'incomplete' }` |
| 5 | otherwise | `none` |

## Steps
1. Write the failing suites first.
2. Declare the three unions exactly as above.
3. Implement `canonicalRedirect` over `parseDomain`: on `ok`, compare the
   canonical key's URL form with the segment as written; differ → `{ redirectTo }`,
   same → `null`. On a parse failure return `null` — a malformed segment is row 1
   of the resolution table, not a redirect.
4. Implement `resolveAddress` as the eight rows in order, each an early return.
   Row 3's `removed` comes from WO-057's `admitFreeScan` returning
   `{ refuse: 'removed' }` — that is the only way this module learns a domain is
   removed, and it holds no `domain_blocks` query of its own.
5. Implement the control derivation as a separate first-match function over the
   stored report, returning exactly one `AddressControl`. Row 3 reads
   `StoredReport.measuredAt` against `FREE_RESCAN_WINDOW_D`; row 4 reads
   `StoredReport.complete` and `StoredReport.fromIncompleteRescan` — the blob's
   own field, which BP-012 notes "REQ-001 c14's re-scan control reads" — rather
   than `scans.from_incomplete_rescan` directly or a walk of a predecessor
   chain; row 1 reads `StoredReport.correctionState`, BP-028's value domain.
6. Implement the notice derivation: at most one `AddressNotice`, or `null`.
   `measurement_failed` and `refused` are notices on a `report` arm whenever a
   report exists — never states of their own (BP-022's rows 5 above 6 and 7).
7. Add the exhaustiveness guard: a `never` check over each union so a new arm
   fails the build until every table maps it.
8. Emit the one structured line per resolution BP-022's NFR budget specifies:
   route id, `AddressState.kind`, `AddressControl.kind`, domain, and the scan id
   where one exists. Never a payload, never an IP.
