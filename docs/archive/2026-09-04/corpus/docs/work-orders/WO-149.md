# WO-149 — Setup reminders: three at 24/72/168 hours, stopped at send time

- Branch: wo/WO-149-setup-reminders
- Estimate: ≤1 day

## Goal
Schedule at most three `setup-reminder` mails at 24, 72 and 168 hours after
payment, each carrying a sign-in link that lands on `/setup`, and suppress any
whose founder has since submitted or cancelled.

## File plan
> Every path below is **NEW** (no `src/` on disk, checked 2026-08-31). Placement
> follows `structure.md` and BP-033's `code:` globs; provisional.

| File | New/Modify | Change |
|---|---|---|
| `src/app/(account)/setup/reminders.ts` | NEW | `scheduleSetupReminders()` — schedules the three offsets through BP-016's `scheduleSequence()`, and the send-time predicate that suppresses a reminder when `setup_completed_at` is set or access has ended, incrementing `sites.setup_reminders_sent` (capped at 3 by the column's check constraint). Never schedules before an account exists. |
| `tests/app/setup/reminders.test.ts` | NEW | Offsets, the cap, send-time suppression at hour 71, the sign-in link's landing path. |

## Interfaces
Consumes: `scheduleSequence()` and `sendEmail()` / `MAIL_KINDS` (BP-016,
`setup-reminder`), `requestMagicLink()` (BP-017) for the link that lands on
`/setup`, and `SETUP_REMINDER_OFFSETS_HOURS` from BP-005's pins.

Exposes (verbatim from BP-033 `## Public interface`):
```ts
/** REQ-025 criterion 6. Bounded, stoppable, and never sent before there is an
 *  account to sign in to. */
export const SETUP_REMINDER_OFFSETS_HOURS: readonly [24, 72, 168]
export function scheduleSetupReminders(a: { userId: string; siteId: string; paidAt: Date }): Promise<void>
```

## Steps
1. Write the failing tests first.
2. Pin `SETUP_REMINDER_OFFSETS_HOURS = [24, 72, 168]` in
   `src/lib/config/constants.ts` (BP-005's file — coordinate with that node's
   work order; this WO re-exports the tuple from `reminders.ts` and adds no
   second literal, structure.md rule 5) and assert it in `tests/pins.test.ts`.
3. Schedule the three offsets from `paidAt`, only once an account is open
   against the payment.
4. Check stoppage **at send time**, not at schedule time, so a founder who
   finishes at hour 71 receives no hour-72 mail.
5. Fail the send when the sign-in link cannot be issued — a reminder with no
   working link is a send-time failure, not a degraded send.
6. Mutation check: move the stop check to schedule time and confirm the
   "finished at hour 71" test fails.
