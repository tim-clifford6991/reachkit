# ADR-012 — LANDMINE — `GeneratedText` is nominal: the brand is the boundary, and deleting it looks like tidying

- Date: 2026-09-04

> **Read this before removing the odd symbol field from `GeneratedText`,
> before "simplifying" it back to `{ source, text }`, before adding a second
> way to build one for a fixture, and before citing ADR-010 alternative 3 as
> grounds that this repository rejected type-level enforcement.** Each of
> those reads like a cleanup. Each of them, and only the deletion of two
> lines, converts an approved requirement's central guarantee back into a
> naming convention — and the whole suite stays green while it happens.

## Context

BP-020 exists so that model-produced text reaches a person only through
`fromStored` and `renderGenerated`, labelled as the content of the page it
belongs to. REQ-093 criterion 1 ("no part of it was produced by a language
model, unless criterion 2 or criterion 3 admits it") and ADR-010 both rest on
that funnel being real.

WO-279 built it and asserted criterion 1 with two source-text checks over the
governed tree: no `as GeneratedText` cast anywhere, and `fromStored` the only
exported function whose declared return type is `GeneratedText`. Its in-code
comment concluded that a `GeneratedText` therefore could not be minted by
hand.

**TST-028 disproved that concretely.** From a file outside the module the
validator wrote

- an object literal of the right shape, typed against the exported interface,
- with **no** cast and **no** second constructor,

and pushed it through `renderGenerated`, which rendered it exactly as it
renders text read from storage. `tsc --noEmit` clean; both source-text checks
silent; the string-literal sweep silent (the sentence never appears in a JSX
position); the flow gate silent (it flags a *raw column read* reaching a
surface, and a hand-minted value passed correctly *through* `renderGenerated`
is by the gate's own design indistinguishable from a legitimate one).
TypeScript's structural typing needs neither of the two things the checks look
for. This is the one hard fact this decision turns on; it is reproduced on
WO-279's page, not asserted here.

### Why the two soft lines do not add up to one hard one

The tempting reading is defence in depth: a convention, plus a sweep, plus a
flow gate — three imperfect things that together cover the surface. That
reading is wrong here, for a reason worth stating so nobody re-derives it
from optimism:

**Defence in depth adds up only when the layers fail to *different* inputs.
These three fail to the same one.** The hand-minted literal is invisible to
all three simultaneously, and it is invisible to each of them for the same
structural reason: none of them looks at *where a value of the type came
from*, because none of them can. The sweep reasons about literals in surface
positions; the value is built in a `.ts` module. The flow gate reasons about
lexical column names; a hand-minted value names no column — and the gate is
already known to miss even a *renamed* column read (declared, `open`, verified
by TST-028 and not a defect). The source-text checks reason about casts and
exports; there is neither.

So the corpus had one line of defence, spelled three ways, against a
manoeuvre no line covered. A guarantee that holds against everything except
the easiest thing to do by accident — write an object of the right shape,
because the type is exported and the editor autocompletes it — is not a
guarantee. It is a naming convention with test coverage pointed elsewhere.

### What the promise is

REQ-093 criterion 1 is not "the module is tidy". It is that a person never
reads model-written text as the product's own voice. The failure it names is
not adversarial: nobody is attacking this repository. The failure is a hurried
author on a screen that does not exist yet, holding a string that came out of
a model, wanting a `GeneratedText`, and finding that typing the shape works.
That is precisely the population ADR-010 was written for — "a reviewer cannot
review a file nobody has written" — and it is why the mechanism has to be one
nobody has to remember.

## Decision

**The `GeneratedText` boundary is nominal. `text.ts` declares a brand it does
not export, and `fromStored` is therefore the only expression in any program
that can produce a value of the type.**

1. **Shape.** A `unique symbol` const declared in
   `src/lib/presentation/generated/text.ts`, **not exported**, used as a
   computed key on the interface with a `true` value. It is created at run time
   (a real `Symbol`), not declared phantom, so `fromStored` constructs the
   value in one object literal and needs no cast — which keeps this module's
   zero-cast invariant, and turns WO-279's `no /\bas GeneratedText\b/`
   source-text check from decoration into a load-bearing check.
2. **No runtime predicate is derived from the brand, and none may be.** A
   symbol key does not survive `JSON.stringify` or a React server→client
   payload, so an `isGeneratedText()` guard would reject a perfectly
   legitimate value on the far side of a serialization boundary. The brand is
   a compile-time gate only.
3. **Consequently, a `GeneratedText` never crosses a serialization boundary.**
   `renderGenerated` runs on the server side of it and what crosses is its
   result — `{ label, text, proposed }` — a value that already carries the
   label criterion 2 requires. This is the correct shape independently of the
   brand; the brand makes it the only shape that works.
4. **`GeneratedColumn` gains nothing and needs nothing.** It is already
   nominal in the only sense that matters: a closed union of seven string
   literals where a wrong value is a compile error at the call site, as
   TST-028 re-verified. Branding it would add a construction ceremony to a
   value that has no construction.
5. **This is ADR-010 point 5's second clause, not its alternative 3.** ADR-010
   rejected branding *at the `src/ui/` component boundary*, on one ground and
   one only: `src/ui/` would import from `src/lib/presentation/`, which
   inverts `structure.md` rule 6 and creates the cycle that rule calls a build
   failure. This brand is declared and consumed entirely inside
   `src/lib/presentation/generated/`. It crosses no module edge, creates no
   import, and is exactly what point 5 already instructs: "Inside
   `src/lib/presentation/`, types do the work wherever they can without
   crossing that edge" — beside `PageIdentity`'s missing `description` arm,
   `WorkStop.resumes` having no absent arm, and `explain()` taking no raw
   number. Nothing ADR-010 asserts is amended.

## Alternatives considered

1. **Leave the boundary conventional and record the hole as a `rests-on`
   row** — rejected. The row would be permanently `open` against a hazard that
   grows with every surface added, and it asks a future author to remember a
   rule at exactly the moment ADR-010's own context paragraph says they will
   not. It is also the alternative with a *measured* price: on the code as it
   stands, **zero**. Every construction of a `GeneratedText` anywhere in the
   corpus — three source files, four test files, eleven fixtures, 21 files
   total — already goes through `fromStored`; there is not one object literal
   to change. Paying nothing to convert a convention into a compiler fact, on
   a boundary an approved requirement rests on, is not a close call. Where the
   cost lands later is a fixture wanting a `GeneratedText` without touching
   storage, and its fix is one call — `fromStored('drafts.body', '…')` — which
   is shorter than the literal it replaces and states the column, which the
   literal never did.
2. **A phantom brand — `declare const b: unique symbol`, no runtime value** —
   rejected, though it is the cheaper-at-runtime option. It forces `fromStored`
   to produce the value by cast, which is the one expression this module
   forbids; the `no as GeneratedText` check would have to be weakened to
   "exactly one cast, and only there", and a check with an exception is the
   check a later author edits.
3. **A class with a `#private` field** — rejected. It is the strongest brand
   and the worst fit: a class instance cannot cross a React server→client
   boundary at all, so it converts a design constraint (point 3 above, which
   we want) into a runtime crash at an unrelated seam, and it makes every
   `GeneratedText` a non-plain object for no gain over a symbol key.
4. **A second sanctioned constructor for tests — `forTest(text)`** — rejected
   pre-emptively, because it is the first thing that will be proposed the day
   a fixture is awkward. It re-opens the exact hole this decision closes, with
   a name that makes it sound sanctioned, and it defeats WO-279's
   only-one-export check as a side effect. Fixtures call `fromStored`.
5. **Type-level enforcement at the `src/ui/` boundary** — not reconsidered
   here; ADR-010 alternative 3 settles it on `structure.md` rule 6 grounds and
   this decision does not reopen it. Point 5 above records why the two are
   different questions.

## Consequences

- `fromStored` becomes the only construction path *in fact*, so BP-020's
  `## Error & edge behavior` bullet claiming exactly that stops being a
  statement about this module's manners and becomes a statement about the
  compiler.
- **The brand closes minting; it does not close lying.**
  `fromStored('drafts.body', "text I typed")` still produces a conforming
  value. Nothing in a single-program type system closes that, and no sweep
  can — the call is well-formed by construction. It is BP-020's
  `undischargeable` `rests-on` row, and it is why the flow gate over the
  data-access path stays: the brand and the gate cover different halves, which
  is what defence in depth actually looks like and what the three checks
  before this decision did not have.
- **A follow-up work order is owed on BP-020** (the planner's to cut, named
  here as owed, not cut): land the brand in
  `src/lib/presentation/generated/text.ts`, adapt `fromStored`'s single object
  literal, and replace `text.test.ts`'s corrected comment with the test that
  discriminates the brand — a `@ts-expect-error` fixture holding **verbatim
  the construction TST-028 used**, so that deleting the brand fails a named
  test instead of passing silently. That test is the load-bearing artifact of
  this decision; without it the brand is one more thing a refactor removes.
  Landing it discharges BP-020's `open` row.
- WO-279 is not re-opened by this. Its implementer corrected the false comment
  and the correction stands; the brand is a change to BP-020's declared
  interface and belongs to a separate order (constitution §4 — the type's
  shape is the architect's, not the implementer's, which is why it was
  correctly not added unilaterally).

## Cost of reversing

- **In code: two lines.** Delete the symbol const and the computed key. Every
  call site keeps compiling — they all go through `fromStored` already, which
  is exactly what made the brand free to add and is exactly what makes it free
  to remove.
- **In effect: total, silent, and indistinguishable from a cleanup.** The
  suite stays green. `tsc` stays clean. The lint count does not move. The
  string-literal sweep and the flow gate do not notice, because neither of
  them ever could — that is the finding this decision was written on. The only
  thing that changes is that the sentence a model wrote can once again be
  hand-typed into the arm reserved for it and rendered to a person as the
  product's own voice, and the corpus will report that everything passed.
- Which is the definition of a landmine, and why this is a file rather than a
  line: the artifact a future cleanup consults first is ADR-010, and ADR-010's
  alternatives list reads, at a glance, as a rejection of branding. Point 5
  above and the pointer added to ADR-010's `## Consequences` exist so that
  glance lands here instead.
