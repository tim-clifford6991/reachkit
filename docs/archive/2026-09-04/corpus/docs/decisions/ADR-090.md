# ADR-090 — One name for the AI-reader set: `AI_CRAWLERS` is folded into `AI_READER_AGENTS`, and REQ-059 criterion 4 states its membership

- Date: 2026-08-31

> Amends **ADR-022** on two points: the constant's name, and whether the
> membership is stated anywhere in the corpus. ADR-022's decision points 1 to 5
> stand unchanged; point 6 is discharged here.

## Context
ADR-022 established one closed, pinned list of AI reader user-agent tokens,
`AI_READER_AGENTS`, read by three things owned by four blueprints: the
blocked-readers count (BP-024), the paste block a founder copies into their own
`robots.txt` (BP-027), and the robots policy ReachKit serves on
`content.{customer-domain}` (BP-004). Its argument is that if those three read
different sets the product contradicts itself on the customer's own property,
silently.

Two facts have since landed that ADR-022 could not see.

**First, a second name for the same set.** BP-047 — the feature node cut from
REQ-059, under BP-004 — records its decision 3, "The `AI_CRAWLERS` list is a pin,
not a string in a template", and names `BP-005`'s `AI_CRAWLERS` as the list its
`robots.ts` renders. ADR-022 decision 4 says the agents that file names are
*exactly* `AI_READER_AGENTS`. So there is one set with two names, in one pins
file, read by nodes that each know only one of the names. That is rule 2.4's
failure arriving by vocabulary rather than by duplication: nothing is copied, and
the two constants still drift the first time a member is added to one of them.

**Second, the membership is in the corpus after all.** ADR-022's `rests-on` row
states that "which AI reader user-agent tokens exist and are worth naming … is
not stated anywhere in the corpus", and holds the list open pending a cited,
dated external source. REQ-059 criterion 4, `status: approved`, states:

> Given the robots policy we serve for the hosted destination, when any crawler
> reads it, then it blocks no general search engine crawler and permits by name
> GPTBot, ClaudeBot, OAI-SearchBot, Claude-SearchBot, PerplexityBot and
> Google-Extended.

`BUILD.md` §9 says the same, verbatim:

> a robots.txt **we serve** that allows GPTBot, ClaudeBot, OAI-SearchBot,
> Claude-SearchBot, PerplexityBot, Google-Extended.

Six tokens, named, in an approved requirement. Combined with ADR-022 decision 4 —
which makes the hosted set and the counted set one set — the membership is
determined by the corpus and needs no external source. Deriving it from an
approved artifact and citing that artifact is what rule 1.3 asks for; it is not
rule 1.2's forbidden invention, which is a fact about the world stated from
memory. Nothing about the world is asserted here beyond what REQ-059 already
promises a crawler will read.

## Decision
1. **`AI_READER_AGENTS` is the one name.** BP-005 declares it once; BP-047's
   `AI_CRAWLERS` is that constant under its ADR-022 name and no second export
   exists. BP-004, BP-024, BP-027 and BP-047 all read `AI_READER_AGENTS`.
2. **The membership is REQ-059 criterion 4's, quoted.** `tests/pins.test.ts`
   asserts the constant against that clause by quotation (rule 5.3), not by line
   number, so a change to the requirement fails the pins test rather than
   silently disagreeing with it. **No token is written into this file or into
   BP-005 from memory**: the assertion cites the requirement and the requirement
   carries the names.
3. **ADR-022's `rests-on` row is discharged, not deleted.** Its disposition moves
   from `open` to `confirmed`, its claim text names REQ-059 criterion 4 as the
   source, and this file is the amendment that did it. The row is kept because
   the record of what was assumed and how it was settled is the artifact's value.
4. **ADR-022 decision 6's mechanism survives.** An empty list still fails the
   pins test, so the constant cannot ship empty by omission, and adding a member
   is still one line that moves the count, the paste block and the hosted robots
   file together on one deploy.
5. **The set does not silently widen.** Adding an agent that REQ-059 criterion 4
   does not name is a change to that requirement first, because the assertion in
   point 2 fails until the quoted clause carries it. That is deliberate: the
   paste block is a technical artefact a founder copies verbatim into a file they
   may not open again for a year, and the hosted policy is a public statement.

## Alternatives considered
1. **Keep both names and assert set equality between them** — rejected. It is
   ADR-022's own alternative 1 with an extra test: two constants, two edit sites,
   and an equality assertion that a member added to both at once passes while the
   *intent* of the two lists has quietly forked. One name has no such state.
2. **Rename to `AI_CRAWLERS` instead** — rejected on scope, not on taste.
   `AI_READER_AGENTS` is named in an accepted standalone ADR with five
   `decides-for` edges; `AI_CRAWLERS` is named in one node's `## Decisions` entry.
   Renaming the cross-node name to match the local one inverts the direction the
   corpus already points. "Reader" is also the word REQ-009 uses ("AI readers
   blocked"), and that requirement is where the count is read by a customer.
3. **Leave the membership open and populate from an external source at
   implementation time** — rejected under rule 1.3. The question has a defensible
   answer derivable from an approved artifact, and the derivation is one line;
   holding it open would mean building against an empty list whose eventual
   contents could contradict REQ-059 criterion 4, which is a promise about a file
   the product serves. An external source may still be consulted to *widen* the
   set later — that path is point 5, through the requirement.
4. **A `## Decisions` entry in BP-005** — rejected under rule 2.2's file test on
   both limbs: the subject spans four blueprints and no one of them owns it, and
   this decision amends another decision (ADR-022). Either limb alone would earn
   the file.

## Consequences
- BP-047's decision 3 stands as written except for the constant's name; its
  reasoning ("a pin, not a string in a template") is unchanged and is not
  restated here.
- ADR-022's `rests-on` row reads `confirmed`, so the generated assumptions view
  stops reporting an open assumption that the corpus had already answered — the
  rule 5.5 failure mode of an index that is correct and silent.
- The pins test now has a quotable source for a list it previously could only
  assert was non-empty and distinct. That is a stronger test, and it is the one
  §8's "cite your source" asks for.
- **Cost of reversing:** low in code — one rename — and that is the point. The
  cost of *not* making it is that the count, the paste block and the hosted file
  drift apart on a customer's own property, which is exactly the failure ADR-022
  was written to prevent and which its own second name reintroduced.
