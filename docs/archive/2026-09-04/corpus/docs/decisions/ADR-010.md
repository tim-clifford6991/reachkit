# ADR-010 — The three presentation laws are enforced by path-glob conformance suites over the surface tree, not by call-site discipline

- Date: 2026-08-31

> Amends BP-019 `## Decisions` entry 1, which named "a lint rule banning string
> literals in JSX and mail templates" as one of three mechanisms. That mechanism
> is replaced by the suites below. The other two — the frozen registry and
> components with no default strings — stand unchanged.

## Context
Three approved requirements state a law over every surface the product renders,
and all three reach forward in time:

- REQ-093 criterion 1 — "including surfaces added after this requirement".
- REQ-091 criterion 2 — "any screen the product renders … including screens
  added later".
- REQ-092 criteria 3 and 7 — "the screen they land on", and "any statement of
  when the next page publishes … wherever it renders".

BP-019 `## Decisions` entry 2 already ruled that these laws are **concentrated**
in one component rather than distributed across fifteen surface nodes, on rule
7.1 grounds and because "a law that must hold on 'screens added later' has no
owner to inherit from". That ruling settles *where the mechanism lives*. It does
not settle the harder half: a concentrated mechanism is still a function, and a
function is something a new surface can simply not call.

The three feature nodes cut from those requirements — BP-020, BP-021, BP-054 —
each hold part of the answer, and none of them owns the enforcement, because the
enforcement necessarily reads the source trees of BP-001, BP-004, BP-016 and
BP-018. Rule 2.2's file test is exactly "spans nodes no single blueprint owns",
and this spans seven; it also amends a decision recorded in an eighth.

Two facts about this repository shape the answer. First, `structure.md` rule 7
fixes the top-level set (`src/`, `supabase/`, `tests/`, `public/`,
`sdlc-factory/`) and rule 2 gives every path exactly one owner, so **the set of
surfaces is a set of paths, and it is closed under a glob**. Second,
`structure.md` rule 6 fixes the dependency direction — `src/app/` and
`src/jobs/` → `src/lib/` → `src/lib/{config,egress,costs,db}` — and BP-019
already depends on BP-018. Any scheme in which `src/ui/` components accept types
minted in `src/lib/presentation/` inverts that edge and creates the cycle rule 6
calls a build failure.

## Decision
**Each of the three law nodes owns a conformance suite whose scope is a path
glob over the surface tree, not a list of call sites; the suites run in CI, and
a surface added later is in scope by construction because it must live under a
governed path.**

1. **BP-020 — the string-literal sweep and the generated-text flow gate.**
   `tests/presentation/copy/**` parses every file under `src/app/**`,
   `src/app/(hosted)/**`, `src/lib/mail/**` and `src/ui/**`, and fails on a
   string literal in a JSX text position, in a text-bearing prop, or in a mail
   template body, unless the file is on a declared allow-list of non-voice
   strings (attribute values, `aria-*`, test ids, class names). Separately it
   fails on a value read from one of `GeneratedColumn`'s columns reaching a
   surface other than through `renderGenerated` or `renderQuestion`. Both scopes
   are globs; a file added tomorrow is swept tomorrow.
2. **BP-021 — the cold-start sweep.** `tests/presentation/coldstart/**` enumerates routes from
   the App Router file tree, renders each against one fixture domain that ranks
   for nothing, and asserts per rendered place: no blank, dash or placeholder
   where a value would sit; every module still present; exactly one written line
   per accounted place; and every rendered numeric value traceable to a
   `Measured` whose domain and scan date are the fixture's. A place rendered but
   absent from `PLACES` fails **by name**.
3. **BP-054 — the stopped-state sweep.** `tests/presentation/stopped/**` renders
   the same enumerated routes twice — stop present and stop absent — and asserts
   that every sentence tagged `law: 'next-publish'` in `COPY_META` was produced
   by `nextPublishStatement`, that under a stop it names the stop and no other
   cause, and that no rendered text matches the internal-cause vocabulary.
4. **The registry is the enumerator, not a checklist.** `COPY_META` is typed
   `Record<CopyKey, CopyMeta>` and therefore total: a sentence cannot exist
   without declaring which law governs it. Each suite derives its own scope from
   that tag plus its glob. No suite holds a hand-maintained list of the places it
   must check, because a list is the thing that gets forgotten.
5. **Enforcement is by test, not by type, at the `src/ui/` boundary** — because
   the type-level alternative inverts `structure.md` rule 6's dependency
   direction. Inside `src/lib/presentation/`, types do the work wherever they can
   without crossing that edge: `WorkStop.resumes` has no absent arm, `PageIdentity`'s
   proposed arm has no description, `Place<T>` has no blank arm, `explain()`
   takes no raw number.
6. **Rule 3.3 applies and is stated, not assumed.** These suites block only where
   something enforces them. Nothing in this repository currently does — there is
   no CI configuration, no branch protection and no pre-commit hook on disk. Until
   one exists, a failing suite is recorded, not enforced. That is a platform
   decision for whoever configures the repository, and it is named here so that
   the gap is visible rather than presumed closed.

## Alternatives considered
1. **A `## Decisions` entry inside BP-020** — rejected. The suites read BP-001's,
   BP-004's, BP-016's and BP-018's source trees and are owned three ways across
   BP-020, BP-021 and BP-054. A reader arriving at BP-001 to add a screen would
   find nothing telling them a sweep exists. Rule 2.2's file test is met twice
   over: it spans nodes no single blueprint owns, **and** it amends BP-019's
   decision 1.
2. **An ESLint rule and a shared config file** — rejected as the primary
   mechanism. It needs a repo-root config file (`eslint.config.mjs`) that
   `structure.md` gives no owner, so the rule's own home would be an unowned
   path; and a lint rule is disabled per-line with a comment, which the string
   sweep's allow-list makes an explicit, reviewable decision instead. A lint rule
   remains available as developer ergonomics derived from the same allow-list; it
   is not the gate.
3. **Type-level enforcement at the component boundary** — make BP-018's
   components accept a branded `Voice` string and a `Place<T>` rather than raw
   props. This is the strongest mechanism and it is rejected on one ground only:
   `src/ui/` would import from `src/lib/presentation/` while BP-019 already
   depends on BP-018, which is a cycle, and `structure.md` rule 6 calls a cycle
   between `src/lib/` modules a build failure rather than a review comment.
   Declaring the brands in `src/ui/` instead would work and would require an edit
   to BP-018's interface, which is a change to another node's contract and is
   named in the consequences below as the one improvement worth taking later.
4. **Distribute each law into every surface node** — already rejected by BP-019
   `## Decisions` entry 2 on rule 7.1 grounds. Restated here only to record that
   this decision does not reopen it.
5. **Review discipline** — rejected. All three requirements bind surfaces that do
   not exist yet; a reviewer cannot review a file nobody has written, and the
   first hurried screen is precisely the one that skips the call.

## Consequences
- A new screen is in scope for all three laws the moment its file lands under a
  governed path. Nobody has to remember, and nobody can opt out without moving
  the file outside the top-level set `structure.md` rule 7 fixes.
- The suites read other nodes' source trees. That is a **test-time** relationship
  and creates no import and no cycle; no `depends-on` edge is drawn for it, and
  each node's body says so explicitly so a future reader does not add one.
- Three suites carry three wall-clock budgets — 120 s, 180 s and 60 s, chosen in
  BP-020 Decisions 3, BP-021 Decisions 3 and BP-054's NFR budget respectively.
  When one is exceeded, the fix is to shard by surface glob, never to raise the
  number quietly: a sweep that grows unbounded gets disabled, and a disabled
  sweep is how a path-glob law dies without anyone deciding to kill it.
- The one surface the globs do not reach is a place rendered from a path outside
  them. That is the `rests-on` row above.
- **Alternative 3 is not a rejection of branding as such, and ADR-012 is not an
  amendment to this decision.** Alternative 3 rejects branding *at the `src/ui/`
  component boundary*, on `structure.md` rule 6 cycle grounds and nothing else.
  A brand declared and consumed entirely inside `src/lib/presentation/` crosses
  no module edge and is what point 5's second clause already instructs; BP-020's
  `GeneratedText` carries one (ADR-012, a landmine record). A reader arriving at
  alternative 3 with a mind to remove that brand as inconsistent with this
  decision should read ADR-012 first: nothing this decision asserts is amended
  by it, and the brand's deletion is invisible to every suite point 1 creates.
- **Cost of reversing:** low in code and high in effect. Deleting a suite is one
  directory; what it removes is the only thing standing between three approved
  laws and the first surface whose author never read them. Anyone proposing to
  replace a suite with review discipline is proposing to un-decide BP-019
  decision 2 as well.
