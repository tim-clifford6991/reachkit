# ADR-091 — Path ownership is by most-specific declared glob, and a feature node may own files inside a container it is not a child of

- Date: 2026-08-31

## Context
`registry/structure.md` rule 2 read, at the time forty-four feature nodes were
cut against it:

> **One owner per path, no exceptions and no overlaps.** `src/app/(hosted)/**`
> is BP-004's and is the only part of `src/app/` BP-001 does not own.

Taken literally that rule is already false of nearly every node in the corpus,
and was false the moment the first feature node was cut. BP-029 globs
`src/lib/mail/leads/**` inside BP-016's `src/lib/mail/**`; BP-047 globs inside
BP-004's `src/app/(hosted)/**`; BP-054 globs `src/lib/presentation/stopped/**`
inside BP-019's `src/lib/presentation/**`; five commerce leaves glob
`*_users_<sub>_*.sql` inside BP-017's `*_users*.sql`. In every one of those the
intent is obvious and the same: **the container or component anchors the
directory and the leaf anchors the files it specifies**, exactly as
`skills/blueprint-writing/SKILL.md` describes. What was missing was a written
rule saying so, and one consequence of its absence:

**BP-036 had nowhere to put two files.** REQ-029 is one behaviour with an engine
half and a screen half. Its node's parent in the hierarchy is BP-012 (the deep
pass), but the waiting route `src/app/(account)/setup/waiting/**` and the
progress endpoint `src/app/api/setup/progress/route.ts` live under `src/app/`,
which BP-001 globs whole. BP-036 globbed both, declared it in its decision 4, and
named the alternative it did not take: mint a sibling node under BP-001 owning
the two files and have it depend on this node's interface. Under rule 2 as
written, the choice it faced was a rule violation or two files with no home —
and rule 5.6 makes an unowned file under governed paths a reported defect either
way. That is a rule forcing a defect, which is the shape rule 4.2 exists to
surface.

This spans every node in the corpus and `structure.md` is not a blueprint, so no
single node owns the rule. Hence a file (rule 2.2), and it amends BP-002's
decision 2 on migration topics and BP-001's decision 1 on api adapters by
supplying the precedence both of them assume.

## Decision
1. **The most specific declared `code:` glob owns the path.** Where two nodes'
   globs both match a file, the node whose glob is the longer, narrower prefix
   owns it and is answerable for it; the broader glob is the container's
   anchoring of the directory, not a claim on every file in it. This is a reading
   rule for globs already written, not a change to any of them.
2. **Two globs that match identically are a conflict, not a precedence.** Where
   neither is more specific — the same glob written twice, as BP-016 and BP-029
   both wrote for `*_leads*.sql` and `*_suppressions*.sql` — rule 7.1 applies and
   one of the two withdraws it. The node that *specifies* the columns keeps it;
   the seam that merely reads them drops it. That case is resolved in BP-016's
   data-model section.
3. **A node may own files inside a container it is not a child of, when it
   declares it.** The hierarchy edge (`- Parent:`) answers *what behaviour is this
   a leaf of*; the `code:` globs answer *what files must move together when it
   changes*. They are different questions and a node cut from one requirement with
   an engine half and a screen half will answer them differently. Such a node
   states the claim in its own `## Decisions`, and the files it claims under
   another container stay bound by that container's rules — under `src/app/**`,
   `structure.md` rule 1's transport-only rule, with no engine logic in the route.
4. **A container's glob is never narrowed to route around a leaf.** BP-001 keeps
   `src/app/(account)/**` and `src/app/api/**` whole. Enumerating exceptions is
   the brittleness BP-001's decision 1 already rejected, and the first forgotten
   exception is a file with no home.
5. **Migration topic tokens follow the same rule.** A component holds a token
   (`*_users*.sql`, BP-017); a leaf narrows it with a sub-token
   (`*_users_erasure_*.sql`, BP-063) and owns that file. `structure.md` rule 3's
   token list is the closed set of *topics*; sub-tokens do not extend it and do
   not need a new entry. BP-002 keeps `*_baseline*.sql`, `*_rls*.sql` and
   `*_domainblocks*.sql`.

## Alternatives considered
1. **Enforce rule 2 literally and mint a sibling under BP-001 for BP-036's two
   files** — rejected. It splits one criterion set across two nodes for a
   bookkeeping reason, against rule 7.1, and BP-036 itself named this as the
   fallback rather than the preference. It would also have to be repeated for
   every future node with an engine half and a screen half, which is most of
   them.
2. **Narrow BP-001's globs to enumerate the routes it owns** — rejected, and
   already rejected once in BP-001's decision 1: the route list is still growing
   in a greenfield repo and the first forgotten glob is an unowned file.
3. **Let the broader glob win** — rejected. The container would then own every
   file, which makes every leaf's `code:` decorative and defeats rule 5.6's
   file → blueprint edge: "which node must change when this file changes" would
   answer `BP-001` for the whole application.
4. **Leave it unwritten, since every node already reads it this way** —
   rejected. It was unwritten and it produced exactly one node that had to choose
   between a stated rule and an unowned file, and had to say so in prose that
   nobody downstream is obliged to read. An unwritten rule that eight parallel
   agents each inferred correctly is a rule that the ninth will infer differently.
5. **A `## Decisions` entry in BP-001** — rejected under rule 2.2's file test:
   the rule governs BP-002's topic tokens, BP-004's hosted subtree, BP-016's,
   BP-017's and BP-019's component boundaries and every leaf beneath them, and a
   reader arriving at `structure.md` rule 2 to enforce it would have no reason to
   open BP-001.

## Consequences
- `structure.md` rule 2 is restated to carry this precedence, and rule 3 to carry
  the sub-token convention. Both are edits to the map, not to any node.
- BP-036's decision 4 stands as written and needs no sibling node; its
  `## Decisions` entry becomes the declaration point 3 requires rather than an
  exception awaiting a ruling.
- The `## Scope conflicts` section of `structure.md` logs one resolved conflict
  under point 2 (BP-016/BP-029) and no `blocked-by` edge, because the resolution
  is subtractive and lands inside the node that withdrew the glob.
- A node that claims a path inside another container and does *not* declare it is
  now a reviewable defect with a named rule, where before it was a judgement call.
- **Cost of reversing:** re-globbing every leaf in the corpus and minting a
  sibling node for each one that crosses a container boundary. High, which is
  why it is a file; but note the rule being written down is the one the corpus
  was already built to, so reversal means changing the corpus, not the rule.
