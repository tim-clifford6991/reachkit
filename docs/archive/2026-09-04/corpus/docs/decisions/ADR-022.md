# ADR-022 — One closed list of AI reader user-agents, pinned once; the blocked-readers count, the unblock lines and the hosted robots policy all read it

- Date: 2026-08-31
- **Amended by ADR-090** (2026-08-31): the constant has one name —
  BP-047's `AI_CRAWLERS` is folded into `AI_READER_AGENTS` — and decision 6's
  open membership is discharged against REQ-059 criterion 4. Decisions 1 to 5
  below stand unchanged.

## Context
"AI readers blocked" is the first of the free report's three problems (REQ-009,
`BUILD.md` §4.1), and the whole trust position of the free funnel rests on the
fix being exactly right: REQ-009's rationale says so — "the fix for blocked AI
readers copyable exactly as it must be pasted, because a wrong robots line is
worse than none."

Three separate things in this product depend on the same set of user-agent
tokens, and they are owned by four different blueprints:

| Reader of the set | Node | What it does with it |
|---|---|---|
| the blocked-readers **count** | BP-024, over BP-010's robots verdicts and BP-006's `readRobots` | how many named AI readers this site disallows — the number REQ-009 criteria 1, 3 and 4 render |
| the **unblock lines** | BP-027 | the verbatim directives the founder pastes, one per blocked reader (REQ-009 criterion 2) |
| the hosted **robots policy** | BP-004 | the agents named and allowed on `content.{customer-domain}` (`BUILD.md` §9, ADR-002's table) |

If these three read different sets, the product contradicts itself on the
customer's own property, and does so silently:

- The count says "0 — nothing is blocking AI readers" (REQ-009 criterion 3) while
  an agent BP-004 allows on hosted pages is disallowed on the customer's main
  site. The founder is told there is nothing to fix, about a reader we ourselves
  consider worth allowing.
- Or the paste block tells a founder to allow an agent the product's own hosted
  robots file does not name — advice we do not follow ourselves, printed in a
  code block a founder copies verbatim into a file they may not otherwise touch
  for a year.
- Or the count moves when one list gains a member and the other does not, so two
  reports of the same site disagree, breaking REQ-009 criterion 8's monotonicity
  in a way no test on that criterion would catch, because the counts came from
  different sets.

No blueprint owns the union. BP-027 owns the instruction, BP-024 owns the
measurement, BP-004 owns the hosted policy, and `structure.md` rule 5 puts the
value itself in BP-005. `BUILD.md` names AI crawlers as a category (§9, §14.6)
and enumerates none.

## Decision
1. **One pinned constant, `AI_READER_AGENTS`, in `src/lib/config/constants.ts`
   (BP-005)** — a frozen, ordered, closed list of user-agent tokens. It is the
   only enumeration of AI readers anywhere in the product.
2. **The count is defined over it.** BP-024's `blockedReaders` is the number of
   members of `AI_READER_AGENTS` that the site's access rules disallow, judged
   from BP-006's `readRobots` verdicts plus the home document's reader
   directives. A generic disallow that gates every reader blocks all of them —
   and, per REQ-004 criterion 7, also makes Foundations a measured 0.
3. **The unblock lines are derived from it, not written beside it.** BP-027's
   `unblockLines(blocked)` composes one directive per blocked member in list
   order. There is no second literal anywhere holding an agent name.
4. **BP-004's hosted robots policy reads the same constant.** The agents named
   and allowed on `content.{customer-domain}` are exactly `AI_READER_AGENTS`.
5. **`tests/pins.test.ts` (BP-005) asserts it once**: the list is non-empty, its
   members are distinct, and — the assertion that matters — the set of agents
   BP-004 emits into the hosted robots file equals the set BP-027 can emit into a
   paste block equals the set BP-024 counts over. One assertion over the sets,
   not over named members, so adding a member cannot break the property
   silently.
6. **The membership is not decided here.** Which tokens exist is a fact about
   the world, not a parameter (rule 1.2), and — as this ADR was written — no line
   of the corpus stated one. **Discharged by ADR-090:** REQ-059 criterion 4 names
   six by name and decision 4 above makes that the same set, so the source is the
   requirement, cited by quotation in `tests/pins.test.ts`, not an external one.
   The rest of this point stands: an empty list fails the pins test, so it cannot
   ship empty by omission, and widening the set beyond what REQ-059 criterion 4
   names is a change to that requirement first.

## Alternatives considered
1. **Each of the three writes its own list** — rejected. Three copies of one
   membership set, diverging silently, with the customer's own site as the
   surface the divergence appears on. This is rule 2.4's failure with a
   third-party consequence.
2. **Derive the unblock lines from what the scan found blocked, with no canonical
   list** — rejected. It cannot answer "0 — nothing is blocking AI readers"
   (REQ-009 criterion 3), because a count of zero needs a denominator: zero *of
   what*. Without a fixed set there is no such thing as a measured zero here,
   only an absence, which is precisely the distinction REQ-004 criterion 7 exists
   to preserve.
3. **Put the list in BP-027 and let BP-004 and BP-024 import from it** — rejected
   under `structure.md` rule 6: `src/lib/` may not import from `src/app/`, and
   BP-027 lives in `src/app/(public)/`. It would also put a shared constant
   inside a rendering node, against `structure.md` rule 5.
4. **A `## Decisions` entry inside BP-027** — rejected under rule 2.2's file
   test. The reader most likely to break the property is whoever next edits
   BP-004's hosted robots file or BP-024's count, and neither would open BP-027.
5. **Let the list be a customer setting** — rejected. `BUILD.md` §17 forbids
   settings that tune the engine, and REQ-070's uniform-value rule requires the
   same measurement for every customer.

## Consequences
- Adding an AI reader is one line in `constants.ts`, and it moves the count, the
  paste block and the hosted robots file together, on the same deploy.
- Every free report's blocked-readers count is comparable with every other
  report's, which is what REQ-009 criterion 8's monotonicity rests on.
- The seam is buildable now and the list is a known, tracked hole rather than an
  invented one. A build that ships with the list empty fails its own pins test.
- **Cost of reversing:** low in code, high in effect. Splitting the list again
  costs nothing at the keyboard and reintroduces a contradiction that appears
  only on a customer's own site, in a file they pasted a year earlier and will
  not revisit.
