2026-10-22  **Editing a live page saves a new version at the same address** (owner ruling R19(a) of 2026-10-22: "edit a live page = a new version at the same address", through the refresh path and the state machine; the details D1–D7 are drafted defaults the owner may correct, #759; #1827). The live row is never edited (ADR-080). D1: opening the editor writes nothing; the first save whose title, body or description differs from the live version creates a `refresh_page` at the page's own address and for its own search (cause `edited`) and one new `drafts` row, and an unchanged save writes nothing. D2: the new row starts as a copy of the live text, is held in `needs_attention`, takes the customer's words through the editor's own save (the same battery and claim check), and a save that passes enters review on a fresh window (`needs_attention → in_review`, the customer's edge), told and scheduled as the evening's pages are; one that fails stays in `needs_attention`, editable, and the live version stays live. The versions already at that address are not near-duplicates of the new one. D3: one version of an address waits at a time: a version already written and not yet out (`generating`, `in_review`, `approved`, `publishing`, `failed`, `needs_attention`) refuses the save with `pending_version` and its id, and nothing is written; a refresh only planned gives way (its row is dismissed, a `planned` draft skipped). D4: §6's floor and the weekly pace do not apply (no model, 0¢, the customer asked); the version carries `meta.first_edited_at`, so the live re-check and the `structure` and `link` refreshes leave the page alone. D5: the new version moves the updated date, `dateModified` and `lastmod`; the published date stays; no `datedAs`. D6: on WordPress it updates the same post through the refresh publish path. D7: a page the customer took down (`unpublished`) is refused with `not_live`; another site's page and the reserved fixture account with `not_editable`.
