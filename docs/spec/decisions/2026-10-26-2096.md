2026-10-26  **A deploy that does not change how a stored scan is scored does not download the corpus** (owner, #2096: stay inside the Supabase Free egress quota without a plan change). (1) The derivation of 2026-10-17 (issue 1481) is a fingerprint of the files under `src/lib` the re-score reaches by its static *value* imports. A type-only import is erased by the build and never runs while a scan is scored, so the module it names, and the vendor transport only such imports reached, no longer count. A change to a file the re-score executes, the guard constants included, is still a new derivation, and the tick still asks the dry run, the apply where the guard holds, and the check, with no owner step. (2) A re-score asks the database for the home reads it scores with, not each domain's whole history: for each report, the newest plain read at or before its on-page facts, and the rendered reads at or after it until one drew the site (or one rendered read where none follows, as any rendered read keeps Content unread). Every stored scan is scored exactly as the whole history would score it. Left alone: the guard, the score, the staleness line, and one download for the dry run, apply and check.
