2026-10-19  **Every hosted host is verified with Google and Bing by ReachKit, and each page shows how far it has got toward being found** (owner on issue 1553: *"approved for all, following precisely the seo master recommendations, to ensure we see clear progress from week 1 with our published content"*, adopting R2 of the SEO metrics review of 2026-10-19; every sentence is drafted and the owner may correct it). (1) *Verified.* Each live hosted host is a URL-prefix property in Google Search Console and in Bing Webmaster Tools under ReachKit's own account, verified by the meta method: the hosted index prints `google-site-verification` and `msvalidate.01`, stored on the destination. Its sitemap is submitted to both. Search Console holds 1,000 properties per account, so the Google credential is a pool of service accounts and a new host goes to the first with room. No customer step. (2) *Read weekly, per page,* before the week is judged: URL Inspection (indexed, coverage, last crawl), impressions, clicks and best place by query over 28 days from Search Console, and impressions, clicks, best place and last crawl from Bing. Bing's AI Performance report has no documented API on this date and is not read; *cited* is an AI answer to the page's own tracked question citing the page, from the stored page questions. (3) *Crawled.* A hosted page counts Googlebot and Bingbot fetches by day, page and engine, as it counts answer-engine fetches, and only from an address inside the engine's published ranges; the address is checked and dropped, never stored. This amends this section's line of 2026-09-20 ("Nothing else about a visit is kept"): verified search-crawler fetches are kept too, as counts with no visitor identity. (4) *Announced.* Each IndexNow request the service accepts stamps the pages it carried, and the weekly pass announces once every live hosted page never accepted, which includes every page published before issue 1511. (5) *The ladder:* published → crawled → indexed → shown → placed → cited, on the page's screen as daisyUI `steps` under the title `record.ladder.title`. Each step is read from a stored row: a step proved is marked, a step a source read but has not seen is drawn plain, and a step nothing can read is not drawn, so "not verified" is never "not indexed". Issue 1538's `seen` also reads URL Inspection: a page Google calls indexed is seen. Without the Google or Bing credential the pass asks that engine nothing and the ladder draws only what ReachKit's own rows prove. 0¢: every call is free.
