2026-11-01  **A scoring deploy reads every stored scan once: one guarded apply replaces the dry run, the apply and the check** (#2254, under the owner's egress ruling of 2026-11-01: *"ship the egress fixes, stay on free for now"*). This amends 2026-10-17 (#1481) (2), the mechanism only. Production's `scan/rescore` tick, finding no run at the deployed derivation, asks one apply itself. That run scores every stored scan in memory and decides the guard of #1481 (3) before it writes anything. Where the guard holds, it writes nothing, says why, and lists every scan it would move as stale. Where the guard passes, it writes each moved scan through `rescore_scan`, which raises on a change that did not land, so no check run follows. A scan written by someone else between the read and the write is left alone, and that run reads the stored scans again. A scan that still moves holds the run (the apply lagging) and stays stale. One that now reads as the deployed code does is not stale. Any finished run at the derivation settles it. A held or failed one asks nothing more, as before. A person may still ask a dry run, which writes nothing. A person's apply is not guarded, because it is how a held run is moved on. #1426 (every stored scan, 0¢), #1481 (3) (the guard) and #1481 (4) (the silent window is at most a tick) are unchanged.
