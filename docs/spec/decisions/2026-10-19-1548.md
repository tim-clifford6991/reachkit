2026-10-19  **A page's place is read from the Google result already bought for it, and a page never seen is never *Not working*** (issue 1548, from the SEO metrics review of 2026-10-19, R1; conditions 1–4). (1) *The result already bought.* Each week's page question buys one Google result for the page's own target (§6, #908). Its organic rows are stored on the page question's row, and a `top20` test on a target outside the twelve reads the page's place from them first, through the page's own addresses (#1518), to the depth bought, then from the ranked rows. A place is the place held: a page at 37 is measured at 37, which is outside the top twenty and fails the test; it is no longer stored as a zero. (2) *Untracked target.* The keyword database's ranked rows can say a page holds no place only on a search it tracks: one it measured demand for (the page's own volume, or a market suggestion with volume). Where it does not track the target and the bought result does not hold the page, the place is `not_measured` — no row is written that week — never a measured zero. (3) *Never seen.* A page no stored result has held (#1538's `not_verified`, now also reading the page questions' results) is never *Not working* on a `top20` or `named_on` test: past three weeks it stays *Too early*, so it suppresses no cluster, is not retired by the retire guards, and asks for no refresh on that ground; #1538's `unseen` fix runs instead. A gate or site-check test is judged as before. Where the stored addresses cannot be read, nothing is stated and the page is judged as before. (4) The page question rows already stored are given their organic rows from the same purchase in `fetches`, at 0¢ (`20261019120000_scans_page_question_organic.sql`). Weekly spend is unchanged: no call is added. An eight-week clock before a new site's page can be judged is condition 5, the owner's.
