2026-11-06  **A day whose new page does not pass takes a ready update from the committed week, in the same run** (owner, 2026-11-04 and 2026-11-05: "each day must have new or updated content, no exceptions"; #2388). Decision: when the day's run ends without a page for a reason of its own (`generate:*`, but not `no_site` or `no_scan`), the same run reads the committed week only, never a re-ranking. It takes first a ready update spare, then a ready update committed for a later date of the week, latest date first. Within each, ReachKit's own refresh comes before an `improve` row. A candidate enters review only where it passes today's whole battery. Tier A0 is a code-mended `structure` refresh at 0¢, on every such day. Tier B is a writer-made refresh from stored research only (no DataForSEO), inside the day's one `CAP_DRAFT`, and only when the day's `select` found no topic and so spent nothing (owner, 2026-11-05, R-F1 yes). It never runs after a page was written, and a day never spends above its cap or opens a second cost context (R-F2 no). A row the rules stopped gives up its date only to an update that takes it. With no passing candidate, the day keeps its own reason, and nothing is padded or invented. No later-hour retry (R-1, 2026-11-04). Until the owner rules R-F3, the 30-day refresh floor stands, so a customer's first 30 days are filled by new pages or stay an honest empty day. The day's record reads `drafted` with reason `refresh:<original reason>`.
