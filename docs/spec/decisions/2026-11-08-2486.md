2026-11-08  **A page load verifies the session locally** (owner, 2026-11-07, #2486, ruling R-C: "use `getClaims()` instead of `getUser()` on page loads"). A page or layout render reads who is signed in from the session token's signature (`getClaims()`), once per request, with no Supabase network call; the account row still decides, so a tombstoned or unreadable account is no session. A session ended on another device keeps reading on pages until its token expires. Every Server Function and Route Handler that writes keeps `getUser()`, Supabase checking the user afresh, and so refuses that session at once. Speed Insights stays off (R-E).
