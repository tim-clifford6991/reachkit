# Design

How a screen is built today. Rulings and their history are in git; this page holds only the rule that is current. Where a dated line in `docs/SPEC.md` says what a screen does, that line wins over anything drawn.

## The stack

1. **daisyUI** — one theme, `reachkit`, in `src/ui/tailwind.css`. A screen is daisyUI classes in its route file: `btn`, `card`, `navbar`, `footer`, `input`, `select`, `badge`, `stat`, `table`, `alert`, `toggle`, `tabs`, `collapse`, `progress`, `steps`, `drawer`, `dock`, `skeleton`, `filter`, `timeline`, `list`, `status`, `tooltip`, `toast`, `modal`, `fieldset`, `validator`, `mockup-browser`, `mockup-phone`.
2. **Recharts 3** — every series (line, bar, sparkline), each in a `ResponsiveContainer`, stroked and filled from the theme's chart colours, labelled directly with no legend box. A grid that is not a series (rivals × questions, the week strip, the AI-answers matrix) is CSS grid.
3. **lucide-react** — stroke 1.75, 20px in chrome, 16px in badges. No emoji.
   - 2026-10-24 E29 (ux-designer, owner-delegated): one icon per concept; the boards' choice wins: AI `Sparkles`; Page-ready mail `MailCheck`; Monday mail `Inbox` (everywhere); Planned `Calendar`; Being written `PencilLine`; Written/waiting `Clock`; Live `CircleCheck`; Update `RefreshCw`; New `Plus`; Stop `CircleStop`; Edit `Pencil`; Your business `Building2`; Links to this page `Link`; Mentions you, no link `MessageSquare`; No answer / too big `CircleMinus`; Names no one `CircleDashed`; Up next `List`. Retired: `Bot` (use `Sparkles`), `Link2` (use `Link`). An icon is imported under its own name, never an alias. `tests/ui/design/icon-vocabulary.test.ts` holds the retired list.
     - Page-ready mail `MailCheck` only; the sign-in link mail `Mail`.

Spacing and type are Tailwind's scale (`p-4`, `text-sm`). Colour is the `reachkit` theme. There is no pixel baseline. The gates check the strategy in this page. The owner looks at `dev.reachkit.app` for taste.

Admitting new UI: a daisyUI class → a daisyUI class plus a theme colour → Recharts → lucide → a library on the list below → stop. A pull request that adds a custom component, a stylesheet, a token, a type scale or an SVG chart where those already cover it is rejected. Do not wrap daisyUI in a `Btn` or `Card`.

## Theme

One `@plugin "daisyui/theme"` named `reachkit`, `themes: false`, in `src/ui/tailwind.css`. Colours have one set of names, daisyUI's slots — `base-100`, `base-200`, `base-300`, `base-content`, `primary`, `success`, `warning`, `error` and their `-content` — and their values live in `src/ui/theme.css`, light and dark (2026-09-25, #1110). Beside them sit only the colours no slot names: `--bg` (the page ground), `--ink-2` and `--ink-3` (muted text), the tints (`--accent-bg`, `--ok-bg`, …), the chart series (`--chart-you`, `--chart-rival`, `--chart-goal`) and the two shadows. A screen reaches them through daisyUI classes and Tailwind utilities (`bg-base-200`, `text-primary`). Every colour spent on text clears 4.5:1 in both themes against the worst ground it is drawn on. Mail carries the same light values in `src/lib/mail/shell/tokens.ts`, because an inbox has no stylesheet; a test holds the two equal.

- 2026-09-25  **Softer ink, tinted ground** (owner, #1104). In light, ink is a dark slate and the ground and its two neighbours a faint cool tint; muted text is `text-base-content/70`, never `text-base-content/60`, which falls under the floor. Dark is unchanged.

Type is Plus Jakarta Sans (400, 500, 600, 700, 800; 800 italic, latin, for catch words only) with JetBrains Mono for domains, dates, searches and code. Big figures — scores and stat numbers — are Plus Jakarta Sans 600 with `tabular-nums`.

- 2026-11-16  **Catch words** (owner, #2745). A public hero H1's 1–3 catch words are `<em>`, Plus Jakarta Sans 800 italic (latin, one file from the installed package), `italic font-extrabold text-primary bg-primary/15 rounded-field px-1.5 box-decoration-clone`. The title key's sibling `.mark` key holds them. Never in `/app`, mail or hosted pages; no new font. A one-word title marks nothing. They are: Landing "Get Found"; How it works "Gets You Found"; Pricing "Everything Included"; About "ReachKit"; Scan library "in the Open"; Compare "ReachKit"; Free tools "Free"; Teardowns none. The two tool pages carry none until a ruling names them.

The theme control is a two-state light/dark switch in the public header, the first visit following the system, and a Light / Dark / System `dropdown` in the `/app` shell (`src/app/_theme/ThemeToggle.tsx`). System sets no `data-theme`; Light and Dark set it on `<html>` before paint. Never on hosted pages.

## The calm layer

The current look of every screen, drawn on board [`Calm`](design/boards/R12-0-Calm/R12-0-Calm.dc.html) ([render](design/boards/R12-0-Calm/R12-0-Calm.jpg)).

- **Type.** `word-spacing: .06em` on `body` and `.04em` on headings. Heading tracking tightens with size: −0.015em at 18px, −0.02em at 20–25px, −0.03em from 31px.
- **Buttons.** One solid primary button per section; the public header's *Scan My Site* is outside the count (2026-10-19, owner, #1581; wording owner, 2026-11-14, #2657), except the public phone offer bar (owner, 2026-11-20, #2981). Secondary actions are `btn-soft` or `btn-ghost`, never an ink `btn-outline`. *Stop* is a ghost in `warning`. Filters are pills, the current one solid ink. Press is `active:scale-[.98]`.
- **Edges and lift.** `--shadow-card` is a 1px ring plus a 1px shadow in both themes. A clickable card lifts 2px on hover and its arrow nudges 3px; a card that does nothing does not move. The deep floating shadow is spent twice only: the landing's app picture and the report's price card (owner pick, 2026-11-16, #2756).
- **Motion.** One easing, `cubic-bezier(.2,.7,.2,1)`. Press 120ms · hover colour 150ms · lift 200ms · tab underline and chevron 250ms · screen enter 600ms (rise 8px, 60ms stagger) on a client navigation only; a document load paints its content at once (owner, 2026-11-07, R-D, #2491) · chart draw 1.4s, once, on first view; a figure is the number, drawn at once · loops: a 2.4s pulse on the *Live* and *Your review* dots. 2026-10-19: there is no *Recently scanned* strip at launch (owner, A5, #1581), and no `animate-drift` loop. Tailwind utilities (`motion-safe:`, `starting:`) and React 19 `<ViewTransition>`; no animation library. Under `prefers-reduced-motion` nothing moves and the final state is drawn; the layout gate renders that way. Anything new gets at most a 150ms colour ease. 2026-11-18: the landing's logo band moves continuously, one site about every 5 s, by one `animate-logos` keyframe. It slows to a quarter on hover, stops while a logo has keyboard focus, has a Pause control, and does not move under reduced motion (owner, 2026-11-18 ~14:05, #2900: "automatically rotating with our logos without interaction. the animation should slow when moused over"). This replaces the 2026-11-16 stepping line (#2745) and reverses the 2026-10-19 A5 line for that band only; no other `animate-*` loop is added.
- **Fold.** 2026-11-20 (owner, #2985): An app screen fits a 1280×800 window with no page scroll; a long list opens in a dialog or scrolls inside its card. It refines the shell's "only the content scrolls". A setting is one line, its label, value and *Change*, and *Change* opens a daisyUI `modal` (`settings/EditDialog.tsx`), full screen below `sm`.
- **Rhythm.** Cards in a row stretch to one height. Empty days, empty lists and zero states are quiet — flat grey cells, a tick and one line — never a white card or a coloured alert per empty thing.

## Busy and done

- 2026-10-02  **One busy pattern for every action that starts work** (owner, #1196). It covers Measure again now, Check connection, Write it again, Skip, Stop this page, setup's steps, every Save in Settings, and billing.
  1. **Pressed.** The button is disabled at once and shows daisyUI `loading loading-spinner loading-xs` in place of its icon, so a second press cannot happen. The pending state comes from React: `useActionState`, `useFormStatus` or `useTransition`. A screen does not build its own flag for it.
  2. **Background work.** A deep pass or a re-measure is described in one place only: the side panel's status line. That line shows the current step, the time the step started, and then its end, which is *done*, *failed* with its reason, or *stopped* with its cause. It never shows a step from an earlier pass. A press clears the previous pass's state before the new one is drawn. A page being written shows its own *writing* state on the screen that holds it. The press that started the work answers once; it does not leave a second status line behind.
  3. **Done.** The screen that started the work refreshes itself when the work ends. The button becomes active again. A `sonner` toast or one inline line says what changed.
  4. **Failed or refused.** One line beside the control that was pressed says why: a rate limit, a check that could not run, a vendor outage.
  5. **Nothing silent.** Any action that can take longer than about a second shows this pattern. No work runs without a visible state.

  Built from daisyUI `loading`, `alert` and `btn`, lucide icons, and `sonner`, with no wrapper component. *No loading screens* (SPEC §4) still applies to routes, which use skeletons. The spinner appears only inside a pressed button, and on the one screen that is itself the wait: setup's time-zone card, which has no button (board SetupZone v36, #2270).

## Layout that cannot overflow

- No element is wider than its container and no text is clipped by its card at 390, 768 and 1280 pixels, in light and dark. CI renders every route at those widths and fails on either; `@axe-core/playwright` runs in the same pass.
- A bar gets its own full-width line under its label, never the space left beside one.
- A label that can grow (a title, a domain, a search) is clamped to one or two lines with an ellipsis; a number is never clamped, so the box changes instead.
- 2026-10-15  **A URL wraps** (owner, issue 1456). A page address — a link or a line that shows one — is `font-mono break-all` in a `min-w-0` box: it keeps the mono face and breaks anywhere, never `.num` (which cannot break) and never a sideways scroller. Found on Settings at 390: a long link scrolled the whole page. The reserved account's Settings fixtures carry an address longer than a phone is wide, so the gate measures one.
- A step indicator is daisyUI `steps` with one-word labels.

## Screen rules

What each screen, public page and mail holds and says. A line keeps the name and section it had in `docs/SPEC.md`, so a citation of SPEC §n *Name* reads here. Where a board and a line here disagree, the line wins; SPEC's own rows win over both.

### Copy

- **One vocabulary** (§0). One word per idea on every surface: free report, app, mail, landing and meta. In an AI answer a site is **mentioned** or **linked**, never named, cited or quoted. A Google position is **the first page** or **the first two pages**. Checking again is a **scan** ("Scan Again"). The Google ladder reads Live, Found by Google, Showing, First page, with no Listed rung. Section, tab and mail names equal the bar names: **Google**, **AI**, **Competitors**. The public header's button says **Scan My Site** (owner, 2026-11-14, #2657). Keys nothing in `src/` reads are deleted. (owner, 2026-10-15, #1444; ladder and button, 2026-10-19, #1581)
- **Short titles** (§0). Every heading, card title, finding line, tab, mail subject and meta title is at most 6 words, one idea and no em-dash; a number goes in the figure and any explanation in one line under it of at most 12 words. Meta titles join with "·". Notices and leads over 20 words are cut to the one fact the reader needs. (owner, 2026-10-15, #1444)
- **Plain words** (§0). Every customer-facing string, from the landing to every mail, follows O6's twelve rules: sentences of 8 to 12 words and at most 15; at most 2 sentences a paragraph; lead with what the reader gets or does; plain words, never SEO, index, crawl, CNAME (outside setup's DNS steps), derivation, pass, re-score, supply, spares, veto, draft, opportunity, keyword, prompt or fetched; "you" and "we"; no asides; numbers from the facts; each thing once a screen; honest claims only, never "recommends you", never name an AI engine the scan did not ask, never a ranking promise; one name a concept; an error says what happened and what to do. Three rules more (owner, 2026-11-14, #2657): a button or link names its act, a verb and its object (*Stop This Page*), and a link that only opens a screen never says *Check*; a status or wait line gives the result and the reason, or until when the reader waits, and a countdown alone is never one; one act has one name on every screen and mail, and its answer keeps the verb (*Stop*, *Stopped*). Customer pages' own text, engine names, legal wording, owner-only keys, `keys/de/` and the Hosted, Review, AppCosts and Legal boards are exempt. `scripts/lib/plain-words.mjs` is the one parser; `audit` and `tests/ui/design/strategy.test.ts` compare each touched key file and board with the pull request's base, and a count may fall and never rise. A rule-4 word with no hit left is a retired name, zero tolerance, on keys and boards. (owner O6, 2026-10-31, #2145; base count, architect, 2026-11-01, #2222; buttons, status lines and one name an act, owner, 2026-11-14, #2657; engines the scan asked, owner, 2026-11-16, #2739)
- **Title Case** (§1). ReachKit's own public pages, `/app`, and the headings and buttons inside ReachKit's mail set nav labels, tabs, titles, headlines, headings, card titles, buttons and calls to action in Title Case. The small words (a, an, and, as, at, but, by, for, in, nor, of, on, or, the, to, vs, with) are lower case unless first or last. A title has no closing full stop. The case is set in the copy keys, never by `text-transform`. Sentence case stays for body text and full-sentence leads, status and error lines, toasts, form labels and badges, mail subjects and preheaders, and legal text. On a page ReachKit writes for a customer the article title is Title Case in English, from the `title-case` library with a word's own casing kept, and a German title stands as written; its section headings stay sentence case. `<title>` and meta titles are unchanged until seo-master answers. (owner, 2026-11-16, #2745; article titles, owner ruling 88.4, 2026-11-22, #3269)

## Libraries

A dependency is admitted only where it deletes hand-written UI code. This is the whole list; anything else needs an owner ruling. Each is pinned and checked against React 19 and Next 16.

| Library | It replaces |
|---|---|
| `date-fns` with `@date-fns/tz` | Hand-built calendar and zone arithmetic: the month grid's dates, a site's local week and midnight. |
| `@tanstack/react-table` 8 | Sorting, filtering and paging of the Search and Rivals lists, rendered as a daisyUI `table`. |
| `nuqs` | Hand-rolled URL state: month, day, tab, filters, setup step. |
| CodeMirror 6 — `@uiw/react-codemirror`, `@codemirror/lang-markdown`, `@codemirror/lint` | The editor textarea; rule breaks are lint marks in the text. |
| `mdast-util-from-markdown` with the GFM-table and directive extensions | A hand-written Markdown parser. The closed, escape-everything serialiser stays ours. |
| `@tailwindcss/typography` | Hand-kept article classes (`prose` on hosted pages and the preview). |
| `sonner`, drawn with daisyUI `alert` classes | Silent actions: every action answers. |
| `react-email` on Resend | A custom mail block system. The one package; every `@react-email/*` package is deprecated. It renders through its own `render()`, never `react-dom/server`, which the App Router refuses to build. |
| `@axe-core/playwright` | Hand checks of accessibility, run with the no-overflow check. |
| `title-case` | A hand-kept small-word list: an English page's title in Title Case, its brand casing kept (owner ruling 88.4, 2026-11-22). |

Use what is installed before adding anything: daisyUI `drawer` and its `is-drawer-open` / `is-drawer-close` variants, `inngest/realtime` and `inngest/react`, React 19 `useActionState` / `useOptimistic`, Next `after()`, Postgres `pg_trgm` and full-text search.

Not admitted: a second component system (shadcn, Radix, Headless UI), a form, state or animation library, `react-markdown` (the preview is the publishing renderer), a second chart library, Storybook.

## Do not

- Add a stylesheet under `src/ui/`. `idiom.css` only shrinks, toward deletion.
- Hand-roll an SVG chart. `chart-primitives.ts` survives only for the OG card's two SVG tokens and goes with that card.
- Write a test that transcribes this file, pins a colour's private name, or forbids Tailwind's scale.
